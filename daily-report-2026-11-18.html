Cloudflare Joins the Jevolution and Labels Itself a Neolab 📄（2026-11-17 15:00 UTC）

文章 · 作者 Richard MacManus · 約 8,100 字 · 非音頻集數，屬深度報導

主題

Cloudflare 的 AI Platform 產品負責人 Michelle Chen 在 AI Engineer Code Summit 演講中，把 Cloudflare 定義為「neolab」，並宣布兩個自家 System One 模型：Clef（決策模型，直接受 TypeSafe AI 的 Jev 啟發）與 Clairic（Cloudflare 稱之為「extract model」的新型 System One）。文章的重點不在模型本身，而在一個判斷：基礎設施公司為什麼要下場做模型。

嘉賓背景

Michelle Chen，Cloudflare AI Platform 產品側負責人。她的表述有兩個身份特徵：一是產品人（談的是「哪些請求不必送去 LLM」），二是平台方（談的是授權、監管、供應風險）。這解釋了為什麼 Cloudflare 的模型戰略從一開始就不是「追前沿」，而是「消除依賴」。

核心論點
  • 論點一：不是所有請求都值得送進 LLM。Chen 把 Jev 的出現形容為「東風」——「當 system one 與 Jev 範式出現時，我們覺得這對我們太合理了。我們不必把每個請求都送去 LLM，可以把一部分送去 System One 模型。」這是整篇文章的技術前提：延遲以毫秒計的場景（Cloudflare 的本業）與以秒計的推理模型天然不匹配。
  • 論點二：NeoLab 的定義正在被稀釋，但 Cloudflare 認為自己符合「能力邏輯」而非「資本邏輯」。文章直接指出 Cloudflare 至少不符合 neolab 定義的一半條件：它是上市公司、有實質營收（Q3 營收 7.82 億美元、年增 39%、年化 30 億美元）、不是「沒有營收牽引力」的初創。Chen 的辯護是能力路徑論：從基礎設施 → 算力（Workers 平台）→ 儲存 → 托管開源權重模型（Kimi、GLM、DeepSeek on Workers AI）→ 自建模型，是一條自然演進線。「成為 neolab 意味著我們可以創造我們缺失的東西。」
  • 論點三：複製的成本已經塌陷。Clef 是 Jev 的複製品，團隊兩星期做出來；而 TypeSafe AI 造 Jev 花了兩年。Chen 把這當成對 TypeSafe 的恭維——「API schema 該長什麼樣，我們已經完全知道」。但這句話同時是整篇文章最锋利的事實：一旦範式被公開，實作就变成兩個星期的工程問題。
  • 論點四：第二個模型才是原創性的證明。Clairic 不是複製，而是把 System One 原則搬到另一個 LLM 被濫用的場景：從非結構化輸入中「抽取、計算、估算、預測」出一個帶型別的值，一次前向傳播完成。Chen 的問題意識很具體——LLM 是自回歸的，所以會幻覺、會吐出格式錯誤的 JSON；而發票上的訂單號「就在那裡，你只要讀它就好」，模型卻會猜「三還是四還是五」。
  • 論點五：自建模型是風險對沖，不只是產品擴張。Chen 的說法異常直白：Jev 是閉源的、他們跑不了；市面上有監管風險（點名中國開源模型）；「很多模型實驗室想真正賺錢，於是執行相當昂貴的授權」。三種風險——不可得、不可用、不可負擔——構成基礎設施公司下場的商業理由。
  • 論點六：不做預訓練。Chen 明確表示未來可能做推理模型與其他 LLM，但「那大概不是我們的重點」，團隊「大部分只做後訓練」，路徑是拿現有資源做得更高效，而非從零預訓練。這是對「neolab」稱號最實質的限定：Cloudflare 要的是能用、能省、能控的模型，不是前沿能力。

技術詳情

System One 是什麼。這裡的「系統一」借用心理學的雙系統：非生成式的模型，輸出的是結構化的選擇、分數或機率，而不是逐字生成的自然語言；推理 LLM 則是「系統二」。關鍵差異有三：輸出空間（離散選項 vs 開放文本）、成本（單次前向 vs 思維鏈）、可靠性（可驗證的 schema vs 幻覺風險）。

Clef。決策模型，直接照 Jev 的 API schema 複製。它回答「這個請求屬於哪一類／該不該做某動作」，所以能嵌進應用程式碼裡，取代一條 if/else 或一次 LLM 呼叫。

Clairic。Cloudflare 原創方向：輸入非結構化文本（發票、表單、文件），輸出帶型別的值——抽取、計算、估算、預測，單次前向完成。技術要點是把「讀取」與「推理」分離：如果答案字面上就在輸入裡，用抽取而非生成，就消掉了自回歸的錯誤累積與 JSON 格式失敗。

為何是後訓練。團隊「大部分只做後訓練」，意味著路線是拿開放權重或既有基礎模型做對齊與蒸餾，而不是重建預訓練管線。這與 Blattmann 在 BFL 那集的觀點形成有趣對照：一邊是「單一骨幹學多模態」，一邊是「用既有資源做便宜可靠的專才」。

行業 insight
  • NeoLab 這個標籤正在從「資本類別」變成「能力類別」。原始定義（The Information 的 Stephanie Palazzolo，去年 11 月提出）是「新一代研究導向 AI 初創」；Deedy Das 的清單再加四條硬指標：精英研究者、大量算力、無顯著營收、巨額募資。Cloudflare 拿下這個標籤，等於宣告：能不能做模型比是不是初創更能定義 neolab。這對所有「基礎設施 + 模型」混合體（Databricks、Snowflake、甚至雲廠）都是先例。
  • 模型層的護城河正在從「訓練」前移到「schema 與分發」。兩星期複製一個兩年的模型，說明範式一旦公開，實作壁壘極低；真正稀缺的是 API 設計、評測方法、以及「知道該在哪裡放系統一模型」的產品判斷。這與十字路口趙晨陽那集「評估是 RSI 唯一瓶頸」其實是同一個結構：誰定義了評測與介面，誰就控制了擴散速度。
  • 推論成本的壓力正在重塑採購決策。一個 CDN 公司說「不必把每個請求送去 LLM」，在兩年前是效能考量，現在是毛利考量。當 token 單價成為財報項目（Anthropic 的 compute 佔營收比例從 251% 降到 48%），路由到小模型就從工程優化升級為財務策略。
  • 「監管風險」首次成為美國公司自建模型的白話理由。Chen 點名中國開源模型的監管風險與授權漲價，這是把地緣政治與授權 economics 直接寫進產品路線圖。基礎設施公司不能承受上游斷供，這條邏輯會在半導體之外重演一次。
  • 但也別忽略反面。Cloudflare 沒有公布 Clef 或 Clairic 的任何 benchmark；「兩星期複製」是單方說法；「System One」的效能優勢在真實流量下是否成立，仍待第三方驗證。文章本身也承認 neolab 標籤「聽起來有點像行銷花招」。
前後脈絡

這條線的起點是 9 月 Jev 發布——Latent Space 稱那集成為他們全年最受歡迎的一集。此後擴散速度極快：Glean 用它做零樣本決策路由（「決策空間的分類法改變時，我們不必反覆微調」）；UiPath 用它做文件 chunk 排序，用「錦標賽」方式分組淘汰，數千次 Jev 呼叫在一秒內完成；Workday 用它做「你還在打字、請假單已經填好」的介面。TypeSafe 的 Diogo Almeida 在 AIE Code 的主題演講把這件事上升到宣言層級：「代碼是自動化的語言，所以你需要與代碼整合」、「你 95% 的時間得到愛因斯坦，5% 的時間得到豆豆先生——如果你分不出哪個是哪個，你要怎麼自動化任何事？」

把 Cloudflare 這一步放進更大的時間線：11-13 Dwarkesh 的 RSI 討論說的是「AI 加速 AI 研究」；11-15 十字路口趙晨陽說的是「評估成本決定 RSI 速度」；11-16 BFL說的是「視覺智能是系統一、與語言模型互補」；11-17 Cloudflare則是「系統一變成基礎設施公司的標配零件」。四集其實在講同一件事的不同樓層：能力在往上衝，而把能力切成可路由的碎片才是產品化的關鍵。

爭議點與待驗證
  • NeoLab 標籤的通脹。一家年化 30 億美元、39% 增長的上市公司自稱 neolab，若這個詞最終什麼都指，就什麼都不指。
  • 「兩星期」的比較是否公平。複製一個已知 schema 的模型，與發明一個範式，難度不可比。Chen 自己承認了這一點，但標題式的數字仍容易被誤讀為「TypeSafe 效率低」。
  • 封閉 vs 開放的雙標。Cloudflare 批評 Jev 閉源、自己跑不了；但 Clef 與 Clairic 同樣沒有開源承諾。它反對的是「別人閉源」，不是閉源本身。
  • 沒有基準。延遲、準確率、成本節省全部缺席。對一個以「毫秒」為賣點的模型家族，這是最大的資訊缺口。

三個值得記住的信號
  • 「便宜」正在成為一種能力，而不只是價格。Qwen4-Max 的分數從 34 升到 43，同時成本降到三分之一、輸出少四成——這不是打折，是效率曲線在移動。當每 index 任務成本變成可比較指標，模型的競爭單位就從「benchmark 分數」變成「每分多少錢」。
  • 開放模型在企業端的臨界點可能已經過了。Databricks 上開放模型 token 佔比 3.5 個月從 7.3% 到 30.9%。這與 Cloudflare 托管 Kimi/GLM/DeepSeek 的動作、以及它對「中國開源模型監管風險」的擔憂，構成同一個現象的兩面：採用速度已經快過風險管理速度。
