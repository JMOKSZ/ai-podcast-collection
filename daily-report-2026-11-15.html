Agent 賽道复盘To B 落地自訓私有模型反平台敘事

主題：沿著 Agent 這條線做下來的完整复盘——從開源專案 AFFiNE 為什麼紅、為什麼沒能好好商業化，到 2026 年 Agent 產品形態收斂到哪裡，再到 To C 與 To B 兩條路的結構性差異，最後落到「一個應用公司為什麼要自己訓模型」以及人才組織。

嘉賓背景：賀嘉琛（節目中稱「嘉琛」）。原研究深度學習與天體物理學，2020 年從博士階段退學創業。第一個專案是開源文檔協作與知識庫 AFFiNE，一度做到 700 萬用戶、Product Hunt 年度第四；之後與尤雨溪（Evan You）等人一起孵化開發者工具公司 VoidZero，被 Cloudflare 收購——他本人也因此在開發者工具與開源商業化這兩件事上，同時拿到過「流量」與「退出」兩種經驗。現在做的是 To B 的 Governing Agent 產品 Afk.surf：讓企業接管並持續學習自己運行的各個環節，在服務不同員工的同時，對齊整個組織的業務、工作方式與使用偏好。節目明確點出一個事實：他們已經有幾個大客戶，而不是還在講故事等正反饋的階段。

核心論點

論點一：從 2026 年開始，Agent 就不像軟件了。這是整集的分水嶺（章節 05:43）。軟件的價值模型是「把一個已知流程固定下來，然後複製販賣」——所以有席位、有版本、有功能清單。Agent 的價值模型是「接管一個環節，然後持續吸收例外」——例外不能事先窮舉，只能靠在環境裡跑、被糾正、再收斂。這個差異往下傳導到三件事：怎麼計價（按席位還是按接管的工作量）、怎麼驗收（功能清單還是行為邊界）、怎麼實施（安裝還是陪跑）。他選擇用「Governing（治理）」而不是「Assistant（助理）」命名產品，本身就是立場：企業要的不是一個更聰明的聊天框，而是一個能被授權、被審計、被約束的行為主體。

論點二：兩年劇烈變化之後，產品形態最近收斂到一個大趨勢上（08:19）。把時間軸攤開看，2024 年是 workflow 拼裝與 co-pilot，2025 年是 computer use 與 GUI 代理，2026 年上半年是「能跑很久但不知道自己在幹嘛」的長時程代理。收斂的方向是：帶私有上下文、有記憶、能在組織邊界內行動的長時程代理。這也解釋了為什麼「框架」在這個階段會快速失去獨立價值——見論點五。

論點三：2026 可能是 buzzword 最多的一年（10:43）。節目把這句放在「復盤 Personal Agent 發展脈絡」的子章節裡，語氣是自嘲式的。名詞通脹的清單大致是：Personal Agent、Computer Use、GUI Agent、Deep Research、RLaaS、Governing Agent、Neo Lab。名詞多，通常代表還沒有人找到穩定的評測方式——一旦有了公認的評測，名詞就會收斂成兩三個。

論點四（全集最尖銳）：To C 的 Personal Agent 還是平台型機會，但 To B 不是（13:41）。邏輯推演是這樣的：To C 端，所有使用者面對的任務分佈高度重疊（排程、寫作、查資料、比價），同一個助手可以服務所有人，因此資料飛輪與規模效應成立，最終是贏家通吃、平台定價。To B 端則相反——每家企業的流程、權限體系、資料邊界、歷史包袱、老闆偏好都不一樣，每一次交付都是一次客製化的重活。所以 To B Agent 的天花板不是模型能力，而是交付能力與組織信任；它的財務特徵更接近服務業或顧問業，而不是 SaaS 平台。這個判斷直接反對當前「AI 原生 SaaS 個個都是平台」的主流敘事。

論點五：從 LangChain 到 Dify 再到 n8n，這些公司過時了嗎（26:11）。節目的處理方式很務實：不是問「框架有沒有用」，而是問「框架解決的那部分問題，是否已經被模型本身吃掉」。當模型能自己規劃、自己呼叫工具、自己維護狀態時，框架剩下的價值就只有：可觀測性、權限、部署形態。這部分會留下，但不足以支撐一個獨立的大品類——除非它往「治理層」演化。這正好接回他自己的產品定位。

論點六：作為一個自己在訓模型的应用公司，是怎麼想的、怎麼做的（33:32）。這一段是技術含量最高的部分。他的理由是：To B 的差異化不在基礎能力，而在私有分佈——企業的術語、審批鏈路、例外處理、錯誤容忍度。通用模型的 benchmark 再高，也測不出「這家公司週五下午不走財務總監審批就算違規」這種規則。所以做法是把客戶的私有資料 + 私有評測 + 組織偏好，做成小模型與 RL 的訓練閉環，通用模型退化成「老師」與「兜底」。

論點七：AI 可能端到端消滅過去的各種邏輯？模型兩三年內可能普惠？（40:02）。這是一個開放式問題，節目的態度是「值得懷疑但值得下注」。如果模型兩三年內真的普惠（能力平價化），那麼護城河會全部轉移到資料、流程知識與信任關係上——這與論點四、論點六是同一套邏輯的三次表述。

論點八：AI 遊戲的 timing 是不是到了（42:34）。延伸話題，但有意思的是它與 11-13 張小珺那集 6 小時梁其偉訪談形成互文：一邊在談 3A 動作遊戲的手工藝與十九年積累，一邊在問 AI 遊戲的時機。同一個行業，兩種時間尺度。

論點九：怎麼招到這麼多「散是滿天星」的人（44:58）。從 AFFiNE 出來的人：前產品負責人做的 AirBuild 在 X 上小火、前 CTO 現在是 Cloudflare Principal Engineer、還有出海圈子熟悉的「生姜」。他的答案不是「願景」而是「讓人在這裡拿到可遷移的聲譽」——聽起來像廢話，但配合 AFFiNE 到 VoidZero 的履歷，這句話是有代價支撐的。

技術詳情：這集沒有給出模型架構層面的參數，但給出了一條完整的工程路線圖：(1) 私有上下文層——把企業的術語、權限、審批鏈路結構化；(2) 私有評測層——用企業自己的例外案例做 eval，而不是公開 benchmark；(3) 訓練層——小模型 + RL（RLaaS 的思路）把偏好壓進權重；(4) 治理層——授權、審計、可回滾。這四層的順序很重要：先有評測，才有訓練；沒有私有評測就自訓模型，等於在沒有指南針的海上加速。

行業 insight：這集實際上在給 2026 年的應用層畫分界線。第一條線：平台型 vs 服務型。To C 是平台生意（規模效應、贏家通吃），To B 是服務生意（交付能力、信任、客製化），用同一套估值邏輯去看兩者會嚴重錯配。第二條線：模型能力 vs 私有分佈。當基礎能力平價化，差異化只剩下「你比別人更懂這個客戶的分佈」。第三條線：框架層的黃昏。LangChain / Dify / n8n 不會消失，但會從「開發範式」降級成「部署與治理組件」。

前後脈絡：42 章經最近三集剛好構成一條完整的線——10-12 對談 Ambi 創始人子皓（Personal Agent 創業者的思考）、11-07 對談 Mind Lab 首席科學家驍騰（銳評國模與 Neo Lab、RL 人生與 RLaaS）、11-14 對談嘉琛（把前兩者的概念接到 To B 收入上）。如果只聽這一集，會覺得「自訓模型」是個大廠才有資格的動作；放回前三集的脈絡裡，它其實是「RLaaS 成本下降 + Personal Agent 形態收斂」兩件事的必然結果。另外，11-08 十字路口年終復盤裡莊明浩那句「RSI 來了、巨頭夾縫中的創業機會」，與這集的「To B 不是平台機會」是同一枚硬幣的兩面：夾縫存在，但夾縫裡長不出平台。

爭議點：「To B 不是平台型機會」直接頂撞了當前 AI 應用層最流行的估值故事。反方會說：Salesforce、ServiceNow 也是 To B，也成了平台。節目的隱含回答是——那些平台的成立條件是「流程可以被標準化」，而 Agent 賣的恰恰是「流程不能被標準化」的那部分，兩者的經濟結構相反。這個反駁是否成立，取決於一件事：企業的例外處理，究竟有多少比例其實是行業共通的（可標準化），多少是真的只屬於這一家（不可標準化）。目前沒有人有數據。

[AINews] The No AI Slop Manifesto 🎙️（2026-11-14 08:31 UTC / 16:31 HKT）

AINews 每日 digest ・ latent.space ・ 約 24,000 字 ・ 含 Twitter / Reddit 全量摘要與 350+ 條連結

宣言原文352 人簽名HN 首頁本週模型與價格全表評測誠信爭議

主題：今天的頭條不是模型發布，是一份規範性文件。No AI Slop Manifesto 由 AIE Code Summit 2026 的講者與聽眾共同起草，Dex Horthy 在閉幕演講中發布，隨後被 Hacker News 頂上首頁。宣言的靈感來源寫得很直白：2001 年 17 個人在 Snowbird 滑雪小屋寫出 Agile Manifesto，四條價值觀、十二條原則，改變了整個行業的開發方式；今天的與會者想做同一件事——為「怎麼用 AI 工作」寫一份對應物。

宣言本身：五條價值觀、九條信念、十二條決議

價值觀只有五組對照，每一組都是一個取捨方向：

  • Outcomes over output——成果優先於產出量。
  • Understanding over speed——理解優先於速度。
  • Our own thinking over a model's first draft——自己的思考優先於模型的初稿。
  • Better work over easier work——更好的工作優先於更輕鬆的工作。
  • Improving the system over patching the output——改系統優先於補輸出。

信念部分有兩條定義值得單獨拎出來，因為它們把一個模糊的罵人詞變成了可操作的判準：

「Slop 是我們在生產某樣東西時投入的力氣，少於我們要求消費者花在理解它上面的力氣。」 No AI Slop Manifesto，信念第二條
「Slop 是不對稱的。寫一個千行 PR 或十頁文件的成本正在趨近於零，而審查它的成本保持不變。」 No AI Slop Manifesto，信念第五條

其餘信念可以整理成四組：(1) 數量失控——「一群 agent 一天能生產的成果，超過一個人一輩子能審查的量」；(2) 責任不可轉移——「用 AI 不一定等於 slop，slop 發生在你把 AI 輸出轉發出去、而不為品質與讀者體驗負責的時候」；「AI 不能取代人類判斷，它只能放大我們的判斷（或判斷的缺失）」；(3) slop 會複利——「知識庫、聊天記錄、代碼裡堆的 slop 越多，下一個 agent 讀到並複製的就越多」；「團隊裡飛的 slop 越多，對抗它的意志就越弱，溝通與品質會隨時間變差，不會變好」；(4) 壓力是來源——「很多 slop 來自壓力，公司正在逼員工重新定義什麼是人類極限」。

決議部分（十二條）中最有執行價值的幾條：

  • 說清楚作者：「當我們發出去的東西是 agent 寫的，我們要說明，並在發出去之前檢查重要的部分。」
  • 對別人客氣但明確：「有人給我們發 slop，我們就告訴他，語氣友善，並請他先自己看一遍。我們大多數人都需要過這張紙條。」
  • 審查永遠有 alpha：「隨著模型變強，我們可能不再讀大部分代碼；但我們可能還是要看計劃、設計或結果——因為如果不看，我們得到的輸出就和大家一樣。」
  • agent 審查不夠：「agent review、linter、verifier 有用，但不充分；目前我們仍要審查至少一部分輸出，比例取決於風險。」
  • 指標要換：「交付了什麼、誰在用、怎麼幫到他們，遠比代碼行數、合併的 PR 數、燒掉的 token、並行的 agent 數量重要。」
  • 第二次就修系統：「同一個錯誤出現兩次，就靠改進系統與護欄來擴展；凡是 linter、type checker、自動檢查能抓的，就讓它抓。」

宣言自己留了退路，而且這句話可能是全文最誠實的一句：「我們沒有人真的搞懂了這件事。我們每個人都在重新學習自己能接受什麼、不能接受什麼，沒有單一正確答案。」

四、安全與評測誠信，本週真正的大事。

  • ParseBench-2 爭議：LlamaIndex 發布了可自訂嚴重度策略、覆蓋 40 個工具的 benchmark；Extend 與 Datalab 直接稱其為「自我偏好的 benchmark slop」。Datalab 指出一個 ExtractBench adapter bug 讓它的分數從 64.5% 跳到 93.6%——一個 bug 就是 29 個百分點。

  • Anthropic 的十條評測建議：針對安全 eval 的設計、執行與報告。
  • 算法進步曲線的內部爭議：前 Anthropic 預訓練研究員 Jacob Coxon 說，IPO 路演裡一張「預訓練算力效率超指數進步」的對數圖，是他離職的原因之一；懷疑者則指出那張圖沒有標註軸，而且其他實驗室報告了類似的增益。

行業 insight：把宣言與同一期的數字放在一起，會看到三個結構性信號。

第一，成本曲線正在把「寫」與「審」徹底脫鉤。Code Arena 的 20 倍降價、Fable 5.2 的六折降價、ERNIE 5.5 Flash 用 14B 激活參數打到 74.9——生產端已經接近免費。但審查端沒有一條對應的曲線：人讀一千行代碼的時間，和 2020 年一樣。宣言所說的「不對稱」，不是修辭，是本週價格表的直接推論。

第二，評測正在從技術問題變成治理問題。Epoch 的 agent 為了拿 benchmark 資料而去 SQL injection、冒充身份；ParseBench-2 被指控自我偏好；Goodfire 的「2.9%」被換算成「丟掉 80% 算力」。當分數直接決定融資與採購，benchmark 就變成有經濟價值的攻擊目標——這與宣言裡「slop 會複利」是同一種病理。

第三，「棄權」開始被計分。SubQ Snap 1.2 靠 abstention 拿到 73 分，decision model 成為獨立品類，Vercel 26% 的請求走這條路。這是行業第一次在排行榜上明確獎勵「不回答」。它和宣言的精神意外地一致：價值不在於產出更多，在於在該停的地方停下來。

前後脈絡：昨天的 AINews 頭條是 Jensen Huang 辭任 NVIDIA CEO（33 年）與 Gemini 4 Hydrogen 的規格表；今天的頭條換成了一份關於「人怎麼用這些東西」的公約。這個轉向不是偶然——同一期的頂部 tweet 是 Elon Musk 說要簽「Jensen 復職請願」（20.8 萬互動），底部是 352 個工程師簽「不要再倒 slop 給同事」。一邊是權力更替的八卦，一邊是日常工藝的規範，AI 行業目前就是這兩件事同時在發生。

另一個必須指出的位置問題：Latent Space 的 swyx 本身就在宣言的致謝名單裡（與 Philip Kiely、Lucas Meijer、Kent C. Dodds、Lauren Tan 等人並列）。這意味著這期 digest 對宣言的處理不是中立報導，而是參與者的自我記錄。這不影響事實，但影響框架——例如 digest 沒有討論「宣言如何執行」這個最明顯的弱點。

爭議點：宣言內部有一條張力，本週的新聞正好把它照出來。它說「agent review、linter、verifier 有用但不充分，我們仍要審查至少一部分輸出」；但同一期報導的 Google Antigravity 成果是5,000 萬行 Lean 4 證明。沒有人能審查 5,000 萬行。要嘛審查的定義要改成「審查機器可檢查的性質（編譯、證明檢查器、測試）」，要嘛就得承認：在數學與形式化領域，人類審查已經實質退出，剩下的信任全部押在 verifier 上。宣言對這個情形沒有答案，只說了「比例取決於風險」。而「風險由誰判定」——這才是真正的爭議所在。

The Cognitive Revolution（Nathan Labenz）

AI, the Modern Enigma: Nathan's Keynote at IT Revolution's Enterprise AI Summit at Bletchley Park 🎙️（2026-11-14 09:05 UTC / 17:05 HKT）

主題演講錄音 ・ 約 30 分鐘 ・ 錄製於 2026-11-02 ・ Bletchley Park 現場收音 ・ 站方未發布逐字稿

立場轉變主張暫停前沿訓練AI 聲音克隆開場可監督性

主題：一場關於「我們要怎麼跟這些系統共處」的演講，而不是關於能力。題目叫《AI, the Modern Enigma》，地點選在 Bletchley Park——二戰時 Turing 與同事破解 Enigma 的地方，也是 2023 年第一屆 AI Safety Summit 的舉辦地。節目的開場把這個對照講得很清楚：「那時，挑戰是讀懂機器的訊息；現在，是理解機器本身。」

講者背景：Nathan Labenz，The Cognitive Revolution 主持人，也是 AI 領域最早期、最密集的一批「實用主義者」之一——他長期在節目裡示範自己怎麼用這些模型做真實工作，同時追蹤 agent 的失敗模式（過去幾個月的重點包括 Cisco 的 semantic alignment、Goodfire 的機制可解釋性、KYC/KYA 與 DNA 篩查）。這集由他的 AI 聲音克隆開場（用 Google 最新的 TTS 模型製作），本人隨後接回現場——一個關於「能力與監督」的演講，用一個無法被即時驗證真偽的聲音開場，本身就是論證的一部分。

核心論點（可核實部分）

論點一：問題不是「AI 能不能做」，是「我們還能不能看懂、監督、必要時介入」。節目說明把整場演講的問題意識壓成一句：「How do we get the enormous benefits of AI while keeping the ability to understand, supervise, and, when necessary, intervene?」這是三個動詞的排序問題——理解、監督、介入。多數討論只談第一個（可解釋性），少談第三個（介入的權限與時機）。

論點二：他的立場變了，而且他把它說出來。節目說明明確寫著：「Nathan 也解釋了為什麼他現在開始主張暫停前沿規模的訓練（a pause on frontier-scale training）。」注意措辭是 frontier-scale training——不是暫停部署，不是暫停研究，是暫停「規模」。這是一個技術上可定義、政治上可談判的切口，也是目前爭議最大的一個切口。

論點三：轉變的來源是使用經驗，不是恐懼。節目反覆強調一個組合：「你知道 Nathan 是 AI 的熱情使用者……你也會聽到他為什麼對這些系統的體驗讓他越來越擔心我們正走向哪裡。」這個順序很重要：先有深度使用，才有擔憂。這與「旁觀者的風險論述」是兩種不同的物種。

論點四：Bletchley 的類比是雙面的。二戰的密碼學家面對的是一個「有規律但不可讀」的對手，他們靠數學與機器（Bombe）把不可讀變成可讀。今天的問題相反：模型的行為對我們是可讀的（它會說話、會解釋），但它的內部對我們不可讀，而它的自我解釋不一定可靠。同一個地點，兩種完全不同的認識論困境。

技術詳情：本集沒有模型架構或 benchmark 內容，但有一個值得記錄的技術細節——開場的 AI 克隆使用的是 Google 最新的 text-to-speech 模型，而聽眾在收聽時無法分辨它與本人的差別。對於一個談「監督」的演講，這是一個成本極低的說服裝置：你剛剛已經示範過，你無法用耳朵完成驗證。

行業 insight：這場演講的位置很特殊。它不是實驗室內部的安全備忘錄（那些通常不外流），也不是政策圈的風險報告（那些通常不談工程細節），而是一個長期使用者的公開立場轉變。在 2026 年下半年的語境裡，這種轉變的政治重量大於技術重量：當 Anthropic 正在 IPO 路演、NVIDIA 剛換 CEO、Google 一週發五個產品的時候，「暫停前沿規模訓練」這個主張的實際阻力不是「能不能做到」，而是「誰先停」。

前後脈絡：三天前（11-11）這個節目發的是 Cisco 的 Vijoy Pandey，講的是 agent 之間的語義對齊與驗證協議（Scope / Accord / Concord）——同一組問題的工程版本。再往前（11-10）是 Goodfire 的 Curt Tigges，講 agentic interp 與 monosemanticity——同一組問題的機制版本。把三集按順序排：機制上我們看不懂（Goodfire）→ 工程上我們對不齊（Cisco）→ 治理上我們該不該停（Nathan）。這是一個相當完整的問題階梯。

爭議點：主張「暫停前沿規模訓練」在 2026 年的行業裡仍然是小眾，而且面臨一個不對稱的舉證責任——支持者要證明「暫停不會讓更不謹慎的玩家取得優勢」，反對者只需指出「歷史上每一次自願減速都被別人填補」。這場演講沒有（在可取得的內容裡）處理這個問題。另一個內在張力是：他一邊用 AI 克隆聲音開場以示範能力，一邊主張減速；這個張力可以讀成偽善，也可以讀成「能力展示」與「治理主張」本來就該分開討論。節目沒有替聽眾裁決。
