當「按小時計費」失效之後

今天只有一集真正的新訪談，但它問的是一個很少人敢正面回答的問題：如果 AI 讓一個工程師的產出翻倍，那他的時薪應該漲，還是應該消失？Tenex 選了最極端的答案——不按時間付錢，按 story point 付錢。18 個月後，他們交出成績單：75 人、一半客戶是財富 2000 強、最高與最低工程師的收入差 4 倍（不是創辦人夢想的 10 倍）。但真正有價值的不是這個薪酬實驗，而是他們在企業內部量出來的採用階梯：90% 的公司裝了 LLM，60% 教了員工，50% 給工程團隊裝了 coding agent，而只有 5% 的公司有一個非工程的 agent 真正在生產環境跑。這 5% 就是「AI 擴散」與「AI 新聞」之間的距離。

AI for the Fortune 2000: How Tenex Builds an AI-Native SDLC — Alex Lieberman & CJ Hess 🎙️

發布時間：2026-10-21 13:01（香港時間）｜2026-10-21 05:01 UTC｜時長約 43 分鐘（章節至 42:28）

資料來源：本節依 Latent Space 官方 Substack 全文，內含官方章節時間碼與完整自動轉錄稿（約 43 分鐘、逾 2.6 萬字元）。所有引語均逐字取自該轉錄稿；轉錄為機器生成、未標註說話人，個別詞語可能有誤（例如把 Codex 聽成 "codecs"、把 Claude Code 聽成 "Cloud Code"），引用時已保留原樣並在必要處加註。
主題

表面上是「一家 AI 顧問公司怎麼用 agent 做軟件」，實際上是一集關於定價單位的訪談。Tenex 兩年前提出一個很尖銳的設計：既然 AI 讓工程師的產出不再與工時成正比，那就不要按工時付錢，按交付的工作量（story point）付錢。這集是在 18 個月之後回來對帳——哪些設想成立了，哪些在真實組織裡碎掉了。

而主持人 swyx 帶來的是另一條線：Latent Space 自己辦了一場「Kill My SaaS」，要用 AI agent 取代一套每年報價 4.3 萬美元的研討會講者管理系統，結果花 1,000 美元就做出來、有 72 份投稿、冠軍即將上線。兩條線在同一個問題上會合：當「建造」變便宜，你憑什麼判斷一件工作值多少錢？

嘉賓背景

Alex Lieberman，Tenex 共同創辦人，18 個月前與技術共同創辦人 Armand 在紐約創立。公司從「AI 驅動的外包開發店」起步，現在定位是「大型企業的應用 AI 合作夥伴」，協助客戶從「AI 缺席」走到「AI 原生」。他先前已上過一次 Latent Space（談「年薪百萬美元的 10x AI 工程師」），是「按產出計酬」這個主張在矽谷最公開的代言人之一。

CJ Hess，Tenex 第一位員工、現任工程總監，同時負責「特殊項目」——用他的話說，就是「找出模型能力的最前沿，然後給它們工具」。他是軟件工程師出身，在加入 Tenex 之前有一串創業墳場，最後一家是自己的工程諮詢公司。他對這套薪酬模型有非常個人的動機：「我的產出愈來愈好、愈來愈快，但最後拿到的錢卻愈來愈少，因為我是按小時向客戶收費的。」

核心論點

論點一：按產出計酬不是為了省錢，是為了讓激勵方向正確。按小時計費的世界裡，AI 提升效率等於工程師自我降薪，這在邏輯上荒謬。Alex 把它上升為一句近乎宣言的判斷：

「The thesis is that AI is really just a leveraged bet on a human's intellect and work ethic.」 — Alex Lieberman（意譯：AI 本質上是對一個人的智力與工作倫理的一場槓桿押注。）

順著這個邏輯，收入離散度必然擴大——這是設計意圖，不是副作用。上一集節目時，Tenex 有兩三個人年收入超過 100 萬美元；這次被追問「最高與最低差多少」，Alex 給的答案是大約 4 倍。主持人明顯意外（「不是 10 倍？」），Alex 的回應是「那是理想」。這句話其實比任何論證都誠實：模型削弱的是「人與人的產出差距」，而不是放大它。每一代模型變強，都是在替平庸的執行兜底，把差距壓回中位數。

論點二：大家預測的兩個失效模式，一個都沒發生。外界的經典質疑有兩個——story point 是主觀的，工程師會虛報（sandbagging）；以及為了衝點數會亂出貨、只勾選框。Alex 說這兩件事「完全不是問題」，原因是組織裡存在一個激勵方向相反的物種：AI strategist（本質上是技術顧問），他們對客戶留存與增長負責，因此有強烈動機去否決那些「對客戶沒用但很好估點」的工作。用他的話，兩邊的激勵是「perfectly at odds」（完美地相互制衡）。

這是一個值得記住的組織設計：不是靠更精細的估點制度去防作弊，而是靠一個利益相反的角色的否決權。任何想複製這套薪酬模型的公司，如果只抄 story point 而不設這個否決角色，大概率會直接撞上這兩個失效模式。

論點三：真正解不掉的是「不寫 code 的時間」。Alex 承認這是最大的難題，不是那些外部質疑。隨着模型變強，CJ 的親身軌跡是「寫很多 code → 寫少一點 → 現在模型拿到正確上下文就能做到 90% 的方案」。剩下那 10% 之前的工作——坐在客戶對面聽他把腦子倒出來、把它整理成模型能吃的形式——恰恰是價值所在，卻最難塞進一張 ticket。

CJ 的推測是：未來會更看「產出到底是什麼、長什麼樣」，而不是傳統的點數，但仍然以點數為錨定單位。這其實是在說：計價單位暫時不會換，但估點的內涵正在從「寫了多少」漂移到「定義了什麼」。

論點四：MetaHarness——把「為什麼」也存進 repo。這是全集技術含量最高的部分。Tenex 內部把工程流程標準化成三層：一組共用的 skills；repo 內一套結構化文檔；以及一層包住它們的 CLI，讓模型自己驅動整個流程（產生計畫、視覺化、給客戶的 readout）。核心是一份 canonical plan document，agent 被要求以非常特定的方式記錄決策與進度，全部進 Git。

「The code can actually be the memory of a code base. And I do think you do. You need to know why you made a decision.」 — CJ Hess（意譯：程式碼可以是 codebase 的記憶；但我認為你確實還需要文檔——你需要知道當初為什麼做這個決定。）
「It's never in someone's head. It's always in the repo.」 — CJ Hess

這段話的份量在於它反駁了一個當下很流行的說法（「有 code 就不需要文檔」）。Tenex 的立場是：code 記錄「做了什麼」，決策記錄記錄「為什麼」，而後者才是 agent 接手長程任務時真正缺的上下文。有趣的是他們隨著模型變強，反而減少了文檔結構的強制性——模型自己會組織，人只需要提供素材。CJ 還提到他現在更喜歡讓 agent 產出 HTML 而非 markdown，「我喜歡看這些繪本」。

論點五：企業採用是一道有五級台阶的階梯，而每個人都高估了別人走到哪一級。這是全集最可直接引用的一組數字。以他們正在談的約 100 家企業為樣本：

  • 90% 已經向員工鋪開通用 LLM（Claude 或 Codex 之類）；
  • 60% 做了真正的培訓與 enablement（Alex 補了一句：這一環「從來沒有得到它應得的重視」，但重要性不亞於技術本身）；
  • 約 50% 在工程組織內部署了 coding agent——他特別點出，在 AI Engineer 現場問大家猜多少，所有人都說 70–80%，實際只有一半；而且「另一半就算有在用，狀態也更接近『沒有 coding agent』」；
  • 5% 有非工程的 agent 真正在生產環境跑。這是整條階梯上最大的一級落差。
「Most enterprises that we talk to that have more than a thousand employees do not have an agent in production that is doing work that is not building software.」 — Alex Lieberman

他給的解釋有兩層。第一層是心理的：這一波由「一小群懂的人」加上「一大群 FOMO 的人」共同驅動，FOMO 不是壞事（它提供動能），但它會讓人抓住最時髦的口號——所以「每年都是 agent 元年」。第二層是工程現實，見下一點。

論點六：「你無法自動化一個不存在的流程。」這句是全集最鋒利的一句，Alex 說他對團隊就是這樣講的：

「You can't automate a process that does not exist.」 — Alex Lieberman

展開的場景很具體：一家公司裡有 40 個人做大致相同的職能，但每個人做法都略有不同。這時你可以坐下來教每個人怎麼用工具輔助自己，但要做出一個「在背景主動推進工作」的 agent，幾乎不可能——因為 agent 無法判斷自己做得對不對，你也没辦法為它建 evals。所以 Tenex 的建議順序是反直覺的：先幫公司在組織內建立流程，再談把工作交給 agent。沒有標準化，就沒有 eval；沒有 eval，就沒有可交付的價值。這也解釋了為什麼「5%」這個數字如此頑固——卡點不在模型能力，在組織的流程熵。

論點七：CIO/CISO 的第二個噩夢是權限，不是模型。當每個員工都有一個 Claude 或 Codex、且都需要存取特定資料，RBAC 與資料權限變成災難。Alex 說市場上「基本上沒有一個好的 gateway」可以做這種控制面板式的資料權限管理。Tenex 一開始為客戶客製，後來把它產品化成自己的 gateway。這是本集少見的「從服務長出產品」的路徑，也是他們從 dev shop 走向平台的具體一步。

論點八：對垂直 AI 偏空——但理由不是「模型會吃掉你」，而是「一對一的期待遇上軟件毛利」。Alex 與 CJ 都說他們對垂直／行業專屬的 AI 方案「整體偏空」，理由來自他們每天待在企業內臟裡的觀察：

  • 買方現在期待的是一對一的軟件體驗，而這正是軟件公司紛紛自建 FDE（forward deployed engineer）團隊的原因——服務與軟件正在收斂；
  • 如果每家客戶都要 one-of-one，垂直方案要怎麼維持軟件毛利？
  • 而且當 frontier model 持續變強，這些任務為什麼不會被通用工具吞掉？

主持人當場用 Harvey（法律）與 OpenEvidence（醫療）反駁，Alex 的回應是「到目前為止你確實錯了」，但仍堅持：這類公司的護城河是「ChatGPT 拿不到的資料」與專屬的介面 affordance（他舉 Harvey 的 Tabular Review 為例），而 Anthropic／OpenAI 也在買同樣的資料源，只是沒那麼專注。

CJ 給出了一個比「垂直 AI 贏或輸」更有用的切分：一種產品，主功能就是「一個 agent 替你做某個任務」；另一種產品，是改善做那個任務的整個工作流。前者會被模型吸收，後者可以活。這與主持人舉的 Superhuman 例子呼應——大家都有 Gmail，但有人願意每月付 30 美元買一個為「整天住在信箱裡的人」重做的介面。

論點九：Salesforce／SAP 不會因為「可以自己做」而被取代，因為風險成本太高。對於「Kill My SaaS」那套邏輯能不能上移到大型系統，Alex 的判斷很清楚：

「The more you move upmarket in business, the harder the proposition of ripping out and building from scratch gets.」 — Alex Lieberman

原因不是技術，是風險趨避：一旦拆換出錯，代價是數億到數十億美元。他反而認為這類系統在當下這個時刻「正在累積價值」。但他也給了中小型 SaaS 一個可操作的判準：這筆錢佔營收／成本的比例，是否大到值得抽調工程資源？以及更根本的——

「One of the beauties of software is not just the utility that you get from it. It is all of the headaches you don't have to think about in maintaining it and improving it when it's not in your core.」 — Alex Lieberman（意譯：軟件的美妙不只在於它帶來的效用，還在於那些你「不必去想」的維護與改進煩惱——當它不是你的核心業務時。）

這是對「AI 讓人人自建軟件」熱潮最冷静的一盆水：自建的真正成本不是第一版的 1,000 美元，而是此後每一天的認知負荷。swyx 的反駁也值得記錄——他承認維護成本，但強調 upside 不只是帳單：他們團隊忍受一個平庸產品很久了，如果自己擁有這個工作流，可以在幾分鐘內迭代，而不是等供應商幾個月。而且他想要的是「對講者和營運都更好的 10 倍版本」，不只是省 4.3 萬美元。

關鍵數據
  • 公司規模：75 人，90% 是工程師或 AI strategist；成立 18 個月。
  • 客戶結構：50% 財富 2000 強，50% 營收 1 億–5 億美元的中型企業。
  • 薪酬離散度：最高與最低工程師收入差約 4 倍（創辦人的願景是 10 倍；上一集時有 2–3 人年收破 100 萬美元）。
  • 產出增長：今年內每位工程師的實際產出「大約翻倍」（2x）。分水嶺是去年 12 月的 Opus 4.5，之後到現在的 Opus 5.5。
  • 點數校準：至少每季重新評估一次 story point 的標準；理論上單點價值應該通縮，實務上大致用 2x 的產出增幅去對沖。
  • Token 支出 / 人力支出：Tenex 約 1:1 到 2:1。參照系：多數企業每員工 10–200 美元／月；AI 原生公司約佔人力支出 10%；一般 AI 新創約 1x，高的到 5–10x。
  • 成本工具：AMP 支援掛接 Claude Code 訂閱後，CJ 說成本「大約砍掉 80%」。
  • 企業階梯：90% 鋪開通用 LLM → 60% 培訓 → 50% 工程組織有 coding agent → 5% 非工程 agent 進生產。
  • Kill My SaaS：原報價 4.3 萬美元／年，重建花 1,000 美元；收到 72 份投稿；人類評審選出的冠軍，在 AI 評審排行榜上只排第 19。
  • 資料公司：Alex 提到這類公司目前 90%+ 營收來自 lab，創辦人們賭未來幾年會翻轉成企業驅動。
重點引用
「I just felt my output getting better and faster, and ultimately getting paid less.」 — CJ Hess，解釋他為什麼離開按小時計費的顧問生涯
「The hardest problem to solve is the final mile to actually diffuse it through the economy.」 — Alex Lieberman（意譯：最難的問題是最後一哩——如何讓它真正擴散到整個經濟體。）
「The bigger challenge has been how do you compensate engineers for all the time that's not spent coding, whether it's architecting, meeting with clients.」 — Alex Lieberman
「Would a 10 times smarter model really justify the cost of moving some cells in a spreadsheet? Probably not.」 — Alex Lieberman，談為什麼模型價格戰會持續往下
「I don't think any business would claim like once we have this solved, there's nothing for this group of people to work on.」 — Alex Lieberman，談就業是「重新配置」而非單純削減
技術詳情

MetaHarness 的四個部件。（一）標準化的 skills 集；（二）repo 內結構化文檔，核心是一份 canonical plan（隨模型變強，結構約束反而放寬）；（三）agent 記錄決策與進度的強制格式——這是「為什麼」的載體；（四）包住前三者的 CLI，讓模型自己驅動產出（計畫、視覺化、客戶 readout）。全部 commit 進 Git，成為人與 agent 共用的工作表面。他們用「每位工程師每月平均 story point 是否呈上升趨勢」作為這套流程是否有效的單一儀表。

模型組合。目前默認 Opus 5.5（CJ：快、便宜、覆蓋他過去需要 2–3 個模型的所有區間）；Codex 用於 computer use 類任務與交叉審查——他們的最佳實踐是讓兩者在自己機器上「互相來回審」。遠端環境用 AMP 的 orbs，CJ 特別稱讚跨模型能力：Opus 在一個 orb 寫，跳到另一個 orb 說「去看那個 orb 並審查它」。他認為 Anthropic 一直沒有把遠端環境這件事做好（Cloud Code in the cloud、Claude Tag 都差一口氣）。

Claude Mods: Flipping the Harness Inside Out（Dan McAteer）

發布時間：2026-10-21 21:04（香港時間）｜2026-10-21 13:04 UTC｜形式：技術評論（非訪談）

這篇不是播客，但它提出了本週最值得記住的一個概念框架，且與上面 Tenex 那集直接互補：Tenex 講的是「把流程寫進 repo」，這篇講的是「把介面翻轉向人」。

核心論點

Harness 正在反轉。agent harness 原本是「agent 與機器之間」的介面——你下提示，agent 執行指令、改檔案、呼叫工具。但隨著模型把 harness 的一部分吸收進權重，剩下的那部分就轉向人類。作者把它命名為 Attention Interface：決定 agent 何時打斷你、給你看什麼、需要你做哪個決定的那一層。

「As models absorb more of the harness into their weights, the part that's left faces the human.」 — Dan McAteer

他的賭注更大：harness 會變成一個平台，其他公司在上面建造，模型只是引擎——就像瀏覽器變成 web app 的平台。

技術詳情

Claude Mods 是 Claude Code 的 plugin，由 TypeScript／JavaScript 函數組成，跑在 Claude Code 內，改寫 CLI 與 Desktop 的行為與外觀。它們回應事件（prompt、tool call、介面渲染），可以觀察事件、改變渲染方式、或直接接管默認行為——本質上是 agent harness 的中間件。Claude Code 內建一個 skill 教 Claude 自己寫 mod，所以你用自然語言描述想要的 mod，它會替你建。

Anthropic 已把六個功能以 mod 形式內建：agents-md（把 AGENTS.md 載入為專案指令）、diff（接管 /diff 並繪製面板）、plugin-authoring（給 Claude 寫 mod 的 skill）、sec-default（隔離組織管控與使用者自裝的 mod）、telemetry、以及 you-should-know（唯一默認關閉）。最後一個是重點：它跑一個旁路 agent 觀察主 agent，把「對輸出有實質影響、但埋在 trace 裡看不見」的決策挑出來。作者舉了一個真實案例——Claude Code 在改 CompareView.swift 時，該檔案與另外約 45 個檔案已有未提交的改動；如果他事後丟棄 demo 的修改，那些未完成的工作會一起消失。這個 mod 在「一切看起來都完成了」之後才把它攔下來。

他自己建的 Next Steps Supervisor 只在「有改檔、有跑指令、或 tool call ≥ 8 次」的回合之後觸發，把六項值得注意的資訊列出，並給一個可點擊的下一步建議。

行業 insight

他把 Claude Mods 放進一個正在成形的小類別裡比較：OpenAI 在 10 月 7 日隨 GPT-6 推出的 ChatGPT Intelligent UI（模型邊回答邊生成介面——圖表、地圖、清單、表單、小工具），以及 Cursor 的 PR Routing & Approval。三者方向一致：競爭焦點從「模型多聰明」轉向「它怎麼把工作呈現給人、在什麼時候向人要決定」。

對做產品的人，這是一個可操作的判斷：如果你的 agent 產品，差別只在「用的模型更好」，那它會被吸收；如果差別在「它如何分配人的注意力」，那是一層可以沉澱成平台的東西。這與 Tenex 那集 CJ 的說法其實是同一件事的兩面——一個說「流程要可被 agent 讀」，一個說「介面要為人的注意力而設計」。

技術細節

架構上把階段切開。視覺編碼、prefill、decode 三段分離，各自針對自己的瓶頸擴容。建議部署形態：prefill 用普通八卡機，decode 用 64–128 卡的 supernode，並以寬專家並行（wide expert parallelism）攤開 MoE 專家、維持大有效批次。

快取是數字的關鍵。支援長達 72 小時的 prompt caching，對照 OpenAI 剛宣布的 12 小時。96% 的命中率意味著這個「155 兆 tokens／天」是一個高度快取的負載，不能直接當成等量的原始計算來讀。
