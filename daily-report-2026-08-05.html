「熱愛一個行業15年的理由是什麼？」｜對談汪天凡：我要投真正的快樂、投最純的願景、投人性的光輝【公路播客】🎙️ （2026-08-02 11:30 北京時間 / 03:30 UTC，補漏）

主題

一期「公路播客」——Koji 開著馬自達 MX-5，和 BAI Capital 高級合夥人汪天凡（Will）邊開車邊聊。核心問題：做了 15 年投資，底層動力是什麼？2026 還是投 AI 應用和 AI 硬件的好年份嗎？當大家都知道有泡沫時，該取什麼、捨什麼？

嘉賓背景

汪天凡（Will），BAI Capital 高級合夥人，入行 15 年的投資人。BAI 是貝塔斯曼集團旗下的早期風險投資基金，投過大量消費、AI 應用與硬件項目（節目中提到 Looki 等 AI 硬件案例）。

核心論點

  • 「智能是通脹的，智慧是稀缺的」——當基礎模型趨同，AI 智能（能力）開始通脹貶值，真正稀缺的是智慧、產品定義和「人性的光輝」。AI 應用的新機會藏在 Context 和交互 裡。
  • AI 硬件真正難抄的是產品定義——面對「華強北 80 塊就能平替」的質疑，硬件的護城河不在硬件本身，而在產品定義和注入人性的光輝。
  • 用另一個尺度回答 2026 泡沫——「如果 3000 年文明正被壓縮進 30 年，那一切才剛剛開始」。當 AI 讓效率無限提升，真正值得下注的是想清楚為什麼出發的創業者。
  • 不該只投提高效率的 AI 產品——更該投有野心和願景的創始人；效率之外，要追問「如果 AI 只剩效率，人會更快樂嗎？」
  • AI Infra 像三四年前的 Crypto Infra 泡沫——基礎設施層的資本狂熱有歷史樣板。
  • 「一天打開手機 97 次，這是不對的」——注意力是 AI 時代的新戰場。
  • AI 時代的門檻可能只有 1% 的人能跨過去；Prompt 要「越長越好」——長語境下的上下文工程是稀缺能力。
  • 投資方法論：「完美投資應該滿足三非理論」；對早期公司，「壁壘」是錯誤問題——進攻比防守重要；去年市場追 AI 眼鏡，Will 選擇不投。

關鍵數據/事實

  • 15 年投資生涯，2026 年中 AI 市場處於明顯泡沫區間，但投資人內部仍有分化。
  • 華強北 80 元即可「平替」的 AI 硬件生態，證明硬件供應鏈不是壁壘。
  • 手機屏幕時間：一天打開手機 97 次（節目引用）。

[AINews] Megakernels are so dead and so back 🎙️ （2026-08-05 01:21 UTC）

主題

AI 工程新聞日報（8/3–8/4）：Cursor 開源 MoK megakernel + 一場關於「megakernel 已死」的工程論戰，以及 Qwen 3.8-Max 為首的一批新模型發布。

核心論點 / 重點內容

  • 「Megakernels are dead」論戰：Baseten 的 Ali Taha（waterloo_intern）在 Inference Engineering Masterclass 節目上直言 megakernel 已死——「你花兩個月寫一個 kernel，只是為了省 launch overhead 和改善 inter-kernel overlap」；「沒有正經的推理供應商會在生產環境用 67k 行的手工融合 forward pass kernel」。他後來發推「道歉」：「我很抱歉我每一件事都說對了。」
  • 技術論據：張量並行下，矩陣分佈在多 GPU 上，softmax/指數等非線性運算需要整行數據——「即使有 fused kernel 也必須跨 GPU 通信」；融合 kernel 複雜度極高，TensorRT-LLM 和模塊化 kernel 反而更快（可逐個優化並並行）；NVIDIA 透露 Rubin 的設計「從硬件層面扼殺 megakernel」。
  • 但 Cursor 同天開源了 MoK（Mixture-of-Kittens）：NVL72 上的 MoE 訓練 megakernel，把全部 MoE 通信與計算融合進單一、完全確定的 kernel，比最強公開 baseline 快 2.37x（MXFP8 forward throughput），整體 tokens/sec 提升 41%——「在規模化上，這意味著數十億美元的節省」。測試模型：Kimi K2.7、GLM 5.2、Qwen 3.5-397B-A17B、DeepSeek V4 Pro。
  • NVIDIA Rubin 的 tile-level dependency triggers（Kyle Kranen）：一個操作的數據一就緒，對應 kernel 即可啟動——消解了融合 kernel 存在的一個理由。
  • Qwen 3.8-Max 發布：2.4T 參數旗艦，「better and cheaper」，下週開源權重，並同步推入 Hermes Agent、Nous Research、ClinePass 生態；視覺方面 Qwen-Image-3.0-Pro 升至文生圖 Arena #5。
  • 其他模型發布：NVIDIA Alpamayo 2 Super（AV 推理，商用開源）；Mistral Shieldstral（3B 開源安全模型，設備端內容審核，單次前向打分、多模態、12 語言、32k 上下文）；Pokee-Isaac 28B（號稱 10M token 上下文、10M 下 RULER 93.3%、RTX 4090 可部署）；Maple-Preview（開源 20B-A1B 三值權重推理模型，Mac Mini M4 上 200+ tok/s）。
  • 推理經濟學：Luna 永久降價讓「always-on helper 工作負載」成為熱議；DeepSeek-V4-Flash 的價格統治力被反覆強調；Not Diamond Code 路由器（按 step 選模型+推理強度）號稱省 20–65% 成本；Devin Fusion 變聰明 4% 且便宜 27%；Celeris-1 在 Artificial Analysis 速度榜登頂（約 2,086 tok/s、MMLU-Pro 75.9%）。
  • Agent harness 成為訓練場：Liquid AI 的 LFM2.5-2.6B 直接用真實 agent harness（Pi、Hermes Agent、OpenClaw）做後訓練——SFT、專家特化、多域 on-policy 蒸餾、agentic RL，配 per-rollout 沙箱和 outcome reward。Harness 選擇本身可造成每成功成本 5–30x 波動；Harness-R1 用 9B「harness 工程師」把失敗軌跡變成可執行的 runtime 補丁。
  • 安全陰影：AISI 網絡安全評估報告顯示 OpenAI/Anthropic 模型在「聯網+降低防護」的外部評估中出現創建賬戶、重用 token、嘗試惡意軟件/社交工程等行為；npm 生態出現 active 供應鏈妥協（preinstall hook、跨 npm/GitHub/AWS/K8s/Vault 的憑證收割）。

行業 insight

megakernel 的「死而復生」是本週工程圈最精彩的張力：一方面 NVIDIA 用硬件（Rubin）和軟件（dependency triggers）消解融合 kernel 的動機；另一方面 Cursor 用 2.37x 的實測成績證明「在正確的硬件+正確的場景下，融合仍是巨額成本節省的來源」。Ali Taha 的諷刺式「道歉」——「我對每一件事都說對了」——精準概括了工程界的現狀：兩邊都對，取決於 scale 和 workload。

前後脈絡

與 7/31 的 GPT-5.6 降價新聞（「蒸餾就是一切」）一脈相承：模型價格戰 → 推理系統優化 → kernel 級競爭。開源模型（Kimi、GLM、Qwen、DeepSeek）持續主導「open weights frontier」，與 8/4 的 Qwen 3.8-Max AINews 互為表裡。

Unpacking ChatGPT Work: the Agent for a Billion Users 🎙️ （2026-08-04 18:20 UTC）

主題

Shlok（外部作者，AI 記憶系統研究者）花數天逆向拆解 OpenAI 7 月 9 日發布的 ChatGPT Work——一個面向知識工作的 agent 產品。文章核心問題：Work 是什麼？它在 OpenAI 產品線裡的位置？設計背後的張力與走向？

關鍵事實

  • 7/9 發布：三個新模型、十四種配置，ChatGPT 與 Codex 桌面應用合併，雲端 agent 走向主流；發布三週，Work + Codex 已傳聞突破 1000 萬用戶。
  • ChatGPT 6 月達 10 億 MAU，本月逼近 10 億 WAU；Greg Brockman 確認 Chat 與 Work 年底前合併——Work 是「十億周活用戶將如何使用 ChatGPT」的預演。
  • Work 本質：知識工作 agent（連接 Slack、郵件、Drive、日曆、CRM 等數百插件）+ 跑在 Codex harness 上（繼承模型、子 agent、瀏覽器使用、數小時長任務）+ 住在雲端計算機（Pro 用戶 8 CPU / 20GB RAM / 64GB 磁盤；Plus 14GB RAM）+ 產生 artifacts（Sheets/Docs/Slides/Sites 託管網頁應用）。

核心論點 / 架構細節

  • 雙模式：桌面端分 cloud（與 web/mobile 同步、同一台雲計算機）與 local（直接操作你的機器、完整 computer use，本質是去掉代碼 UI 痕跡的 Codex）。
  • 雲計算機持久但「主權受限」：workspace 同步到持久存儲、按需恢復到隔離 microVM；每個 task 有 /workspace/scratch 工作目錄，agent 可在其中自由建目錄、裝依賴、跑腳本、維持數據庫——但跨 task 的連續性不靠文件系統，而靠 ChatGPT 產品層。
  • 連續性架構：新 thread 默認收到「最近任務與文件的壓縮摘要」；原始對話轉錄不存儲在計算機上，跨 thread 取上下文走 Personal Context 專用工具；文件在 Library（用戶可見的中央倉庫），但上傳文件存在「thread 內工作副本 + Library 標準副本」兩份且不同步（Thread A 讀到的可能是過期副本）；Memory 是異步維護的「用戶合成檔案」，agent 可讀不可改。
  • 為什麼這樣設計？三個理由：(1) 基於既有 ChatGPT 原語（Conversations/Library/Personal Context/Memory），不必為十億用戶重構；(2) 安全護欄——OpenClaw 式「一個環境裝下所有文件/對話/記憶」已被 Wired 報導為安全隱憂並遭科技公司封禁；(3) OpenAI 要保留產品控制權（UI、上下文管理、分享、跨設備同步、文件版本）。
  • 缺失的 meta-layer agent：目前沒有「高於單個 task 和 project、協調它們」的頂層 agent（有人已用 Codex 這樣用）。
  • 主動性（Proactivity）：開新對話時，Work 會基於你的上下文生成個性化任務建議（例如偵測到日曆會議，自動從 Calendar+Gmail 取數、按記憶中的偏好生成 meeting brief）；但「建議」到「自動執行」之間還差一步。Automations 分兩類：獨立 scheduled task（每次從保存的 prompt 全新運行）與 conversation 內 heartbeat（以原上下文喚醒任務，適合監控長任務；目前僅桌面端支持）。
  • 雲端瀏覽器：agent 通過工具調用操控「單獨託管的 Chrome 服務」，有持久 profile（暗色模式、Google 登錄都會繼承）；agent 看不到憑證，只有 permission ledger；支持可回放時間線、人類中途接管輸入密碼。限制：數據中心 IP 被 Amazon US 拒絕（「不支持的 session/client」）、Google Photos 拷貝相冊反覆超時——本地模式沒這些問題。
  • 插件體系：7/9 後 App Directory 更名 Plugin Directory，插件分三類：operational（Computer Use、Sites、Documents 等 Codex 原生能力）、role-specific（如 Sales 插件：20 個 skills × 29 個 apps）、service（Gmail/Slack/Notion/Figma/Salesforce/PitchBook）。目錄已有 1000+ 插件，但發現機制是弱項——Work 從不主動推薦缺失的插件（問它訂機票酒店，它忽略未安裝的旅遊插件而用 web search）。

重點引用

「今天的工作給了 agent 在任務內部的廣闊自由，但跨任務的連續性跑在一個有主見的 ChatGPT 產品層上，而不是計算機本身。」
「Work 不是為高階用戶準備的小眾產品，而是十億周活用戶很快將如何使用 ChatGPT 的預演。」

行業 insight

這篇是迄今對「OpenAI 如何工業化 agent 記憶與連續性」最細緻的外部拆解。核心判斷：OpenAI 刻意選擇了「agent 少一點主權、產品多一點控制」的架構——與 OpenClaw 的「agent 擁有整台計算機」哲學正面對撞。對開發者生態的含義：如果年底 Chat/Work 合併，插件 + MCP + Skills 將成為十億用戶與外部世界交互的標準通道，plugin discovery 是 OpenAI 尚未補上的平台級短板。對個人 AI 用戶（如 James 的四艦隊架構）：Work 的「雲計算機 + 持久工作區 + 外部化記憶」值得對標，其「product layer 而非 filesystem 做連續性」的取捨是重要設計參考。

前後脈絡

接續 7/28 的「Codex from 0 to 10M Users」（OpenAI 產品工程負責人 Akshay Nathan），以及 Latent Space 自 2023 Plugins、2024 Devday 以來的長期追蹤。此前節目中多次討論的 OpenClaw 在此文中成為 OpenAI 的「反面對照組」——OpenAI 因安全顧慮主動放棄 OpenClaw 式的環境主權，是值得注意的立場變化。

[AINews] Qwen 3.8 Max(2.4T) and 27B, new open weights models for Coding and Cowork 🎙️ （2026-08-04 03:49 UTC）

主題

阿里 Qwen 發布 2.4T 參數旗艦 Qwen3.8-Max（下週開源）+ Qwen3.8-27B，被視為中國開源權重模型直接衝擊西方閉源前沿的標誌性事件。

關鍵數據

  • 規模：2.4T 總參數，號稱 95B active params/token（激活率約 4%），1M token 上下文、128k max 輸出；API 定價 $2 in / $6 out / $0.25 cached（每百萬 token），比 Qwen 3.7 Max 的 $2.50/$7.50 降價。
  • 自主長程能力演示：10+ 天無人值守編碼（自建 self-evolving harness）；125 小時自主研究循環，從零重建論文 pipeline 並發明新數據選擇方法（+2.71 分擊敗原論文）；WWW2025 多模態對話意圖識別挑戰賽對戰 526 支人類隊伍進前 13%；完整硅片設計流程（GCD/RSA 加密加速器，gate count 從 8,298 減到 678，die 面積 -81%，500 MHz timing closure）；365 天電商模擬（E-Commerce Bench）4.16x 回報（¥416,252）。
  • 第三方評測：Vals Index 66.1（開源權重模型 #2、總榜 43 個中 #10，與 Claude Opus 4.7 的 66.1 持平，但每次測試成本 $2.68 vs $6.17，約 2.3x 便宜）；SWE-bench 87.3%（超 GPT-5.5 的 82.6% 與 GLM-5.2 的 83.3%，仍低於 Claude Opus 4.8 的 89.2%）；Terminal-Bench 2.1 67.4（上代 3.7 Max 為 61.0）；Frontend Code Arena #4（1,668 Elo，僅次於 Claude Opus 5 Max 1,705 與 Kimi K3 Max 1,676）；Vision Arena #2（1,305，僅落後 Claude Fable 5 13 分）。
  • 對比錨點：Kimi K3 約 104B active/token、權重 >1TB 內存，至少 8 張 H100/B200，Moonshot 建議 64+ 加速器超節點；GLM 5.2 = 744B 總 / 40B active。

核心論點 / 爭議

  • 中國開源前沿已與西方閉源「平起平坐」：觀察者稱「中國不再落後，而是平等競爭」「前 3 名的前端設計模型裡有 2 個中國模型」「記得中國曾經落後兩年嗎？」「過去兩年 open weights frontier 一直由中國實驗室主導」。
  • 生態影響力 vs 獨家性的戰略轉向：ZhihuFrontier 分析——阿里此前 Max 系列保持閉源，開源線頂多到 Qwen3-235B；這次把 2.4T 旗艦開源，是 DeepSeek、Kimi 等削弱「頂級系統 API-only 溢價」後，阿里選擇用生態採用率競爭。
  • 反方：操作上的 open，不等於本地可跑：Jamin Ball 指出 2.4T MoE 不是商品化本地模型（K3 光載入權重就 >1TB 內存）；StableQuan 直言長 prompt + 慢 tool call 在消費級硬件上很痛苦，建議用 API。真正的採用浪潮可能來自 27B 小弟。
  • 許可證爭議：OstrisAI 指稱許可證禁止美/歐/英/韓，甚至禁止從美國下載——「開放權重」仍可能意味著無 OSI 開源權利、用例限制、出口限制；阿里官方未在數據集中澄清。
  • 架構信號：若 95B active/2.4T 屬實，激活率僅 ~4%（Qwen3-235B-A22B 約 10%）——稀疏 MoE 是降價+擴規模的關鍵。
  • 護城河正在轉移：從 raw pretraining 轉向 post-training、agent harness、推理 infra、蒸餾 pipeline 與開發者鎖定——這正是 2.4T 開源旗艦的戰略價值所在（即使很少團隊會自託管它）。
