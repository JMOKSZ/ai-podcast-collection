「我相當確定，整個 swarm 嘅 95% 都完全冇用」——Latent Space × Alex Zhang（MIT）：Harness 係組合泛化器，而未來嘅「語言模型」其實係一整隊 agent

📅 2026-10-02 00:28 UTC（北京 08:28）·🎙 Latent Space（主持 swyx + Vibhu）·👤 嘉賓：Alex Zhang（MIT PhD，RLM 第一作者、KernelBench、GPU Mode）·⏱ 約 1:41·🏷 RLM / Harness / Agent Swarm / Research Taste

呢集係 Latent Space 每年「發掘一位新星 PhD」傳統嘅 2026 版（2024＝Shunyu Yao、2025＝Jack Morris）。以下內容按 feed 官方完整逐字稿（約 127 KB，含全部時間軸同講者標註）整理，引號內全部係逐字稿原文。

一句話總結

Harness 唔只係「一堆工具」，而係一個可以大幅改變模型泛化能力嘅組合泛化器。主流 harness（Claude Code、Codex、Pi）結構上其實一樣；真正嘅差異化在 RLM 這類新抽象。而 agent swarm 之所以能解未解難題，係因為它被訓練過、能收斂——唔係免費嘅。最後，Alex 押注：未來你 query 嘅「語言模型」本體，會係一隊你看唔到嘅 agent。

「我相當確定，整個 swarm 嘅 95% 都完全冇用——你只係喺度燒 token。……我們太把『一個 swarm 要收斂到一個答案』呢件事當作理所當然了。」 —— Alex Zhang

一、由 GPU kernel 講起：verification gap 同「人類直覺」嘅 alpha

Alex 嘅起點係 GPU Mode（前身 CUDA Mode）同 KernelBench——「如果 GPU code 都可以有幾百萬條題目，就可以規模化、自動化 GPU kernel 開發」，因為 Mamba 呢類論文「唔係每隊都有一個 Tri Dao」。

但 leaderboard 揭露咗一個硬問題：近期題目「幾乎所有解法都係 AI 生成」，但 top 10 之中只有一個（由人類專家 Gauners 引導 AI 完成）喺真實端到端系統中穩定。核心洞察：GPU kernel 有 verification problem / reward hacking，而「識得睇、識得諗」嘅人類依然係極強嘅 verifier。「當你掟足夠算力落去，你可以探索好多解；但往往有人識得個問題，就可以為模型挖出一個洞見，抹掉嗰一萬億 token 嘅花費。」

二、Harness 作為組合泛化器（核心）

Alex 對「harness」嘅流行討論唔滿意：大家比較 Claude Code / Codex / Pi / Oh My Pi / Prime Agent，「但老實講，佢哋全部都一樣」。他提出 locally in-distribution 概念：傳統 harness 把整條 trajectory 當 prompt 不斷附加，最終大多變成 out-of-distribution；而 RLM 把一個 out-of-distribution 嘅整體任務，拆成一連串每個都係 in-distribution 嘅局部 LLM call。

關鍵實驗結果：當 RLM「充分卸載 context、要模型對 context 寫 code」，會出現一個奇怪但有用嘅性質——好多唔同任務嘅解法其實好相似（檢索任務 vs 彙總任務，領域完全唔同，但 meta 策略一樣）。於是喺一個任務上訓練，可以即刻解另一個任務；短任務訓練能遷移到 8–30 倍長嘅任務（數學 vs 寫作亦然）。而呢個論證可以歸納遞迴——子代理解嘅子任務，可能又係同一種形式。

三、RLM 嘅極簡定義

「一個 RLM 基本上就係一個 harness 設計，其中唯一嘅工具係 code——即係程式化嘅子代理呼叫，佢可以選擇呼叫自己作為工具……而佢處理嘅 context 永遠存喺 code 環境某個記憶裡面（可以係檔案系統）。」 —— Alex Zhang

他以 Prime Agent 為例：Prime Agent 建於 Pi（極簡 harness）之上，唯一工具係 IPython，其餘工具以 Python module / Bash script 載入；context 連「壓縮」後嘅內容都存喺磁碟，模型永遠可以引用原始 context；另加 continual harness（可自我修改技能、子代理、system prompt）同 persistent subagents（子代理可存活於原 agent 之外，可再 prompt、有更高可見度）。

四、Agent swarm：OpenAI 嘅 4,000 萬美元實驗

成本 OpenAI 解 Navier–Stokes / ARC-AGI-3：10,000 個 agent、88 小時、1,300 億 output tokens，以公開定價估計約 4,000 萬美元（Alex：「比我想嘅少」；Vibhu 補充總 agent 訊息量係此數兩倍以上）。

Alex 對「harness 對解題是否重要」嘅判斷：唔太重要。「一個 GPT-6 Astra 級模型，喺有正確資訊嘅條件下，技術上夠聰明去諗出證明。問題係你點樣攞到嗰啲資訊——佢哋嘅情況，大概係喺 swarm 上做咗非常長嘅搜索，加上研究者注入直覺。」重點係：細節唔重要，重要嘅係「你點樣有意義地組合呢啲 agent 去得到最終答案」——而「收斂」本身就係一個唔可以當作理所當然嘅成就。

對比 Kimi 嘅 swarm：「讀起上嚟有趣，但我唔確定佢能否解任何新問題」；對 OpenAI 嘅 dynamic workflows：「我認為呢次發布算係一次失敗——太貴、少人用，行為亦不如預期」，但承認「佢哋明顯訓練過個 swarm，令佢真係朝目標收斂，呢樣非常難」。

五、Capability overhang：呢個係 skill issue，唔係能力問題

「我一直覺得，前沿模型連『連續一個月穩定把一份簡單工作做好』都做不到，呢件事好蠢。我真係認為我們能解決佢……某程度上，呢個係技能嘅失敗（skill issue）。……講到底，呢個其實係 continual learning 問題。」 —— Alex Zhang

他主張：即使唔用 RLM、唔碰新抽象，單靠設計一個 harness 就可以做到——「你唔需要係前沿實驗室、為咗 IPO 做嗰啲花巧嘢」。

六、Jev、輸出空間、同「語言模型唔一定係自迴歸解碼器」

Alex 把 Jev 放喺一個更大嘅問題框架：語言模型嘅正確形式係咩？「語言模型只係喺建模語言，佢唔一定係呢個 transformer decoder。」Jev 嘅價值唔在「又一個分類器」，而在佢開出一個新嘅可調維度——輸出空間 vs 推理延遲/成本：「如果我只需要二元分類，點解要付 400 倍代價？」他認為 Jev 對 RLM 特別有用，因為 RLM/swarm 最大瓶頸就係慢——「你可以叫一個簡單模型做嘅 trivial 嘢，你而家做唔到，因為你嘅語言模型係一件笨重嘅嘢。」他亦點名 Thinky（interaction models）同 loop transformers 屬同一脈絡。

Neo lab 生存之道：「如果一個 neo lab 嘅策略只係複製 OpenAI 或 Anthropic，嗰個係糟糕透頂嘅策略——你等於喺資料同算力上同佢哋競爭，而你必然輸。」前沿實驗室為何唔做新賭注？「舊賭注已經有效，你點解要冒險掟大量算力落新注？」——呢個正是 neo lab 誕生嘅機制。

七、重點引用

「一個 harness 係一個非常有意見嘅程式，關於你希望如何把一個語言模型『形塑』到某個問題上。」 —— Alex Zhang
「未來我們所講嘅『語言模型』——你 query 嗰個嘢——可能其實係一個 swarm，或某種 scaffold，或某種好怪、但擴展性好好嘅 harness 設計，只係用戶睇唔到。」 —— Alex Zhang
「如果你只想做會令業界實驗室覺得好看嘅題目，噉你就去業界實驗室。作為 PhD 學生，你能對幾乎任何事情為所欲為——呢個係你最大嘅優勢。」 —— Alex Zhang 論「敢下大注」

八、技術細節速查

主題要點
Context offloadingcontext 存於檔案系統/REPL；即使壓縮後，模型仍可引用原始 context
Speculative PTC工具呼叫提前並行啟動（JIT + 靜態分析）；函數式語言（Lisp/OCaml/Effect-TS）更易做 pipeline
Calibration被問「你多有信心」時，模型吐「最可能嘅下一個答案」而非真實校準；Jev 嘅 grounded classification 係關鍵差異

九、爭議點

  • 「所有 harness 都一樣」本身具爭議，但他以 harness tax paper 為背書，並承認 Grok Bot、Prime Agent 係例外。
  • 稱 OpenAI dynamic workflows「算係一次失敗」（太貴、少人用）——與 OpenAI 對外敘事直接衝突。
  • 對 Gemini / AlphaProof 嘅保留：「有點被誇大」；GDM「太官僚、有才華資源卻交唔出產品」（「我識嘅人冇一個用 anti-gravity」）。
  • 數學家反 AI 立場：Alex 認為「若佢哋好多人冇先同 OpenAI 合作過，論點會更站得住」；swyx 即刻指出係 ad hominem。
