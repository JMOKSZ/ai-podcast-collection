「巨鯨歸來」——DeepSeek V4.1-Flash：763B-P8B-D16B 全新因果 Encoder–Decoder、KV cache 壓到 1/8、每題成本僅 $0.27（約同行 1/7），同「改數據品質嘅 ROI 已高過搞新演算法」

📅 2026-09-12 05:56 UTC 發布·🎙️ Latent Space（swyx + Alessio）·📰 AINews 週報（覆蓋 9/9–9/10）·🏷 架構 / 推理效率 / 模型評測

呢一期 AINews 表面上只係一條模型發布——DeepSeek 出咗個叫「V4.1-Flash」嘅嘢。但凡係只讀版本號同 benchmark 標題嘅人，正正就係 DeepSeek 今次想「愚弄」嘅對象。Latent Space 嘅判斷好直接：版本號只升咗 0.1，實際上係一整個全新架構家族，佢哋甚至順手軟退役咗 V4 Pro。Sebastian Raschka 講得最白——「佢哋應該叫佢做 DeepSeek V5」。呢篇復述會由架構、評測數字、成本經濟學、本地部署，一路拆到社群爭議同同集其他信號，讀完你可以完全跳過原文。

呢集嘅中心論點：DeepSeek 喺 R1 引爆之後潛伏咗差不多一年，任由 GLM 同 Kimi 領跑開源，今次用一個「看似只有 v4.1 小版本號」嘅命名回歸。真正嘅技術突破唔係參數變大，而係prefill／decode 分離——總參 763B，但輸入（prefill）只激活 8B、輸出（decode）激活 16B，稀疏度低到 1–2%。配合 Sliding-Window Attention Bounded Replay 等新技巧，KV cache footprint 最低可以做到 V4 Flash 嘅 1/8。結果係一個「最囉嗦」但「每題只收 $0.27」嘅前沿模型——大約係 GLM-5.3 同 Kimi K3 嘅七分之一。而 DeepSeek 自己嘅判詞更值得記低：「現階段改進數據品質嘅 ROI，已經超過鑽研新奇嘅後訓練演算法。」
一、命名係一場「閱讀理解測試」：V4.1 Flash 嘅真身係新架構家族

Latent Space 對 DeepSeek 嘅研究節奏有個好精準嘅觀察：喺每個大版本之間（v2 → v3 → v4），DeepSeek 會發「中間論文」，每次都係一個極度聚焦嘅架構改進，而且命中率近乎 100%——由 Math（尤其 GRPO）、Coder、R1，到近期嘅 Manifold Constrained Hyperconnections 同 Compressed Sparse Attention，全部係咁。

R1 喺 2025 上半年引爆之後，DeepSeek 開始「潛水」，大約一年時間樂意讓 GLM、Kimi 喺開源模型度領跑。今次回歸，佢哋做嘅嘢反而矛盾又耐人尋味：搞一個全新架構、軟退役 V4 Pro、全押新家族，但偏偏只叫佢 v4.1 Flash。作者嘅解讀係——呢個係一個「測試你識唔識穿過表面標題、睇出真正進展」嘅命名遊戲。

「如果你係嗰種只讀模型版本號同 benchmark 標題嘅人，你就正正係 DeepSeek 想愚弄嘅嗰類膚淺嘅人。」 — AINews 編輯按

官方 X 帖文（9/10）講嘅係「smarter, faster, more efficient」，並自稱係「新建構家族中最小嘅成員，帶原生視覺理解」，設計目標係「更強能力、更快推理、更高吞吐，同可以 scale 到更大模型」。留意「最小嘅成員」——即係話仲有大模型排隊。呢句低調嘅表述，其實已經預告咗整個新家族。

二、核心突破：prefill／decode 分離（763B-P8B-D16B）

最受討論嘅技術新意，係一個因果 Encoder–Decoder（causal Encoder–Decoder）設計，目的係壓低激活算力同 KV／cache 成本。Artificial Analysis 指出，呢個模型用咗全新嘅因果 Encoder–Decoder 架構：輸入／prefill 激活 8B 參數，輸出／decode 激活 16B 參數。

Latent Space 把呢件事延伸成佢哋嘅「字母湯」記號——「DeepSeek v4.1-Flash: 763B-P8B-D16B」，即係沿用 MoE 記號：總參 763B、prefill 主動 8B、decode 主動 16B。呢個稀疏度係 1–2% 嘅量級。配上新技巧「Sliding-Window Attention Bounded Replay」，令 KV cache footprint 最低可以做到 V4 Flash 嘅 1/8——對長時程 agent 嚟講係「更好、更快、更便宜」。

架構一句總結 總參 763B｜prefill 主動 8B／decode 主動 16B（稀疏度 1–2%）｜因果 Encoder–Decoder｜Sliding-Window Attention Bounded Replay｜KV cache ≤ V4 Flash 嘅 1/8（~890 bytes/token）｜1M context｜文字＋圖像輸入｜MIT 授權。

社群對「現代 GPT 式 LLM 點解會返去用 encoder」有好大反應。Reddit r/LocalLLaMA 上嘅技術討論集中喺：個 encoder 對長 prompt 做咩？係將 prompt embed 定係壓縮之後先交畀 decoder self-attention？如果長輸入按句子／段落／模態切開，點 scale？其中一種解讀係——呢個非對稱設計可能代表一條結構上唔同於標準 decoder-only transformer 嘅生成路徑。

Stochastic Chasm 嘅精簡讀法係：同 HySparse、NSA、以及 DeepSeek 自家 V4 嘅 CSA/HCA 對比，呢個設計哲學可以總結為「local sliding-window 分支 ＋ sparse retrieval 分支」，並指呢種「稀疏／局部混合」正逐漸成為行業普遍模式。

TeortaxesTex 就指出 DeepSeek 一貫嘅一個怪癖：總係喺前 N 層做啲唔尋常嘅事——以前係 dense 或 hash-routed，而家變成 SWA-only。佢推測呢個可能反映「早期層反覆訓練困難」。佢後來仲話整個 stack「降到 40 層，當中有爭議地只有 20 層係真正嘅 decoder 層」——即係 DeepSeek 可能喺 decode 關鍵路徑上極度壓縮有效深度。

三、KV cache 壓縮：呢個模型嘅真正主角

Nrehiew 嘅技術筆記將 KV cache 壓縮放喺設計嘅中心，稱呢篇報告係「點樣迷戀 KV cache 壓縮，就得到一個超高效嘅前沿模型」嘅案例研究。佢由報告摘出多項基建細節：

  • 為減少長尾停頓而設計嘅 dispatch 策略；
  • router replay——沿用前一個 checkpoint 嘅 router；
  • 用 dataset-level capping 管理「短 completion 嘅 off-policy 效應」；
  • 丟棄機制、bounded off-policy ratio 同 loss masking；
  • 新 checkpoint 更新時持久化 KVs 同 routers；
  • 末端有一個對 40+ 個教師模型嘅 full-vocab OPD（on-policy distillation）。

佢總結呢個設計比 V4 舊有嘅 HSA + CSA 組合「更乾淨」，而且「非常清楚係為推理而設計」，並引用一個相當驚人嘅數字：喺 benchmarked 分數區間，KV 大小約 ~890 bytes/token。Stochastic Chasm 進一步推斷 KV cache 用咗 QAT（量化感知訓練）——呢個可以解釋點解喺 FP4 KV cache 之下，佢表現仍然優於同儕。

「怎麼迷戀 KV cache 壓縮，就能得到一個超高效嘅前沿模型。」 — Nrehiew 對技術報告嘅總結

Reddit 另外有人由 HF safetensors 反推出一個更誇張嘅數字：自第一代以嚟 KV-cache 壓縮達 437×。如果屬實，呢種級別嘅縮減會從根本上改變長上下文服務嘅吞吐同部署經濟學——尤其對比傳統 decoder-only 嘅 attention caching。

四、原生視覺：3×3 pixel unshuffle，同 K3 明顯分岔

今次 DeepSeek 直接內建視覺，唔使另等一個獨立視覺模型。Stochastic Chasm 指多模態改動「唔算激進」——DeepSeek 基本上係「讓骨幹處理大部分，畀佢視覺 token」，並用咗 3×3 pixel unshuffle，而唔係更常見嘅 2×2。佢之後仲特別指出，呢個視覺前端同近期中國同儕（如 K3）有「重大差異」。

Reddit 上嘅人亦提出實際問題：視覺前端同 encoder 點樣配合？如果輸入按模態切開，編碼路徑係咪一致？呢啲問題喺報告公開後仍未完全解答，但已經足夠令人意識到：呢個唔係一個「加個 vision adapter」嘅簡單做法。

五、後訓練哲學：數據品質嘅 ROI 已超過新演算法

其中一個最被廣傳嘅觀察，係 DeepSeek 喺後訓練上嘅表態。Latent Space 話佢哋「大致同意 Prof Jie Tang（唐傑）」嘅觀點。Jasper Lu 嘅評論一針見血：

「呢個值得注意。DeepSeek——一個通常最先開拓新奇演算法同架構嘅 lab——而家話：現階段改進數據品質嘅 ROI，已經遠超過鑽研新奇嘅後訓練演算法。」 — Jasper Lu 引 DeepSeek 論述

呢句話嘅份量在於「講嘅係邊個」。如果係一間產品公司咁講，可以理解為「唔想投資研究」；但當一間以架構創新見稱嘅實驗室都咁講，就係一個行業級嘅信號：2026 年模型進步嘅槓桿，可能已經由「發明新演算法」轉移到「數據工廠 + 獎勵設計 + 系統工程」。

當然，呢個結論唔係人人接受。Shikib Mehri 就明確反駁「研究已死」嘅講法，認為槓桿面只係由架構擴展到數據工廠同獎勵設計——研究依然存在，只係換咗戰場。呢個反駁好重要，因為佢阻止咗一個常見嘅過度解讀：唔好把「架構回報遞減」讀成「研究冇價值」。

六、獨立評測數字：AA Index 40、AutomationBench 追平 Astra

Artificial Analysis 嘅評測係今次最硬嘅一手數據。V4.1 Flash 超越 V4 Pro 0813，但價錢平好多；AA Intelligence Index 得 40，略低於 GLM-5.3-Flash、高於最新 V4 Pro。完整數字如下：

  • AutomationBench-AA：69%——追平 GPT-6 Astra（69%）、高於 Grok 4.6（67%）；比 V4 Flash 0731 提升 15 分，比 V4 Pro 0813（57%）高 12 分，比 GLM-5.3（62%）高 7 分。
  • GDPval-AA v2：+164 Elo（1468 → 1632），反超 Kimi K3（1584）。
  • AA-LCR v1.1：84%——同 GPT-5.6 Sol、Gemini 3.8 Flash 同級（84%）。
  • Vals Index：#1 開源權重模型（超越 Kimi K3），每測試 $0.30，係開源前十中最便宜嘅；評測設定：1M context、384 max output tokens、temperature 1、預設 top-p/top-k、high reasoning effort。

定價方面：$0.30 / 1M 輸入、$1.20 / 1M 輸出，cached input $0.006 / 1M，另有 50% 離峰折扣；1M-token 上下文、文字＋圖像輸入、MIT 授權、美國 API 可用。Baseten 同日 day-0 支援，定位為「比 V4 Pro 0813 更聰明、更快、更高效，帶文字同視覺，US-only，ZDR，1M context」。Ollama 亦開始向 Max、Team 帳戶推出，再擴展到 Pro 訂閱者。

七、成本經濟學：「最囉嗦」嘅模型，每題只收 $0.27

呢度有個反直覺嘅細節。Artificial Analysis 指 V4.1 Flash 係量度過最囉嗦嘅模型之一——平均 89k tokens / 題：比 GLM-5.3（71k）多 25%、比 GLM-5.3-Flash（69k）多 29%、比 V4 Pro 0813（55k）多 62%，甚至高過 Fable 5.1（78k）同 Claude Opus 5（73k）。

但即使咁囉嗦，AA 估計每題成本只係 $0.27——大約係 GLM-5.3（$2.01）同 Kimi K3（$2.00）嘅 1/7，約 V4 Pro 0813（$0.67）嘅 1/2.5。呢個就係「極平 token 單價」帶嚟嘅槓桿：講多咗，但總成本仍然遠低。

成本對照（AA 每題估算） V4.1 Flash $0.27（89k tokens/題）｜GLM-5.3 $2.01（71k）｜Kimi K3 $2.00｜V4 Pro 0813 $0.67（55k）｜→ Flash 每題成本約為頭兩者嘅 1/7。Vals 每測試 $0.30，開源前十最便宜。

有個社群帖文更進取咁講：V4.1 Flash 喺 DeepSWE 上表現好過 GPT-5.6 Sol 同 Opus 5，而 API 成本低 94%。但 Latent Space 特別註明：呢個係二手轉述，唔係一手 benchmark 帖文，所以唔應該當成已驗證嘅事實。呢個 caveat 好重要——當一個模型發布，社群好容易將「疑似」講成「證實」。

八、本地部署：4 張消費級 GPU、128GB M5 Max SSD 串流

呢一 part 係令 systems 圈最興奮嘅地方。多個一手報告顯示，V4.1-Flash 喺「平民級」硬件上跑得意外地順：

  • Fraser Price：全精度 V4.1 Flash ＋ DSpark，喺 4 張 Max-Q、只有 64GB 系統 RAM 上跑到 200 TPS，做法係將 200GB 嘅 Engram／hash table offload 到 NVMe；之後喺 4 張 RTX Pro 上提升到 300+ TPS，峰值 RAM 仍低於 32GB（用自訂 vLLM fork ＋ SSD 支援）。
  • Antirez：用 DwarfStar 喺 128GB M5 Max 上跑 V4.1 Flash，話 SSD 串流令佢「意外地快」；佢推測除咗近期 SSD-streaming 改進，DS4.1「用同一批專家多咗」都可能係原因。
  • TeortaxesTex：「簡直難以置信——你可以把前沿模型大部分放在 SSD 上跑。」

推理基建亦緊跟：vLLM 新版將 DeepSeek-V4 嘅 shared experts 融進 MegaMoE，而 Mooncake Store 可以 offload decode KV。呢個組合正正解釋咗，點解呢一類模型嘅 serving 喺開放基建上迅速變易。

不過，Reddit 有另一條重要嘅反駁線：唔好被「本地可跑」沖昏頭腦。有人由 safetensors 檢查後指出，V4.1 Flash 其實係 ~748.5B 參數（backbone 551.566B ＋ engram 196.929B；加埋可選 DSpark/MTP 14.225B ＋ 視覺 encoder 0.485B，儲存版約 763.21B / 511.76 GB），並認為「552B」「485B」等數字係計數／metadata 錯誤（例如 HF 把 FP4 packed weights 當成 bytes 而唔係兩個參數／byte）。結論係：即使有稀疏激活，552B 總參令本地推理對多 DGX Spark／Strix 級設置仍然唔現實。實務建議係——用大型 V4 級模型做 planning，再用細啲嘅蒸餾模型（Q38-27B、Q38-35B-Distill、Ornith35B）做本地 agentic coding 嘅執行。

本地部署嘅兩個平行事實 ① 已有實測：4×Max-Q / 64GB RAM = 200 TPS、4×RTX Pro / <32GB = 300+ TPS、128GB M5 Max SSD 串流可行（關鍵：200GB Engram 放 NVMe）｜② 但總參實測約 748B（儲存 763B / ~512GB），對多 Spark 級設置仍吃力；實務上 planning 用大模型、執行用細蒸餾模型。KV ~890 bytes/token、自第一代壓縮 437×。
九、軟退役 V4 Pro：細模型贏大模型嘅怪現象

其中一條高熱度嘅討論，係 DeepSeek「軟退役」V4 Pro——V4 Pro 嘅流量會自動 route 去 V4.1 Flash，並按更便宜嘅 Flash 價錢計費，直到 V4.1 Pro 推出。官方理由係：V4.1 Flash 喺性能、成本、速度同總使用時間上都勝過舊 V4 Pro。

社群有幾個耐人尋味嘅觀察：

  • 有人指 V4 Pro GA 可能「深受 reward hacking 困擾」，而且「雖然差不多 6 倍大，但表現冇實質好過 Flash 模型」。呢個令退役變得理性——如果大模型嘅每 token 成本高但能力冇拉開，就冇理由繼續服務。
  • 有人將 DeepSeek 同 Google 嘅情況並列——兩個案例都出現「細 Flash 變體追平或超越大模型」，並推測呢啲唔一定係由單一大型訓練 run 蒸餾出嚟，gap 可能來自唔同架構、訓練 pipeline 差異、或數據 mix。
  • 有人區分「API 退役」同「模型消失」：DeepSeek 停咗服務 V4 Pro，但權重據報仍然可得。

呢個「細模型贏大模型」嘅現象，其實同 DeepSeek 自己嘅敘事一致——真正嘅前沿唔再係「邊個參數大」，而係「邊個 leverage 用得好」。

十、爭議：TeortaxesTex 唱反調，同「單打可能勝團隊」

AI 圈最出名嘅 DeepSeek 咬人者 TeortaxesTex，今次一如既往唱反調。佢嘅核心論點係：DeepSeek「出嘅係內部研究產物而非產品」，所以常見「內部評測高、外部穩健性弱、脆弱、技能缺口怪異」。佢稱部分評測結果「非常奇怪」，尤其係 AutomationBench 排第一同 CritPt 退步，並叫 DeepSeek 團隊「冥想一下」。

佢亦指 V4.1 一個優點：相比 V4 GA（受益於大量 tool／skills harness access），V4.1 喺「minimal harnesses」下表現更好、較唔依賴 scaffolding。

最實用嘅一手觀察係關於 multi-agent：佢報告話，除非個 project 有非常清晰嘅模組化，否則 multi-agent「DSH agent teams」會降低質素——子代理產出 slop、浪費 token 喺唔必要嘅研究上，至少喺一個例子裡面，V4.1 單打勝過團隊模式。呢個同 AINews 同集其他 agent 研究（例如 Salesforce 指「喺更強專家完整軌跡上訓練弱模型」反而降分）互相呼應。

「簡直難以置信——你可以把前沿模型大部分放在 SSD 上跑。」 — TeortaxesTex（同一帳號，時而盛讚、時而開炮）

另一邊，Gordic Aleksa 借呢篇論文做 pretraining-data 分類，將 DeepSeek 放入「organic data」陣營，並對「佢哋根據出版物睇，好似連合成 rephrasing 都唔用」表示驚訝。呢點同「改數據品質 ROI」嘅宣言形成一個張力：DeepSeek 講數據重要，但佢哋強調嘅似係「真實數據嘅品質」，而唔係合成數據嘅量。

  • OpenAI GPT-Live-1（語音）：以 API 形式推出，係一個全雙工語音介面——可以邊聽邊講，並將 tool use 或推理委派畀後端模型。開發者可控制語氣、節奏、表現力、回覆長度同語言。OpenAI 自家 benchmark 稱：搭配 GPT-6 Astra 時，Tau3 首次任務完成率 83.6%、AA Conversational Dynamics 97.3%、Full Duplex Bench v1 響應起始延遲 0.798s。同日亦公布 Agents API 公測（Codex harness）同 OpenAI 託管沙盒。生態跟進：LiveKit、HeyGen、Telnyx、Speak、Cognition Devin Voice。

  • Cognition SWE-2：自稱「最接近前沿嘅自家模型」，在主流 coding 評測上以「低至 70% 成本」取得相近表現，並明確講把 RL 擴展到數萬億參數；團隊自建演算法／基建／數據。同日發布 Devin Voice（基於 GPT-Live 同 SWE-2），Dioxus Labs 併入 Cognition 負責 Devin 嘅 VM、computer use 同測試。
  • Cursor「Projects」：持久線程 ＋ coordinator agent、跨 agent 共享記憶／工件、跨裝置同「agent 電腦」同步——由「一任務一對話」走向長生命週期嘅軟件專案基質。配合 Claude Code 新嘅 pane pop-outs 同 managed-agent session viewer，市場正收斂到一個共識：coding agent 需要持久上下文、可檢視 session、同顯式編排控制，唔只係更好嘅 completion。
  • Agent 研究：Salesforce 論文指「喺更強專家完整軌跡上訓練弱模型，經 harness 演進後反而降 4–30 分」（因學到不相容嘅規劃風格），修法係「只重寫失敗輪次於弱模型自身 rollout 中」；ByteDance HarnessDev 讓 agent 自建並迭代 harness（僅 34/64 改動可方向性遷移）；Qwen Elastic Horizon 用「成功軌跡長度 90 分位」自適應調整互動視野，最多省 25% 軌跡 token；PARSER 用平行凍結子代理 ＋ RL 主代理做 scatter-gather，896K 上下文 +12 分、延遲降至 1/11；SkillAdam 將技能自演化當離散優化；Google ToolGrad 先產出 tool-use chain 得近 100% 資料通過率。
  • 安全／治理：Anthropic 發布迄今最詳盡嘅濫用報告（網絡攻擊、影響力操作、監控、生物、武器），聲稱已瓦解所有描述嘅行動；Redwood Research 提出「透明性規範」，針對可能削弱或消除 CoT 可見性嘅架構；Ryan Greenblatt 主張部署前先公布證據同政策；Neel Nanda 認為 GPT-6 Astra 係「無 CoT 推理」嘅可疑躍升，可能代表超出普通 scaling 嘅架構變化；Hugging Face 新設 Open Alignment 團隊；Richard Ngo 批評 Paul Christiano 加入 OpenAI 董事會、以及「安全社群被 AGI 公司俘虜」。另有 OpenAI 因 Astra 產能問題暫停新 $200 Pro 註冊（現有使用者不受影響）。
