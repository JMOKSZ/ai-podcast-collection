「佢哋想要 agent 像人一樣強大，卻又想要佢像機械人一樣可控」——MLST × Shawn Wen：語音 agent 嘅節奏、噪聲、同認知債

📅 2026-10-01 20:00 UTC（北京 10/2 04:00）·🎙 Machine Learning Street Talk（主持 Tim Scarfe）·👤 嘉賓：Tsung-Hsien（Shawn）Wen，PolyAI CTO·⏱ 70:10·🏷 語音 agent / 端到端模型 / 企業部署

本集與 PolyAI 合作製作。以下內容按 YouTube 官方字幕（約 69 K 字元）整理，引號內係字幕原文（口語、含少量轉錄誤差）。

一句話總結

語音比文本難，因為多了「時間」——你必須喺對嘅時刻回應，並且適應對方（老人放慢、地方口音）。企業要一個矛盾體：像人一樣強、像機械人一樣可控。而 AI 世界嘅瓶頸，已由「生產內容」轉向「驗證與審計內容」。

「他們想要 agent 像人一樣強大，卻又想要 agent 像機械人一樣可控。呢個係一個非常矛盾嘅組合——而我認為，呢個正是將 AI agent 部署到企業嘅困難所在。」 —— Shawn Wen

一、為何語音比文本難？

ChatGPT 之後，大家一度以為「語音好快就解決」，於是出現大量「把 ASR + TTS 串埋一齊」嘅公司。但現實更難：

  • 語音多了一個維度——時間。文本世界有海量文件、線上論文，連博士級物理題都唔算難；但語音係「通往真實世界嘅一步」，「我哋仲未訓練模型去真正理解『時間』呢個概念」。
  • 智能嘅本質係「適應」，唔係「推理」。人類對話中嘅智能「唔在於推理，而在於適應」。
  • Cascade 天生唔協調。傳統 ASR + LLM + turn-taking 三段「唔係好配合」，要靠「加多個偵測器、再 tweak 一個參數」硬湊，「非常 cranky，而現實根本唔係噉運作」——因此必須塌縮成端到端。
  • 同機械人同理。物理世界嘅數據極少（「我想要機械人斟啤酒」呢個測試就極難）；語音同理，只係「人類之間有咁多對話，但機器從來觀察唔到」。

二、企業到底想要咩？

  • 品牌化聲音：能準確念出品牌名、能揀身份。
  • 矛盾組合：像人一樣強 × 像機械人一樣可控。
  • 錨定最好嘅人類：「佢哋嘅期望係——只要同我團隊最好嘅人一樣好就得。」採用曲線嘅關鍵係先搵到「效率」切入點。

三、點解自建模型：demo 神、部署即崩

「所有最新嘅 speech-to-speech 模型，喺 demo 都好神——我可以畀你睇一段好自然嘅對話，你會話『哇，奇點到了』。但一部署到 contact center，佢喺好多地方崩掉。打斷太激進——如果你喺同一個老人家講電話，佢第一次同 bot 講嘢、一直困惑、停低，而 agent 一路搶住講，嗰種挫折……」 —— Shawn Wen

「我認為前沿實驗室唔係為咗我們在意嘅嘢（B2B 嘅真實對話輪替）優化。」

四、Dialog-RSN-1：audio-native 模型嘅推理順序

架構 底層仍係一個輸出文本嘅 LLM（因為企業需在 text 上施 guardrail），但原生接收串流音訊 chunks——輸入係 mel 頻譜圖，對模型而言似「逐段影像辨識」。
  1. 第一個 token ＝ turn-taking 訊號（對方剛開始說／仍在說／已說完）；極便宜，每秒音框都生成，直到判定句尾。
  2. 音訊已在嵌入空間預處理好，不必從頭再編碼整句，直接預測回應（text 或 tool call，像典型 chat API 串流）。
  3. 生成 citations（引用知識庫哪一條事實）。
  4. 最後才輸出 transcript（供審計/除錯）——「我哋把舊嘅順序反轉」。檢索亦改寫：無 transcript 可 embed，改為讓 LLM 生成「search 工具＋查詢」。

五、噪聲、頻譜圖、雞尾酒會效應

  • 刻意加噪：真實 call 已含大量噪聲，再用生成模型疊加（如「機械人念我名字 ＋ 背景嬰兒哭聲」）。
  • 過度清洗反而更差：傳統「去噪/清洗」組件令新模型更差——「佢從未見過被過度清洗嘅環境」。呼應 The Bitter Lesson：失敗模式組合呈指數增長，端到端訓練能覆蓋大量失敗模式。
  • 雞尾酒會效應：傳統 speaker diarisation 假設「speaker1/2/3」，係為 ASR 而生、唔自然；端到端後模型原生感知 crosstalk，且可 prompt 控制（「唔好回應背景插話」或「背景插話時也主動加入」）。差異在於「你點訓練佢、收集咩資料、下咩指令」。
  • 歷史錨點：Victor Zue（1990s 主張光看頻譜圖即可辨識語音）、mel scale。

六、延遲、信任同「思考時做咩」

  • 模型大小選對，模型處理本身延遲唔大；難嘅係「何時判定句尾」嘅粗參數（太短打斷老人、太長令人不耐）。端到端後由模型基於音框（語速 + 語義）自行判斷。
  • 自託管模型，避免網路長尾延遲（P99.5）。
  • latency-budgeted auto reasoning：模型自問「停喺呢度能唔能畀好答案？能唔能壓喺 1 秒內？」——「好似比賽答題倒數」。
  • 信任工程：思考時播電梯音樂、打字聲、filler sentence；「AI 喺電話沉默 3–5 秒，用戶會恐慌」。contact center 有現成做法（等真人問同事時播音樂）。

七、聲音嘅外交學

  • 最好表現嘅聲音通常帶地方口音：英國 Newcastle 口音受歡迎（因客服多來自當地）；南美賭場客戶想聽「howdy」開場，最終仍覺「太過了」沒上線。
  • 最自然嘅英文聲音，早期竟係「帶法國口音嘅法國聲音去講英文」——不完美令其真實。
  • 通用聲音（聯想到傳統 IVR）表現最差——用戶一聽到就掛線。

八、重點引用

「瓶頸已經從生產內容，轉移到驗證與審計內容。」 —— Shawn Wen
「Slop 係冇能力嘅生成（generation without competence）。」 —— Tim Scarfe
「現在 Gmail、Slack 都在用 Claude……人們開始互相發大段 AI 文字；久而久之更多人會講——『你乾脆讓 Claude 讀完，再總結畀我。』」 —— Shawn Wen 談 cognitive debt

九、行業 insight

  • 語音會分兩支：consumer（娛樂/日常，Alexa、Google Assistant 系）vs enterprise（客服/專業，須可審計、合規）。硬件上語音係 IoT 天然模態，預期新一波 IoT/機械人。
  • 企業嘅控制焦慮：大型公用事業客戶明言，未來所有 PR 都要兩週 review、可審計、可靠，不接受 coding agent 直接 auto-merge；平台提供流程可視化 + 工具白名單 + 引用審計——「傳統 no-code flow 唔再係主要介面，而係審計介面」。
  • Harness vs weights：企業想「擁有智能」，但唯一能 in-house 嘅係 harness；Shawn 建議多數客戶先由 harness 著手，真係繞不過才微調權重；新定位＝語音 agent 當前台，品牌/主腦留後台。
  • 語音 benchmark 困境：公開 benchmark 不足且偏合成；PolyAI 用真實 call 數據自建（含延遲、ASR、指令遵循、引用、tool call），計劃數月內公開。production agent 每輪 output 約 50 tokens。

十、爭議點

  • consumer 語音採用曲線嘅懷疑：技術就緒 ≠ 行為改變；「我們係稀有的一群（agent-pilled），但多數人未到」。
  • 語音 benchmark 嘅主觀性：地方口音偏好係文化特定；最終要靠 production 指標（用戶有無完成任務）補足，但那牽涉整個 agent + harness。
  • 「slop」係主觀嘅：作者自認精心 context-engineer 嘅輸出，對收件人可能仍係 slop——他反問一個開放問題：「人類到底應唔應該親自讀？」
