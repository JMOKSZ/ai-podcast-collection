智能跑得好快，落地要等日曆——Astra 之後，Agent 卡身份、機器人卡速度、製藥卡時間

📅 2026-10-20·🎙️ 泓君 Jane·👤 嘉賓：許華哲、朱哲清 Bill、王晟

呢集最值錢嘅唔係「Astra 有幾強」，而係一個好簡單、但好少人講清楚嘅框架：同一個模型，放進三個行業，落地速度可以差幾個數量級，而差別唔在智能，在反饋迴路有幾長。Agent 嘅迴路係秒到分鐘，機器人係分鐘到小時，製藥係週到月。所以同一個 GPT-6 Astra，可以令 Agent 一星期迭代一次，令機器人十八個月後才叫「實用」，而令一款藥仍然要等五到十年。

「AI 圈子看到的是能力曲線，行業裡的人看到的就是落地週期。」 泓君，節目收尾語

一、三個人，三種「距離」

泓君今次嘅設計好聰明：唔係搵三個機器人專家，而係搵三個離同一件事唔同距離嘅人。

  • 朱哲清 Bill——Pokee.ai 創辦人兼 CEO，前 Meta AI 應用強化學習團隊負責人。公司主打 30B 級、可以喺端側同私有算力上跑嘅小模型。佢離商業化最近，所以佢睇 Astra 嘅角度係成本、延遲、可部署性，而唔係榜單分數。
  • 許華哲——破殼機器人創始人、清華大學交叉信息研究院助理教授。佢離物理世界最近，直接部署本體、直接做具身模型。佢嘅評價係三人中最兩極：定性飛躍，但物理上唔可以直接用。
  • 王晟——華盛頓大學計算機學院助理教授、Apodex Lead Scientist。佢做 AI for Science 嘅生物醫學應用，日常任務係 8 到 24 小時嘅長程 pipeline。佢離科學驗證最遠，因為驗證要等老鼠同猴子。

三個人放埋一齊，同一件事就被拆成三種時間尺度。呢個組合嘅信息量，比任何單一嘉賓嘅「Astra 評測」都高。

二、Agent：Computer Use 回歸，本質係「身份」問題
1. 對 coding 唔係換代，對長程任務才係

Bill 嘅判斷好克制，甚至同發布會嘅敘事相反。佢認為單純由 coding 角度睇，真正嘅範式轉變係 Opus 4.5 到 4.6：工具調用幾乎唔再出錯，長程 coding 可以自主跑。Astra 只係「喺更長嘅任務上做到更長」——幻覺更低、審美更好、上下文更穩，但冇解決以前完全解決唔到嘅問題。佢甚至話，發布會強調嘅後訓練同模型開發迭代能力，「試下來並沒有那麼驚豔」。

但呢個「冇換代」嘅判斷，唔等於冇價值。對 Agent 產品嚟講，真正嘅價值係更少掉鏈子：跑一個晚上 24 小時仍然會出現幻覺，只係頻率下降；對前文同已完成任務嘅記憶更穩，唔會頻繁「忘記自己做過乜」。呢種提升唔會出現在 demo 裡面，但會出現在你第二朝起身睇 log 嘅時候。

2. Computer Use 回歸，係 API 經濟嘅倒退

過去兩年，業界默認「所有工具都會開 API、都會有 agent access」，App 同系統都喺度做 agent native。現實係 Amazon、旅遊、購物類 App 唔願意開放接口——唔係技術問題，係流量同定價權問題。於是 browser use 又返嚟。

「最後有可能還是一個 mixture 的狀態。」 朱哲清 Bill，談 API 與 browser use 的長期格局

呢句話聽落好平淡，但係對過去兩年「API 優先」嘅產品哲學係一個修正。Bill 自己嘅路徑就係證據：Pokee 做 30B 級小模型，目標係跑喺 AI PC、AI Box 呢類本地硬件上。如果 browser sandbox 由雲端搬返本地，browser use 嘅瓶頸就會由「商家封 IP」變成「你自己部機有幾快」。

3. 雲端瀏覽器 Agent 嘅死穴：IP 同身份

Meta Muse 畀每個用戶一台雲端虛擬機，本質同當年 Manus 一樣：商用 IP、雲端瀏覽器，商家一封就死。Amazon 已經屏蔽咗 Meta Muse。Bill 嘅破局思路係把 browser sandbox 放回本地——跑喺自己嘅 AI PC、AI Box 上，用用戶自己嘅家庭 IP，商家就冇理由封。

「如果這個硬件本身屬於這個用戶，他就可以直接確認這個 agent 就是這個用戶的代表行為，我就會願意把 access 開給你。」 朱哲清 Bill，談 toC Agent 的破局點

呢個係整集最尖銳嘅商業判斷。商家真正怕嘅唔係 AI，而係「一個用戶變成 20 個 agent，20 個 agent 不停比價、刷流量，消費能力卻仲係原來嗰一個」。一對一嘅代理冇問題，一對二十嘅代理會把商家嘅流量入口同定價體系一齊打爛。誰能證明「呢個 agent 代表呢個人」，誰就拿到 access。呢個亦解釋咗點解 Meta 要把 wearable 做大——硬件係身份嘅自然載體。

4. 免費 token 係一場燒錢換習慣嘅賭局

Meta Muse 每人每週 1 億 token 免費。Bill 按 input 成本粗算，大約 成本每用戶每週約 100 美元。但真正貴嘅唔止 token：雲端 VM 嘅 CPU 同記憶體成本一樣驚人。Bill 話佢哋做 RL rollout 時，CPU 價格一度同 GPU 一樣貴，最後乾脆自己租大 CPU box 架 sandbox。

所以佢嘅判斷係：呢一波 toC 唔可能短期長出 Google Search 嗰種體量。

「我們可能未來需要看到一個完全免費、Token 根本不是一個限制的這麼一個產品才行。」 朱哲清 Bill，談 toC Agent 的經濟模型

注意呢句話嘅邏輯：唔係「補貼到習慣為止」，而係「成本要低到 token 唔再係變量」。兩者係唔同嘅命題。前者係市場策略，後者係技術條件。以目前 frontier model 嘅定價（Astra 每百萬 input 10 美元、output 50 美元，約為 GPT-6 Sol 嘅 4 至 5 倍），後者仍然好遠。

5. 行業分差：前面的人咩都用得，後面的人仲喺泥潭

Bill 身邊用 Grok Bot 嘅人多數係嘗鮮，真正接進工作流嘅好少。而大量傳統企業嘅員工，仲困喺 Microsoft Copilot 裡面，連自由使用 Codex 同 Claude Code 都做不到。

「整個行業現在分差非常大，走在前面的人什麼都可以隨便用，走在後面的人現在還在泥潭裡掙扎。」 朱哲清 Bill

呢個觀察比「AI 普及」嘅宏觀敘事更具體：同一時間點，唔同公司嘅 AI 能力可以差一個世代。而呢個差距唔會因為模型再強而自動收窄，因為瓶頸喺採購、合規、IT 政策同員工習慣。

三、機器人：能力係真嘅，但「思考時長唔跟難度走」
1. 最震撼嘅唔係動作，係「反思變成動作」

許華哲話，過去嘅機器人模型可以把 CoT 寫出嚟，但寫完就結束；Astra 係把反思直接接到下一個動作——撞到桌子會話「呢張枱都幾高，我係咪應該把手抬得更高」，然後真係抬手。畫金門大橋嘅 demo 之所以出圈，係因為佢第一次畫得好差，第二、三次明顯變好。呢個係自我更新，唔係預設軌跡。

第二個能力係 Real-to-Sim：畀幾張圖，Astra 就可以把整個實驗室或辦公室嘅三維場景復現出嚟。過去需要大量拍攝、人工標定同建模。許華哲承認呢個對仿真訓練有實質幫助，亦令好多做 Sim-to-Real 嘅公司鬆一口氣。

2. 但佢把分層架構條線壓咗落去

過去業界嘅分工好清楚：VLM 做任務規劃（「拿雞蛋、開冰箱」），小模型或具身模型做低層控制（「點開門、點打蛋」）。Astra 而家可以直接給出「把手往右伸兩公分」「冇抓住就再往前靠一靠」呢種低層指令——佢把規劃層嘅邊界往下壓咗一格。

呢個變化嘅真正含義，唔係「VLM 變強」，而係整個機器人圈嘅架構討論，由「誰負責邊一層」變成「呢一刀到底切喺邊」。許華哲認為端到端仍然唔現實，但理由唔止速度，仲有缺乏「直覺物理」。

3. 佢慢到唔可以做閉環控制

網上所有 Astra 操作機器人嘅 demo，都要 16 倍或 24 倍速播放，否則就係純等待。原因係模型大，加上內部 CoT 極長；而最關鍵嘅一點：

「面對複雜任務和簡單任務，它的思考時長基本上是相似的。」 許華哲，談 Astra 的推理成本結構

複雜任務顯得聰明，簡單任務就變成純開銷。泓君當場嘅總結好準：「內耗型人格。」

呢個唔係工程細節，而係產品定義問題。如果一個模型嘅思考成本係固定嘅，咁它嘅適用範圍就由「任務難度」決定，而唔係由「任務價值」決定。你可以叫佢做一件值 100 美元嘅事，也可以叫佢做一件值 0.1 美元嘅事，成本一樣。對機器人嚟講，大量任務係後者。

4. 佢缺嘅係「直覺物理」

人隨手碰一個杯，知道裡面有水會灑、係玻璃會碎；Astra 要靠語言推理才能得出呢個結論，而喺任務執行嘅瞬間，佢來唔及。許華哲認為呢一層仍然需要世界模型或高速模型做反射式反應，端到端讓 Astra 控制一切「還不是很合理」。

5. 筷子夾小球：兩種智能嘅正面對照

自家模型快、連續嘗試、失敗咗就換角度，中間冇邏輯思考；Astra 每做一步都要分析「為什麼失敗」，再給自己下指令，更像人類思考，但慢，而且一旦分析錯就卡喺死局，無法繼續推進。旋轉類任務（抓起物體再塞進牆上嘅小孔）Astra 亦明顯偏弱；疊衣服完全做唔到；雙臂任務幾乎冇辦法做。

「在一個語言不太好描述的任務上面，Astra 的能力其實並沒有很強。」 許華哲，談疊衣服與雙臂任務
6. 學習天花板：永遠都係 45 分鐘

許華哲團隊反覆測試發現：第一次做一小時，第二次 45 分鐘，第三次之後「永遠都係 45 分鐘」，變成常數。人或充分訓練嘅小模型會越做越快，Astra 唔會——佢每次都喺重新推理，冇把經驗壓縮成技能。

「第一次做一件事會花一個小時，第二次可能花 45 分鐘，然後我們讓它持續不斷地去做，它永遠都是 45 分鐘。」 許華哲，談 Astra 缺少技能壓縮

呢個係比「慢」更根本嘅限制。慢可以靠算力同蒸餾解決；唔會累積係架構問題。一個唔會把經驗壓縮成技能嘅系統，本質上係每次都在重新計算，而唔係在學習。

7. 對產業嘅衝擊係分化
  • 利好本體與硬件。Astra 出嚟兩三週，史丹佛就有課題組把它接進宇樹機器人做家庭任務，論文兩週就寫出嚟。跨本體泛化能力強，本體質量夠好就可以直接做一部分事情——即使只係 demo 級。
  • 「大腦」公司係分水嶺。一派繼續做更快嘅專用具身模型，從 Astra 身上學數據標註同 CoT 範式；另一派乾脆放棄自研，轉型成部署公司，把自己嘅能力包成 Astra 可調用嘅工具。
  • 中間那層最危險。唔夠快，又唔夠通用。

許華哲對 Real-to-Sim 嘅評價反而冷淡：

「它只是把 3D 的外觀做得非常好，但是它並沒有因為 Astra 出現，然後物理引擎變得更準確了。」 許華哲，對 Real-to-Sim 熱潮的冷水

呢句話值得反覆讀。Real-to-Sim 解決嘅係「場景多樣性」，唔係「物理真實性」。如果你嘅策略轉移失敗係因為物理參數唔準，咁更靚嘅場景只會令你更快咁訓練出一個錯嘅策略。

8. 數據標註嘅門檻變咗：要標因果，唔止標動作

過去嘅標註係「我做了什麼」；而家要標「我為什麼成功、為什麼失敗」——係抓嘅位置偏上，定係東西沾咗水太滑，定係被遮擋。只做正向標註，訓練唔出通用機器人大腦。

許華哲提到一個傳言：OpenAI 而家只買唔標註嘅生數據，認為外面嘅標註都係錯嘅，全部內部重標；某種程度上亦係為咗保密標註方法。呢個令數據市場分成兩層：

  • 賣「生肉」——靠規模同覆蓋，管理一千人一萬人去採數據、把所有家庭 map 一遍。
  • 賣「熟肉」——要理解最前沿模型點樣訓練，知道「這是 OpenAI 的標註方式、這是 π 的標註方式」，單價可以差十倍以上。

呢個分層嘅深層含義係：當模型能力商品化，稀缺性會轉移到「標註方法論」同「不可爬取嘅真實交互數據」。而方法論係唔會寫喺論文裡面嘅。

9. 時間表：2028 年初

許華哲給嘅預測係，由錄製時間（2026 年 9 月底）起約 18 個月，通用機器人開始真正實用；到時一般人在家裡可以用自然語言讓機器人做 90% 家務。佢亦承認呢個相當激進，但認為「物理世界的東西總是要慢一點」，機器人比大模型慢一倍速度係正常。

值得注意嘅係呢個預測嘅內部張力：如果 Astra 連疊衣服都做唔到、雙臂任務幾乎冇辦法做、旋轉插入偏弱，咁「90% 家務」要靠嘅係一個仲未出現嘅模型，而唔係 Astra 嘅下一代。許華哲自己都話，下一步係「系統 1 同系統 2 點樣結合」，而界面設計（Astra 給咩粒度嘅指令）才係關鍵工程問題。

四、製藥：唔係智能唔夠，係日曆太長
1. 佢哋已經整體切換到 Astra，理由唔係知識

王晟團隊已經由 Claude 系列整體切換到 Astra。理由有兩個：Computer Use，同長程任務。

生物醫學裡面有大量「古董級軟件」，係領域默認工具，界面難用、術語多，跨領域嘅人上手成本極高。Astra 可以直接睇屏幕、點滑鼠、照住網上 tutorial 同 user log 學會操作，仲可以順便教會使用者。團隊任務常常跑 8 到 24 小時，Astra 慢，但慢得令人放心——「做得慢說明它可能會更深思熟慮」。

2. 但 Astra 喺生物醫學「知識」上冇進步

王晟講得好直接：提升主要嚟自 general coding、查文獻、長程任務，唔係 biomedical knowledge。專門測生物醫學知識嘅 benchmark，Astra 並沒有提升。真正被解決嘅係 dry lab 裡面嘅 coding 型任務——佢估計 Astra 喺 Terminal-Bench Science 上六十幾分，但「它其實已經做得比我好了」。

呢句話嘅份量在於：一個華盛頓大學教授、AI for Science 一線研究者，話一個六十幾分嘅模型已經做得比佢好。呢個唔係 benchmark 問題，而係benchmark 已經追唔上實際工作。

3. 最嚴重嘅問題係拒答

模型能力越強，對生物醫學任務嘅防範越嚴，動不動就 refuse。團隊內部因此用 Kimi K3 或 Muse Spark 1.3 做日常，需要用 Astra 時得用特殊方式說明「這不是危險任務，我只是在設計一個 benchmark」。

前沿模型在敏感科學領域，越強越不能用。

呢個係一個很少被公開討論嘅反直覺現象。安全對齊嘅半徑越大，科研嘅可用性越低；而呢種摩擦成本唔會出現在任何 safety report 裡面，因為它係「什麼都沒有發生」——研究員只係默默換咗一個較弱嘅模型。

4. 實驗設計嘅完成度只有 30%

模型可以預測蛋白活性、可以生成分子式，但真正重要嘅場景係「給出一個可執行嘅實驗方案」——什麼溫度、什麼濕度、用什麼分子、怎麼合成、怎麼給老鼠用藥、什麼週期。呢啲佢做得仲差。王晟嘅比喻好狠：

「我這個飯店裡有一些原材料，有番茄、有雞蛋、有土豆，我讓 Astra 來做一道菜，它並不能夠理解這個飯店有哪些原材料。」 王晟，談模型缺乏對現實資源的感知

呢個比喻嘅重點唔係「模型唔識煮飯」，而係模型嘅優化目標裡面冇「約束」。它會設計一道海鮮大餐，因為海鮮大餐在訓練語料裡面係「好答案」；但現實實驗室只有番茄、雞蛋、土豆，同一台舊離心機。模型缺嘅係對現實資源嘅感知同調度，而呢種能力幾乎冇辦法由靜態語料學到。

5. Human Use AI：方向反轉

王晟提出一個概念反轉：過去叫 Computer Use（AI 操作電腦），而家真正需要嘅係 Human Use AI——AI 學會點樣指揮真實世界裡面嘅實驗員同機械人。

所以濕實驗室係必需品，而且要為 AI 重新設計。唔係「AI 設計、人工驗證」呢種分割流程，而係把細胞、培養皿、小分子全部前置準備好，AI 一預測完就即刻進實驗，讓乾濕閉環盡量短。

「如果一個問題我已經知道答案，那這個問題其實我沒有必要去研究。」 王晟，談為什麼真正有價值的科學問題無法被 benchmark 衡量

呢句話係整集方法論嘅核心。所有真正值得研究嘅問題，都係冇答案嘅；所以所有可以用 benchmark 衡量嘅問題，都已經偏離咗真正嘅研究。呢個逻辑同時適用於機器人 benchmark——如果一個 benchmark 可以被刷爆，咁它測嘅就唔係通用能力，而係「匹配測試嘅能力」。

7. AlphaFold 3 開源之後，護城河搬到濕實驗數據

模型同工具開源，等於底層基礎設施 ready，垂直科學公司反而更有利——因為它們手上有真實老鼠同人體實驗累積嘅數據。一條完整動物實驗數據價值幾萬到幾十萬美元，而且完全唔喺網絡預訓練語料裡面。

呢個係一條用時間同金錢堆出嚟、無法爬取嘅護城河。而它嘅定價邏輯唔係「數據量」，而係「驗證成本」：一條數據之所以值幾十萬，係因為產生它需要一隻老鼠、幾個月時間同一個實驗室。

8. 新商業模式：幫 AI 做實驗

Adaptyv Bio 同 Anthropic 合作，把濕實驗包成 MCP，模型一給預測就即刻排隊做實驗，剛融了 4,000 萬美元。王晟預測未來每一個濕實驗公司都會用 MCP／API 直接接進大模型，中間嘅人類溝通成本被整段刪掉。

Anthropic 已經明確配備濕實驗能力，最近辦嘅蛋白質設計比賽亦以濕實驗驗證為最終標準；OpenAI 應該亦在布局。DeepMind 嘅路線則更像把驗證放在 Isomorphic Labs。

呢個趨勢嘅深層含義：前沿 lab 嘅競爭，正由「誰有更好嘅模型」轉向「誰有更好嘅驗證迴路」。模型可以買、可以蒸餾、可以開源；濕實驗室唔可以。

9. Claude 嘅 ART 酶：21 小時，但生物圈好冷靜

九月底 Claude 只花 21 小時自己找到一個叫 ART 嘅新酶系統，結構非常像 CRISPR，被懷疑係新嘅基因編輯機制，基因編輯公司股價應聲跌約 10%。但泓君喺 Alignment 2026 大會上問王晟，得到嘅觀察係：AI 圈非常興奮，生物圈相對平淡——「大家想在實驗室裡驗證了再說」。

呢個反差，就係整集嘅主題句。AI 圈睇到嘅係能力曲線；生物圈睇到嘅係驗證日曆。兩邊都冇錯，但佢哋講緊唔同嘅嘢。

五、蒸餾：邊個仲值得被蒸餾

節目後段，泓君提到一個流行講法：很多前沿模型實驗室嘅研究員話，普通人而家可能連蒸餾嘅價值都冇。三位嘉賓嘅回答，恰好代表三種立場。

許華哲：機器人領域，每個人都係生活專家

佢嘅反駁好直接：你擅長做飯、我擅長疊衣服、他擅長走路跳舞，「在今天就是家常菜的每個人做的都值得被蒸餾」。但佢亦承認，一兩年後當機器人可以做今日大模型對普通人做嘅事，門檻就會升到「必須是舞蹈專家或 Gordon Ramsay 才值得被蒸餾」。

呢個係一個動態門檻嘅觀點：唔係人冇價值，而係價值嘅定義會隨模型能力上移。今日嘅「家常菜」係明日嘅「基本功」。

王晟：雙向蒸餾，人負責定義問題

知識層面 AI 確實比單個科學家全面，但科學發現需要長期投入同背書；反過來，佢亦天天喺蒸餾 AI——跨學科嘅新東西唔懂就快速向 AI 學，獲取知識嘅速度變快，反而可以做更好嘅研究。

更關鍵嘅係，人負責「定義問題」：新嘅疾病、想活到 200 歲、每個人不同嘅身體狀況，呢啲問題源源不斷，AI 唔會自己長出來。

「就像飛機就算能自己飛，我們也希望有個駕駛員在上面。」 王晟，談人類科學家為何仍需背書
Bill：而家只係「過擬合得不夠」

Bill 嘅版本更技術：模型記住了大量知識同 know-how，喺固定 benchmark 同落地場景上做大量 overfitting，但很多領域其實仲值得被 overfit。真正嘅 general intelligence 要跳出「每個場景蒸餾一次」，變成「從零開始學」——唔係蒸餾人做得多好，而係蒸餾人點樣學，並且學得比人快。

呢個區分好重要：蒸餾「結果」同蒸餾「過程」係兩件唔同嘅事。前者產生一個更快嘅模仿者，後者產生一個真正嘅學習者。而後者，正係目前模型最缺嘅嘢——亦呼應許華哲講嘅「45 分鐘常數」：Astra 唔會把經驗壓縮，因為它冇學「點樣學」。

呢個框架嘅推論係：模型能力係必要條件，但從來唔係充分條件。而「充分條件」喺每個行業都唔同——Agent 係 identity，機器人係 latency，製藥係 calendar。呢三個字，比「AGI 已經到來」有用得多。

三個更具體嘅判斷

1. toC Agent 嘅競爭會由模型層轉向 access 層。誰能拿到商家嘅 API 或不被封嘅瀏覽器，誰就有產品；而 access 嘅前提係身份驗證，身份嘅載體係硬件。呢條推理鏈把「AI 軟件公司」重新拉回「軟硬結合」，亦解釋咗 Meta 點解要做 wearable。

2. 前沿 lab 嘅 token 大戶唔係 toC，係 AI for Science。泓君提到，前沿模型研究者認為 toC 同消費級 agent 嘅 token 消耗其實花唔多錢；真正燒錢嘅係未解決、未定義嘅科學問題——OpenAI 解一個 Navier–Stokes 就燒掉約 2,200 萬美元。呢個改變咗對「模型公司商業模式」嘅想像：最賺錢嘅應用未必係最燒 token 嘅應用。

3. 監管與安全會成為科研嘅生產力瓶頸。王晟團隊要繞過拒答才能做正常研究，呢個係很少被討論嘅摩擦成本。當模型越來越強，安全對齊嘅半徑亦越大，前沿科研嘅可用性反而下降——呢個會催生一批「合規科研模型」或「私有科研模型」嘅需求。

九、爭議點與未解問題

1.「機器人 benchmark 失效」是否等於能力飛躍？許華哲話 RoboDojo 等公認仿真 benchmark 上 Astra 都拿第一，係定性變化；但王晟對生物醫學 benchmark 嘅批評（Kaggle 化、定義不良）同樣適用於機器人。如果 benchmark 本身測嘅係錯嘅東西，拿第一說明嘅係「匹配了測試」，唔完全係「通用能力」。

2. Real-to-Sim 係突破還是炒作？許華哲直指物理引擎精度冇變，只係外觀更真，屬於 hype；但產業界普遍把它當成 sim 訓練嘅文藝復興。分歧在於「視覺真實」對策略遷移到底有幾大貢獻。呢個問題目前冇共識，而它會直接影響做仿真嘅公司嘅估值。

3. 小模型追平大模型，可能追錯方向。Bill 由工程角度睇到差距縮小；王晟由科學角度提醒，大家追嘅 benchmark 本身定義得唔好，追平咗都唔代表有用。呢個係「指標最佳化」同「真實能力」嘅經典衝突。

4. 能力越強、拒答越嚴。呢個係本集最反直覺、亦最少被公開討論嘅觀點。安全對齊讓模型喺生物醫學場景越來越不可用，科研人員只能繞路或改用較弱嘅模型。呢個係一個真實嘅生產力損失，但喺安全話語裡幾乎冇位置。

5. OpenAI 只買生數據、認為外部標註都係錯的。呢個係許華哲聽到嘅傳言，未經證實。如果為真，意味住數據標註產業嘅價值會被壓縮到「原材料」層，方法論溢價消失。但反過來講，如果「熟肉」真係值十倍價，咁方法論溢價唔會消失，只會更集中喺少數團隊手上。

6. Jev 的「系統 1」敘事與機器人實測不符。Jev 喺疊積木任務上明顯不如 Astra，因為它冇視覺輸入、缺乏物理常識。呢個對「快思考模型可以取代具身模型」嘅講法係一個直接反例。但要注意：呢個測試係用 Jev 嘅非原生輸入方式（先由 VLM 轉狀態向量），所以它反映嘅可能係接口問題，而唔係模型能力上限。

7. 2028 年初的時間表。18 個月做到 90% 家務，與目前雙臂任務、疊衣服完全做唔到、旋轉插入偏弱嘅實測差距好大。許華哲自己都話呢個預測「相當激進」。呢個預測最大嘅價值，唔係它會唔會成真，而係它提供咗一個可以被證偽嘅時間點。

十、結尾：三個字

如果只帶走一句話，唔係「Astra 好強」或者「Astra 好慢」，而係：

智能曲線已經跑出去了，落地週期還在原地；中間隔著的東西，每個行業都不一樣。

Agent 隔住嘅係身份，機器人隔住嘅係速度同直覺物理，製藥隔住嘅係濕實驗嘅日曆。呢三個「隔住嘅東西」，決定咗未來兩年 AI 行業嘅真實形狀——而它們都唔會因為下一個模型發布而自動消失。

對創業者嘅含義亦好直接：如果你做應用，唔好同模型比智能，去解決 access、身份、驗證、部署呢啲「模型不屑做也做不了」嘅髒活；如果你做模型，唔好只在公開 benchmark 上追分，因為那些 benchmark 可能本身定義錯咗——王晟同許華哲由兩個完全唔同嘅領域，得出咗同一個結論。
