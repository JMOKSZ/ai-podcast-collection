一、Agent 運行時：「一次對話，多個雲端線程」

Anthropic 把 Projects 推進 Claude Code：單個對話可以派生出並行嘅雲端會話、喺多個線程之間傳遞上下文、並且喺用戶離開之後繼續運行。內部描述佢係「一個更高層嘅協調器抽象，帶住進化中嘅長時記憶同聚合狀態更新，由單一 Claude 控制」（Cat Wu、MikeyK）。AINews 評價：「呢個係迄今最清晰嘅『多會話編排』產品化之一，而唔止係『chat + tools』。」

同期，Google 亦把 Agent 基礎設施標準化——更新 Gemini 託管 Agent，配一個新嘅 Antigravity-based harness，加埋兩個好實用嘅 API：

Google 新 API Credentials API：用佔位符＋受信域出口代理（trusted-domain egress proxying），把密鑰擋喺模型上下文之外。
Files API：產物搬運＋持久沙盒（persistent sandboxes）。
同一發佈宣稱：成本最多降 30%、緩存命中升 22%。

除此之外，Perplexity 嘅 Computer、Base44 嘅打電話 Superagent、Google Labs 嘅家庭向 CC agent、Meta 桌面版 Muse for Mac——「全部指向同一方向：持久 Agent + 收窄權限 + 用戶專屬上下文 + 異步執行，成為默認 UX 而唔係附加功能。」

二、Jev 同學「System One」分類模型，成為新嘅 Agent 原語

TypeSafe 嘅 Jev（即本系列日報用嘅前置過濾工具）係當日討論中心。但社區最清晰嘅模式係：builders 唔當佢係聊天機械人競品，而係當佢係一個「路由／判斷／結構化決策層」，嵌入更大系統之中。用途集中喺 LLM-as-judge、harness 路由、子 agent 創建、結構化輸出。LangChain 嘅評價好精準——「Jev 有用，正係因為佢唔係為自由生成而設計」。Cloudflare 已經透過 AI Gateway 暴露佢，開源復現（openjev-s + Qwen3.6-35B-A3B + SGLang radix cache）亦迅速出現。

技術論點：「喺可能嘅地方，用判別式控制流（discriminative control flow）替代 prompt。」 — AINews 對 Jev 討論嘅總結

社區把 Jev 講成一個「AI if statement」或者「harness 邏輯嘅泛化分類器」。核心吸引力同系統工程師熟悉嘅道理一致：把簡單、高頻嘅決策推畀一個小型、低延遲嘅判別模型，令昂貴嘅前沿模型可以把預算花喺更難嘅推理上。

反方：分類器優先思維嘅邊界（compaction 之爭）

呢段係整期最有價值嘅部分——因為一個尖銳嘅反駁逼出咗概念嘅清晰分離。Theo 嘅論點：

  • 用 Jev 做逐行歷史壓縮（compaction）係誤解咗 Agent 記憶、推理軌跡同緩存經濟學；
  • compaction 唔只係過濾——丟掉隱藏嘅推理負載會損害前沿模型；
  • 而編輯歷史可能比唔郁佢更貴，因為會令緩存前綴（cached prefixes）失效。
「真正有意思嘅唔係『更好嘅 compaction』，而係未來 harness 能唔能夠把 KV caching 嘅顧慮徹底抽象掉。」 — Theo（AINews 引述）

AINews 嘅判斷好中肯：「呢場辯論比 Jev 嘅 hype 本身更有價值——佢逼出分類（classification）、記憶管理（memory management）、推理保留（reasoning preservation）三者嘅清晰分離，而呢個正係 Agent 運行時設計嘅真正分水嶺。」

三、OpenAI 嘅 Astra 擴張：垂直化包裝

Astra for Law 上線：26 個合作方插件 + 47 個社區插件，先喺 ChatGPT 同 Codex 透過 Trusted Access 投放，API 稍後。第三方（Vals）稱，OpenAI 報告嘅跑分顯示 Astra for Law 喺其法律基準上「喺每個價位段」都勝過「通用 GPT-6 Astra + 網頁搜索」。

AINews 點出關鍵：「包裝本身比基準差距更重要——OpenAI 正把前沿能力包成帶維護配置、工具同安全默認值嘅領域化產品，而唔係留返啲垂直行業自己由 zero 開始 prompt-engineer。」
