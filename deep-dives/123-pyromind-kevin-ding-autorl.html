「AI 下半場，唔會只剩一個超級模型」——Pyromind Kevin Ding：Agent 已經會工作，但仲未識成長；AutoRL 點樣將後訓練由一次性交付變成持續管道

📅 2026-08-30 16:00 UTC（北京 8/31 00:00）·🎙️ 十字路口 Crossing（主播 Koji 楊遠骋）·👤 嘉賓：Kevin Ding（火思動力 Pyromind 創始人/CEO）·🎧 小宇宙

當全世界仲喺度爭「下一個超級模型」嘅時候，Pyromind 創始人 Kevin Ding 喺呢集十字路口拋出一個完全相反嘅判斷：AI 下半場唔會只剩一個超級模型，需求世界係多元嘅，唔係所有問題都應該收攏到一個中心化大模型入面解決。佢押注嘅賽道叫「RL as a Service」（後訓練即服務），而且認為呢個只係起點——真正嘅形態係 AutoRL：將訓練、獎勵、反饋、部署、數據回流串成一條自動循環嘅管道。一句話概括成集核心：「今天的 Agent 已經會工作，但還不會成長」。

一、呢集係咩：由「RL 即服務」到「AutoRL」嘅一次完整商業論證

Kevin Ding，Pyromind（火思動力）創始人/CEO。公司所處賽道常被稱作 RL as a Service——後訓練即服務，前不久完成天使輪融資，投資方包括高瓴、百度風投、藍馳、Atypical 等一線機構。真落地場景包括工業質檢、工藝參數優化、GUI Agent、Coding Agent。佢嘅職業路徑好跨：類腦計算/脈衝神經網絡（SNN）出身，做過 CV、大規模訓練基礎設施、IoT、端側到雲——佢自己話呢啲唔係跳嚟跳去，而係「從不同視角理解 AI 產品和技術路徑」，一直想回答嘅問題係：點樣將 AI 由一個算法結果變成可用嘅系統。

創業嘅 trigger 係 2026 年初一個 GUI Agent 實驗。當時佢哋認為 Base Model 已經夠好，理論上應該做到界面理解同任務規劃；但換更強嘅 VLM、加 System Prompt 同規則、補少量數據做 SFT 之後，已知任務嘅 Pass@1 確實提高咗，但只要出現新任務或者新應用，表現就迅速回落。Kevin 由此得出一個後來變成公司信條嘅判斷：

「把已知題修好，不等於 Agent 會從經驗中學習。今天的 Agent 已經會工作，但還不會成長。」 ——Kevin Ding（Pyromind）：GUI Agent 實驗嘅核心教訓——修好已知問題 ≠ 獲得學習能力

佢認為時機到咗，係因為三個條件第一次同時具備：① 基礎模型提供咗足夠好嘅 Baseline（企業唔使從零開始訓練）；② Agent 真正進入生產（企業手上有持續產生嘅任務軌跡同業務反饋）；③ RL 基礎設施同 Reward 工程逐漸成熟（領域知識、歷史任務、人工覆核記錄可以被轉化成可訓練、可驗證嘅獎勵信號）。「市場需求、技術條件和數據供給第一次對上了。」

二、核心論點一：RL as a Service 只係起點，AutoRL 先係終局

Kevin 對「Service」嘅批評好直接：Service 只解決咗一半問題——將模型訓好交出去唔夠。真正要令 Agent 喺生產環境中持續改進，必須將訓練、獎勵、反饋、部署同數據回流串成一條可以自動循環嘅管道。呢個就係 Pyromind 押注嘅 AutoRL——RL as a Service 嘅進化形態，五環節自動循環，唔再係「交付即結束」。

產品演進過程亦印證咗呢個判斷：去年產品只定義到 Studio 層（面向全棧開發者同大規模訓練需求，Product Manager 可以用可視化方式編排訓練流程）；但實際執行之後先發現，有需求嘅人唔淨止係算法工程師——唔可以要求所有客戶先理解預訓練、後訓練同 RL。於是加咗 AutoRL 層，將 RL 入面複雜嘅環節盡量自動化。「對客戶來說，他們真正關心的是部署後的業務表現，以及隨著生產數據回流，效果能不能持續提高。」

「RL as a Service 只是起點，不是終點。Service 只解決了一半問題；真正要讓 Agent 在生產環境中持續改進，還需要把訓練、獎勵、反饋、部署和數據回流串成一條可以自動循環的管道。」 ——Kevin Ding（Pyromind）：AutoRL 嘅定義——由一次性交付轉向持續管道
三、核心論點二：AI 終局係「Agent 蜂群」，唔係超級模型一統天下

成集最反主流嘅一個判斷：需求世界係多元嘅，唔係所有問題都應該被收攏到一個中心化大模型入面解決。多個專精小模型協作，會比單一超大模型更符合真實需求。Kevin 用 Hugging Face 嘅下載數據支撐呢個觀點——HF 上小模型下載仍然佔主流，證明「需求唔會都歸攏到一個 Base Model」唔係空談。

呢個論點直接同 OpenAI/Anthropic 嘅「單一超級模型」敘事相悖，亦係 RLaaS 賽道存在嘅根基：如果一個模型搞掂晒所有嘢，後訓練服務就冇存在價值。而佢哋嘅產品架構本身亦係呢個哲學嘅體現——PyroDash 由 4B 小模型 + 強基座模型 + 協作引擎組成：小 Worker Model 負責具體執行任務（高頻、低成本），強基座模型負責推理與規劃，協作引擎負責調度。目標係喺效果與成本之間取平衡，讓小模型承擔高頻、低成本工作，只喺搞唔掂嘅時候先 Handoff 俾大模型。

四、核心論點三：企業 AI 唔應該係項目制諮詢

Kevin 對 AI ToB 嘅最大擔憂係「做成一單一單嘅項目制諮詢」：如果每次進入客戶場景都要高度依賴人工，公司最終只會變成一個高級外包團隊。佢承認第一次進入客戶場景時，FDE（前線部署工程）嘅工作不可省——要理解數據制式、評價基準、業務流程同獎勵信號；但 Pyromind 追求嘅係讓呢部分工作喺相似模態、相似場景中逐步遞減，將一次性交付沉澱成可橫向複製嘅 AutoRL 管道。

「定制應該成為產品化的輸入，而不應該成為商業模式的終點」——佢對生意嘅判斷標準係：做完之後公司留低咗啲乜。如果一單生意做完淨係留低幾個人幾個月嘅定制代碼，下一個客戶要重新做一遍，咁收入雖然增加，公司卻冇因此變得更可擴展。所以佢哋會主動劃邊界：只有足夠中立，橫向寬度嘅收益先會遠大於吃掉一個縱向市場。

五、核心論點四：RSI 喺 2026 年點解變得重要

節目專門討論咗「自舉式改進」（Recursive Self-Improvement）點解喺呢一年成為後訓練賽道嘅關鍵詞。邏輯好清晰：當 Agent 開始長期參與生產，做過嘅任務要點樣自然變成下一次嘅能力——呢個問題唔屬於任何單一應用，而係會反覆出現喺唔同場景。RSI 嘅敘事就係將呢個閉環自動化：模型將自己嘅經驗變成訓練信號，再更新自己。

Kevin 喺甲子光年專訪入面有一個好重要嘅區分：Prompt、記憶、Harness 同工作流只係改變模型收到嘅上下文，但只有後訓練先可以穩定提升模型自身嘅能力。佢用一個好貼地嘅比喻——「這就像一個員工反覆出錯，管理者不斷在他的工位旁貼流程卡。卡越貼越多，他卻沒有真的學會判斷。Prompt 和規則很多時候是在加流程卡，後訓練要改變的是員工本人的能力。」

六、核心論點五：模型越訓越好，公司未必賺得更少

節目直面「後訓練需求會被模型進步吃掉」嘅質疑——模型越嚟越強，微調市場係咪會萎縮？Kevin 嘅答案係商業模式層面嘅，唔係技術樂觀：Base Model 越強，後訓練嘅起點越高，但企業自己嘅業務流程、數據同判斷，唔會隨住 Base Model 升級自動進入模型。而且生產環境有一個現實約束：效果、成本同隱私好難靠單純調更大嘅模型同時解決——呢個就係「企業 AI 不可能三角」。

「Base Model 解決的是入場資格，後訓練決定它能不能留在場上。基礎模型越強，Agent 進入真實業務的起點越高；但能不能長期適應具體業務，還是要靠後訓練。」 ——Kevin Ding（Pyromind）：回應「後訓練需求會被模型進步吃掉」嘅質疑

佢嘅完整論證：Base Model 越強，反而會出現更多路由、協同同成本優化嘅 RL 需求——有啲任務適合直接調用 Base Model，有啲適合喺本地小模型上完成，有啲需要兩者協作。所以兩者唔係替代關係，「模型會折舊，數據會過期，能持續學習的系統才會持續增值」。

七、核心論點六：雲廠商做後訓練？中立先係護城河

面對「雲廠商又掌握算力、又識做後訓練，Pyromind 點樣唔會被吞掉」嘅威脅論，Kevin 嘅回應係「出發點唔同」：基礎模型公司嘅主航道係繼續將 Base Model 做强，雲廠商有算力但缺縱深服務能力；而 Pyromind 關注嘅係模型進入真實生產之後，點樣將訓練同持續學習做成一項可以服務不同場景嘅 Service。呢個產業位置要求佢哋必須足夠中立——唔依附於任何一個 Base Model，亦唔會自己落場做具體應用。

「中立」對客戶嘅實際意義好具體：換一個 Base Model 之後，過去積累嘅任務軌跡、Reward、評估標準同訓練流程能否最大程度延續，而唔係全部由零開始。企業可以俾 Agent 換「大腦」，但唔應該令佢失去業務層面嘅積累。呢個定位同時係商業化嘅邊界：佢哋唔會為咗短期收入將公司拉返去項目制——「最好的商業化，是今天創造現金流，明天還能留下可複用的能力。」

八、深度分析：呢集點解重要——價值鏈正在由「訓大模型」向「讓模型持續變好」轉移

第一，佢將「後訓練」由一個技術話題講成一個商業模式話題。市場上講 Agent 嘅節目大多聚焦能力——模型幾強、工具幾多；呢集嘅問題意識係「Agent 每日做咗咁多嘢，究竟留低咗啲乜」？呢個提問方式本身，就係行業由「讓它會做更多事情」轉向「讓它長期參與工作」嘅信號。Salesforce 7 月底嘅自我改進 Agent 文章、OpenAI 嘅企業 Agent 產品 Presence（將生產環境嘅持續評估、問題發現同上線後調整放到更重要位置），都指向同一方向——Agent 競爭轉向上線之後。

第二，「需求不會都歸攏到一個中心化大模型」係一個值得認真對待嘅產業判斷。佢同「Agent 蜂群 vs 超級模型」嘅路線之爭直接掛鉤。HF 小模型下載主流 + PyroDash 嘅大小模型協作 + 2026 年開放權重模型崛起（GLM-5.3、Qwen3.8 開源潮）——呢啲證據加埋一齊，令「中心化超級模型」敘事喺真實需求面前冇咁理所當然。呢個判斷對投資人同創業者嘅含義都好大：如果終局係蜂群，咁 infra、後訓練、Reward 工程呢啲「讓 Agent 持續變好」嘅層就會分走「讓模型變好用」嘅利潤。

第三，FDE 人效數據（兩個 FDE 支撐十幾個 B 端客戶）係中國 AI ToB 一個好罕見嘅亮點。中國 SaaS 難做係共識，但 Kevin 認為 AI ToB 可以將 ROI 重新算清——因為 AI 直接作用於生產結果，價值可度量（質檢誤報率、漏檢率、成本都係硬指標）。佢哋客戶篩選三條標準（ROI 明確、數據富集、好壞標準清楚）本質上就係喺度揀「價值可度量」嘅場景先行——呢個紀律值得所有 AI 創業公司抄。
