推理工程大師課——Baseten 點樣將權重變成產品：200K token 嘅旅程、量化誤差互相抵消、megakernel 之死與 Rubin 時代

📅 2026-08-03·⏱️ 1 小時 40 分·🎙️ swyx + Vibhu·👤 Philip Kiely + Ali Taha（Baseten）

Baseten 啱啱融咗 130 億美元 Series F，成為 AI Infra 獨角獸新群體嘅代表。呢集請嚟《Inference Engineering》作者 Philip Kiely 同埋「48 小時拆解 Kimi K3」嘅網紅工程師 Ali Taha（waterloo_intern），由一個 200K token 請求入閘講起，一路拆到量化、speculative decoding、megakernel 論戰、Rubin 硬件同「模型自己優化自己」嘅閉環。三年前「推理工程」幾乎唔存在，今日佢已經係 AI 最關鍵嘅獨立學科之一——呢集就係佢嘅全景圖。

一、一個 200K token 請求入閘之後發生咩事

swyx 第一條問題就好刁鑽：「我 send 一個 200K token 嘅長 query 入 Baseten 嘅推理系統，跟住會發生咩？」Philip 嘅答案係一堂完整嘅 cache-aware 推理課：

  • 第一句係問「你 send 過呢條 query 未？」——cache-aware routing：系統有多個 instance/replica 服務緊同一個模型，要將請求送去「一，有 prefill worker 可用；二，最好已經有 cached input」嗰個。200K token 嘅請求九成係 coding 或 multi-turn agent，好大機會有緩存，可以跳過一部分 prefill。
  • Prefill 同 decode 分離：一組 GPU 淨係處理輸入、建立 KV cache、出第一個 token；然後交俾另一組 GPU 跑 decode 逐個 token 生成。
  • Speculator model 前置：一個細模型快速 autoregressive 預測 3 個 token，再用大模型一次 forward pass 驗證，啱就接受——慳 decode 時間。呢個 draft model 係「traffic-specific」：假設你係 coding traffic，acceptance rate 就會高；如果你叫佢「總結晒 Harry Potter 全套書」，佢會慢。
  • 計費：「幾蚊美金，然後話：『想唔想再嚟一條？』」
「第一個問題我會問：『你之前 send 過呢條 query 未？或者至少部分？』我真係希望你 send 過——因為對我嚟講會易好多，對你嚟講會平好多。」
——Philip Kiely，200K token 請求嘅第一反應（譯自節目轉錄）
二、共享 API vs 專用部署：幾時轉、點解轉

對高流量用戶嚟講，按小時租成部機，比按 token 畀錢平好多——如果你推緊每小時幾百萬 token，你只需要自己設法塞滿部機。但「幾時由共享轉專用」係有講究嘅：

  • 可靠性：最大原因——唔使同人哋嘅 benchmark 流量爭資源（「你服務緊用戶嘅時候，人哋啱啱喺個 endpoint 度跑咗一億 token 嘅 benchmark」）；
  • 自己嘅 spec dec：為自己嘅 traffic 訓練專屬 draft model——例如你想總結 Harry Potter，就 train 一個淨係預測 Harry Potter 內容嘅 draft model，保證三粒 token 次次中；共享 endpoint 冇可能做呢樣嘢；
  • 自訂 batch size / 並行策略：想 optimize throughput 定 latency，自己話事；
  • 精度控制：如果 NVFP4 量化過唔到你嘅 benchmark，你可以用更高精度跑。

典型 journey：人人都想試 open models，所以 pay-per-token API 需求好大；一旦搵到一個 sticky 嘅 use case，就搬去 dedicated。

三、Tool calling 嘅真相：唔係沙箱問題，係「JSON 閉合」問題

呢度有個好重要嘅認知校正。Ali 話：tool calling 最難嘅地方唔係沙箱——唔係驚個 agent 用 tool 逃出沙箱所以要 containment——而係 JSON 閉合：模型輸出 JSON 如果唔以特定方式閉合，個 request 就會出問題。佢見過有模型做完 tool calling 同 thinking 之後，因為冇見到結果而直接幻覺咗個結果出嚟。

「LLM 本身冇能力做任何嘢。佢只係有能力提出『應該做啲咩』嘅建議——而當啲建議以某種方式被格式化，並交俾一個知道點樣執行嘅系統，動作先至發生。」
——Philip Kiely（譯自節目轉錄）

解法其實兩年前已經有：structured output——用 state machine 將輸出限制喺指定格式，即係將舊式「只准 output JSON，唔係就阿婆會死」嗰類 prompt 工程化。但 Philip 坦白：佢解決到「輸出結構」問題，解決唔到「確定性」問題——模型依然可以 call 錯 tool、或者唔 call tool。MCP 喺呢個框架入面「只係另一種 tool，冇乜特別」。

四、Day-0 支持新模型：一場重體力活嘅 inference war

「支持一個新 open model」唔係「能吐 token」就算，而係生產級。GLM-5.2 同 Kimi K2.5 發布嗰陣爆發咗一場 inference war：swyx 承認係自己嗰條 50 萬瀏覽嘅 GLM-5.2 推文點燃嘅——「X 家 90 tok/s，第二日我哋 150」。呢啲數字戰背後係真功夫：要處理好 prefill、KV cache、量化配置先可以上線。

仲有個好靚嘅例子證明 open source labs 點互相「借用」：GLM-5.2 冇 vision，Baseten 團隊嘅 Haley 將 Kimi 嘅 vision encoder 嫁接咗上去——唔使郁個 language model 本身。呢種「手術式 retrofit」喺 open weights 世界會越嚟越常見。

另外一個實務教訓：同一份權重，喺唔同 cluster 上面表現可以唔同——硬件、kernel、race condition 會造成 nondeterministic failure，例如模型有時會 collapse 成重複同一個 token。呢啲都係「推理工程」作為獨立學科要面對嘅問題。

五、量化誤差可以互相抵消——反直覺但被實證

全場最反直覺嘅部分。Ali 用 GLM-5.2 實驗解釋：量化更多層，反而可以保持 benchmark 質量，同時 throughput 提升 20%——因為唔同層引入嘅量化誤差會互相抵消。你 quantize layer 1、5、10，可能好過淨係 quantize layer 1、5——一層偏右、一層偏左、再一層偏右，最後 logits 分佈反而更接近原始模型。

「error(layer a) + error(layer b) < error(layer a) alone——以前行業以為量化越多越差，因為引入越多損失。呢個諗法唔一定啱。」
——Ali Taha 同 Joshua Hill 論文嘅核心結論（譯自節目轉錄）

佢哋同事 Joshua Hill 用 Fourier Analysis on Groups 做咗數學證明：可以預測邊啲層嘅量化誤差會互相抵消，然後專揀嗰啲層嚟量化。驗證方法唔係淨睇 benchmark，而係用 KL divergence 比較量化模型同原始 full precision 模型嘅 logits 分佈——分佈越似，fidelity 越好。結果：比起其他 provider 多量化 20% 嘅層（所以多 20% throughput），而質量仲要好過對方嗰個 quant，因為揀咗啲「誤差會抵消」嘅層。論文叫《Fourier Analysis on Groups》，SOTA 量化法。

六、Megakernel 論戰：fusion 救唔到張量並行

Ali 對 megakernel 好 bearish，而且有硬技術理由：張量並行下，矩陣分佈喺多個 GPU 上面，softmax／指數呢類非線性運算需要成行數據——即使有 fused kernel，你都必須跨 GPU 通信先做得到下一步。加上 megakernel 本身複雜度極高：寫一個極度優化嘅 fused kernel 好難，而佢識嘅公司（佢唔開名）做咗 fused megakernel 之後，好多人最終都冇喺生產環境用——因為 TensorRT-LLM 同 modular kernel 反而更快：每個 component 可以獨立優化，仲可以互相並行。

同一日嘅劇情反轉：Cursor 開源咗 MoK（Mixture-of-Kittens）——NVL72 上嘅 MoE 訓練 megakernel，比最強公開 baseline 快 2.37x。Ali 後來發推「道歉」：「我好抱歉我每一件事都講啱咗。」呢個先係重點：megakernel「死而復生」嘅張力，取決於 scale 同 workload——兩邊都啱。

仲有硬件層嘅助攻：NVIDIA 一個 tech lead 喺 Twitter「揭開 Rubin 嘅面紗」，第三條推文顯示Rubin 嘅設計「從硬件層面扼殺 megakernel」——仲有 Kyle Kranen 提到嘅 tile-level dependency triggers：一個操作嘅數據一 ready，對應 kernel 即刻可以啟動，消解咗 fusion 存在嘅一個理由。Ali 嘅總結：「成個研究領域好似唔會再繼續。」

七、Rubin 同「GPU 演化成可程式化 AI ASIC」

講到硬件，Philip 話自己經歷咗三個硬件週期：Ampere、Hopper、Blackwell——vLLM 最初 targeting Ampere，之後要更新去 Hopper、再更新去 Blackwell，每個週期更快更急但複雜度大幅上升。對 Rubin 嘅預判：Dynamo 透露咗好多線索——KV cache offloading、KV-aware routing、disaggregation 喺 Rubin 時代會更重要；inference engineering 唔再淨係 CUDA kernel 問題，而係好傳統嘅 hardware infrastructure 問題。

「相比 Ampere 或者 T4，Rubin 係一部 ASIC——就係一件被用嚟做某啲嘢嘅嘢。佢係第一粒完全喺『公開開源模型架構世界』入面建造嘅芯片。」
——Ali Taha + Philip Kiely 對 Rubin 嘅定位（譯自節目轉錄）

Ali 仲講咗 inference 嘅「auto-tuning 文化」：同 training 唔同（training 可以計 flops、睇數學），inference 好多時係「你 define TP1/TP2、EP1/EP2，然後用真實 prod traffic 做 shadow test，睇邊個 config 嘅 TPM/TPS 最好就用邊個」。Kernel 都一樣——launch 幾多 threads、用幾多 shared memory，全部 sweep 參數空間搵 empirical 最佳。佢坦言「你冇辦法理性推斷邊個 config 一定最好，但 auto-tuning 就係搵到最好嗰個嘅方法」。

八、本地 AI vs 數據中心 AI：一個令模型「冇咁蠢」，一個令佢「冇咁慢」

呢句係全場最精警嘅一句：

「本地 AI 嘅問題係點將個模型塞入我嘅硬件，然後令佢冇咁蠢；數據中心 AI 嘅問題係點載入個模型，然後令佢冇咁慢。我哋關心『冇咁蠢』，佢哋關心『冇咁慢』。」
——Philip Kiely（譯自節目轉錄）

而且數據中心有好多嘢要同本地生態學：本地 AI 工程師係 dynamic quantization、pruning、distillation、layer removal 嘅專家——呢啲技術數據中心「完全冇掂」。但 tensor parallelism 唔適合本地（佢假設 NVLink 級嘅高頻寬互連），本地被迫用 pipeline parallelism。

九、訓練同推理融合：模型自己優化自己

最後一節講「訓練為推理、推理為訓練」嘅閉環：持續 post-training、部署-評估-改進循環；GLM-5.2 自己幫手優化服務緊 GLM-5.2 嘅 kernel（self-optimizing loop）——呢個就係 2026 年最熱嘅「遞迴自我優化」敘事嘅基建版；更快嘅網絡可能解鎖大幅更快嘅 decode。

仲有 continual learning 之辯。Ali 同 Charlie 喺 Twitter 上拗過：持續學習有兩條路——一，模型學嘢就推入權重（inference 要不斷 fetch 新權重）；二，KV cache compaction（將 KV cache 壓縮到近乎無限而唔流失知識）。Ali 用一個例子解釋權重路線嘅死穴：「如果我喺你嘅 knowledge base 度編輯『Waterloo 係最好嘅大學』，你點解唔用呢個事實去做推理？」——喺 MLP 權重入面改一個事實，係 fundamental 地難。佢最後當眾認輸：「Charlie 嘅 point 係啱嘅，我睇到 KV cache 先係前路」——用 KV cache 做持續學習，inference 本身幾乎唔使變，只係多一步更新 KV cache，權重唔郁，inference time 唔郁。

十、Vee 嘅萃取：呢集對 James 嘅實際意義

「推理拐點」= AI 價值鏈重心由訓練移向 serving

Baseten 融 130 億美元呢件事本身，就係「推理拐點」嘅里程碑信號。對企業決策者嘅意義好直接：模型價格戰（DeepSeek-V4-Flash、GPT-5.6 降價）嘅背後係推理工程師嘅軍備競賽——20–200% 嘅優化空間意味住「同一個模型、唔同服務商，成本可以差數倍」。揀 API 供應商唔再淨係睇模型分數，要睇佢嘅 serving 工程能力。

量化誤差抵消 = 「多即少」嘅工程哲學

「量化更多反而更好」同「error(a)+error(b) < error(a)」係一個可遷移嘅思維模式：系統優化好多時唔係「減嘢」，而係「聰明咁揀邊度犧牲」。Joshua 嘅方法論（用 KL divergence 驗證 fidelity 而唔淨係睇 benchmark）都值得記住——衡量「變壞咗幾多」要用對嘅尺。呢個對任何做模型選型、量化、蒸餾決策嘅人都適用。

「本地 = 冇咁蠢、數據中心 = 冇咁慢」係四艦隊架構嘅分工註腳

James 嘅四艦隊架構（VPS 指揮官 + Mac Mini + Mac Studio + 騰訊雲）橫跨本地同數據中心兩個世界，呢句說話就係最佳分工原則：本地機嘅價值喺「回應質素」同私隱，數據中心嘅價值喺「規模同速度」——唔好攞錯尺去衡量對方。Mini/Stu 呢類本地機可以玩 dynamic quantization、layer pruning 呢啲數據中心「冇掂」嘅技術，呢個係本地部署嘅隱藏優勢。

KV cache 做持續學習——agent 記憶嘅另一條路

Ali 認輸嗰個結論（KV cache compaction 先係持續學習前路，改權重係 fundamental 地難）對 agent 架構有直接啟示：與其不斷 fine-tune 模型去記嘢，不如將「記憶」放喺 context 層——壓縮、檢索、重用。呢個同 Work 拆解文（84）入面「連續性行產品層而唔行權重層」嘅判斷互相呼應：2026 年嘅行業共識係——記憶應該外置，唔好諗住塞入參數。

🔑 總結性洞察：呢集係 2026 年推理工程現狀嘅全景圖：推理已由「訓練嘅收尾步驟」變成獨立學科，有自己嘅研究問題、基建同專業角色。三個最值得帶走嘅觀點：一，量化誤差可以互相抵消——「量化越多越差」係行業迷信，揀啱層可以又快又準；二，megakernel「死而復生」——Ali 話佢死（張量並行 + 非線性 = 一定要跨 GPU 通信，Rubin 硬件直接扼殺），Cursor 同日證明佢未死（2.37x）——答案係「睇 scale 同 workload」；三，推理正在變成系統問題——KV cache 移動、KV-aware routing、Dynamo、本地 vs 數據中心嘅分工，以至「模型自己優化自己」嘅閉環，全部指向同一件事：AI 價值鏈嘅重心，已經由「點樣練出嚟」移向「點樣 serve 得好」。
