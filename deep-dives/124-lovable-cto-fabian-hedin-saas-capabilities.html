一個 App 兩個界面：人類 UI + Agent 界面——Lovable CTO Fabian Hedin 講 SaaS 嘅未來，係「Agent 可以直接呼叫嘅 capabilities」

📅 2026-08-26 16:16 UTC·🎙️ Latent Space（swyx + Alessio Fanelli，記者 Richard MacManus）·👤 嘉賓：Fabian Hedin（Lovable CTO）·📝 latent.space/p/lovable-future-of-saas

好諷刺嘅一幕：Lovable 係一間靠「AI 起 App」出名嘅公司，但佢而家押注嘅未來，係越來越少人會用傳統 App。CTO Fabian Hedin 喺呢集 Latent Space 清楚咁講：軟件會變成 Agent 可以直接呼叫嘅「capabilities」，人類會越來越透過 AI 層同軟件互動——「10 個 SaaS 併成一個 Agent 入口」。佢哋最近完成 $400M Series C（估值 $13.3B），公司正由「AI 起 App 平台」轉向「公司大腦」。

一、呢集係咩：一間「AI 起 App」公司點解要親手終結 App 時代

Lovable 嘅源起好短暫但好戲劇化：2023 年開源工具 GPT Engineer（最初 focus 喺 prototyping）→ 2024 年 11 月商業化 → 2024 年 12 月改名 Lovable。三年內由「AI 寫 App 嘅玩具」變成「全棧軟件建立 + 托管公司」——月收入早就破億人民幣級，而家 ARR 超過 $500M、6,000 萬個 projects、每月 9 億次 visits、Fortune 500 近三分之二公司嘅員工用過。

關鍵轉折係用戶行為嘅變化：先係有人喺平台上面唔再淨係起 prototype 或者 MVP，而係起「真嘢」——「an actual product that serves real customers」；之後再進一步，用戶開始建立內部軟件——CRM、admin panel、客服 console 呢啲支撐公司營運嘅工具。「People started creating not only software to enable a business, in terms of a customer-facing product, but also the operations behind the company.」Lovable 由「AI 生成軟件平台」變成同 Vercel、Cloudflare 爭食嘅「軟件建立同托管公司」。

「You can get to a place where you're using one entry point to all the work that you're doing.」 ——Fabian Hedin（Lovable CTO）：公司大腦願景——一個入口點連接你所有工作
二、核心論點一：Capability——App 嘅有用部分可以直接俾 Agent 呼叫

Hedin 定義咗一個會成為 2026 下半年關鍵詞嘅概念：Capability = 一個應用程式入面，Agent 可以直接呼叫嘅有用部分；唔使有人類用戶打開個 App。技術上係將 App 嘅函數透過 hosted MCP server 暴露成 tools——結果係一個 App 有兩個界面：傳統人類 UI + 一個可以由 ChatGPT、Claude 或者其他 MCP-compatible AI client 使用嘅 Agent 界面。

呢個 shift 對 SaaS 嘅含義好深：應用程式變成「capabilities 嘅集合」，用戶會透過組織 Agent 存取——代替，或者係喺實際應用之外。Hedin 強調平台嘅職責係「確保所有獨立 capabilities 透過一個 Agent 連接——唔係你為每個任務都要建一個唔同嘅 agent」。佢哋自己都咁用：內部建咗一個俾 support team 用嚟發 credits、管理平台嘅工具，而家啲 capabilities 已經可以透過 Lovable agent 用。

「Orchestrating these capabilities is the easy part. Making sure they are well connected, built correctly and reliable is the hard part.」 ——Fabian Hedin（Lovable CTO）：點解 Lovable 嘅 wedge 係「最適合 build capabilities 嘅地方」——編排容易，可靠性先係難
三、核心論點二：公司大腦——「context + capabilities」而唔係「agent」

Lovable 嘅長期願景叫「公司大腦」：一個界面，連接你嘅日常工具；有盡量多嘅 context（你、你公司、世界），加上通用 + 公司特定嘅 capabilities。最終目標係「everything that you're building can be reused in an agentic way」——你 build 嘅一切都可以 agentic 重用。

Hedin 仲解釋咗點解用「brain」而唔係「agent」呢個詞——呢段係成集最有哲學味嘅部分：

「I'm careful about using the word 'agent.' It suggests something like an employee performing a task, which is an easy way to think about it. But underneath, it is really about connecting the right context and capabilities.」 ——Fabian Hedin（Lovable CTO）：點解用「大腦」而唔係「agent」——底層係連接正確嘅 context 同 capabilities

公司大腦仲要異步工作：agent 可以 schedule 自己之後 resume——例如檢查 deployment 或者監察 recurring process，然後將結果返返同一段 conversation。呢個「異步公司大腦」係佢哋同「即問即答 chatbot」式 agent 嘅根本分別。

四、核心論點三：SaaS 未來——人會越嚟越少開 tab，但垂直能力仍然值錢

Hedin 對 SaaS 命運嘅判斷好直接：人類會越來越透過 AI 層同軟件互動——「People are not going to have as many tabs open in different tools as they have historically. That experience is going to consolidate, but the vertical capabilities those tools provide will remain valuable.」即係話：開 tab 嘅體驗會收斂，但工具提供嘅垂直能力依然有價值。有啲傳統 SaaS 會「fight」呢個趨勢，死守傳統 App 唔適應；但 Lovable 想做嘅係一個開放平台——「anyone can connect to, anyone can use」。

最後佢俾 SaaS 公司嘅 advice 已經成為被引用最多嘅一句：

「I think SaaS businesses are going to have to focus more on providing the shovel for AI to use their capabilities.」 ——Fabian Hedin（Lovable CTO）：SaaS 公司嘅未來——做「AI 用你 capabilities 嘅鏟」

五、安全：capabilities 時代嘅最大挑戰——permissioning graph

Hedin 承認 agent + capabilities 範式嘅最大挑戰係安全：如果一個員工用 Lovable 起咗個連住公司 Slack 嘅 App，你要確保佢唔會意外將私人訊息或者其他機密暴露俾公司大腦。佢哋嘅答案係 Connectors + 一套「permissioning graph」。

技術細節（Lovable 官方技術文章）：app user connector 保留每個用戶嘅身份同源系統權限；credentials 加密存 server-side，由 connector gateway 處理，生成嘅 App 永遠攞唔到 credentials——App 只攞一個 bound 到相關用戶嘅 short-lived key。Hedin 嘅總結：「We separate the connection to external systems from the application code being written. The application interfaces with the Lovable platform, but the application itself never gets access to those credentials.」呢個設計令「員工 build 嘅 App」同「公司系統嘅權限」徹底分離——App 代碼可以自由生成，但權限永遠由平台閘道控制。

六、深度分析：呢集點解重要——「harness > model」由觀點變成產品現實

第一，呢係「App 即 capabilities」敘事最清晰嘅一次產品化陳述。過去一年「Agent 會取代 UI」「SaaS 會死」嘅討論好多，但多數停留喺觀點層面；Lovable 係第一間用實際產品路線圖（hosted MCP server 暴露 functions）將呢個願景工程化嘅大平台。MCP 作為「App 嘅 Agent 界面」標準開始落地——呢個同 Kimi Code Remote Control、Claude /resume、appshots 等 harness 第一公民化嘅趨勢完全同頻。「harness 成為模型系統嘅一部分」由觀點變成產品現實。

第二，佢對「agent」呢個詞嘅警惕好有價值。「agent 令人聯想到一個執行任務嘅員工」——呢個諗法太容易令人低估底層嘅複雜性：真正難嘅唔係「搵個 agent 去做嘢」，而係連接正確嘅 context 同 capabilities，而且保證佢可靠。Hedin 話編排容易、可靠性先係難——呢個判斷同 8/22 Latent Space「The Evolution of the Agent Harness」（模型持續吸收 harness 入 weights）互相呼應：層次越嚟越清楚，「買模型不如砌 harness」已經成為實證結論。

第三，安全模型係呢集最被低估嘅部分。「App 永遠攞唔到 credentials、只攞 short-lived key」呢個設計，本質上係將「代碼」同「身份權限」分離——呢個係 agent 時代 SaaS 安全嘅基本盤，亦係 permissioning graph 概念點解會變成企業級需求嘅原因。企業容許員工「亂咁 build App」嘅前提，就係平台層面有能力做權限隔離。
