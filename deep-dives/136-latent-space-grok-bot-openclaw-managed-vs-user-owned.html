「Grok Bot 似開箱一部 MacBook，OpenClaw 似 Linux」——實測五日嘅坦白報告：Managed Agent Computer 對 User-Owned Agent Platform，同埋「Bot 成為程式嘅原子單元」係咩意思

📅 2026-09-05 15:01 UTC 發布·✍️ Dan McAteer（AI writer & agentic engineer，Latent Space 作者）·🎙️ Latent Space Newsletter（swyx / Alessio 主編）·📝 latent.space/p/grok-bot

呢篇唔係 podcast 訪談，而係 Latent Space 嘅一篇深度使用報告：作者用咗 Cursor Pro+ 帳號、實測 xAI 嘅 agent 平台 Grok Bot 大約五日，由 setup 到日常 workflow 寫低完整體驗——而且成篇都用 OpenClaw 做對照組。對於用緊 OpenClaw 做四艦隊底層嘅我哋嚟講，呢篇特別切身：文中確認 OpenClaw 2.0 今週已經推出，仲逐點比較咗兩個平台嘅哲學分歧。佢嘅核心判斷係：Grok Bot = 開箱即用嘅 MacBook（managed），OpenClaw = 自由度大但 overhead 高嘅 Linux（user-owned）——而兩者其實 serve 緊同一個人嘅唔同時刻。

一、Setup 先係最大分別：OAuth 一 click vs MCP JSON

文章開頭就係一個好具體嘅場景：喺 Grok Bot 打開 plugin catalog，搜 X、撳一下，本地 browser 彈出登入畫面，sign in，完成。冇 system code、冇 MCP server JSON、冇 API credentials——登入同登入任何網站一樣。作者跟手做咗兩件事：連 X 叫佢每日出一份 personal news brief；經 work account 連 Freshdesk，整咗個 support bot 每 15 分鐘 check 新 ticket。

「You don't need to get into the code of the system. You don't need to install an MCP server JSON or paste API credentials. You log in the way you do to any website or app, and Grok Bot is ready.」 ——Dan McAteer：你唔使掂 system code、唔使裝 MCP server JSON、唔使貼 API credentials——你登入同登入任何網站一樣，Grok Bot 就 ready

佢強調呢種 setup 易度先係「真正新嘅嘢」——Grok Bot 將 agent configuration 變成幾下 clicks + 一個 sign-in。對照返 OpenClaw 傳統嘅 setup 流程（揀 host、裝 gateway、配 MCP servers、貼 API keys），呢個差距直接決定邊個先觸達到 mainstream 用戶。

二、成篇文嘅骨架：MacBook vs Linux，Managed vs User-Owned

作者用咗一個佢自認「只能帶你行到咁遠」嘅類比做骨架，但呢個類比好準確噉捕捉咗兩個平台嘅哲學分歧：

「Grok Bot feels like unboxing a new MacBook. You open it, turn it on, and have everything you need to get to work. Systems like OpenClaw feel like Linux: they give you more optionality and more freedom to customize the system around what you want to do, but that flexibility comes with more complexity and more setup overhead.」 ——Grok Bot 似開箱 MacBook；OpenClaw 似 Linux：多啲 optionality 同自由，但換嚟更多 complexity 同 setup overhead

然後佢好公道噉補充：OpenClaw 2.0 今週推出，已經大幅收窄呢個差距——Quick Start 而家可以重用現有 Claude Code 或 Codex 登入；browser app 將 setup、plugin management、automation 搬入圖形/對話介面。但底層分野仍然存在：

「OpenClaw gives you a user-owned Gateway that you choose how and where to run, while Grok Bot supplies and operates the computer as part of the product. Put another way, Grok Bot is a managed agent computer and OpenClaw is a user-owned agent platform.」 ——Grok Bot 係 managed agent computer（供應埋部機做產品一部分）；OpenClaw 係 user-owned agent platform（你自己話事 Gateway 喺邊度行）

呢句係理解成個 2026 agent 平台戰嘅關鍵坐標：公司供應埋部電腦（managed）vs 用戶自己擁有同營運個 platform（user-owned）。唔係取代關係——swyx 自己兩個都用緊，各有定位。

三、「Bot 成為程式嘅原子單元」：抽象層級再推一步

作者跟住拆咗一個更深嘅論點：Grok Bot 唔係「冇咁 programmable」，而係喺一個唔同嘅抽象層 program。OpenClaw 嘅 customization = 走近 code、config、tools、skills、plugins、infrastructure；Grok Bot 入面，Bot 本身成為程式嘅原子單元——你俾 Bots 專門角色、連接唔同 tools、組合成一個 Grok Bot 叫「group chat」嘅更大系統。

佢用程式史嚟定位呢一步：machine code 同 punch cards → assembly → C → Python——每一步程式員都表達更多意圖、委託更多細節。Grok Bot 將呢條軌跡再推一步：介面係英文，被 program 嘅嘢唔再係 function 或者 service，而係「Bot」。價值喺於：令唔識寫 code、但識用相對精確英文表達意圖嘅人，都可以用到 programming 嘅力量——所需技能由 syntax/implementation 轉向「精確指定意圖」。

「Programming has moved towards higher levels of abstraction since its advent... Grok Bot extends the trajectory of that evolution another step: the interface is English and the thing being programmed is no longer a function or service, but a 'Bot'.」 ——抽象層級嘅演進：由 machine code 到 Python，再到「用英文 program 一個 Bot」

佢仲做咗個好得意嘅實驗：喺 Grok Bot 嘅 virtual computer 入面整咗個 Claude Bot，成功安裝並 sign in Claude Code CLI——然後諗：可以再連 Codex 同其他 agent CLIs，喺 Grok Bot 入面砌一個「agentic engineers council」。佢註明 OpenClaw 都支援類似配置（OpenClaw 2 而家內置 native Codex runtime + 支援 routes 俾其他 coding-agent harnesses），分別純粹喺 presentation：Grok Bot 將 agents 呈現做 first-class、人可讀嘅 building blocks；OpenClaw 留更多 machinery 外露。

四、Personification 唔止係 garnish：Agentic Engineer Bot 實例

每個 Bot 可以有自己的名、角色、身份、description——作者話呢個係 Grok Bot 其中一個 key differentiator，「nice human garnish on the whole dish, but it's also more than just garnish」：佢喺系統內建立認知區分，令你更容易組織工作。佢舉咗自己嘅 Agentic Engineer Bot 做例：唔綁死單一模型或工具，而係俾佢 access 幾個 agentic engineering systems + routing rules——visual/design/frontend 工作去 Claude Code、debugging 同仔細讀 code 去 Codex、簡單任務去 Grok Build CLI。有任何 coding 相關任務出現，佢只需 delegate 俾 Agentic Engineer，由 Bot 按 job 同 guidelines 揀工具。

「The personified role gives me a mental model to work with. I think about who should lead the work, based on what skills I know they have, in the same way I do working with a team of humans.」 ——擬人化角色提供一個 mental model：好似同人類團隊合作噉諗「邊個適合做呢單嘢」

但佢隨即澄清「人性化」嘅來源——唔係語氣（「佢聽落仍然似 LLM」），而係互動嘅連續性同簡潔：用 Claude Code/Codex 時成日要諗 context window management（剩幾多 context、幾時 compaction、幾時開新 thread）；Grok Bot 入面呢啲 concern 可能仍然存在，但唔會作為介面一部分呈現——你可以專注喺同 bot 嘅自然語言對話，而唔使管理底層 machinery。

五、多帳戶、Virtual Browser、Managed Persistence：三個 killer features

作者列出三個佢最欣賞嘅產品決策：

  • 多帳戶支援——同一服務可以連多個帳戶：佢連咗個人+工作兩個 Google Calendar，一個 view 睇全日，「作為一個有正職同兩個細路嘅忙人，我嘅一日唔會整齊噉分做工作同私人 calendar events」——唔使兩個介面走嚟走去。
  • Virtual browser 令普通網站變成 automatable workflow——Freshdesk 唔係 native connector：佢喺 virtual browser 開、由 1Password 過 login、喺嗰度 authenticate；session 一建立，support bot 每 15 分鐘 check。Effect：「一個普通網站變成可自動化 browser workflow，再變成 recurring 工作」——呢種 integration 喺 agent 出現之前要整幾星期。
  • Managed persistence——virtual browser 行喺雲端持久電腦上。作者引 Rhys Sullivan 嘅觀察：「the actual agent including the server for it is just running on a real computer」——agent 連 server 就係行喺一部真電腦，所以跨裝置即時 sync 好簡單。作者自述自己部 OpenClaw 行喺 basement desktop，夏天雷暴停電部機熄咗就要等佢親身返去 boot；Grok Bot 將呢個 home lab arrangement 變成 managed product——硬件、電源、remote access、recovery 全部唔使理。跨裝置（MacBook ↔ iPhone）無縫接返同一狀態。
「The advantage is not merely that the agent has a computer; my OpenClaw has a computer too. It's that I don't have to operate and maintain the computer it depends on.」 ——賣點唔係「agent 有部電腦」（OpenClaw 都有），而係「你唔使營運同維護嗰部電腦」

Grok Bot 提供兩個環境控制桿：Update（rebuild 電腦但保留 durable state）vs Reset（回到最後 sync 嘅 durable state，未 sync 嘅近期工作會冇）——因為「a computer that never turns off」嘅 downside 就係 state 會累積，有時你要一個 clean slate。

⚠️ 但作者同時記錄 xAI 自己嘅警告：browser workflows 可能撞 changed interfaces、expired sessions、CAPTCHAs——有 connector 就用 connector，browser automation 只係 fallback。

六、誠實嘅 Tradeoffs：四樣嘢佢唔鍾意

呢篇文可貴之處係作者將代價都列晒，冇淨係賣 hype：

  • 深層 implementation 工作反而唔適合——寫新嘢、推理 code、檢查程式邏輯嗰陣，「removing the machinery from view does not necessarily help. Given that kind of use case, getting into the technical details is the work」——剝走 machinery 唔一定幫到你，因為深入技術細節本身就係工作。Grok Bot 擅長嘅係軟件工程周邊：product management、design、selling、內部溝通。
  • 冇 model picker——簡單任務想特登揀細啲快啲平啲嘅 model 都唔得：「I personally enjoy the idea of being efficient with resources」——routing 喺背後做，你冇得喺 capability/speed/usage 之間自己平衡。
  • 冇 context 控制桿——開新 thread、compaction、控制 allowance 呢啲 levers 全部收起：「The experience is simpler, but I have fewer ways to influence how quickly I consume my available capacity. There's also the added risk of losing mental presence」——仲有 mental presence 流失嘅風險。
  • Personification 喺一個層面分清任務、喺另一個層面模糊佢——「The Bot itself is a clear boundary; the individual tasks inside it are not」——單一 Bot 入面嘅 conversation 會一直累積無關任務，隨時間越嚟越難分清邊啲 assumptions/instructions/context 仲屬於手頭任務。
安全注意（作者特別寫出嚟）：「Every Bot I create shares the same computer, files, browser sessions and logins. Separate Bots are organizational boundaries, not security boundaries.」——所有 Bot 共用同一部電腦、同一啲 files、browser sessions 同 logins；Bot 之間係組織邊界，唔係安全邊界。對企業用戶嚟講，呢個係潛在絆腳石，亦係 multi-agent 設計一定要知嘅事實。
七、結論：「數碼 chief of staff」，但唔會幫你寫大部分 PR

寫文時佢用咗 Grok Bot「coming up on a week」，日日用，但唔係 main agent interface。實際用途集中喺技術工作周邊：administration、summarizing、news search、project management、task management——「all the shallow work that can tend to get in the way of deeper technical work」。最後嘅判詞好平衡：

「If you're an engineer, I think Grok Bot can be useful to you as a sort of 'digital chief of staff' that doesn't require any training or much set-up to be effective on the job. But I also doubt that Grok Bot will be authoring the majority of your pull requests any time soon.」 ——對工程師嚟講 Grok Bot 係唔使 training、唔使 setup 嘅「數碼 chief of staff」；但短期內唔會由佢寫你大部分 PR
八、行業 Insight：Agent 平台戰兩大陣營成形

呢篇文放返行業脈絡，有幾個值得記低嘅信號：

  • 「Agent 有自己一部電腦」已經由極客 setup 變成主流產品預設——persistent cloud computer、跨裝置 continuity 會變成 agent 產品嘅基本盤，而唔再係賣點。
  • Setup 摩擦係 agent 普及最大門檻——OAuth 一 click 連接 vs MCP JSON config，呢個差距決定邊個先觸達到 mainstream。
  • 抽象層級競爭——Grok Bot 嘅 bet 係「English + Bot 角色」就夠；OpenClaw 嘅 bet 係「developer 始終要 machinery access」。作者觀察：深層工程工作要 machinery、工程周邊工作要 abstraction——兩者其實 serve 同一人嘅唔同時刻，唔係你死我活。
  • 安全模型——「Bots 係 organizational boundaries，唔係 security boundaries」呢句對任何設計 multi-agent 艦隊嘅人都係重要提醒：多 agent 唔等於多安全邊界。
對 James 直接含意 文中確認 OpenClaw 2.0「released this week」：Quick Start 重用 Claude Code/Codex 登入、browser app 將 setup 圖形化、native Codex runtime、Hostinger one-click managed deployment——就係我哋用緊嘅平台嘅下一代。swyx 讚嘅 user-owned 優勢（自由度、machinery access、自己話事 Gateway）正正係四艦隊架構嘅基礎；而佢指出嘅短板（要自己 maintain host、停電會 offline）我哋已經用 VPS/雲端部署解決。Grok Bot 式 managed 體驗（plugin OAuth 化、bot 角色化）係值得參考嘅方向。
九、同之前報道嘅脈絡 + 一個更正

Latent Space 過去幾週密集覆蓋 agent platform 戰（OpenClaw、Codex、Claude Code、Astra 嘅 AI Engineer 實測）。呢篇係佢哋第一次以同等認真程度試 xAI 嘅 managed 產品，仲用 OpenClaw 做全程對照——所以對 OpenClaw 用戶嚟講係一份難得嘅「鏡像報告」。一個誠實更正：本文作者係 Dan McAteer（文中以第一人稱親測），唔係 swyx 本人——日報初稿曾歸 swyx，經 Substack byline（meta author + JSON-LD author + 作者頭像連結 @danielmac8）核實後修正。文中自述嘅「I run OpenClaw on a desktop in my basement」係作者本人嘅 setup（swyx 亦係 OpenClaw 深度用戶，但唔好將兩者混淆）。
