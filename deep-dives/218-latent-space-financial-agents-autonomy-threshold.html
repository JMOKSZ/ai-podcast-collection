護欄唔係路障，係煞車——OpenAI、Anthropic、Two Sigma、Bloomberg 點樣把金融 agent 放上手

📅 2026-10-14·🎙️ Latent Space（作者 Richard MacManus）·🏛️ 講者：Joseph Kim（OpenAI）、John Feminella（Two Sigma）、Belinda Neal／Keon Shahab（Anthropic）、Andrey Rybka（Bloomberg）

呢篇唔係一集普通訪談，而係 Latent Space 對 AI Engineer New York 2026 一場主題演講群嘅整理：同一日之內，OpenAI、Anthropic 兩間前沿實驗室，加埋 Two Sigma、Bloomberg 兩間「唔可以出錯」嘅金融機構，分別由產品、架構、安全三個角度回答同一條問題——一個 agent 幾時可以唔問人就直接做嘢？四場演講拼起來，答案唔係「加多幾條限制」，而係一句更工程師嘅話：把控制點放喺模型外面，然後把「提議」同「執行」分開。

「Why do cars have brakes? It's not just so that you can stop, it's so that you can go fast and stop safely.」 John Feminella（Two Sigma SVP Architecture），AI Engineer New York 2026
⚠️ 來源說明：本篇主要來源為 Latent Space 官方文章〈Crossing the Threshold: How OpenAI and Anthropic Approach Autonomy and Safety in Financial Agents〉（作者 Richard MacManus，2026-10-14 發布），內容為 AI Engineer New York 2026 場次報道；本文並非逐字稿復述，引號內容全部取自該文章直接引述，其餘為忠實改寫。文中分析、架構圖與「我嘅萃取」屬本站視角；文章未逐篇核實各機構產品細節，本文亦不作額外事實補充。
一、場合：四場演講，一條共同問題

AI Engineer New York 2026 呢一週，其中一個反覆出現嘅主題係「agent 自主性 vs 安全」。有趣嘅係，今次唔係得實驗室講「我們有 guardrails」，而係前沿實驗室同金融機構同台——一邊賣模型同產品，另一邊每日要對住監管機構、交易紀錄同客戶資產。金融業係 agent 落地最矛盾嘅場景：價值最高（一個分析師一星期嘅工作可以壓縮成幾分鐘），但錯誤成本亦最高（一個未經批准嘅交易改動可以係合規事故）。

文章開頭已經把結論講白：

「The main lesson: safe autonomy depends on where you put controls and human judgment, rather than how many restrictions you impose.」 Richard MacManus，Latent Space

注意呢句嘅重點係 where，唔係 how many。呢個分別，正好解釋咗點解同一間公司可以同時「好大胆」同「好保守」：大膽係因為佢知道邊幾個位一定要人手簽名；保守係因為佢知道其餘幾百個位可以完全放手。真正嘅設計問題唔係「準唔準 agent 做」，而係「邊一個動作係不可逆、邊一個動作只係提議」。

二、OpenAI：Joseph Kim 同「threshold of usefulness」

Joseph Kim 係 OpenAI 嘅 Head of ChatGPT for Financial Services，喺 AIE New York 做主場演講。佢提出一個比「AGI 時間表」實用得多嘅概念——threshold of usefulness（有用性門檻）：

「the point where a model becomes capable and reliable enough to save you time.」 Joseph Kim（OpenAI），定義 threshold of usefulness

呢個定義有兩個關鍵字：capable 同 reliable，而且係「同時」。模型可以寫出一份漂亮嘅 DCF，但若果你要花四十分鐘核對每一個假設，佢就未過門檻；模型可以答對九成問題，但若果你唔知邊一成錯，佢都未過門檻。門檻唔係模型能力嘅函數，而係「能力減去驗證成本」嘅函數。呢一點，正好同 10-08 硅谷 101 張闊講「模型越來越強，為什麼用戶沒感覺」係同一個硬幣嘅兩面：用戶感受到嘅唔係 benchmark 分數，而係淨節省嘅時間。

Kim 對 2027 年嘅預測相当具體：金融業會減少依賴 Excel 同 PowerPoint，而且 agent 會強到可以做「investment idea generation and trading」。呢句喺一個金融合規場合講，其實幾大膽——「產生投資想法」同「執行交易」係兩個完全唔同嘅風險級別，前者錯咗只係一個壞建議，後者錯咗係真金白銀。把兩者放喺同一句預測入面，某程度上係刻意模糊「建議」同「執行」嘅界線；而全場演講嘅其餘部分，其實就不斷想把呢條界線畫返清楚。

Kim 亦提到「capability 上升嘅潮水」帶動咗更好嘅 traceability（可追溯性）：

「In finance, you need to be able to check where a number came from and understand the context around it. We wanted that review to be a natural part of the [ChatGPT for Financial Services] experience. These are the kind of product details that help turn a model's capabilities into work that someone can use.」 Joseph Kim（OpenAI）

呢段係全篇最容易被低估嘅一段。佢講嘅唔係「模型更準」，而係「審查係產品體驗嘅一部分」。傳統軟件嘅審計係事後 log；AI 產品嘅審計必須係使用過程本身——你喺同一個界面睇到數字、睇到來源、睇到上下文，然後決定信唔信。如果審查要開另一個工具、另一次匯出、另一個人手核對，嗰個門檻就永遠過唔到。所以 Kim 把「human in the loop」重新定義為產品設計問題：

「How would the interface change? What would the user still need to control, review, or approve? Those are product design questions you can start working on now.」 Joseph Kim（OpenAI）

呢句幾乎係整篇報道嘅方法論：唔好等模型變強先去諗界面，因為界面決定咗模型變強之後值幾錢。

三、Anthropic：Belinda Neal 同 Keon Shahab 嘅「信任層」三步

Anthropic 嘅角度唔同：佢哋賣嘅係「信任」作為一層基礎設施。上個月 Anthropic 發布咗 Claude for Financial Advisors，讓財務顧問把系統接入 Claude 同一個工作流技能集。AIE 現場由 Belinda Neal（Managing Director of Financial Services）同 Keon Shahab（applied AI）講解。

Neal 嘅開場句好有 Anthropic 風格——把技術突破講成一種文明節奏：

「Every so often, a model crosses a threshold. And when it does, a wave of working changes.」 Belinda Neal（Anthropic）

Shahab 接住講「building the trust layer for the agents」，並把它拆成三步：

「Who the agent is acting as with an identity and permissions layer. How we can sandbox and determine the approval layer of the agent, so that someone is signing off before it acts. And lastly, how we know the agent will still work once we adjust any variables over time.」 Keon Shahab（Anthropic）

呢三步值得逐個拆開，因為佢哋其實對應三個完全不同嘅工程學科：

層問題工程對應失效模式
身份與權限「呢個 agent 以誰嘅身份行事？」AuthN／AuthZ、service account、scoped credentialsAgent 用咗過大權限嘅 token；離職員工嘅 agent 仍然活着
沙箱與批准「邊個動作要人手簽名？」Sandbox、approval workflow、權限邊界批准疲勞；批咗但冇睇；或者全部攔死
回歸與持續有效「改咗變數之後，佢仲 work 唔 work？」Eval、regression test、版本鎖定模型升級／prompt 改動後行為漂移，無人發現

第三步係最容易被忽略、但亦最「Anthropic」嘅一步：信任唔係一次性驗收，而係持續證明。傳統企業軟件買咗就係買咗；agent 唔同——模型會更新、工具會改、資料分佈會漂移，今日過到嘅測試，下個月未必過。「how we know the agent will still work」其實係一句評估（eval）需求，而唔係安全需求。

Shahab 用一個「trade break investigation agent」示範提議同執行嘅界線：個 agent 會建議修改訂單，但只可以提出修訂，唔可以真正改落去：

「We want it [the agent] to just propose new amendments to our orders data, not actually make those amendments.」 Keon Shahab（Anthropic），談 trade break 場景

呢個 pattern 好值得記住：把 agent 嘅輸出變成一個 changeset，而唔係一個 commit。同軟件工程嘅 pull request 一樣——agent 可以做盡調查、寫盡理由、改盡代碼，但合併嘅權力留喺人手。好處唔止安全：proposal 本身係可審計嘅 artefact，你可以比較十個 proposal、可以否決、可以事後追溯邊個批准。「提議／執行」分離，係把不可逆動作變成可逆動作嘅最便宜方法。

最後 Shahab 嘅總結係一句基建論：

「By building once with a foundational layer that you trust, you can work at speed to deploy many agents at scale.」 Keon Shahab（Anthropic）

呢句同 Two Sigma 嘅「composable controls」其實係同一個諗法嘅兩面：唔好每個 agent 重新發明安全，而係建一層共用嘅、可組合嘅信任基建，然後上面快速砌 agent。

四、Two Sigma：John Feminella 同「approval fatigue」

John Feminella 係對沖基金 Two Sigma 嘅 SVP Architecture。佢嘅演講係四場之中最「反直覺」嘅：佢明確反對把安全同創新當成光譜嘅兩端，而且特別批判「approval fatigue」——即係乜都要人手批，結果係兩重風險：

  • 拖慢創新：團隊為咗避免審批，索性唔做 agent 項目；
  • 製造新風險：當一個人一日要批兩百件事，佢唔會真的睇每一件——「批咗」唔等於「審查過」，只係等於「撳咗掣」。

呢個觀察其實比好多安全論文更狠：過度審批唔係「保守」，而係「把風險轉移去一個注意力已經耗盡嘅人身上」。表面合規，實際無人把關。

Two Sigma 嘅解法係一套五個控制，佢哋嘅定義係：

「guardrails and shared capabilities that let teams move in ways that don't hinder what they're trying to do.」 John Feminella（Two Sigma）

而且係可組合（composable）嘅：

「each one does one job and then together they let us run agents with real autonomy at an appropriate level of safety.」 John Feminella（Two Sigma）

文章只具體展開咗五個控制之中嘅一個：auto-mode classifiers——用分類器判斷邊啲係例行呼叫，只把最重要、最可能改變結果嘅請求送比人：

「make decisions about routine calls and then send a person only the requests that are most important, the ones that are most likely to make a difference.」 John Feminella（Two Sigma）

Feminella 亦給出一條好實用嘅分工原則：模糊嘅 case 用分類器，清晰嘅 case 用確定性規則。呢句值得抄落 notebook——

原則唔好用 ML 去解一條可以用 if-else 寫死嘅規則；亦唔好用人手去批一件分類器可以可靠路由嘅例行工作。規則用喺「已知嘅已知」，分類器用喺「已知嘅未知」，人用喺「未知嘅未知」。

呢個分工聽落簡單，但多數團隊啱啱相反：用 prompt 去硬解合規規則（不可靠），用真人去批日常小額交易（疲勞）。把兩者調返轉，已經可以釋放大部分被卡住嘅自主性。

五、Bloomberg：Andrey Rybka 同「把安全放喺模型外面」

如果 OpenAI 講產品、Anthropic 講信任層、Two Sigma 講控制組合，咁 Bloomberg 嘅 Andrey Rybka（Head of Architecture & Emerging Technologies, Office of the CTO）講嘅就係真實事故。佢列出多宗 agent 造成混亂嘅事件，以及對應嘅防禦：

  • Scoped identities and credentials——每個 agent 用自己嘅、最小權限嘅身份；
  • Controls over tool calls——工具呼叫要過閘；
  • Outbound traffic restrictions——限制 agent 可以對外連去邊；
  • Audit trails——每個呼叫都要留痕；
  • Budgets——用錢／用量做硬上限；
  • Kill switches——一撳即停。

其中最具體嘅例子，係一個 agent 把市場評論入面嘅指令當成「要入貨」嘅指示，結果真的去落單。呢個係典型嘅 prompt injection，但佢嘅教訓唔止「要防 injection」——而係agent 嘅輸入面（網頁、評論、電郵、文件）同佢嘅動作面（落單、改資料、發通知）之間，冇任何結構性隔離。只要 agent 同時「讀得」同「做得」，任何一段被污染嘅文字都可以變成一句命令。

Rybka 嘅建議係：input validation、prompt injection defenses、provenance tracking、high-value actions 要人手批准。而最核心嘅一句係：

「We want deterministic controls outside the model. Check every call, log it, and keep a kill switch.」 Andrey Rybka（Bloomberg）

呢句係整篇報道嘅技術核心。「outside the model」四個字，等於承認一件事：你唔可以叫模型自己保證安全。模型可以被說服、可以被 injection、可以因為上下文而改變行為；但一個放在模型外面嘅 policy engine、一個網絡層嘅 egress 規則、一個資料庫層嘅唯讀權限，唔會被說服。安全必須寫在模型管不到的地方。

呢個觀點同 Anthropic 嘅「identity and permissions layer」、Two Sigma 嘅「composable controls」其實完全一致，只係用詞不同：把不可協商嘅約束，從機率性的組件轉移到確定性的組件。

拼起來，其實係一條由「值唔值」到「停唔停得切」嘅完整鏈：

  1. 經濟層：呢個任務過咗有用性門檻未？（OpenAI）
  2. 身份層：agent 以誰嘅身份做？權限有幾大？（Anthropic）
  3. 動作層：呢個動作係提議定執行？邊個簽名？（Anthropic／Two Sigma）
  4. 執行層：約束係寫在模型內定模型外？（Bloomberg）
  5. 時間層：模型／工具／資料改咗之後，仲證明到佢 work 嗎？（Anthropic 第三步）

多數團隊只做第 2、3 層（權限＋審批），因為呢兩層最直觀、最容易 demo；但真正決定「可唔可以大規模放手」嘅，係第 1、4、5 層——淨值計算、模型外嘅硬約束、持續回歸。

七、我嘅萃取：五個判斷
1. 「自主性」唔係一個開關，而係一張權限表

四場演講冇一場講「我哋準唔準 agent 自主」。佢哋講嘅全部係「邊個動作、喺咩條件下、要邊個批准」。呢個轉變好重要：當你仲喺度爭論「agent 應唔應該有自主權」，你已經問錯問題；正確問題係「呢個 agent 嘅動作空間入面，邊幾個格子係不可逆？」把不可逆嘅格子鎖死，其餘全部放手——呢個就係 Two Sigma 講嘅「real autonomy at an appropriate level of safety」。

2. Approval fatigue 係安全問題，唔係效率問題

Feminella 嘅觀察值得放大：當審批變成例行公事，合規就變成儀式。一個每日批三百件事嘅人，實際上冇辦法對第三百件保持同樣嘅注意力。所以「加多一層人手審批」往往唔係增加安全，而係把安全責任分散到一個唔可能履行嘅人身上。真正嘅解法係減少需要人手批嘅事情——用分類器路由、用規則寫死、用預算封頂——而唔係增加审批關卡。

3. 「Propose, don't act」係最被低估嘅設計模式

Anthropic 個 trade break 例子，其實可以推廣到幾乎所有高風險場景：agent 產生 proposal，人負責 commit。呢個模式嘅好處係雙向嘅——對安全，它把不可逆變成可逆；對產品，它把 agent 嘅工作變成一份可以被 review 嘅 artefact，於是你可以在 approve 之前看到推理、來源、影響範圍。相比之下，「agent 直接做，事後 audit」嘅模式，等於把審計變成驗屍。

4. 確定性控制放喺模型外面，係唯一可審計嘅承諾

Rybka 嘅「deterministic controls outside the model」應該成為所有 agent 系統嘅默認架構原則。原因唔係「模型不可信」，而係模型嘅行為本質上係機率性嘅，而監管需要嘅係確定性嘅保證。你可以寫「呢個 agent 只可以讀 orders 表，唔可以寫」——呢句喺資料庫權限層係可證明的；你唔可以寫「呢個模型唔會改 orders 表」——呢句只係一個希望。把前者做足，後者就唔需要證明。

5. 金融業係 agent 治理嘅「煤礦金絲雀」

呢四場演講之所以值得讀，唔係因為金融特別，而係因為金融最早被迫面對「不可逆動作」嘅問題。醫療、法律、工業控制、企業 IT 遲早都會遇到同一條問題：agent 幾時可以自己動手？金融業今日給出嘅答案——身份、沙箱、提議／執行分離、模型外硬約束、持續回歸——大機會會成為其他行業嘅模板。與其等自己行業出事，不如現在抄呢套架構。

八、未解問題／批判
  • 「五個控制」只公開了一個。Feminella 講咗有五個，但報道只具體展開 auto-mode classifiers。其餘四個係咩？呢個係報道嘅空白，亦係最想知嘅部分——因為「可組合控制」嘅價值喺於佢哋點樣組合，而唔係單一控制有幾好。
  • 分類器本身係一個攻擊面。用 ML 分類器去決定「邊啲請求要人手批」，等於把安全邊界交給另一個可以被對抗樣本、分佈漂移影響嘅模型。文章冇討論分類器失效時嘅 fallback。
  • 「Threshold of usefulness」缺少分母。Kim 嘅定義係「capable and reliable enough to save you time」，但冇講清楚係邊個嘅時間、邊種任務、咩錯誤率。對一個每小時收費嘅分析師同一個內部合規人員，門檻完全唔同。
  • 2027 年「agent 可以做 investment idea generation and trading」係一個好進取嘅預測。「產生想法」同「執行交易」之間，仲隔住監管批准、最佳執行義務、市場操縱風險——呢啲唔係模型能力問題，而係法律問題。
  • Traceability 同商業機密嘅張力。Kim 講「check where a number came from」，但金融機構嘅 alpha 往往就係嚟自「唔話你知個數點嚟」。可追溯性做到幾細，會直接碰撞商業利益。

一句總結：呢四場演講合起來，把「agent 安全」由一個倫理問題，變成一個擺位問題——身份擺邊、批准擺邊、硬約束擺邊、回歸測試擺邊。當你把呢四樣擺啱，自主性唔再係要唔要給嘅恩賜，而係一個可以計算、可以審計、可以放膽使用嘅工程參數。
