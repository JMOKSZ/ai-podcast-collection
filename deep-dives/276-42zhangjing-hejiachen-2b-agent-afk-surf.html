To B 不是平台——賀嘉琛把 Agent 的兩條路分開，然後決定自己訓模型

這一集表面上是「Agent 賽道復盤」，實際上只做了一件事：把 To C 與 To B 兩條路拆開，然後指出它們不屬於同一種生意。

在 2026 年的語境裡，這句話的重量不在於它多新，而在於說它的人剛剛把兩種經驗都賺過一遍——流量（AFFiNE 七百萬用戶）與退出（VoidZero 被 Cloudflare 收購）——現在他選了 To B，並且已經有幾個大客戶。所以這不是評論員的判斷，是當事人的下注。

一、先把履歷攤開：他賣過兩次「流量」，一次是社群，一次是工具鏈

節目的第一個小時（嚴格說是前十分鐘）在建立可信度，但這段履歷本身有信息量。

賀嘉琛原本研究深度學習與天體物理，2020 年從博士階段退學創業。第一個產品 AFFiNE 是開源文檔協作與知識庫，做到 700 萬用戶、Product Hunt 年度第四。這是一個典型的「开源即分发」故事：產品力帶來社群，社群帶來聲量，聲量帶來下一輪。

但節目沒有停在成功敘事。它明確提到 AFFiNE「為什麼紅、為什麼沒能好好商業化」——這句話是整集的方法論起點。開源產品的用戶與收入之間沒有自動轉換器；你可以有七百萬人用，卻找不到七百萬人付費的理由。這個失敗經驗，比任何成功案例都更能解釋他後來為什麼對「平台」這個詞這麼警惕。

之後他與尤雨溪（Evan You）等人一起孵化開發者工具公司 VoidZero，被 Cloudflare 收購。這是另一種經驗：在開發者工具這條線上，退出不是靠訂閱制堆出來的，而是靠「這個團隊與這條工具鏈對某個戰略買家有價值」。兩次經驗，一次是「有流量但沒商業化」，一次是「有戰略價值所以被買走」。

現在他做 Afk.surf，一個 To B 的 Governing Agent 產品。節目對它的定義值得逐字抄下來：

「想讓企業能真正接管並持續學習自己運行的各個環節，在服務不同員工的同時，對齊整個組織的業務、工作方式和使用偏好。」 —— 單集簡介原文，描述 Afk.surf 的產品定義

注意三個動詞：接管、持續學習、對齊。這不是「幫你寫得更好」的助手語法，是「接手一個環節並對結果負責」的治理語法。他選擇用 Governing（治理）而不是 Assistant（助理）命名品類，本身就是立場。

二、分水嶺：從 2026 年開始，Agent 就不像軟件了

這是整集的第一個轉折，章節標題寫得很直白：

「從 26 年開始，Agent 就不像軟件了。」 —— 章節標題，05:43

為什麼「不像軟件」是一個分水嶺？因為軟件的價值模型是把一個已知流程固定下來，然後複製販賣。這個模型推導出我們熟悉的一切：席位（一個使用者一份授權）、版本（功能清單的增量）、發佈（安裝與升級）。軟件的成本結構是「一次開發、邊際成本趨近於零」，所以規模是唯一重要的變量。

Agent 的價值模型相反：接管一個環節，然後持續吸收例外。例外不能事先窮舉，只能靠在環境裡跑、被糾正、再收斂。這裡的關鍵詞是「收斂」而不是「完成」——一個 Agent 的價值不在它第一次做對，而在它第十次遇到同類例外時已經不需要人教。

這個差異往下傳導到三件事，節目把它們並列處理：

維度軟件Agent
怎麼計價按席位（seat）按接管的工作量（或按結果）
怎麼驗收功能清單（有沒有這個按鈕）行為邊界（哪些情況下不能做什麼）
怎麼實施安裝、部署、培訓陪跑、糾正、共同收斂

這張表看起來只是商業模式的分類，但它其實解釋了一個很實際的現象：為什麼企業買了 Agent 之後，試用期往往比軟件長得多，而且很難「驗收」。因為驗收的對象不是功能，是行為；而行為只能在真實例外裡被觀察。這也是為什麼 To B Agent 公司很難做出漂亮的 demo——demo 展示的是能力上限，客戶关心的是例外下限。

一個容易被忽略的推論：如果驗收標準是「行為邊界」，那麼產品文檔裡最重要的部分不是「我能做什麼」，而是「我在什麼情況下會停下來、會問人、會拒絕」。這正好是現有 SaaS 採購流程最不熟悉的一種文件。

三、兩年劇烈變化，最後收斂到一個形態

節目把 2024 到 2026 的產品形態攤成一條時間軸（章節 08:19）：

  • 2024：workflow 拼裝與 co-pilot。人在環裡，AI 在旁邊給建議。
  • 2025：computer use 與 GUI 代理。AI 開始操作介面，但仍然「一次任務一次會話」。
  • 2026 上半年：「能跑很久但不知道自己在幹嘛」的長時程代理。能力上去了，可靠性沒有。
  • 收斂方向：帶私有上下文、有記憶、能在組織邊界內行動的長時程代理。

這條線的敘事很順，但真正有價值的是最後那個定語組合。「私有上下文 + 記憶 + 組織邊界」——三個條件缺一不可：

沒有私有上下文，Agent 只是一個更貴的 ChatGPT；沒有記憶，它每次都要重新被教一遍，永遠停在 2025 的「一次會話」形態；沒有組織邊界，它要麼什麼都能做（不可授權），要麼什麼都不敢做（不可用）。

而這三個條件，恰好都是平台型產品最難標準化的東西。這就是為什麼下一節的判斷不是突然跳出來的，而是這條形態收斂線的必然結論。

四、名詞通脹：2026 可能是 buzzword 最多的一年

節目在 10:43 自嘲了一句：2026 可能是 buzzword 最多的一年。清單大致是：Personal Agent、Computer Use、GUI Agent、Deep Research、RLaaS、Governing Agent、Neo Lab。

這句話好笑，但背後的判斷很嚴肅：名詞多，通常代表還沒有人找到穩定的評測方式。一旦有了公認的評測，名詞就會收斂成兩三個——因為市場需要用同一把尺子比較。反過來說，當一個賽道同時出現七、八個名字，通常不是因為產品差異大，而是因為沒有人能證明誰更好。

這也解釋了為什麼大家這麼努力地造詞：在沒有評測的市場裡，命名就是定位。誰先定義品類，誰就暫時擁有解釋權。

五、全集最尖銳的一擊：To C 是平台，To B 不是

章節標題是一個問句，但節目的立場是肯定的：

「To C 的 Personal Agent 還是平台型機會，但 To B 不是？」 —— 章節標題，13:41

推演邏輯值得完整走一遍，因為它是整集的地基。

To C 端：所有使用者面對的任務分佈高度重疊——排程、寫作、查資料、比價、訂票。同一個助手可以服務所有人，使用越多、資料越多、模型越準，資料飛輪與規模效應成立。結論：贏家通吃、平台定價。

To B 端：每家企業的流程、權限體系、資料邊界、歷史包袱、老闆偏好都不一樣。同一個「請假審批」流程，在 A 公司是三天內任何人可批，在 B 公司是週五下午必須財務總監簽字。這些規則不會寫在公開網頁上，只存在於組織的肌肉記憶裡。

所以每一次交付都是一次客製化的重活。天花板不是模型能力，而是交付能力與組織信任。

「To B Agent 的天花板不是模型能力，而是交付能力與組織信任；它的財務特徵更接近服務業或顧問業，而不是 SaaS 平台。」 —— 本文整理自章節 13:41 的論證

這句話的殺傷力在於它反對的是當前最流行的估值故事。過去兩年，「AI 原生 SaaS」的默認假設是：只要產品夠好，就能像傳統 SaaS 一樣做到 80% 毛利率、淨收入留存 120%、邊際成本趨零。但如果 To B Agent 的本質是「每次交付都要重新理解一個組織」，那麼它的成本結構就更像顧問業——收入隨人頭線性增長，毛利率被交付能力鎖死。

節目用一個很具體的對照收尾：Afk.surf 已經有幾個大客戶，不是還在講故事等正反饋的階段。這句話看似只是補充背景，實際上是在說：這個判斷不是推演出來的，是做出來之後回頭總結的。

但這裡有一個節目沒有回答的問題：Salesforce、ServiceNow 也是 To B，也成了平台。差別在哪？節目的隱含答案是——那些平台的成立條件是「流程可以被標準化」，而 Agent 賣的恰恰是「流程不能被標準化」的那部分。兩者的經濟結構相反。這個反駁是否成立，取決於一個沒有數據的問題：企業的例外處理，究竟有多少比例其實是行業共通的（可標準化），多少是真的只屬於這一家（不可標準化）。

六、框架的黃昏：LangChain、Dify、n8n 過時了嗎

26:11 這一段的處理方式很務實：不是問「框架有沒有用」，而是問「框架解決的那部分問題，是否已經被模型本身吃掉」。

當模型能自己規劃、自己呼叫工具、自己維護狀態時，框架剩下的價值就只有三樣：

  1. 可觀測性——你到底跑了什麼、花了多少、錯在哪一步。
  2. 權限——誰能讓 Agent 做什麼，邊界在哪。
  3. 部署形態——跑在誰的雲上、資料出不出邊界。

這三樣會留下，但不足以支撐一個獨立的大品類——除非它往「治理層」演化。這正好接回他自己的產品定位：Governing Agent 不是取代框架，而是把框架降級成基礎設施，自己站在「授權、審計、可回滾」這一層。

這個判斷對創業者的實際含義是：如果你今天的護城河是「幫人把 LLM 串起來」，那條護城河正在乾涸。串接會變成模型的原生能力；剩下的是治理，而治理是一門完全不同的事——它賣的不是便利，是責任。

七、核心技術段：一個應用公司為什麼要自己訓模型

33:32–40:02 是全片最長的一段連續論述，也是技術含量最高的部分。理由只有一個詞：私有分佈。

他的論證是這樣的：To B 的差異化不在基礎能力，而在企業的術語、審批鏈路、例外處理、錯誤容忍度。通用模型的 benchmark 再高，也測不出「這家公司週五下午不走財務總監審批就算違規」這種規則。因為這條規則不在任何公開語料裡，它只存在於這家公司的流程與人的記憶中。

所以做法是把客戶的私有資料 + 私有評測 + 組織偏好，做成小模型與 RL 的訓練閉環，通用模型退化成「老師」與「兜底」。

節目給出了一條完整的四層工程路線圖，而順序比內容更重要：

層做什麼為什麼在這個位置
① 私有上下文層把企業的術語、權限、審批鏈路結構化沒有這層，後面的評測沒有對象
② 私有評測層用企業自己的例外案例做 eval，而不是公開 benchmark先有評測，才有訓練
③ 訓練層小模型 + RL（RLaaS 的思路）把偏好壓進權重只在②成立後才有意義
④ 治理層授權、審計、可回滾讓前面三層可以被企業信任地運行
「先有評測，才有訓練；沒有私有評測就自訓模型，等於在沒有指南針的海上加速。」 —— 本文對章節 33:32–40:02 論證的概括

這句話值得單獨拿出來講，因為它是對當前「人人都在微調」風氣最直接的反駁。微調的成本已經很低，低到任何人都可以跑一次；但微調的方向仍然需要一個判準。公開 benchmark 只能告訴你「這個模型在一般任務上好不好」，不能告訴你「它在我們公司的例外上會不會犯錯」。沒有私有評測，你優化的是一個跟你無關的目標函數。

而「通用模型退化成老師與兜底」這個說法也很有意思：它不是「用小模型取代大模型」，而是用大模型生成訓練信號、用小模型承接日常推理。這是一種成本結構的設計，不是能力上的替代。

四層 私有上下文 → 私有評測 → 訓練 → 治理。順序不可顛倒。
一個閉環 客戶資料 + 私有評測 + 組織偏好 → 小模型與 RL。
兩種角色 通用模型＝老師（生成信號）＋兜底（處理長尾）；小模型＝日常執行。
八、如果模型兩三年內普惠，護城河去哪裡

40:02 的章節把這個問題拋出來：AI 可能端到端消滅過去的各種邏輯？模型兩三年內可能普惠？

節目的態度是「值得懷疑但值得下注」。但真正的內容不在態度，而在推論：如果模型能力真的平價化，護城河會全部轉移到資料、流程知識與信任關係上。

這與前面的論點四、論點六是同一套邏輯的三次表述：

  • 論點四說：To B 的瓶頸是交付與信任，不是模型能力。
  • 論點六說：差異化在私有分佈，不在基礎能力。
  • 論點八說：如果能力平價化，剩下的就只有資料、流程與信任。

三次表述指向同一個結論：模型的進步不會消滅 To B Agent 的生意，只會把競爭移到我聽不懂你家術語的那一段。這是一個相對樂觀的結論，但它同時意味著——這門生意的規模化速度，永遠受制於「理解一個新客戶」的速度。

九、兩個延伸：AI 遊戲的 timing，與「散是滿天星」的招人法

AI 遊戲（42:34）。這是一個延伸話題，但放在 11 月 13 日張小珺那集六小時梁其偉訪談旁邊，互文效果很強：一邊在談 3A 動作遊戲的手工藝與十九年積累，一邊在問 AI 遊戲的時機。同一個行業，兩種時間尺度——一種是「十九年做一件事」的尺度，一種是「模型能力每半年變一次」的尺度。節目沒有給答案，但問題本身有價值：當工具的能力週期短於作品的製作週期，創作者要怎麼下注？

招人（44:58）。從 AFFiNE 出來的人：前產品負責人做的 AirBuild 在 X 上小火、前 CTO 現在是 Cloudflare Principal Engineer、還有出海圈子熟悉的「生姜」。他的答案不是「願景」，而是「讓人在這裡拿到可遷移的聲譽」。

這句話聽起來像廢話，但配合 AFFiNE 到 VoidZero 的履歷，它是有代價支撐的：一個曾經把團隊成員送到 Cloudflare Principal Engineer 位置的創始人，說「我這裡能讓你拿到可遷移的聲譽」，說服力完全不同。這也是 To B 服務型生意的一個隱藏優勢——交付重，代表每個人都會接觸真實問題，而成長是可見的。

這條時間線有一個容易被忽略的模式：兩次都是「先做出聲量，再找商業模式」。AFFiNE 是社群聲量，VoidZero 是開發者聲量。第三次他反過來——先找商業模式（To B、有大客戶），再談聲量。這個順序的改變，本身就是他從前兩次經驗裡學到的東西。

十一、爭議與弱點

一、「To B 不是平台」可能只是「現在不是」。Salesforce 當年也是從「每個客戶都要客製」開始的，platform 化是後來的事。如果 Agent 的例外處理有足夠比例的行業共通性，標準化仍然可能發生。節目沒有處理這個時間維度的問題。

二、樣本只有自家客戶。「已經有幾個大客戶」是事實，但這幾個客戶的行業、規模、流程複雜度沒有公開。如果它們恰好都是「流程相對可標準化」的行業，那麼這個案例反而支持反方。

三、自訓模型的成本沒有給出。四層路線圖很漂亮，但沒有說：一個客戶要多少資料、多少 GPU 小時、多久才能收斂？如果每個客戶的訓練成本高到需要一個專門團隊，那它就更像顧問業——而這正好是他自己的結論，只是他沒有把成本數字攤出來。

四、「框架會被模型吃掉」低估了治理需求。可觀測性、權限、部署形態這三樣確實會留下，但「留下」不等於「不值錢」。如果監管要求企業能解釋每一個 Agent 決策，治理層可能比模型層更值錢。這一點節目只輕輕帶過。

十二、行業 insight：三條分界線

第一條：平台型 vs 服務型。To C 是平台生意（規模效應、贏家通吃），To B 是服務生意（交付能力、信任、客製化）。用同一套估值邏輯去看兩者，會嚴重錯配。這條線的實用價值是：當你看到一個 To B Agent 公司用 SaaS 倍數融資時，先問它的交付成本怎麼隨客戶數增長。

第二條：模型能力 vs 私有分佈。當基礎能力平價化，差異化只剩下「你比別人更懂這個客戶的分佈」。這條線解釋了為什麼「自己訓模型」不是大廠專利——你不需要訓一個更好的通用模型，你只需要訓一個更懂這家公司的模型。

第三條：框架層的黃昏。LangChain / Dify / n8n 不會消失，但會從「開發範式」降級成「部署與治理組件」。這條線對開發者的含義很直接：如果你的價值是「會用某個框架」，那個價值正在被模型吸收；如果你的價值是「能設計治理邊界」，那個價值正在上升。
