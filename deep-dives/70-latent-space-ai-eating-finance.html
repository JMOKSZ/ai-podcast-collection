AI 全面入侵金融業：Code 之後的下一個萬億垂直市場

二、OpenAI 嘅金融攻勢

🏢 OpenAI NYC 活動

OpenAI 喺紐約舉辦咗一場「AI in Finance」主題活動，最大嘅 news 係推出咗兩個專用 Plugin：

  • Equity Investing Plugin — 針對股票投資研究，整合實時市場數據、財務報告分析、估值模型
  • Investment Banking Plugin — 覆蓋投行工作流程：盡職調查、財務建模、交易文件起草

呢兩個 Plugin 都已經納入 Codex 生態，即係話用戶可以喺 ChatGPT Work 入面直接使用。呢個策略嘅聰明之處在於：唔使金融機構自己開發 AI infra，直接用 Codex 嘅 agent 框架 + 專用金融工具。

🏢 Anthropic 金融服務 Templates

Anthropic 同步喺紐約舉辦活動，發布咗 Cowork & Claude Code Agent Templates for Financial Services。涵蓋：

  • 企業金融全流程 agent（應付賬款、合規檢查、風險評估）
  • 內建嘅 security framework 同 audit trail
  • 專為金融業長文檔處理優化嘅 context window 管理

Anthropic 嘅 approach 同 OpenAI 略有不同：佢哋更強調 agent template 嘅可定制性同企業級安全，而唔係 plug-and-play。

三、七個企業案例深度拆解

呢期嘅真正金礦係 AIE（AI Engineer Conference）發布嘅完整 Finance Track——7 間金融機構分享咗佢哋嘅 AI 部署經驗。

1. FactSet — AI Skills 嘅企業級基礎設施

講者：Yogendra Miraje

背景：FactSet 服務數千間金融機構，提供金融數據同分析。

核心觀點：AI skills 需要五個要素先可以成為企業級 agent 基礎設施：

  • Ownership — 每個 agent 要有明確嘅業務擁有者，唔係 IT project
  • Search — 唔係 keyword search，而係 semantic + 結構化數據混合檢索
  • Evals — 金融業唔接受「大約正確」，答案必須可以驗證
  • Audits — 每個 agent 操作必須有完整嘅審計軌跡（regulatory requirement）
  • Governance — 權限管理、數據隔離、合規檢查

Insight：FactSet 嘅視角好有代表性——佢哋唔係 sell AI，而係 sell 「AI-readiness infrastructure」。金融機構唔缺數據，缺嘅係可以安全、可控地使用 AI 嘅基礎設施。

2. Nubank + Snowglobe — Agent Evals 從瓶頸變 Release 機制

講者：Lucas Palma

背景：Nubank，巴西最大嘅數位銀行，服務 1 億+ 客戶。

核心觀點：Nubank 同 Snowglobe 合作，建立咗模擬環境用嚟測試 agent。傳統嘅 eval 係發布瓶頸——你要人工審核每個 agent 嘅每個 output。Nubank 嘅做法係：用模擬環境自動化 eval，變成 release 機制嘅一部分。

佢哋有數千個 AI skills 需要審核，每個都關乎客戶資金安全。人手審核根本唔可能。所以佢哋嘅解決方案係：

  • 建立金融場景嘅 sandbox environment
  • agent 喺 sandbox 入面執行，自動生成 eval report
  • 只有 pass eval 嘅 agent 先可以進入 production

Insight：Nubank 嘅案例證明咗：agent safety 唔係靠人手審核，而係靠 automation + simulation。 呢個思維對所有準備大規模部署 AI agent 嘅公司都適用。

3. Intuit — 通用 LLM 唔夠，金融 AI 要理解「結果」

講者：Udi Menkes

背景：Intuit 服務約 1 億消費者、小企業同會計師，產品包括 TurboTax、QuickBooks、Mint。

核心觀點：通用 LLM 對金融場景遠遠唔夠。金融 AI 必須：

  • 理解真實狀態（用戶嘅財務狀況、稅務歷史）
  • 理解行為（用戶做咗咩交易、點解咁做）
  • 理解結果（呢個推薦會導致咩稅務後果）
  • 理解風險（如果推薦錯咗，用戶會損失幾多錢）

Udi Menkes 話：「金融 AI 唔可以 approximate——差一個小數點嘅稅務建議都可能令用戶損失幾千蚊。」

Insight：呢個係一個重要嘅 cautionary tale——好多 AI 公司 rush to deploy，但低估咗金融場景嘅精確度要求。

4. Kepler — 「可驗證 AI」喺金融研究

講者：Vinoo Ganesh

背景：Kepler 喺金融研究中索引數百萬份報表文件。

核心觀點：金融研究嘅 game changer 唔係「AI 可以分析更多數據」，而係「AI 可以俾你 verify 每個答案嘅來源」。

具體做法：

  • 每個答案都要有來源文件引用（唔係「模型知識」）
  • 來源記錄可以追溯，方便審計同覆核
  • 支持對答案進行 fact-check 同 cross-reference

Insight：金融業嘅痛點唔係資料唔夠多，而係 source verification 太慢。Kepler 嘅 approach 係用 AI 做 indexing，然後靠人類 analyst 做 decision——呢個 division of labor 好可能係金融 AI 嘅標準 pattern。

5. Nubank（再次）— AI Skills 嘅供應鏈安全

講者：Lucas Palma（同一個 Nubank，另一個角度）

核心觀點：當你嘅銀行有 數千個 AI skills，每個可能由唔同嘅 internal team 或者 vendor build，supply chain security 就變成頭號問題。

主要風險：

  • 一個 rogue agent 可以 access 唔應該 access 嘅數據
  • 第三方程式庫可能有 vulnerability
  • Agent prompt injection 可以導致金融交易被篡改

Insight：呢個同 HuggingFace 嘅 rogue agent 攻擊 time-line visualization 呼應——AI security 唔再係理論問題，而係每日都要面對嘅現實威脅。

6. Morgan Stanley — 多 Agent 研究嘅實驗環境

講者：Brendan Hogan Rappazzo

背景：Morgan Stanley Wealth Management，管理 數萬億美元 客戶資產。

核心觀點：多 agent 系統喺金融研究有好大潛力——一個 agent 做宏觀分析、一個做行業研究、一個做公司估值——但呢啲 agent 需要喺可信嘅實驗環境中優化先得。

Morgan Stanley 嘅做法：

  • 建立咗隔離嘅沙箱環境，用歷史數據模擬真實市場
  • Agent 之間嘅 interaction 可以記錄同分析
  • 每個 agent 嘅 output 都係「可解釋嘅」——知道點解佢俾呢個 recommendation

Insight：華爾街對 AI 嘅態度係「cautious but committed」。Morgan Stanley 呢個案例說明：金融機構唔係唔想用 AI，而係需要用正確嘅方式用。

7. Fidelity Investments — 群聊 Agent + 可穿戴安全

講者：Sai Krishna Rallabandi

背景：Fidelity，管理 數萬億美元 資產。

核心觀點：Fidelity 正在 experiment 群聊 agent 同可穿戴 device 上嘅 AI assistant——但呢啲新界面強制佢哋重新思考三個方面：

  • Memory — agent 應該記住幾多對話歷史？邊啲信息可以跨 session 保留？
  • Permissions — 群聊入面，agent 可以 access 邊個嘅數據？唔同參與者有唔同權限
  • Prompt injection defense — 喺開放式群聊環境，agent 更容易受到攻擊

Insight：Fidelity 嘅 approach 係「build for the edge cases first」——即係假設最壞情況（prompt injection、數據洩漏）會發生，然後從個 base case 度 design。呢種 security-first 思維好值得其他金融機構參考。

四、共通嘅 Pattern 同 Insight

呢 7 個 case studies 加起來，幾條清晰嘅 thread 浮出水面：

Thread 1：Agent Safety = 自動化 Eval，唔係人手審核

FactSet、Nubank、Morgan Stanley 三間公司獨立噉得出同一個結論：金融機構嘅 agent 數量會快速增長到人手無法管理嘅規模。 唯一可行嘅方法係 build 自動化 eval 同模擬環境。

Thread 2：金融 AI 嘅 Killer App 係 Research，唔係 Trading

Kepler、Morgan Stanley、FactSet 嘅案例都 focus 喺金融研究同分析——唔係高頻交易。呢個說明咗：AI 喺金融業嘅第一個大規模應用會係「知識工作自動化」，唔係「交易自動化」。

Thread 3：OpenAI vs Anthropic 嘅金融路線差異

OpenAI 走 plug-and-play path（Equity Investing Plugin + Codex），Anthropic 走 template + security framework path。呢個差異反映咗兩間公司對金融市場嘅策略判斷：OpenAI 認為速度係關鍵，Anthropic 認為信任係關鍵。

Thread 4：AI Security 唔再係理論

從 Nubank 嘅 AI supply chain 問題到 Fidelity 嘅 prompt injection concern，再到 HuggingFace 嘅 rogue agent 攻擊時間線——AI security 已經從「可能嘅問題」變成「每日嘅現實」。 金融機構對此尤其敏感。

五、Codex 嘅自我優化同推理成本革命

呢期仲有一個值得單獨拎出來講嘅 news：

Codex 自我優化 OpenAI 生產線 — GPT-5.6 Sol 被應用到生產推理優化，GPU kernel 改進降低 20% 推理成本，speculative decoding 提升 15%+ token 生成效率。

呢個係 AI 改善 AI 系統 嘅具體案例。Codex 唔係被動等新模型，而係主動將最新嘅 model capability 應用到 infrastructure 層面。呢個 loop 一旦閉合，改進速度就會指數級加速。

同金融業嘅關聯：推理成本降 20% 對 coding agent 係好事，但對金融 agent 呢？金融 agent 嘅瓶頸向來唔係推理成本，而係 accuracy、security、同 compliance。 所以呢個改進對金融業嘅直接影響有限，但間接影響係：便宜嘅推理 = 更多 agent 嘗試 = 更快摸清金融場景嘅 best practices。

六、我嘅分析

為咩金融業係 Code 之後嘅第一個垂直市場？

swyx 嘅判斷係啱嘅——金融業同 coding 有幾個共通點令佢成為 AI 嘅天然 playground：

  • 高數據密度：金融機構嘅數據比任何其他行業都結構化同乾淨
  • 清晰嘅 ROI：金融分析嘅價值可以精確量化（better research = better returns）
  • 強烈嘅競爭壓力：邊個先用 AI，邊個就有信息優勢
  • 監管推動數位化：合規要求（SOX、Basel III）迫使金融機構建立完善嘅 audit trail，呢個同 AI agent 嘅需求天然吻合

風險同挑戰

  • Hallucination 喺金融業係災難：一個錯誤嘅財務分析可以導致幾千萬嘅損失。金融 agent 需要 ground truth verification——唔係「大概啱」
  • Black box 問題：監管機構要求「可解釋嘅」金融決策。如果 AI agent 嘅 decision making process 係不可解釋嘅，金融機構就用唔到
  • 人才競爭：金融機構要同科技公司搶 AI 人才——呢場仗金融業好難贏

香港／中國嘅金融 AI 機遇

雖然呢期 Latent Space focus 喺歐美市場，但中國金融業嘅 AI 機會同樣巨大——甚至可能更大：

  • 中國金融機構嘅數位化程度參差不齊，跳躍式升級嘅空間大
  • 監管環境相對集中，一次獲批可以大規模部署
  • 區塊鏈金融 + 數字人民幣 + AI 可以產生化學反應

七、結論

呢期 Latent Space AINews 雖然係「quiet day」嘅產物，但內容密度好高。佢捕捉到咗一個重要嘅行業信號：AI 正在離開 coding 呢個 comfort zone，進入下一個萬億級垂直市場。

對於 James 同佢嘅 Trinity 項目（豆包 + PMS + 硬件）：金融業 AI 嘅進展係一個重要嘅參考——酒店業同樣係高數據密度、清晰 ROI、強競爭壓力嘅行業。金融業踩過嘅坑（eval automation、security-by-design、regulatory compliance）好快就會喺其他垂直行業重演。

「模型安全研究需要評估完整的 chatbot/harness/system stack，而不僅僅是 base models——因為記憶、搜索、工具、長會話漂移和 scaffolding 實質性地改變了風險配置文件。」

呢句係成期最值得記住嘅 advice。無論你做邊個行業嘅 AI agent，呢個都係 bottom line。
