兩個星期，一個潘朵拉盒子——Cloudflare 把 System One 變成一條基礎設施的標準零件

〈Cloudflare Joins the Jevolution and Labels Itself a Neolab〉
出品：Latent Space·作者：Richard MacManus·受訪：Michelle Chen（Cloudflare AI Platform 產品負責人）
發布：2026-11-17 15:00 UTC（11-17 23:00 HKT）·約 6 分鐘閱讀·非音頻，屬現場報導＋會後專訪
來源：Latent Space 文章原文（約 8,100 字元）＋ AI Engineer Code Summit 演講內容；引語為原文英譯中

這篇文章很短，事件也很小：一家 CDN 公司在一個開發者大會上說，我們也做模型了，兩個，一個是別人的複製品，一個是自己想的。它沒有 benchmark，沒有定價，沒有發布日期，甚至連「neolab」這個標籤本身，作者都在文裡直言「聽起來有點像行銷花招」。

但它值得單獨寫一篇，因為它把過去兩個月發生的事，壓縮成一個可量化的句子：TypeSafe 花了兩年發明 Jev，Cloudflare 花了兩個星期複製它。

這句話不是指控，是這整個產業的定價表。當一個範式被公開之後，剩下的工作不是研究，是規格對齊；而一家有算力、有客戶、有分發渠道的基礎設施公司，正好是世界上最擅長「照規格施工」的組織。

「全部功勞歸 TypeSafe，真的——是他們攻擊這個空間、發明了新東西，而且讓人能如此強烈地共鳴、能夠使用。我們很快就做出模型，但他們做了大量苦工，我們已經完全知道 API schema 該長什麼樣。」 — Michelle Chen，論兩星期複製 Jev

「我們已經完全知道 API schema 該長什麼樣」——這句話是整篇文章的鑰匙。它把模型的價值拆成兩半：知道要做什麼，和把它做出來。前者是研究，後者是工程。而 2026 年的殘酷之處在於，第一半一旦被公開展示，第二半的價格就會以週為單位崩跌。

2 週 Cloudflare 做出 Clef 的時間；對照 TypeSafe 做 Jev 用了 2 年。
$782M Cloudflare 2026 Q3 營收，年增 39%，年化跨越 $30 億。
2 個 已發布的 System One 模型：Clef（決策）與 Clairic（抽取）。
2026-10 Clairic 上線，官方定位為「System One extraction models」的第一個模型。
ms vs s 文章的核心對比：System One 的輸出以毫秒計，推理 LLM 以秒計。

一、先看清楚她是誰在說話

Michelle Chen 的頭銜是 Cloudflare AI Platform 產品負責人——「產品側」。這個細節決定了整場訪談的語言。她談的不是架構、不是損失函數、不是訓練配方，而是三件產品經理才會談的事：哪些請求不必送去 LLM、客戶要付多少、上游斷供怎麼辦。

這也解釋了為什麼 Cloudflare 的模型戰略從第一天起就不是「追前沿」。前沿實驗室的問題是「下一個能力在哪裡」；Cloudflare 的問題是「我已經有 20% 的毛利被 token 吃掉了，怎麼把它拿回來」。兩個問題都會導向「做模型」，但會導向完全不同的模型。

文章把她描述成一個雙重身份的人：產品人（談路由）與平台方（談授權、監管、供應風險）。我認為還有第三重身份，而文章沒有展開：上市公司高管。一家年化 30 億美元、年增 39% 的公司，不能對華爾街說「我們在做一個五年後才有收入的賭注」。它必須把每一個技術動作翻譯成財務語言——而「自建模型 = 降低單位成本 + 降低供應風險」正好是一個完美的翻譯。

二、「NeoLab」這個詞，正在從資本類別變成能力類別

先把定義講清楚。「NeoLab」是 The Information 的 Stephanie Palazzolo 在去年 11 月造的詞，原始定義是「新一代研究導向的 AI 初創」。Menlo Ventures 的 Deedy Das 後來把它做成一份清單，並加了四條硬指標：

  • 僱用精英研究者；
  • 投入大量算力（通常是為了訓練自己的模型）；
  • 沒有顯著的營收牽引力；
  • 通常是募了很多錢的初創。

Cloudflare 至少不符合一半。它是上市公司，有實質營收，而且剛剛公布史上最好的一季。文章引了 CEO Matthew Prince 的話：第三季是 Cloudflare 最好的一季，年化收入跨過 30 億美元，營收 7.82 億美元、年增 39%。

所以 Chen 的辯護不是「我們符合定義」，而是「定義該改了」。她的說法是能力路徑論：從基礎設施 → 算力（Workers 平台，現在也給 agent 用）→ 儲存 → 托管開源權重模型（Kimi、GLM、DeepSeek 跑在 Workers AI 上）→ 自建模型，是一條自然演進線。

「成為 neolab 意味著我們可以創造我們缺失的東西。」 — Michelle Chen，演講

這句話比它聽起來更激進。它把「neolab」從一個資本身分（你拿了誰的錢、你燒了多少算力）改寫成一個能力狀態（你能不能造出你缺少的零件）。如果這個改寫成立，那 Databricks、Snowflake、甚至每一家雲廠都可以自稱 neolab——這個詞就會變成「我們有模型團隊」的同義詞，也就失去了區分力。

我的判斷是：Chen 自己也清楚這一點。她沒有花時間論證 Cloudflare 是 neolab，她花時間論證的是「為什麼基礎設施公司必須做模型」。標籤是給媒體的，理由是給客戶的。

三、「東風」：Jev 如何改寫了一條產品路線

文章裡最有畫面感的一段，是 Chen 用一句中國諺語形容 Jev 的出現——「東風」。她說，當 system one 與 Jev 範式開始進來時，團隊的反應是「這對我們太合理了」。

「當 system one 與 Jev 範式開始進來，我們就想，這對我們太合理了。我們不必把每個請求都送去 LLM，可以把一部分送去 System One 模型。」 — Michelle Chen，演講

「東風」這個比喻值得停一下。在中文語境裡，東風是「萬事俱備，只欠東風」的那個東風——它不是主角，它是一個讓既定計畫忽然可行的外部條件。這個用法精準得不像公關話術：Cloudflare 早就有延遲敏感的場景、早就有海量請求、早就有路由層；它缺的只是一個「便宜到可以撒進每一個請求」的分類器。

Jev 給的不是技術，是許可。它證明了「非生成式模型可以作為一個獨立類別存在、可以被放進代碼、可以被定價」——一旦這件事被證明，剩下的事情對一家工程能力極強的公司來說，只是排期問題。

四、Clef：兩星期能複製的，究竟是什麼

先講清楚 Clef 是什麼。它是決策模型，直接照 Jev 的 API schema 複製：輸入一段上下文與一組選項，輸出一個選擇、一個分數或一個機率。它不生成文字，所以沒有「格式錯誤的 JSON」這種失敗模式；它一次前向傳播完成，所以延遲以毫秒計。

「兩星期」這個數字之所以刺眼，是因為它让人誤以為複製很簡單。實際上被複製的不是模型，是問題的形式化。Jev 真正難的地方在於：

  • 說服市場相信「決策」是一個獨立的模型類別，而不是 LLM 的一個 prompt；
  • 設計一個 schema，讓它在零樣本条件下仍然可校準；
  • 建立評測方法，讓買家相信自己買到的不是一個更便宜的分類器；
  • 把價格定在 $0.042 / 1M input tokens，讓「多呼叫幾次」在經濟上可行。

這四件事，每一件都比訓練一個模型難。而一旦它們全部被公開展示，第五件事——「照著做一個」——就變成了兩個星期的工程問題。

「我們不是只為了推出 system one 模型才當 neolab，雖然那對我們的基礎設施來說很合理。我們算是打開了潘朵拉的盒子——我們打開了它，現在可能性無窮。」 — Michelle Chen，談 Cloudflare 的模型路線圖

「潘朵拉的盒子」在這裡有兩層意思，而 Chen 只說了第一層（可能性無窮）。第二層是文章沒有明說的：盒子打開之後，就關不回去了。一家基礎設施公司一旦開始做模型，它與上游模型供應商的關係就從「客戶」變成「客戶＋競爭者」。這是一個不可逆的戰略位置，而 Cloudflare 是在一個只有 6 分鐘閱讀長度的報導裡，平靜地宣布了它。

五、Clairic：第二個模型才是原創性的證明

如果只有 Clef，這篇文章會是一篇關於「複製」的文章。Clairic 讓它變成一篇關於「類別擴張」的文章。

Cloudflare 對 Clairic 的定位是「System One extraction models」的第一個模型，去年 10 月上線。它的工作是把非結構化輸入——發票、表單、文件——轉換成帶型別的值：抽取、計算、估算、預測，一次前向傳播完成。

「當你把它送去 LLM，它們會說：等等，我想訂單號是三，也許是四，也許是五。但那數字就在那裡，你只要讀它就好！」 — Michelle Chen，論 Clairic 要解決的問題

這個例子選得極好，因為它把「生成」與「抽取」的差別變成了一個常識問題。LLM 是自回歸的：它逐 token 預測下一個最可能的符號，所以它會猜。而發票上的訂單號不是一個需要被預測的符號，它是一個需要被定位的字串。用生成模型去讀它，等於用一個會即興發揮的演員去當證人。

技術上，Clairic 做的是把「讀取」與「推理」分離：

環節LLM 的做法Clairic 的做法
定位注意力隱含在生成過程裡顯式的抽取頭
輸出自由文本，需事後 parse帶型別的值（number、date、enum）
失敗模式幻覺、格式錯誤、數字漂移抽取失敗（可偵測）
成本按輸出 token 計費單次前向，無輸出 token
延遲秒級毫秒級

值得注意的是，Clairic 解決的不只是成本問題，而是可驗證性問題。當輸出是一個帶型別的值，你就可以寫一個 assertion 去檢查它；當輸出是一段自然語言，你只能再找一個模型來判斷它對不對——而那第二個模型，又會引入它自己的誤差。

這也是為什麼我認為 Clairic 比 Clef 更重要。Clef 證明 Cloudflare 會抄；Clairic 證明 Cloudflare 會推廣——它把「System One」從「分類」擴張到「抽取」，等於替這個類別找到了第二個殺手級場景。一個類別只有一個場景時，它是產品；有兩個場景時，它是範式。

六、不做預訓練：一句話限定了整個野心

文章最實質的一句限定，出現在談未來路線圖的時候。Chen 說，未來可能會有推理模型與其他 LLM，但「那大概不是我們的重點」。

「我不認為那是我們的重點，但我覺得我們可以把外面已有的資源拿來，讓它們更有效率、更有效。」 — Michelle Chen，論是否做預訓練

她補充，團隊「大部分只做後訓練」。這句話把 Cloudflare 與前沿實驗室之間畫出了一條清楚的界線：

  • 前沿實驗室：預訓練 → 能力邊界 → 再想產品。
  • Cloudflare：產品需求 → 後訓練／蒸餾 → 夠用就好。

「夠用就好」不是謙虛，是財務紀律。預訓練是一場以十億美元為單位的拍賣，而後訓練是一條以「找一個好基座＋對齊＋評測」為單位的產線。對一家要對季度財報負責的公司，後者是唯一理性的選擇。

但這也意味著一件事：Cloudflare 的模型能力上限，被它的基座決定。如果它托管的是 Kimi、GLM、DeepSeek，那它的 Clef 與 Clairic 就是這些基座的函數。這在商業上完全合理（便宜、快、可控），但也解釋了為什麼它不急著做預訓練——因為它賣的不是能力，是路由。

七、為什麼是現在：三種風險，一種對沖

整篇訪談裡最直白的一段，是 Chen 談自建模型的商業理由。她沒有談技術理想，她談的是風險：

「我覺得 AI 空間有很多風險，就像 Jev 是閉源的、我們跑不了；市面上有很多模型可能有監管風險，比如中國的開源模型。很多模型實驗室也想真正賺錢——於是執行相當昂貴的授權。」 — Michelle Chen，論自建模型的風險理由

這段話可以拆成三種風險，而它們的性質完全不同：

風險具體內容對基礎設施公司的意義
不可得Jev 是閉源的，Cloudflare 跑不了別人的護城河，就是你的單點故障
不可用監管風險，點名中國開源模型合規地雷會讓一條產品線突然下架
不可負擔模型實驗室要賺錢，授權費會漲毛利被上游定價權吃掉

三種風險疊加，結論只有一個：不能把核心路徑交給一個你無法控制的供應商。這條邏輯在半導體業已經演過一次（自研晶片、扶植第二供應商），現在它在模型層重演。

而「監管風險」首次以白話形式出現在一家美國上市公司的產品路線圖裡，這一點值得單獨記一筆。它意味著：地緣政治不再只是政策新聞，它已經變成採購決策的一個欄位。當一家 CDN 公司因為「中國開源模型可能有監管風險」而決定自建模型，這條供應鏈就已經開始分裂了。

八、反面：這篇文章沒有告訴你的事

把上面的分析全部加起來，會得到一個很順的故事。但這篇文章有一個巨大的資訊缺口，而它恰好是判斷这件事是否成立最需要的一頁：沒有任何 benchmark。

  • Clef 的準確率、校準度、與 Jev 的差距——沒有。
  • Clairic 的抽取準確率、在真實發票上的表現——沒有。
  • 延遲的具體數字（是 5ms 還是 50ms？）——沒有。
  • 成本節省的幅度——沒有。

對一個以「毫秒」為唯一賣點的模型家族，這是最大的資訊缺口。而「兩星期複製」是單方說法，沒有第三方驗證；「複製一個已知 schema」與「發明一個範式」的難度不可比，Chen 自己也在同一段話裡承認了，但標題式的數字仍然容易被讀成「TypeSafe 效率低」。

還有一個更微妙的雙標。Cloudflare 批評 Jev 閉源、自己跑不了；但 Clef 與 Clairic 同樣沒有任何開源承諾。它反對的不是閉源，是別人閉源。這一點文章沒有追問，而它其實是整個「neolab」敘事裡最容易被忽略的權力問題：當基礎設施公司開始做模型，它們會用開放標準來取得正當性，但不會用開放權重來放棄議價權。

九、放回時間線：四集，一個問題的四個樓層

這篇文章單獨看是一個公司公告；放進最近一週，它是一條線的第四段。

日期內容它在回答什麼
11-12Jev Revolution（AIE Code Summit 現場）決策模型如何被寫進代碼
11-13Google Decision 1 發布決策層如何被商品化、定價
11-16Dwarkesh × Paul Christiano能力上限與時間表
11-17Cloudflare 自稱 neolab決策層如何變成基礎設施的標準零件

四集其實在講同一件事的不同樓層：能力在往上衝，而把能力切成可路由的碎片，才是產品化的關鍵。Christiano 談的是最上層（我們要不要停）；BFL 談的是感知層（模型如何理解世界）；Jev／Decision 1 談的是決策層（一次呼叫值多少錢）；Cloudflare 談的是部署層（誰有權把這些呼叫放進全球邊緣網路）。

而 Cloudflare 這一層的特殊性在於：它離使用者最近。當一家公司同時擁有 CDN、DNS、邊緣運算、和一個分類器，它就可以在請求到達你的伺服器之前，先做一次決策。這是歷史上第一次，「路由」與「判斷」可以在同一個位置完成。

這才是這篇文章真正的新聞：不是 Cloudflare 做了模型，而是 Cloudflare 可以在網路層做模型。一個分類器的價值，取決於它被放在哪裡——放在別人的 API 後面，它是一個工具；放在全球邊緣網路的每一個節點上，它是一個新的網路原語。

十、三個可以帶走的判斷

1. 模型層的護城河，正在從「訓練」前移到「schema 與分發」

兩星期複製一個兩年的模型，說明範式一旦公開，實作壁壘極低。真正稀缺的是 API 設計、評測方法、以及「知道該在哪裡放系統一模型」的產品判斷。這與十字路口趙晨陽那集「評估是 RSI 唯一瓶頸」其實是同一個結構：誰定義了評測與介面，誰就控制了擴散速度。

推論下去：未來的競爭不會發生在「誰的模型更強」，而會發生在「誰的 schema 成為默認」。這是一場標準戰，不是能力戰。

2. 推論成本的壓力，正在把架構決策變成財務決策

一個 CDN 公司說「不必把每個請求送去 LLM」，在兩年前是效能考量，現在是毛利考量。當 token 單價成為財報項目（Anthropic 的算力成本佔營收比例從 251% 降到 48%），路由到小模型就從工程優化升級為財務策略。

這也意味著：「用哪個模型」這個問題，正在從 CTO 的桌子移到 CFO 的桌子。而一旦它到了 CFO 的桌子，決策標準就會從「哪個最強」變成「哪個每任務最便宜」——這正是 AINews 那一期「每 index 任務成本」指標在做的事。

3. NeoLab 標籤的通脹，是這個類別成熟的訊號，不是衰敗的訊號

當一家年化 30 億美元的上市公司自稱 neolab，這個詞確實快要什麼都指、也就什麼都不指。但換個角度看：一個標籤開始被濫用，通常是因為它描述的活動已經變成常態。「AI 公司」在 2015 年是標籤，在 2020 年是廢話；「neolab」正在走同一條路。

對從業者的實務意義是：不要再問「我是不是 neolab」，要問「我缺少哪個零件、我能不能自己造」。Chen 那句話——「成為 neolab 意味著我們可以創造我們缺失的東西」——把一個身分問題變成了一個採購問題，而這大概是這篇文章最可複製的一句方法論。

附：一句話總結

Cloudflare 這一手真正示範的，不是「基礎設施公司也能做模型」，而是「當範式被公開，模型的價值會從發明者轉移到部署者」——兩星期不是 efficiency 的證明，是定價權轉移的速度。

如果這個判斷成立，那接下來要觀察的不是 Cloudflare 的模型有多好，而是三件事：①它會不會把 Clef／Clairic 的 schema 開放成標準；②它的定价會不會低到讓獨立模型公司無法在中間層生存；③它會不會在下一次財報裡，把「token 成本節省」寫成一個可量化的數字。第三件事一旦發生，整個行業的敘事就會從「誰的模型更強」正式轉向「誰的路由更便宜」。
