「Agent = Model + Harness」——屠龍之術 × AICC2026：智能體把 Token 消耗推成「智能體數量增速嘅 37 倍」，同「算力缺口係持續性嘅」

📅 2026-09-22 17:24 UTC（09-23 01:24 CST）·🎙 屠龍之術（莊明浩，單口）·👤 無嘉賓｜內容為他對 AICC2026 主論壇发言嘅二次整理·🏷 算力 / 智能體 / IDC 報告 / 國產芯片生態

呢集唔係訪談，係一份「現場財報」。莊明浩 9 月 21 日去北京聽完 AICC2026 人工智能計算大會（已辦 7 年、國內最頂級、最聚焦「計算」本身嘅行業大會），返嚟做嘅單口復盤。佢一開場就點出自己覺得最關鍵嘅差異：AICC 唔講模型能力，講底層基礎設施——算力系統、芯片、軟硬適配、Token 生產。當一個國家最頂級嘅「計算」大會把主論壇時間畀 IDC 報告、院士嘅可靠性評測、同服務器廠商嘅系統方案，而唔係模型跑分，呢個安排本身就係一個訊號。

一句話抓住全集：需求側由 Chat 轉向 Agent，令 Token 消耗唔再係線性外推，而係被「智能體數量 × 單體行為」乘數放大；供給側受上游芯片供應鏈（尤其 HBM）制約，所以算力缺口唔係短期波動，而係持續性嘅結構問題。國產替代嘅真正戰場唔係單卡峰值，而係軟件生態——FlagOS 嘅價值就係「國產模型 × 國產芯片嘅 Day 0 適配」。
一、先講清楚一件事：本集嘅來源性質

呢點對閱讀判斷好重要，必須前置講明。小宇宙 RSS 提供咗完整官方 shownotes（41 段章節時間軸至 40:53），但冇官方逐字稿。所以本復述中「講者原話」只保留 shownotes 上嘅章節標題用語；其餘論述係按章節軸 + 一手大會報導重建。所有 IDC 數字均屬二手轉述（大會現場發布後嘅媒體報導，未見報告原文 PDF 逐頁核對），引用時我會盡量註明出處層級。

二、第一章：從 Chat 到 Agent——需求側嘅結構性躍遷

第一章嘅骨架係「從 Chat 到 Agent」，而切入點係一條等式：

「Agent = Model + Harness」 —— 第一章小節標題（02:40）。全集最凝練嘅一句框架。

呢條等式嘅意思係：Agent 唔係一個新模型，而係模型本體 + 外殼／工具／執行環境嘅組合體。而佢真正想講嘅係——需求側嘅變化唔止係「用量增加」，而係工作形態嘅改變。同一個任務，由「一問一答」變成「多輪推理 + 工具調用 + 跨系統協作」，Token 消耗嘅量級完全唔同。

佢引 IDC 觀察指出，當前業界共識收斂到兩類場景：work + coding（章節 08:52）。呢個同 IDC 報告嘅行業成熟度評估一致（見第五節），亦係本集最實用嘅一句：唔好問「Agent 可以食邊個行業」，要問「邊個行業嘅任務邊界夠清晰、結果夠可驗證」。

Token 增長嘅三個係數（09:47）

呢個係全集最有分析價值嘅一段。佢用「Token 增長嘅三個係數」作為中間變數，去解釋為何 IDC 要大幅上調中國智能算力嘅增長斜率——注意係上調，唔係小幅修正。邏輯結構係：把 Token 消耗拆成幾個可分別觀測嘅乘積項（智能體數量 × 單任務步數 × 單步上下文長度這一類結構），而每一項都在變大。

呢個拆法嘅重要性在於：它解釋咗「為何算力預測會被反覆打臉」。單看模型數量或單看用戶數，都會嚴重低估；因為 Agent 令「單位任務嘅 Token 成本」本身就係一個上升嘅乘數項。

三、IDC × 浪潮信息《2026 中國人工智能計算力發展評估報告》

報告於 9 月 21 日 AICC 現場發布，官方定性為業內首份聚焦智能體基礎設施嘅研究報告，措辭相當高規格：

「算力躍升為與水利、電網、鐵路同等級嘅國家戰略基礎設施。」 —— IDC 報告措辭（經《中華網》《每日經濟新聞》《虎嗅》等一手報導引述）。呢句係整份報告嘅定調句。
項目數字備註
全球活躍智能體數量7,940 萬（2026）→ 22.16 億（2030），CAGR 129.8%中國同期 CAGR 更高，達 151.2%
同期全球 Token 消耗量 CAGR4,822.6%，約為智能體數量增速嘅 37 倍中國 Token 消耗 CAGR 為 3,499.3%
中國智能算力規模2026 年 2,576.5 EFLOPS（同比 +87.9%）→ 2030 年 10,524.3 EFLOPS2025–2030 CAGR 由前版 46.2% 上調至 50.3%

全球 AI 算力需求滿足率79%（2024）→ 71%（2027 谷底）→ 77%（2030）即 2030 年仍有 約 23% 需求等唔到供應

一句話 智能體數量 4 年增約 28 倍，而 Token 消耗嘅複合增長率係它嘅 37 倍——即係話，就算智能體數量增長停咗，Token 需求都仍會因為「單體行為變複雜」而繼續爆炸。呢個就係「乘數效應」嘅數學含義。
「錯配」比「不足」更刺眼

IDC 副總裁周震剛喺現場訪談中指出一條完整因果鏈：需求（智能體 × Token）指數增長 → 供給受上游芯片供應鏈制約 → HBM 係最大瓶頸（壟斷、擴產慢）→ 廠商做分級存儲（把上下文放傳統內存或閃存）→ 壓力外溢到內存與閃存 → 連內存同閃存都開始短缺漲價。

而佢講得最刺眼嘅一句係「錯配」：過去嘅集群係面向訓練（要求算力峰值極高），但智能體普及之後需要嘅係保存上下文、大吞吐、低時延——舊集群「投了很多但用不上」。呢句對任何要採購算力嘅公司都係最實用嘅判斷：你唔係唔夠算力，你係買錯咗算力。

報告對「智能體時代基礎設施」嘅結論亦相應地由「規模擴張」轉向「系統效率競爭」：競爭核心由「擁有幾多算力」轉向「能夠多高效地持續產出智能」。配套兩個概念——能力型智算（Capability）（以超節點為代表嘅 Scale-up 架構，擴大高速互聯域與統一內存尋址，支撐突破智能上限）與容量型智算（Capacity）（多元算力協同、推理解耦、緩存與調度優化，提高 Token 產出效率）。以及一個新嘅運營尺度：Token 運營——唔追求單一指標最優，而在業務場景與服務等級約束下，搵「交互性 vs 吞吐量」嘅最優平衡。

四、第二章：智能本身嘅重新定義——從「概率擬合」到「可信生產」

第二章以同濟大學鄭慶華院士嘅演講為主軸（15:08）。路線係三段式：先指出當前大模型嘅局限（16:29）→ 再從「人腦」結構搵解法（17:29）→ 落到機器記憶智能（18:23）。

但本集真正嘅題眼唔係「記憶」呢個詞，而係莊明浩反覆強調嘅一組張力：「可靠性」與「評測體系」係一體兩面（21:21 / 25:13）。要走進生產，就需要：

  • 全鏈路覆蓋嘅評測（22:27）——唔係單點 benchmark；
  • 明確什麼叫「可靠」（23:34）——定義先於工程；
  • 發布相應嘅評測體系（24:01）。

呢個立場同國際上同一週嘅討論高度共振（見第八節）：當所有人都承認模型能力曲線在上升，「可靠性」就成為下一個瓶頸嘅名字。而中國學術側對呢件事嘅表述方式，就係「可靠評測體系 + 全鏈路覆蓋」。

五、第三章：算力與芯片——系統、器件、生態三線並進

第三章（25:46 起）係供給側嘅「廠商主張」段，主體係浪潮信息嘅方案，另有「芯算一體」等更上游嘅主張。時間軸非常清晰：

  • 浪潮信息嘅主張：智算系統嘅雙唯進化（26:41）→ 能力型智算嘅極端要求（27:48）→ 雙軌實施（28:59）→ 新產品發布（30:17）；
  • 再往上到 芯算一體（31:13）與 讓計算走進存儲（32:02）——把計算下沉到存儲側，正對上面講嘅 HBM／搬運瓶頸；
  • 已有嘅實施效果（33:12）與場景拓展（33:42）作為證據段；
  • 最後係生態層：FlagOS 生態（35:09）→ 軟件生態也是壁壘（35:52）→ 萬能插座（37:01）→ 國產模型與國產芯片嘅 Day 0 適配（37:25）→ 生態壯大中（39:01）。
「軟件生態也是壁壘」 —— 第三章小節標題（35:52）。全集最尖銳嘅一個立場。

呢個立場嘅推論係：制程嘅落後可以用系統同生態去補。而「Day 0 適配」係一條非常高規格嘅目標線——唔係「可以用」，而係芯片一發布就能跑主流模型，把過去幾個月嘅移植工程壓縮到發布當日。FlagOS 被比喻成「萬能插座」，價值就在呢度。

點解「Day 0」係一個可以驗收嘅指標：模型／芯片嘅熱度窗口只有幾週。如果適配要三個月，國產芯片就永遠只能食「已經唔係前沿」嘅模型；如果可以做到發布當日就跑，它才有資格被放進前沿團隊嘅選項清單。所以「Day 0 適配」唔係宣傳口號，而係國產算力能否進入主流供應鏈嘅門檻線。
六、行業成熟度：Coding 同 Work 率先規模化，傳統行業核心閉環仍係 0%

報告首次從「當前應用成熟度」與「長期生產力影響」兩個維度評估行業智能體，而兩個維度並唔同步。落地層面嘅事實相當硬：

行業 / 場景狀態
代碼開發（Coding）、辦公任務（Work）數字化程度高、任務邊界清晰、結果可驗證 → 已率先進入規模化應用
製造、醫療健康、能源／電力真正進入核心業務並形成「執行—反饋—優化」閉環嘅比例仍為 0%
運營商已有 70.0% 接入部分業務流程，但進入核心業務閉環嘅比例只有 3.3%
教育、科研與研發、醫療健康當前成熟度有限，但專業知識密度高、可被 AI 重構嘅環節多 → 長期生產力影響更突出

呢張表其實回答咗一個好現實嘅問題：「Agent 落地」嘅真實進度，唔係睇 demo，而係睇「有冇形成閉環」。70% 接入 vs 3.3% 閉環嘅落差，說明絕大多數部署仍停留在輔助層，未進入業務嘅責任鏈。

報告亦首次把智能體應用落地、具身智能產業布局、大模型開發、推理算力基礎設施納入城市 AI 算力評價指標。2026 年城市榜前三為北京、杭州、深圳（深圳由第四升至前三，理由係 AI 服務器與算力芯片製造基地嘅供給側地位）；上海、廣州、成都、南京、武漢、濟南、蘇州進入前十。

七、我嘅萃取（Insight）
  1. 敘事重心由「模型能力」轉向「基礎設施與可靠性」。當中國最頂級嘅「計算」大會把主論壇時間畀 IDC 報告、院士嘅可靠性評測與服務器廠商嘅系統方案，而唔係模型跑分，說明行業共識已默認瓶頸在供給側。呢個係一個可以攞嚟做前瞻嘅訊號。
  2. 供需剪刀差嘅因果鏈被明確講出，可以直接當採購時序用。需求（智能體 × Token）→ 上游芯片供應鏈 → HBM 瓶頸 → 分級存儲 → 內存／閃存漲價 → 2027 滿足率谷底。呢條鏈每一環都有時間點，比「算力唔夠」呢類空話有用得多。
  3. 「錯配」比「不足」更值得寫入決策備忘。過去面向訓練嘅集群不適配推理與智能體負載。對雲廠商同自建算力嘅公司，呢句係採購決策層面最實用嘅一句判斷。
  4. 國產替代嘅戰場在軟件生態，唔在單卡峰值。「生態也是壁壘」「萬能插座」「Day 0 適配」構成一個清晰立場：可用性嘅門檻線係「發布當日就能跑」，而唔係峰值跑分。
  5. Token 正由「成本項」變成「運營尺度」。報告提出 Token 運營要在交互性與吞吐量之間搵平衡——呢個係一個會傳導到產品設計嘅概念：同樣嘅算力，點樣配置模型、調度與緩存，會直接決定用戶體驗同毛利。
