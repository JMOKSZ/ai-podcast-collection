「No code is code」——Zapier CEO Wade Foster：約 600 項真實知識工作最高成功率得 40%，大部分任務其實應該用確定性代碼

📅 2026-09-17 13:56 UTC（北京 09-17 21:56）發布·🎙 The Cognitive Revolution（Nathan Labenz）·👤 嘉賓 Wade Foster（Zapier 聯創兼 CEO）·⏱ 全長訪談·🏷 AI 落地 / Agent / 企業轉型 / 基準

呢集係本週最「潑冷水」嘅一集。當行業（Dwarkesh × Noam Brown）喺度講 10,000 個 agent 解千禧年難題嘅時候，一位真正把 AI 賣畀企業嘅 CEO——Zapier 聯創兼 CEO Wade Foster——帶住一組硬數據上嚟：Zapier 自家嘅 AutomationBench 基準，涵蓋約 600 項真實知識工作任務（市場、銷售、HR、運營），最高成功率（GPT-6 Astra）都只係大約 40%。而佢最落地嘅一句判斷係：「大部分人用 agent 做嘅嘢，其實應該用返『舊式確定性代碼』去做。」

呢集嘅中心論點：Wade 嘅框架係一個「形狀勝於功能」嘅判斷——過去兩年 Zapier 乜都砌咗（Agents、Chatbots、MCP server、SDK、AI Guardrails），但真正學到嘅唔係功能，而係「AI 工作實際會喺邊度發生」。答案係：大部分人只揀一個「daily driver（日常主力入口）」，然後所有嘢喺嗰度做。由此推出三個連鎖判斷——① 「headless（無頭）」係贏家：唔好迫用戶入嚟你嘅平台，而係把你嘅能力「做入」用戶已經用開嘅 harness（Zapier MCP 就係呢個邏輯）；② 「No code is code」——構建方式已經反轉：agent 負責寫同改，人類睇視覺化流程做驗證；③ 真正嘅競爭對手唔係 OpenAI／Anthropic，而係「唔採用」——平均用戶「坦白講冇做幾多嘢」，市場比 Zapier 原本諗嘅「大一千倍」。
一、場合：兩年之後，Zapier 由「No-code 先驅」變成「乜都砌齊」

這是 Wade Foster 第二次做客 Nathan Labenz 嘅節目。第一次係 2024 年 9 月——當時 Zapier 係一間「學緊 call LLM」嘅 no-code 自動化公司，已有 40 萬客戶、用 Zapier 把 1 億+ 任務委託畀 AI，YC 主席 Garry Tan 稱佢為「未來嘅 AI 驅動知識工作者」。

兩年後，Zapier 已經「砌晒一切」（Nathan 嘅講法）：

  • 任何一步都可以 invoke AI 嘅 workflows；
  • Agents（agents.zapier.com）；
  • Chatbots；
  • MCP server；
  • SDK（docs.zapier.com）；
  • AI Guardrails。

但問到「呢啲建設教咗你啲咩」，Wade 嘅答案係關於「形狀」而非功能：2024 年佢哋唔知道「AI 工作實際會喺邊度發生」——係喺現有產品入面？新產品入面？定係實驗室自己嘅 app 入面？結果係：大部分人揀咗一個 daily driver（Cursor、Claude Code、ChatGPT），然後大部分工作喺嗰度做。

二、核心形狀：daily driver 收斂，同「headless 贏」

呢個「daily driver 收斂」嘅現象，直接決定了 Zapier MCP 嘅定位——把一個人嘅上下文同數據，帶入佢已經用開嘅任何 harness。Wade 視之為「知識工作移動嘅方向」。

佢仲觀察到市場出現一條分界線：

  • 一邊：仍然試圖迫用戶去用佢哋自家嘅 agent 構建平台；
  • 另一邊（headless 陣營）：話「bring it wherever you want（帶去你邊度都用得）」——佢點名 Salesforce Headless。
「我絕對認為後者（headless）係贏嘅策略。」 — Wade Foster

Wade 自己嘅 daily driver 係 Cursor，再加 Zapier 自家嘅 internal harness——一個「虛擬文件系統 context 層」＋ automations ＋ 可部署 app——透過 MCP 拉入去。

Nathan 引入 Tasklet 創辦人 Andrew Lee 嘅論點（「所有人喺度砌同一個橫向嘅『機械外骨骼』，只有少數會贏」）。Wade 同意前提——冇人想被單一模型供應商綁死——並用數據back佢：AutomationBench 就係佢嘅證據。

AutomationBench 約 600 項真實知識工作任務，覆蓋市場推廣、銷售、HR、運營。公開任務集（github.com/zapier/AutomationBench）＋論文（arXiv:2604.18934）全部開源。最新 SOTA：GPT-6 Astra，約 40% 任務正確完成；Gemini 3.7 Flash「做得幾好，但成本係一小部分」。

「成本 vs 能力」呢條曲線，正係為什麼「任何現代組織都想要一層『可以逐任務換模型』嘅中間層」。Wade 讀出一個樣本任務，好具體：

「敲定 Meridian Core 單 deal、標記為成交、按 routing policy 派發成交通知、對照 hierarchy spreadsheet 核對帳戶、換算貨幣、檢查有冇未結嘅 escalation。」 — AutomationBench 樣本任務（Wade 朗讀）

Nathan 補一句：呢種任務喺任何成交頻繁嘅公司一日會觸發好多次，唔係一次性嘅——而個基準「離飽和仲遠」。

三、最耐用嘅一句：「大部分嘢應該用確定性代碼」

呢個係全集最值錢、亦最可操作嘅判斷。Wade 由 2024 年講到 2026 年，而今次有更多證據back佢：

「大部分人用 agent 做嘅絕大多數嘢，其實佢哋應該用返舊式嘅確定性（deterministic）代碼。你真正想 AI 去推理嘅，只係嗰啲你確實需要佢推理嘅步驟。」 — Wade Foster

Zapier MCP 就係圍繞呢個分工去砌：模型負責起 workflow、為「應該便宜同可靠」嘅部分寫代碼，而把推理（佢叫「the ghost in the machine」）留返畀真正需要嘅步驟。

Nathan 追問「如果畀模型一個 Zapier 當工具，分數會升幾多？」Wade 話：AutomationBench V2 就係要量度呢個 lift——「分數會升幾多、成本會降幾多」。

「No-code is code」：構建方式已經反轉
「『喺 no-code 入面構建』呢個諗法，我覺得已經好過時——就好似一種新代碼：no-code is code。」 — Wade Foster

人類由視覺化 workflow 中得到嘅好處，仍然係驗證同文件；但編輯由 agent 做，越嚟越係當一個 hardening 咗嘅 workflow 壞咗嗰陣，由 agent 去 troubleshoot。

四、內部樣本：五個 agent 嘅「陪審團」

呢段係一個好具體嘅「agent 落地」示範。喺 Zapier 自家嘅 support org 入面，一個「自動 email 排障」程序會起五個獨立 agent：

  • 當 五個之中有四個同意同一個診斷，通常就係啱嘅；
  • 人類審閱者畀一個 thumbs-up 或 thumbs-down，並附上一個理由；
  • 呢啲理由會回饋入系統，形成一個改進迴路。

Nathan 探問「底層係唔係有個好精巧嘅檢索堆疊？」Wade 唔上釣：

「好多呢啲嘢，歸根究柢都唔特別花巧。就係——攞個例子，你鍾唔鍾意，然後洗、沖、重複（rinse, wash, and repeat）。」 — Wade Foster

護城河係咩？「15 年嘅自動化數據，加埋同乜都接得埋嘅 hook」——如果呢啲可以淬煉成一個「單憑模型做唔到」嘅產品。

五、競爭：唔驚實驗室，驚「一片相同」同「唔採用」

呢段係全集最有商業洞察嘅部分。Wade 唔擔心 labs，佢擔心另一樣嘢。佢記得 Paul Graham 喺 Zapier 過 YC 時嘅建議：問題永遠係「如果 Google 砌呢樣嘢會點？」而 PG 嘅答案係——

「你唔係同 Larry 同 Sergey 競爭，你係同『一個想升職嘅中層產品總監』競爭。」 — Wade Foster 引 Paul Graham

今日：「OpenAI、Anthropic——佢哋而家係大科技公司……佢哋冇可能砌晒所有嘢。佢哋真係砌唔到。」真正更難嘅問題係「一片相同（sea of sameness）」，以及一個事實：平均用戶「坦白講冇做幾多嘢」——少少 ChatGPT 或 Gemini，返工用 Copilot。

Wade 嘅市場判斷 真正嘅競爭對手係「唔採用（non-adoption）」；而機會係去教育一個市場——佢而家估計呢個市場「可能比我哋當初著手去砌嘅嘢大一千倍」。

Nathan 坦承自己錯估咗經濟改變嘅速度；Wade（由密蘇里州連線）同意——佢嘅朋友同家人「生活大致一樣」，用 ChatGPT 整 meal plan 同度假計劃，而唔係用 Astra 級嘅嘢。佢認為真正會打動人嘅，係「具體性（specificity）」——一個會觀察你做咩嘅 agent。

Wade 自己嘅「每週自動化」

佢有一個每週 automation：透過 Zapier MCP 收集 Gmail、Slack、瀏覽器上嘅 event stream，然後主動「提議」佢應該砌嘅工具。佢打算把呢套產品化。點解用 log 而唔係 screen recording？答案好務實：「我哋擅長 API」——而 Nathan 補一句：AI 讀 log 本來就叻過人類顧問。

佢嘅標準好寬鬆：啲 idea「50% 夠好」就可以開始 brainstorm——呢個係一個好重要嘅「唔好過度設計」訊號。

六、定價：「座位制已死或將死」
「座位制（seat-based）定價已經死咗，或者正在死。」 — Wade Foster

Wade 嘅拆解：

  • 商品類產品漂向用量制（usage-based）——Sam Altman 嘅「intelligence too cheap to meter／utility」框架；
  • 企業產品則伸手去搵結果制（outcome），例如客服工具「按解決咗嘅 ticket 收費」；
  • 但大多數產品停喺「乾淨結果」前一兩步，最後仍然係「賣緊某些部分嘅工作」。

問到「模型公司嘅消費者方案 token 補貼，係唔係對生態嘅價格歧視？」Wade 傾向自由市場，但引用微軟捆綁時代（United States v. Microsoft）作為「用優勢去『box out』更好產品」嘅案例，並話規則應由各國去定；佢嘅工作係喺規則內搵 edge。

七、向內：點解由「首席人力官」管 AI 轉型？

呢段係全集最反直覺嘅組織觀察。Zapier 把首席人力官 Brandon Sammut（現為 Chief People & AI Transformation Officer）放喺 AI 轉型嘅位——同 Wade 2024 年「AI 應該係每個人嘅事」嘅講法有張力。

Wade 嘅解釋係：瓶頸換咗。 ChatGPT 出現之後約一年內，Zapier 幾乎 100% 員工每日用 AI——所以「採用」已經唔再係問題。真正嘅挑戰係把個人流暢度轉化成公司級嘅 production-grade workflow，而呢個睇落係「人的工作」——重寫 job description、重新諗 compensation、re-skilling 團隊——Brandon 嘅團隊本來就最擅長。

「佢本來都好容易係 CMO、CPO，或者任何其他角色。關鍵係：把個 leader 配對去個瓶頸。」 — Wade Foster
「默認透明」：有幾多嘢其實唔需要保密？

Zapier 嘅「default to transparency」價值，今次得到升級：Slack 嘅 public／private 讀數顯示工作正漂移入 DM；同時 agent 有齊 Slack 上下文明顯更有效；於是佢哋搞咗個「友好嘅高管隊際比賽」，鬥把更多嘢放喺 public channel。仍然保持私密嘅係：HR 事件同活躍嘅安全漏洞。

「大部分人遠為高估『需要保密』嘅事情數量，而嚴重低估『當人類同 agent 都有齊全公司上下文時會發生咩』嘅威力。」 — Wade Foster
八、安全：揸住最多 credential 嘅公司，同 Mythos 級模型

Nathan 預期呢度會令 Wade 驚——因為 Zapier 代好多用戶揸住好多服務嘅 credential，「僅次於冇人」。Wade 嘅答案係：呢種 stewardship（受託管理）已經係佢哋 15 年嘅工作。新嘅嘢係 Mythos 級模型——佢可以「耐心地逐個 issue 逐個 issue 去 loop」，搵到漏洞。

「每個軟件項目都有漏洞。問題只係：有冇人搵到佢哋。」 — Wade Foster

而同一啲模型亦令 patching 更容易，「所以醒目嘅公司會用佢嚟做攻同防」。佢形容 Hugging Face 事件係「直接由科幻小說走出來」，並預期會有一次性嘅重新適應，然後進入新嘅 steady state。佢確認 Zapier 想要前沿模型嘅早期訪問權；Nathan 主張「好似 Project Glasswing 呢類計劃嘅會員資格，可能成為『任何人都要求揸住你 credential』時嘅真正差異化」。

花費數字 工程師每月跑 $30,000 token（Wade 自己嘅帖）——佢話呢啲人係outlier，而家仲未有個人預算；但 Zapier 砌咗 dashboard，令員工睇到「同一 workflow 用強模型 vs 平模型」嘅成本。有人「極度高效」，有人「根本唔需要用 Fable 或者 Astra 去做呢樣嘢」。對一間近 800 人嘅公司嚟講，呢個係教育問題——佢預期「綁定流暢度嘅 token 預算」會成為常態。
九、AI 寫作：唔係禁 AI，係反低質

Nathan 好小心咁提出 AI 輔助寫作——「唔係想捉你，因為我喺同一條船」，並自認佢自己嘅 Pangram 分數有時讀落都似 AI，同時指出 Zapier 部分輸出都係咁。Wade 嘅答案係一套規範（norms）而唔係禁令：

「問題唔係 AI，而係低質量嘅溝通——而 AI 令一個低判斷力嘅人可以用高產量嘅垃圾淹沒同事。」 — Wade Foster

佢嘅具體規範：

  • 自己負責你自己發嘅嘢——「你投入去 author 呢樣嘢嘅時間，應該多過讀者去讀嘅時間」；
  • 要理解到可以答問題；
  • 把請求講明；
  • 核實細節——「一個有 Slack access 嘅 agent 可以拉一個三個月前相關但錯嘅 project 出嚟」，而「AI 摘要會變成『AI 摘要嘅摘要』」；
  • 洗走啲 tell：「it's not this, it's that」、em dash（破折號）、「the honest truth」、「the load-bearing point」。
「用 AI 唔係問題。問題係低質量——呢個先係要打嘅仗。」 — Wade Foster
十、團隊組成：EPD 冇咗，但「公司感覺差唔多」

最後一條問到 team composition，Wade 畀咗一個好有層次嘅答案：經典嘅 EPD（Engineering–Product–Design）大幅消失、管理層扁平化、人人都變成自己嘅 mini data analyst——但，「公司感覺上仲係幾似」。方向係一個「軟件工廠 + support 工廠」，人類設計 loop，而每次模型發布就啃走剩餘嘅 human-in-the-loop 步驟。

Wade 嘅收尾 plug：「去裝 Zapier MCP。」

十二、重點引用
"The vast majority of what people are using an agent for, in fact, they probably should be using old-fashioned deterministic code. You really only want the AI to reason over the things that you need it to reason for."— Wade Foster（全集最耐用嘅一句）
"The idea of building in no-code, it feels antiquated to me. It's like the new code — no-code is code."— Wade Foster
"Seat-based pricing is dead or dying."— Wade Foster（論定價範式轉移）
"You're rarely competing with Larry and Sergey — you're competing with a potential mid-level product director who's trying to get a promo."— Wade Foster 引 Paul Graham（論競爭）
"Using AI is not the problem. It's low quality — that's the fight, at the end of the day."— Wade Foster（論 AI 寫作規範）
"Most people far overestimate the number of things where [privacy] is required, and definitely underestimate the power of what happens when both humans and agents have access to the full context."— Wade Foster（論默認透明）

整合 insight：呢集係本週「反泡沫」嘅關鍵鏡頭。當整個行業喺講千禧年難題同 RSI（Dwarkesh／Noam）嘅時候，一位把 AI 賣畀真實企業嘅 CEO 帶嚟：約 600 項真實知識工作，最高自動化成功率只係 40%，白領工作被改造嘅程度遠低於炒作。三個可操作嘅 takeaway：① 「確定性代碼 + 結構化驗證」應該係 agent 落地嘅默認架構——只把真正需要推理嘅步驟交畀模型（呢個對錦鯤 13,000+ 酒店、Trinity 呢類企業級場景直接相關）；② headless 策略——唔好迫用戶入嚟你嘅平台，而係把能力做入佢哋已經用開嘅 daily driver；③ 「採用」唔係問題，「把流暢度轉化成 production-grade workflow」先係問題——瓶頸係人的工作（job description、compensation、re-skilling），所以由 HR 定由 CMO 去管唔重要，重要嘅係「把 leader 配對去個瓶頸」。
