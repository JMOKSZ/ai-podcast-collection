「讓 Claude 完全編排自己嘅 multi-agent 拓撲」——Latent Space × Anthropic：Dynamic Workflows、70 個 bug 捕獲 66 個，同「模型唔知自己有幾多預算」

📅 2026-10-12（北京時間 10-13 02:18）·🎙️ Latent Space（作者 Richard MacManus）·👤 CJ Avilla ＋ Harrison Stall（Anthropic MTS）·📍 AI Engineer NYC 2026 開幕日 workshop

AI Engineer New York 2026 開幕日，Anthropic 兩位技術人員介紹咗一個上周五（10 月 9 日前後）啱啱喺 X 宣布、代號 dynamic workflows（會上反覆簡稱「flows」）嘅新特性——定義係「一種全新嘅 multi-agent 編排，為你最有野心嘅 workload 而生」。佢嘅核心一句話講得晒：由 Claude 自己決定整個 multi-agent 拓撲。開發者唔再配置 coordinator 同 roster，而係由 Claude 寫一段編排程式（orchestration program）——由佢啟動 agents、收集結果、管理資訊流。呢篇係當前對 flows 最完整嘅公開現場解說，同時亦係一次「貴但值」嘅誠實定位。

「Flows are essentially the next version of multi-agent orchestration, where you can let Claude fully orchestrate the entirety of its own multi-agent topology.」 Harrison Stall, Anthropic MTS（原文引語）
一、人物同場合
  • 嘉賓：CJ Avilla 同 Harrison Stall，皆為 Anthropic Members of Technical Staff（MTS）。
  • 場合：AI Engineer New York 2026 開幕日 workshop；本集為 Latent Space 編輯 Richard MacManus 撰寫嘅現場報導型 article-interview（latent.space）。
  • 特性狀態：dynamic workflows 於 2026-10-09 前後喺 X（@ClaudeDevs）宣布，屬 public beta，需以特定 beta header 啟用（第三方報導指 managed-agents-2026-04-01；另說 agent type 選 multiagent_20261001）。本集係其公開後首場深度現場解說。
  • 所屬平台：Claude Managed Agents，全部功能都在 Claude Console 中提供（開發者經 API 存取 Claude 嘅界面）。
二、核心機制：由 Claude 自己寫編排程式

① 「下一代 multi-agent 編排」

Stall 嘅定義（見上引）——讓 Claude「完全編排自己整個 multi-agent 拓撲」。運作方式分兩步：lead agent 先為任務制訂計劃，Claude 接着自己寫一段 orchestration program——呢段程式負責啟動 agents、收集結果、管理資訊流。

② 同舊機制嘅關鍵差異

此前嘅 Claude Managed Agents 需要開發者自行配置一個 coordinator 加一組 roster 子代理；有咗 dynamic workflows，由 Claude 自己決定點樣切分同編排工作。Stall 原話：跨越多個編排階段，「它能在你完全不需管理任何互連關係的情況下，完成一個個離散、可驗證的工作單元」。呢個係一次責任轉移——「管理互連關係」由人手上轉移到模型手上。

③ 組織學類比：由 Ken Thompson 到 Linus

開場以作業系統史作喻：由 Ken Thompson 寫出初版 Unix，到 Linux 由「一個人（Linus Torvalds）」演化為層層 trusted maintainers。教訓係——agents 需要同等嘅組織度，才能承擔 Anthropic 設想嘅嗰種大型任務。問題意識亦講得好直白（Avilla）：

「I think a lot of us who are orchestrating and managing lots of agents now might start to feel this feeling of being the bottleneck and being the breaking point as we have lots of agents contributing tons and tons of PRs… And we're sitting there in our GitHub trying to approve PRs.」 CJ Avilla（原文引語）

呢句點出咗整場 workshop 嘅真正痛點——當大量 agent 貢獻大量 PR，負責編排同管理 agent 嘅人，會開始覺得自己係瓶頸、係斷點。flows 想解決嘅，正係「人肉審 PR」呢個新嘅樽頸。

④ 仍然可以注入專家子代理

Avilla 補充：喺 agent config 中可以傳入預先配置好嘅 sub-agents。即係話，模型自編排同「人類指定專家」可以並存——你唔係完全放棄控制權，而係由「逐個配置」變成「按需注入」。

三、示例：股票 watchlist scanner

現場示範一個故意簡單嘅 workflow（遠不及 Anthropic 所鼓吹嘅大型項目），用嚟講清基本模式：

  • scan 階段：把個別 ticker 分發畀帶 isolated context 嘅 agents；
  • review 階段：檢查呢啲發現，然後產出一份報告。

呢個兩階段結構（scan → review）就係 flows 嘅最小骨架——把任務切成離散單元、由帶隔離上下文嘅子代理並行處理、再由後續階段匯總。示範裏面亦見到「以 brain/hands 概念理解 Managed Agents」嘅圖示：模型負責思考，工具／agent 負責動手。

四、Q&A 環節：五個尖銳問題

① Claude 點決定要用幾多個 agent？

觀眾問：一次簡單嘅 ticker 掃描會唔會失控觸發數百個子代理？Stall 答：

「The answer really is evals and lower defaults.」 Harrison Stall，答「Claude 如何決定需要多少個 agent」

並補充，有野心嘅任務通常需要顯式地鼓勵更高嘅並行度。呢個答案嘅深層含義值得留意——「該開幾個 agent」呢個決定，已由開發者嘅靜態配置，變成由 evals 同默認值（lower defaults）調校嘅經驗參數。即係話，編排嘅「油門」仍然需要人去踩，但踩嘅方式由寫配置變成調評估。

② Token 預算：模型唔知道自己有幾多錢

有人問 lead agent 係唔係知道可用預算。Stall 答：模型喺運行時並不知道自己的預算，但開發者可設定 session budget。佢補咗一句引來全場輕笑嘅話——把預算告訴模型，可能會讓呢啲 agent「有點焦慮」（a little bit anxious）。

「把預算告訴模型，可能會讓這些 agent『有點焦慮』。」 Harrison Stall（原文：a little bit anxious）——全場輕笑

呢句幽默但尖銳。它點出咗一個結構性事實：agent 嘅經濟理性仍然係外部強加嘅——模型並唔「內生」预算約束，錢係由外面嘅 session budget 卡住。所謂「自主 agent」，喺成本維度上仍然係被人牽住嘅。

③ 如何讓重複嘅 flow 越來越便宜：dreaming

除咗叫 Claude 檢視自身成本，Avilla 建議用另一個較新特性 dreaming（目前為 research preview）。按官方文檔，一個 dream「讀取既有嘅 memory store 同過往 session transcripts，然後產出一個新嘅、重組過嘅 memory store」——其中重複條目被合併、「陳舊或互相矛盾嘅條目」被替換、「新洞見被浮現出來」。Avilla 用 flow 語境講，它能「crystallize 並基本上改進同那些 sessions 相關嘅 memory store」。

④ flow 能否自我改進？

有人問 watchlist flow 能否察覺「自己嘅掃描模型唔夠好、並改掉下一次排程」。Stall 話呢個唔係內建功能，但佢同 Avilla 建議可用 hill-climbing ＋ dreaming 嚟改進呢個迴路。呢個係一個關鍵誠實位——自我改進迴路未內建，目前要靠外部機制拼裝。

⑤ 子代理之間能否互相通訊？

Stall：agents 共享一個 filesystem，可藉此交換資訊；但開發者唔可以透過 API 直接指示某個 workflow 子代理去畀另一個發消息。即係話，子代理之間嘅「通訊」係透過共享文件間接發生，而唔係一條可編程嘅消息通道。

＋ 可觀測性同成本權衡

  • 可觀測性：開發者隨時可透過 Claude Console 內嘅 graphing 功能檢視。Avilla：「你可以看出 lead agent 究竟把什麼傳給了 sub-agent——在這裡檢視那個 payload，去深入理解整張圖中每一次轉移到底發生了什麼。」
  • 成本：喺 watchlist-scanner 嘅對比中，Avilla 話 flows 比單 agent 方案「貴得多」（much more），但也「在找出所有細節上有效得多」（much more effective at finding all of the details）。
五、野心有幾大？——由 Navier–Stokes 講到「平民化科學發現」

有觀眾問 dynamic workflows 能否驅動大型科研項目，並援引 OpenAI 近日宣布嘅 Navier–Stokes 千禧年大獎難題證明。Stall 唔願就 Anthropic 如何處理大型科學問題嘅細節多談，但表示目標係讓一般用戶也能處理這類問題：

「Flows are basically a way to throw test-time compute at hard problems and get more capability faster out of the models… unlocking the power of this is the first step for us making these types of discoveries, or scientific progress, broadly doable by the general public.」 Harrison Stall（原文引語）

呢句係全場嘅定位宣言：flows ＝ 把 test-time compute 砸到難題上嘅一種手段；算力換能力，且目標係平民化科學發現。呢個同 10-10 Cognitive Revolution × Bigelow 嗰集互證——「推理≈對自己採樣 token 做 ICL、決定發生喺採樣處」；本集正係把「採樣／決策」由單模型層面抬升到多 agent 拓撲層面去自動化。

六、關鍵數據／事實
規模第三方報導指：單次執行最多可並行 1,000 個 agent。Anthropic 提醒 flows 會燃燒「大量 token」，建議由小規模開始。
基準測試Anthropic 自測：喺一個 116,000 行嘅代碼庫中藏 70 個 bug——單一 agent 每次捕獲 14–27 個，而 dynamic workflow 穩定達 66 個。公司口徑、未經獨立核實。

七、Vee 嘅萃取
  • 編排嘅瓶頸由「人」轉移到「預算同評估」。當 agent 拓撲由模型自生成，「該開幾個 agent」不再由開發者配置，而由 evals 同 lower defaults 決定；人退到「設預算、看圖、審查」嘅位置。呢個係一次職能重定義——開發者由「編排者」變成「評估者 ＋ 審計者」。
  • test-time compute 成為能力擴展嘅主軸。Stall 直接把 flows 定義為「把 test-time compute 砸到難題上」嘅手段——算力換能力，且目標係 democratize 科學發現。呢個係 2026 下半年一條清晰嘅主線：能力嘅增長唔再單靠 pretrain，而係靠推理時嘅算力調度。
  • Anthropic 把 multi-agent 由「開發者配置」推向「模型自編排」。呢個係繼「a harness for every task」（Claude Code 起源）之後嘅下一步——flow 可運行得比單 agent 或 roster 更久，且承擔「離散、可驗證嘅工作單元」。
  • 成本結構嘅誠實披露值得記低。Anthropic 自己承認 flows「貴得多」，但「找出所有細節嘅能力強得多」——一次明確嘅「貴但值」定位。對比同期 OpenAI 有工程師公開稱 agent swarms 係「巨大嘅 token 浪費、零質量提升」，兩家喺 multi-agent 上嘅路線分歧已經擺上檯面：Anthropic 用 70-bug 自測撐「質量提升」，OpenAI 質疑成本效益。
  • 模型「唔知自己有幾多錢」係一個幽默但尖銳嘅註腳。agent 嘅經濟理性仍然係外部強加嘅——「自主 agent」喺成本維度上仍然被人牽住。呢點同 42 章經 × Ambi 嗰集嘅「涉及名和利的需求才做，因為算得清 ROI」恰好互為鏡像：一個講預算嘅自動化，一個講 ROI 與人性嘅產品選擇。
八、前後脈絡
  • 承接 Latent Space 10-10〈Building AI for Reliable Execution: Lessons From Industrial Robotics〉：同一主旋律——決定產出品質嘅係系統嘅組織方式同上下文，而唔係單純更大嘅模型（該集核心係「數據質量遠勝數據量」）。
  • 同 10-10 Cognitive Revolution × Bigelow 互證：「推理≈對自己採樣 token 做 ICL、決定發生喺採樣處」——本集把「採樣／決策」由單模型層面抬升到多 agent 拓撲層面去自動化。
  • 同本日中文檔 42 章經 × Ambi 構成母題兩端：一端係模型自編排（Claude 自己決定拓撲、用 test-time compute 砸難題），另一端係產品自編排之外嘅人（Personal Agent 為何此刻爆發、為何天然不帶網絡效應）。
  • 同近年「model eats scaffolding」母題同向：當 harness／編排逐漸由模型自己生成，外層 scaffolding 嘅價值就被 reprice（可對照 21〈Model Eats Scaffolding〉、151〈Forward Deployed Engineer〉）。
九、爭議點／存疑（必讀）
  • flows 明顯更貴，Anthropic 自認。watchlist-scanner 對比中「貴得多」，官方亦建議由小規模開始——「貴但值」係官方口徑，性價比仍取決於你嘅任務類型。
  • 模型唔知預算、且「知情會焦慮」——agent 成本控制仍靠外部 session budget；所謂「自主」喺經濟維度上有限。
  • 自我改進迴路未內建，目前要靠 dreaming／hill-climbing 拼裝；dreaming 仍屬 research preview。
  • 「evals 與 lower defaults」係經驗性而非保證性答案——觀眾對「野心型任務會否失控觸發數百子代理」嘅擔憂，官方並無硬性上限承諾。
  • 70 個 bug／66 vs 14–27 係 Anthropic 自測數字，第三方無法覆核；同期 OpenAI 有工程師公開質疑 agent swarms 嘅 token 效益——呢個係路線之爭，唔係中立事實。公司口徑 · 未經獨立核實。
