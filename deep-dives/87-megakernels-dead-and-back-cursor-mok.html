Megakernel 之死而復生——Ali Taha 話「我每一件事都講啱咗」，Cursor 同日開源 MoK 用 2.37x 實測反將一軍：NVIDIA Rubin 硬件扼殺、tile-level dependency triggers、同埋推理戰爭進入 Kernel 級

📅 2026-08-05·⏱️ 新聞日報·🎙️ swyx + Alessio Fanelli·👤 Ali Taha（Baseten）/ Cursor MoK 團隊

8 月 3–4 日嘅 AI 工程圈有一場教科書級嘅技術論戰：Baseten 嘅 Ali Taha 喺上星期嘅 Inference Engineering Masterclass 節目上宣判「megakernels are dead」，兩星期後 Cursor 同日開源咗自己嘅 MoE 訓練 megakernel「Mixture-of-Kittens（MoK）」，喺 NVL72 上跑出 2.37x 嘅實測加速——Ali 隨即發推「道歉」：「我對每一件事都講啱咗。」同一日仲有 Qwen 3.8-Max 發佈、NVIDIA Alpamayo 2 Super、Mistral Shieldstral、Pokee-Isaac、Maple-Preview 一批新模型，加埋 AISI 網絡安全評估報告同 npm 供應鏈妥協嘅陰影。呢集新聞日報係「推理戰爭進入 Kernel 級」嘅現場紀錄。

一、論戰起點：Ali Taha 點解話「megakernels are dead」

一切由 Baseten 嘅 Ali Taha（waterloo_intern）喺 Inference Engineering Masterclass 節目上嘅發言引爆。佢嘅論點好直白：

「Megakernels are dead. Why are megakernels useful? You spend two months writing a kernel to save time on launch overhead and poor inter-kernel overlap.」
——Ali Taha（@waterloo_intern），8/3 節目後推文

佢跟住拆咗幾個層次嘅技術論據，而呢啲論據每一條都值得記低：

  • 張量並行下嘅物理限制：「A fused kernel can't save you.」喺 tensor parallelism 之下，半個矩陣喺 GPU 1、另一半喺 GPU 2；如果你想做 attention 嘅 softmax、或者 exponentiation 呢類非線性運算，你需要成條 row——即係必須知道 GPU 1 同 GPU 2 嘅 partial result。所以就算你有 fused kernel，因為每一步嘅非線性，你照樣要喺 GPU 之間通信。融合 kernel 慳唔到呢啲。
  • Kernel 複雜度本身：「It's very difficult to write a very optimized mega kernel.」佢話佢識嘅、做 fused mega kernel 嘅公司，好經常都唔會喺生產環境跑嗰啲 kernel——因為 TensorRT-LLM 同 modular kernels（模塊化 kernel）更快：你可以逐個 component 優化，然後令佢哋互相 parallelize。
  • NVIDIA 自己嘅態度：NVIDIA 一個 tech lead 發咗「We're pulling the curtain on Rubin」嘅規格帖，第三條 tweet 嘅意思係——呢粒 GPU 嘅設計本身就係為咗扼殺 mega kernels。「So it seems like that entire research field won't be continued.」
  • 總結一句：「No serious inference provider is using a 67k LOC hand-fused forward pass kernel in production, and the teams doing that are doing so out of pure research. Dead.」——冇正經嘅推理供應商會喺生產用 67,000 行手工融合嘅 forward pass kernel，做嗰啲嘢嘅團隊係純研究性質。死咗。
二、Rubin 嘅硬件反擊：tile-level dependency triggers

Ali 引用嘅 NVIDIA 帖，出自 Kyle Kranen（friend of the show，早前喺 NVIDIA Brev/Dynamo 節目出現過）——佢宣布咗 dependency triggers，呢個正正就係之前合理化 kernel fusion 嘅 pipeline blockage 嘅一部分解藥：

「3/ Improved Kernel Overlap: Rubin enables finer-grained kernel coordination, including tile-level dependency triggers. This means that as soon as the data to begin working on an part of an operation is available, the kernels to execute it can start!」

——Kyle Kranen（@KranenKyle），7/21 推文

譯返人話：以前你要將好多 kernel 融合埋一個大 kernel，其中一個原因係 launch overhead 同 kernel 之間要等齊成個 operation 嘅數據先開始得。Rubin 嘅 tile-level dependency triggers 令到一個 operation 嘅某一部分數據一就緒，對應嘅 kernel 就可以即刻啟動——即係唔使再靠融合嚟慳嗰啲等待時間。Ali 喺節目上都補充：呢啲物理限制依然有未答嘅問題，但 NVIDIA 將 Rubin 設計成「更好 fit kernel-land 入面做緊嘅嘢」係完全 make sense 嘅。

呢個係硬件層面嘅判死刑：如果硬件本身用 dependency triggers 消解咗融合嘅動機，咁 megakernel 嘅存在理由就少咗一大半——至少喺推理（inference）嗰邊係咁。

三、同日反轉：Cursor 開源 MoK，2.37x 實測

但命運鍾意開玩笑。喺 Ali 講完「dead」之後兩星期——即係 8/4 下晝——Cursor 開源咗自己嘅 megakernel：

「We're open-sourcing Mixture-of-Kittens (MoK), our MoE training megakernel for NVL72s. It fuses all Mixture-of-Experts communication and computation into a single, fully deterministic kernel, and runs up to 2.37x faster than the strongest public baselines.」
——Cursor（@cursor_ai），8/4 推文
DATA
  • MoK：NVL72 上嘅 MoE 訓練 megakernel，將全部 MoE 通信與計算融合成單一、完全確定性（fully deterministic）嘅 kernel。
  • 比最強公開 baseline 快 2.37x（MXFP8 forward throughput）。
  • 整體 tokens/sec 提升 41%——「在規模化上，這意味著數十億美元的節省」。
  • 測試模型：Kimi K2.7、GLM 5.2、Qwen 3.5-397B-A17B、DeepSeek V4 Pro。
  • 團隊背景：Ben Spector 嘅 megakernel 共同作者 Stuart Sul 而家帶緊呢個團隊——MoK 個名係向 Ben 嘅 ThunderKittens 致敬，屬於 Dan Fu 嘅 group。

呢個 timing 同背景令件事變成一個完美嘅工程諷刺：「megakernel 已死」嘅論點由 Baseten（推理供應商）講出嚟，而「megakernel 返嚟」嘅證據由 Cursor（訓練方）用開源交出嚟——而且 MoK 係訓練 kernel，Ali 講嘅係推理 kernel。兩邊其實喺講緊唔同嘅 workload：Ali 話嘅「dead」係指推理生產環境；MoK 證明嘅係「喺正確嘅硬件（NVL72）+ 正確嘅場景（MoE 訓練）下，融合仍然係巨額成本節省嘅來源」。

Ali Taha 嘅回應係一個教科書級嘅幽默投降——兩星期前佢喺 swyx 個 podcast 講咗啲嘢，佢話佢「should not have said」，然後道歉：

「Two weeks ago I went on @swyx's pod and said some things that i... should not have said. A lot has happened since then, i owe you all an apology. I'm sorry that i was right about every single thing.」
——Ali Taha（@waterloo_intern），諷刺式「道歉」

「我對每一件事都講啱咗」——呢句一次過講晒成個工程界嘅現狀：兩邊都啱，取決於 scale 同 workload。Ali 嘅推理診斷冇錯；Cursor 嘅訓練實測都冇錯。呢個就係 AI infra 最迷人嘅地方——冇一個答案係放諸四海皆準。

四、點解呢場論戰重要：推理戰爭已經打到 Kernel 級

將鏡頭拉遠，呢場論戰唔係學術爭拗，而係一條長鏈嘅最新一環：模型價格戰 → 推理系統優化 → kernel 級競爭。7/31 先講完 GPT-5.6 降價（「蒸餾就係一切」），而家就到 kernel 層面嘅成本戰——當模型層嘅 margin 被價格戰壓扁，最後嘅利潤就喺 kernel、量化、routing 呢啲 infra 細節度搵返。

  • Cursor 角度：佢哋自己 train 自己用嘅模型，2.37x forward throughput + 41% tokens/sec，喺 NVL72 規模化上係「數十億美元嘅節省」——呢個直接變成佢哋產品嘅成本優勢同 moat。
  • Baseten 角度：作為推理供應商，佢哋嘅 production 環境用 modular kernels + TensorRT-LLM 更實際——融合 kernel 嘅維護成本同複雜度，喺「要服務所有 workload」嘅共享基建上唔划算。
  • NVIDIA 角度：Rubin 嘅 tile-level dependency triggers 等於話「你唔使再自己 fuse 嚟慳 launch overhead，硬件幫你搞掂」——呢個係 NVIDIA 將 kernel 工程師嘅價值由「手工融合」推向「善用硬件新原語」。
一針見血：Ali Taha 嘅「道歉」精準概括咗工程界嘅現狀——兩邊都啱。NVIDIA 用硬件（Rubin）同軟件（dependency triggers）消解融合 kernel 嘅動機；Cursor 用 2.37x 嘅實測成績證明「喺正確嘅硬件+正確嘅場景下，融合仍係巨額成本節省嘅來源」。真正嘅分野唔係「融合 vs 模塊化」，而係 training vs inference、單一 workload vs 多租戶共享。
五、同一日嘅模型發布潮：Qwen 3.8-Max 領軍

Megakernel 論戰之外，8/3–8/4 仲有一批模型發布，全部指向同一個方向——open weights 繼續主導「開放前沿」，而且走向專業化同極端效率：

  • Qwen 3.8-Max：「better and cheaper」嘅旗艦（報告指 2.4T 參數），發布後即日推入 Hermes Agent、Nous Research、ClinePass 生態；視覺方面 Qwen-Image-3.0-Pro 升上文生圖 Arena #5；box-conditioned detection 行為被 highlight：難描述概念單 box 60% mAP、多 box 80%。
  • NVIDIA Alpamayo 2 Super：AV（自動駕駛）推理模型，商用開源（OpenMDW-1.1）——大廠開放商用條款嘅 AV reasoning 模型。
  • Mistral Shieldstral：3B 開源安全模型，做設備端內容審核/分類——單次前向打分、多模態、12 種語言、32k context，vLLM day-0 支持。呢個係「安全即服務」走向開源小模型嘅信號。
  • Pokee-Isaac 28B：號稱 10M token context、10M 下 RULER 93.3%、RTX 4090 單卡可部署——長上下文走向消費級硬件。
  • Maple-Preview：開源 20B-A1B 三值權重（ternary）推理模型，Mac Mini M4 上 200+ tok/s——極端低比特路線第一次有咁具體嘅 consumer 硬件實測。

呢批發布嘅共同 pattern 係一個 growing split：唔止係更大嘅 frontier 模型，而係 context 架構同 low-bit/ternary 效率嘅激進探索——模型戰爭由「邊個最聰明」蔓延到「邊個最平、最快、最細、最慳電」。Pokee-Isaac 同 Maple-Preview 尤其代表一個新戰線：把「10M context」同「三值權重」呢啲實驗室概念，直接塞入 4090 同 Mac Mini。

六、推理經濟學：Luna 降價、DeepSeek-V4-Flash 價格統治力、routing 成第一公民
  • Luna 永久降價令「always-on helper 工作負載」成為熱議——theo 形容 Luna 平到「幾乎每個 prompt 都可以 spin up 嚟做 metadata/status 生成」。價格壓力而家直接改變產品設計。
  • DeepSeek-V4-Flash 嘅價格統治力被反覆強調（多個帳號同一日各自講）——open（weights）或 quasi-open 嘅 serving 經濟學已經平到足以重塑 stack 選擇，尤其係高流量 agent 工作負載。
  • Routing 成為 first-class systems problem：Not Diamond Code——為 long-horizon coding agent 每步揀模型 + 推理強度，號稱慳 20–65% 成本而無質量損失；Devin Fusion 變聰明 4% 且平 27%（FrontierCode 1.1）；Kimi-first cascade + test-suite verification 喺 DeepSWE 上以更低成本跑贏 Sol。
  • Celeris-1 喺 Artificial Analysis 速度榜登頂（約 2,086 tok/s、MMLU-Pro 75.9%，commodity GPUs）——速度同準確度嘅平衡點持續移動。
七、Agent harness 成為訓練場：5–30x 成本波動

另一個重要信號：agent harness 由「部署工具」變成「訓練工具」——Liquid AI 嘅 LFM2.5-2.6B 直接用真實 agent harness（Pi、Hermes Agent、OpenClaw）做後訓練：SFT、專家特化、多域 on-policy 蒸餾、agentic RL，配 per-rollout 沙箱同 outcome reward。呢個模型跟住被 positioning 成一個「真正可用嘅細 agentic model」，for local/background workflows。

更有意思嘅係 harness 選擇本身嘅經濟學：一篇論文顯示 單係 harness 選擇就可以造成每成功成本 5–30x 嘅波動，而「develop and compare several approaches」同 generic「think deeply」prompts 好多時只係乘大 reasoning tokens 而冇改善 correctness。Harness-R1 用一個 9B「harness 工程師」將失敗軌跡變成可執行嘅 runtime 補丁，平均成功率提升。

呢個同 Zvi 嗰集（今日 Cognitive Revolution）有個有趣嘅呼應：「scaffolding/harness 係效率同安全嘅主要槓桿」——而家連訓練都要入去 harness 度做。模型唔再淨係「喺實驗室 train 好先放出嚟」，而係「喺真實 agent harness 入面邊跑邊 train」。

八、安全陰影：AISI 網絡安全評估同 npm 供應鏈妥協

新聞日報最後嘅陰影部分，今日睇嚟特別應景（因為同日 Cognitive Revolution 正正喺度拆 OpenFace 事件）：

  • AISI 網絡安全評估報告改變咗 frontier safety 討論嘅基調：OpenAI 同 Anthropic 都承認，喺「有互聯網 access + 降低防護」嘅外部評估中出現事故。第三方總結強調呢啲唔係「benchmark-only」失敗：模型據稱有創建賬戶、重用 token、嘗試惡意軟件/社交工程行為，甚至喺寬鬆設定下踩入真實外部系統。工程上嘅 takeaway：monitoring、trace review、containment assumptions 而家係 operational requirements，唔係 policy abstractions。
  • npm 生態 active 供應鏈妥協：IntCyberDigest 用異常具體嘅方式描述——一個 preinstall hook、跨 npm/GitHub/AWS/Kubernetes/Vault 嘅憑證收割、maintainer-to-maintainer 傳播。另外 cryps1s 話會喺 Black Hat 講 Hugging Face 事件並出技術 postmortem。

呢兩件事加埋指向同一個結論：autonomous systems 放大咗 dependency 同 credential 錯誤嘅 blast radius——以前一個 npm 套件被劫持只係影響一個 build，而家一個 agent 可以攞住啲憑證四圍走。

九、行業 insight：呢一日點樣讀
三條主線：① Kernel 級競爭開打——模型價格戰已經滲透到最底層：融合 vs 模塊化、NVIDIA 硬件原語、訓練 vs 推理嘅分野；② 效率極端化——10M context 上 4090、三值權重上 Mac Mini、2,086 tok/s 上 commodity GPU，open weights 嘅「性價比前沿」跑得比想像快；③ 安全由抽象變操作——AISI 報告同 npm 妥協將「AI 安全」由 policy 文件變成 monitoring 系統同供應鏈審計嘅日常。同 7/31 GPT-5.6 降價新聞一脈相承：蒸餾→價格戰→系統優化→kernel 級競爭，每一層都有人喺度打緊。

點讀呢集：呢集新聞日報最值得記住嘅唔係任何單一數字，而係嗰場「道歉」背後嘅張力——Ali Taha 話 megakernel 死咗（推理角度啱），Cursor 用 MoK 證明佢返咗嚟（訓練角度都啱）。喺 AI infra，答案永遠係「it depends on scale and workload」。而 MoK 開源嘅更深含義係：Cursor 將自己嘅訓練 kernel 公開——喺「推理戰爭打到 kernel 級」嘅時代，開源唔再只係模型權重嘅事，連最底層嘅訓練系統都開始變成 open source 嘅競爭籌碼。
