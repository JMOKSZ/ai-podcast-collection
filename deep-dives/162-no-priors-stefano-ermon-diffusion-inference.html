「擴散會贏下推理」——No Priors × Stefano Ermon：RNN→Transformer 嘅歷史，將喺推理時重演一次，Mercury 比自回歸快 10×

📅 2026-09-18 10:00 UTC（北京 09-18 18:00）發布·🎙 No Priors（主持人 Sarah Guo，嘉賓 Stefano Ermon）·👤 Stefano Ermon（Stanford 教授、Inception 聯創兼 CEO、擴散模型與 score-based 生成模型先驅）·⏱ 約 38 分鐘·🏷 架構 / 推理 / Serving / 效率

呢集係本週最有「技術賭注」含量嘅一集。當全行業默認 LLM 就等於「一次預測下一個 token」嘅自回歸架構時，斯坦福教授、擴散模型先驅、Inception 聯創兼 CEO Stefano Ermon 上嚟講一個少數派但技術論證完整嘅判斷：「擴散（diffusion）會贏下 AI 推理」。佢唔係講圖像——圖像/視頻擴散早就橫掃——佢講嘅係離散嘅文本同代碼：一個原本為連續像素而設嘅架構，點樣被搬到 token 上面，點樣喺標準 GPU 上跑得比自回歸快約 10×，以及點樣令一間語音 Agent 公司由定制芯片「切返」Nvidia。

呢集嘅中心論點：Ermon 嘅框架係一條歷史類比——2017 年行業由 RNN 轉向 Transformer，原因係 RNN 必須串行處理 token、訓練太慢；Transformer 允許並行，先撐得起 LLM 嘅成功。但佢指出：推理階段嘅自回歸模型，仍然係串行嘅。呢種負載「極度 memory-bound」——大部分時間花喺把權重喺內存層級之間搬嚟搬去，算術運算好少。而擴散模型喺推理時嘅負載，同訓練時幾乎一樣（多 token 並行），正好係 GPU 最擅長嘅計算密集模式。於是佢把結論直接扣喺 Sutton 嘅「苦澀教訓」上：「更並行嘅方案，最終一定會贏。」 推理時代嘅「Transformer 時刻」，就係擴散模型。
一、人物：由「唔熱門嘅領域」到擴散模型之父之一

Sarah Guo 開場嘅介紹好準：Ermon 係「生成模型領域一個極廣嘅工作體系」，被稱為「擴散模型之父之一（one of the fathers of diffusion）」。佢 2014 年加入斯坦福做助理教授，一開始就做生成模型——「當時呢個研究領域一啲都唔熱門」。佢回憶嗰個年代嘅標準低到難以置信：

「我哋仲係喺度砌一啲喺 MNIST 上面嘅小型生成模型，能生成嗰啲帶顆粒感嘅數字圖像，已經算係一個大成功。當時連喺呢個題目上發表論文都好難——你要 justify 訓練生成模型係一種『由無標籤數據學特徵』嘅方法，因為監督學習先係當時人人關注嘅嘢。」 — Stefano Ermon（談 2014 年嘅起點）

佢當時嘅動力唔係 LLM，而係世界模型（world model）嘅直覺：「我有一個世界模型，我就可以想像如果我企起身行出門口會發生咩事——呢種世界模型對做決策、對 model predictive control 好重要。」佢當時以為呢個問題「會佔用我成個職業生涯」，結果「我錯得好緊要，事情發展得快好多」。

研究路徑清晰可查：自回歸模型（好慢、好模糊）→ VAE → GAN 當道。但 GAN 唔穩定、難復現，於係 2019 年佢同博士生提出 score-based 生成模型——即今日擴散模型嘅底層。「訓練一個神經網絡去去噪圖像；如果你能去噪，你就真係理解咗圖像嘅結構，咁就可以基於呢啲去噪器構建一個生成程序。」呢個技術後來橫掃圖像、視頻、音樂、蛋白質。除此之外，佢仲係 FlashAttention 嘅共同指導、DPO（直接偏好優化）嘅發源實驗室——兩者後來都被工業界廣泛採用。

二、兩種範式：連續世界已經分出勝負，離散世界未定

Ermon 把當下嘅世界狀態描述成「一個對研究者而言好有趣嘅狀態」——生成模型有兩條路：

  • 自回歸（autoregressive）：預測下一個 token / 下一個像素，然後從左到右逐個生成。
  • 擴散（diffusion）：coarse-to-fine 嘅迭代去噪生成——由純噪聲開始，逐次精煉，最後得到一致嘅結果。

分野係：連續模態（圖像、視頻、音樂、蛋白質），擴散已經係主導；離散模態（文本、代碼），所有大實驗室都押自回歸。而當行業走向「一個模型通吃所有模態」嘅未來，Ermon 講得非常坦白：

「當我哋走向更多模態、走向『一個模型可以處理所有模態、知道世間一切』嘅諗法時——究竟嗰個架構會係自回歸定擴散？冇人知道。陪審團仲喺度（the jury is still out）。」 — Stefano Ermon（談架構之爭）

Inception 選擇押擴散，理由唔係「擴散更聰明」，而係佢相信最終決定勝負嘅係推理時擴展（inference-time scaling），而擴散喺推理時有結構性優勢。

三、核心論證：RNN→Transformer 嘅歷史，將喺推理時重演

呢個係全集最有份量嘅一段，值得完整復述。Ermon 嘅論證鏈係層層遞進：

第一步，回顧歷史。2017 年人們由 RNN 轉向 Transformer，原因好清楚——RNN 必須串行處理 token，一個接一個，訓練太慢。於是行業造出一個可以同時並行處理好多 token 嘅架構，佢喺訓練上擴展得更好，先撐得起 LLM 嘅成功。

第二步，指出盲點。但如果你睇推理而唔係訓練——自回歸模型仍然係串行嘅：

「你唔可能生成第 10 個 token，直到你已經生成咗佢前面所有嘢。呢種負載同 GPU 完全唔夾——佢極度 memory-bound：你大部分時間都花喺把權重喺內存層級之間搬嚟搬去，做嘅算術運算好少。呢個係自回歸模型嘅根本問題。」 — Stefano Ermon（談推理時嘅串行瓶頸）

第三步，提出對應物。「如果 RNN→Transformer 係訓練時代嘅對應，咁推理時代嘅對應物就係擴散模型」——因為擴散模型天生就係為「推理時同時處理多 token」而設計，佢嘅推理負載幾乎同訓練負載一樣，正好映射到 GPU 最擅長嘅計算密集模式。

第四步，扣上經濟學。佢把呢個架構選擇連到「每一瓦智能、每一美元智能（intelligence per watt / per dollar）」——經濟學由效率主導。而且推理唔止係推理：

  • 推理模型靠測試時計算擴展（test-time compute scaling）；
  • RL 後訓練嘅大量瓶頸喺生成 rollout（讓模型探索、打分軌跡、再更新）。

所以「推理擴展得更好」→「RL 後訓練都擴展得更好」。呢條邏輯鏈把「架構選擇」同「後訓練效率」直接扣埋一齊。最後佢亮出全集嘅金句：

「苦澀教訓係——更並行嘅方案，就係最終一定會贏嗰個。」 — Stefano Ermon（談為何押注擴散架構）
四、點樣敲開「離散」呢粒堅果

擴散天生貼合連續數據——「兩個像素顏色之間可以插值，中間嘅嘢都仲講得通」。但文本唔同：

「如果你攞兩個詞，「好」同「壞」中間究竟係咩？兩個唔同詞嘅意思之間冇明確嘅嘢。呢個空間冇真正嘅幾何結構。為連續空間開發嘅數學，唔會自動翻譯到離散空間。」 — Stefano Ermon（談離散空間嘅困難）

Sarah 追問：咁喺 embedding 空間做擴散得唔得？Ermon 話呢條路試過，但唔成功，原因好務實：「你最終要解碼返做文本。你唔可以畀 embedding 用戶或者客戶。而擴散模型最終會犯一些小錯誤，可能唔會落喺字典入面任何一個詞上面。」 呢個解碼問題令 latent-space 擴散好難做得好。

真正打破僵局嘅係 2024 年嘅一篇論文。Ermon 特別強調呢個實驗有幾乾淨——「幾乎好似一個 A/B test，唔係一個好唔公平嘅比較」：

2024 年突破 用完全相同嘅 Transformer 架構、完全相同嘅參數量、完全相同嘅數據，一邊按自回歸訓練（預測下一個 token），另一邊當擴散模型訓練。喺 GPT-2 規模（少於 10 億參數）上，擴散模型首次匹配自回歸模型嘅困惑度（perplexity）——即識別出同樣多嘅數據結構——而文本生成速度快約 10×（需要嘅神經網絡評估次數約少 10 倍）。差異「完全來自建模範式本身」。

呢個結果係 Inception 成立嘅直接依據。Ermon 講：「我好想睇吓如果 scale up、如果訓練更大嘅模型會點。」於係佢成立咗 Inception。

五、Mercury：由研究原型走到生產服務

現時嘅成果：

「我哋已經訓練出質量上可以同前沿實驗室嘅『速度優化版』模型（haiku、flash、mini／nano）媲美嘅擴散 LLM，同時明顯更快。我哋由純研究原型，走到今日真係喺生產環境服務緊。」 — Stefano Ermon（談 Mercury）

但呢度有個關鍵嘅「門檻即護城河」細節：擴散 LLM 跑唔到 vLLM 或者 SGLang 上面，必須自建 serving engine。

「你冇 serving engine，就真係服務唔到呢啲模型。所以我哋由一開始就迫自己端到端部署，學識點 serve 呢啲模型、點砌佢哋需要嘅軟件——呢啲本身又變成 IP。就算你訓練咗一個擴散 LLM，如果冇 serving engine，你仍然卡住。」 — Stefano Ermon（談自建棧）

案例：OpenCall 由 Cerebras 定製芯片「切返」Nvidia GPU

呢個係全集最落地嘅一個案例，Sarah 亦話係佢最想問嘅部分。語音 Agent 嘅管線係 ASR + 推理 LLM（做工具調用、決定講咩）+ TTS，對速度要求極高。OpenCall 原本用 Cerebras 定製芯片換取所需嘅速度。改用 Inception 嘅 Mercury 之後：

「佢哋切去我哋嘅擴散 LLM，因為佢哋可以得到同『自回歸模型跑喺定製硬件上』一樣嘅速度——只要個擴散 LLM 係為並行而建、喺軟件層加速，你就可以喺 Nvidia GPU 上拿到同樣速度。咁就意味住更好嘅可得性（GPU 雖然稀缺，但都比定製芯片多）、更低嘅成本、更高嘅質量。」 — Stefano Ermon（談 OpenCall 案例）

Ermon 強調軟件加速同硬件加速係相乘（multiplicative）而唔係替代關係：「呢個係最令人興奮嘅一點——你由軟件拿到嘅增益，同你由硬件拿到嘅增益係相乘嘅。」NVIDIA 投資 Inception 亦係同一邏輯：芯片設計要幾年，NVIDIA 需要提前理解「替代性負載」（未來 LLM 嘅算力模式），先可以將下一代芯片優化到位。

六、「一旦用過快嘅，就返唔到轉頭」——速度喺邊度贏

Sarah 問到 2026 年 9 月、速度喺邊度已經夠重要。Ermon 嘅答案分兩層：

「一般嚟講，人人都想要速度——如果可以畀我同樣質量但更快，人們總會揀快嗰個。你睇前沿實驗室嘅『fast 版』模型，人們願意畀更多錢去用更快嘅模型。一旦你習慣咗快模型，就好難返轉頭。佢就好似寬帶。」 — Stefano Ermon（談速度為何係剛需）

具體到市場規模，佢用咗 OpenRouter 嘅任務分類法（研究、對話、編程、軟件工程、日誌處理——一個相當清晰嘅硬分類）做估算：

20–30% 按 OpenRouter 任務分類估算，大約 20–30% 嘅工作負載「延遲真係好重要」。作為下限，呢啲係擴散模型可以觸及嘅市場——「喺畀定嘅延遲預算內，佢哋會畀到最高嘅質量」。
七、三個被低估嘅產品線：數據效率、可控性、兼容 API

Sarah 問：五年——唔，兩年後，擴散同傳統模型嘅工作負載會點分？Ermon 先謙虛：「我哋仲未到前沿水平嘅智能，好多工作負載真係需要前沿智能。」然後指出速度只係「楔子」，真正未知嘅係擴散喺其他地方嘅能力。

① 數據效率

學術文獻顯示擴散模型更省數據——因為去噪訓練等於對同一份數據做咗隱式數據增強（同一張圖被好多個加噪視角增強過）：「所以當數據成為瓶頸、要掂啲少數據任務嘅時候，呢點就會變得更加有趣。」

② 可控性——一條自回歸根本冇嘅接口

呢一段係 Sarah 最尖銳嘅提問（語音 Agent 之所以要「中間放個 LLM」，正因為可控性／對齊），Ermon 嘅回答好有信息量：

「自回歸模型你必須生成完整個對象，先知道佢滿唔滿足某個約束。但擴散係 coarse-to-fine——由最早階段就知『呢個係唔係我想要嘅嘢』，你可以用外部獎勵函數或者一組約束，實時牽引生成方向。學術文獻有大量證據顯示擴散更容易控制，而且存在啲自回歸根本冇嘅操控方式。」 — Stefano Ermon（談可控性）

佢舉例：生成分子、你關心溶解度——自回歸要生成完整個分子先可以用獎勵函數打分；擴散就可以喺生成途中就引導。「呢個可能係一個自回歸根本提供唔到嘅新接口，我哋一直喺度諗圍繞呢啲新能力應該砌咩產品體驗。」

③ 兼容 API——「text in, text out」

落地層面，Mercury 保持 OpenAI 兼容 API，擅長指令遵循同結構化輸出（例如 JSON）。呢點對 OpenCall 嘅遷移至關重要：「接口一樣，你就可以直接复用你原本嘅技術棧。」

八、David vs Goliath：護城河唔止係模型

Sarah 提出一個結構性擔憂（而且 Ermon 坦承係「我哋 top of mind 嘅嘢」）：今日好難投資新架構，因為如果架構或者方法有咩突破，擁有算力嘅大玩家可以輕易吸收。Ermon 嘅回應係佢整個商業策略嘅核心：

  • IP／技術訣竅：模型本身嘅想法同秘密。
  • 自建 serving engine 同 kernel：「就算你訓練咗擴散 LLM，冇 serving engine 你都仲係卡住用唔到。」呢啲軟件本身就係 IP。
  • 真實客戶反饋閉環：「我哋同真實客戶合作、攞反饋，知道咩得咩唔得，有時由佢哋收數據，基於佢哋睇到嘅嘢建 eval。」呢啲「比較難複製」。

呢個亦係佢哋選擇唔完全開源嘅原因。佢老實講出代價：「社區貢獻嘅機會少咗、採用更難、on-prem 部署更困難——兩個選擇各有優劣。」

九、對 RSI 嘅務實態度，同學術嘅角色

Sarah 提到「用模型做遞歸自我改進（RSI）」呢個令研究朋友又興奮又絕望嘅話題。Ermon 嘅回答好克制：

「我哋當然大量用模型，佢好大程度加速咗我哋迭代嘅速度……但至少現在，人類嘅創造力仍然超重要——提出啱嘅想法、剪枝空間、識別更有希望嘅方向。或者我哋冇其他實驗室咁嘅模型訪問權，但（起碼而家）我唔覺得已經到咗 AI 自我改進、人類冇事可做嘅階段。」 — Stefano Ermon（談 RSI）

組織層面：Inception 約 50 人、公司約 2 年歷史，分一個產品／平台團隊（服務當前最優模型、支援客戶）同一個模型團隊（訓練、RL、推理研究）。Sarah 驚訝 50 人唔算多，Ermon 嘅回應直指本質：

「公司細，但每個人都好有才華、好勤力，我哋可以用 agent 令自己高效好多。而好多時候，我覺得瓶頸更加係算力，而唔係人。」 — Stefano Ermon（談 50 人團隊）

最後，Sarah 問佢喺 2024 年結果出嚟之前，點樣對方向有信心。Ermon 列舉咗一批「完全誕生於學術」嘅成果——早期擴散（→ Stable Diffusion／Midjourney）、FlashAttention、DPO：

「學術嘅一個好處係，佢容許你落啲逆共識嘅賭注（contrarian bets）。你有出色嘅學生，大家唔怕落注。」 — Stefano Ermon（談學術界嘅角色）
我嘅萃取：呢集真正講緊嘅三件事
  1. 呢個唔係「擴散 vs 自回歸」嘅口水戰，而係一條可證偽嘅工程命題。Ermon 嘅論證有清晰嘅結構——(a) 推理係 memory-bound、(b) 擴散推理負載 ≈ 訓練負載、係 compute-bound、(c) GPU 偏好 compute-bound、(d) 所以擴散喺推理時更有效率。呢條鏈每一環都可被測量。佢押嘅係「苦澀教訓」——能更好利用算力嘅方案長期會贏。可觀察嘅驗證點：Mercury 客戶會唔會持續由定製硅／大廠快模型遷過嚟，以及擴散 LLM 喺長程 agentic 任務上能唔能夠站住。
  2. 「呢個架構之爭，其實係一個『推理經濟學』之爭」。Sarah 嘅框架點係全集的隱藏主線：過去效率係工業研究嘅「二階變量」，而家喺算力／供給約束下，「點樣把手上嘅算力喺訓練同最有價值嘅用例之間分配」已經係 AI 公司嘅頭號決策。Ermon 把呢條主線具體化成一句話：軟件層並行加速 × 硬件加速 = 複利。呢個判斷對任何要為推理付帳嘅組織都有直接含義。
