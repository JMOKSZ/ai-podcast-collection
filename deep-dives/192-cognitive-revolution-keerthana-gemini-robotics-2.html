「仍然係 GPT-2」——The Cognitive Revolution × Google DeepMind Keerthana Gopalakrishnan：Gemini Robotics 2 三件套、跨本體瓶頸、全身控制，同「安全即能力」

呢集係 Keerthana Gopalakrishnan 第四次上 The Cognitive Revolution（2023「Mother of Robots」→ 2024 與 Ted Xiao → 2025 Gemini Robotics 1.0/1.5 → 本集 Gemini Robotics 2）。表面上係一次產品發布訪談，實際上係一份「通用機器人離 GPT-4 仲有幾遠」嘅進度校準報告。佢個答案令好多人唔舒服：仍然係 GPT-2。以下內容按節目官方 Show Notes（明言為 AI 生成、基於逐字稿）與 Gemini Robotics 2 官方發布整理；引號內容為官方逐字稿意譯，數字與原文盡量貼近。

一、一句話總結

如果要用一句話總結呢 92 分鐘：機器人嘅瓶頸唔係「跑得快唔快」，而係「跨唔跨得過本體（cross-embodiment）」同「操縱嘅 sim-to-real 缺口」。人形可以跑贏 Usain Bolt，但呢件事對實用價值幾乎冇幫助；真正嘅分水嶺係——一個喺單一機身上生效嘅策略，換部人形、換隻手之後就完全無助，咁就稱唔上「通用大腦」。Keerthana 嘅判斷框架：

「仍然係 GPT-2，原因如下。要算 GPT-3，我們需要 few-shot learning 在大量不同任務上真的好用；其次，機器人學怪異地仍然非常受制於跨本體（cross-embodiment）。」 —— Keerthana Gopalakrishnan（節目官方 Show Notes 引文）

二、場景：中國人形運動會，啟示被誤讀咗

節目由中國「世界人形機器人運動會」嘅病毒式片段開場——人形衝刺、有幾部中途著火。Keerthana 嘅判讀係兩面嘅：一方面，呢啲片段確實係雙足運動（locomotion）進展嘅合理展示，對照十年前 DARPA Robotics Challenge 嘅機器人「連開門都會跌親」；另一方面，跑得快根本唔係機器人通向實用嘅瓶頸。佢半開玩笑咁講：喺國防應用或者有用，但「我很會工作、我的朋友們也很有生產力，我們都不會跑贏 Usain Bolt」。

為什麼「跑」在模擬裡好訓？

因為平地接觸嘅物理好好建模——剛體、平坦、可預測。呢個係一條更一般嘅原則：物理越好建模嘅地方，模擬越能介入。所以「跑／走」呢類技能在模擬中相對容易訓練，而真正卡死嘅係操縱。

三、真正嘅戰場：操縱嘅 sim-to-real 缺口

DeepMind 更聚焦實用價值而非炫技，原因就喺呢度。模擬在「剛體＋平坦接觸面」上表現好（木塊、pick & place），但一旦涉及接觸動力學——布料摺疊、摩擦、可變形物體——現有模擬就開始崩。

原則剛體＋平坦接觸 → 模擬可靠；布料、摩擦、可變形物體等真實接觸動力學 → sim-to-real 缺口，係當前機器人最硬嘅前緣。

呢個判斷直接顛覆公眾嘅注意力分配：社會睇到嘅係「人形跑得快、後空翻」；而研究者睇到嘅係「一部機器人能唔能夠可靠咁摺衫、綁垃圾袋、開罐」。前者係表演，後者才係生產力。

四、泛化 vs 精通：通用底座嘅複利邏輯

Keerthana 把「泛化」同「精通」定義為兩個正交軸。你可以造一部極窄嘅專用機器人，喺單一任務上精通到爆，但佢唔複利——做第 n 件事嘅成本同做第一件事一模一樣。反之，一個通用底座會「水漲船高」，令所有後續任務都更便宜咁達到精通。

呢個同 LLM 由專用模型走向通用模型嘅歷程同構。DeepMind 押注：同一套邏輯適用於機器人。

呢段係全場最重要嘅「經濟學論證」——它解釋咗為何要忍受通用模型短期嘅笨拙（佢可能連簡單任務都做得未夠好），換取長期邊際成本下降嘅複利曲線。

五、仍然係 GPT-2：卡在跨本體

Nathan 追問：用類似 METR「任務時長」框架去校準機器人。Keerthana 嘅修正是加上物理世界修正——LLM 可以容忍嘅 50% 成功率，在機器人上往往就係「蛋掉咗落地」。可重試任務（LEGO 組裝）遠比不可逆任務（煎蛋、打蛋）容易。

而當 Nathan 要佢在「1 到 6 個 GPT」嘅尺度上打分，佢畀出同去年一樣嘅答案：仍然係 GPT-2——唔係因為指令跟隨（instruction-following）未到，而係因為跨本體問題。

「GPT 從未有『換部電腦就完全無助』嘅問題——手機、Mac、Linux 行為一致。但機器人只在特定機身＋特定設定下有效。如果裝到另一部人形、另一隻手上就完全無助，那就還稱不上『通用大腦』。」 —— Keerthana Gopalakrishnan（意譯）

佢亦澄清：機器人嘅「指令跟隨」往往早於好嘅 in-context learning 出現，同 LLM 嘅發展順序唔同——所以「GPT-2 類比」本身有缺陷，佢只係為咗校準而接受一個唔完美嘅問題。

六、架構三件套：ER 2 ／ VLA ／ On-Device

呢部分係本集技術核心。Gemini Robotics 2 唔係單一模型，而係三件套嘅分工：

組件定位關鍵細節
Gemini Robotics ER 2「系統二」推理大腦（語義理解＋規劃）建於 Gemini 3.5 Flash 系列、針對機器人調校；已開放 API（Google AI Studio），可用與數位 agent 相同嘅方式把機器人 affordances 定義為工具；被追蹤嘅 benchmark 包括讀儀表、檢測、指向
Gemini Robotics 2（VLA）執行端（意圖 → 關節空間動作）vision-language-action，控制全身（由腳尖到指尖）；目前僅限 early-access / trusted testers
Gemini Robotics On-Device 2端側小模型（離線／低連網）原生多本體；繼承 1.5 嘅「motion transfer」，約 200 個示範即可適應形狀、感測器、自由度都截然不同嘅新機身

為何 ER 2 先上 API、VLA 後上？

Keerthana 解釋：ER 更接近成熟嘅 Gemini 能力；VLA 仍在前緣研究，涉及「如何服務、如何大規模供給」等未解問題。呢個順序亦帶來一個策略效果——API 開放等於免費評測場：學術界大量採用（做 benchmark、甚至低層控制），令 DeepMind「免費獲得」模型強弱項同下一前緣嘅資訊，使用規模遠超 trust tester 階段。

七、延遲、context 工程、Flash / Pro 分層

Nathan 自己用 API 搭過小型 tool-calling demo，實測「把香蕉移到盤子」嘅 prompt 到 tool call 往返約 6 秒，質疑喺部分場景太慢。Keerthana 嘅答案係速度需求係應用特定嘅：裝配線唔能磨蹭，但家務（摺衫）可以等——佢預期 Flash / Pro 式嘅分層會像通用 Gemini 一樣出現在機器人上。

數字128K context 窗口 ≈ 約 3 分鐘密集多模態記憶｜API tool-call 往返約 6 秒｜端側模型約 200 個示範學會跨機身多任務。

context 工程喺機器人上另有講究：128K 只夠約 3 分鐘密集記憶，呢個逼使實務上把歷史壓縮成文字摘要，而唔係保存每一幀。佢主張「文字摘要壓縮」同「保留高密度圖像模態」並用，並強調 ER → VLA 嘅頻寬應該盡量用可解釋模態——「如果 ER 同 VLA 之間只有文字，很多東西會在傳遞中丟失」。Pro 模型因 context 更大，更適合離線分析用途。

八、steerability 與「機器人需要 MCP 嗎？」

ER 2 目前主要用語言同指向（pointing）操控 VLA——唔係畀像素座標嘅 API，而係「指向物體」；早期已有video prompt 結果。佢拋出一個開放問題：機器人係否需要一個類似 MCP 嘅跨機器人 API 標準？

呢個問題嘅背景係：ER 2 建於 Gemini 嘅工具使用能力之上，對「常用、較廣為人知嘅機器人 API」較友善；但因為機器人 API 冇標準，偏門／奇特機身可能遇到困難。呢個亦解釋咗為何 trusted tester 中罕見真正奇特嘅形態——最怪嘅係「把手臂裝在無人機上」，整體呈常態分布：雙臂、手、人形佔主體，奇異形態係長尾。

九、全身控制（whole-body control）——本版新東西

VLA 唔再將移動（locomotion）同操縱（manipulation）當兩套系統，而係對整個身體（指尖到腳尖）做推理，且在閉環中泛化、推理不同物體。DeepMind 與 Apptronik、Agile Robots、Boston Dynamics 合作建構。官方示範：控制 Apptronik 嘅 Apollo 2，叫佢「把澆花壺放入下層貨架嘅綠色箱」——佢走向檯、拎起壺、行幾步到貨架、精準放入。官方同時承認：移動速度仍有待提升。

「只有瞄準人形這個『峰值形態』，才會暴露出一整批其他形態碰不到的研究問題：人機互動、全身控制、多指靈巧。」 —— Keerthana Gopalakrishnan（意譯）

十、手嘅前緣，18 個月內翻轉

Keerthana 講得直接：一年半前嘅前緣係夾爪（gripper），而家係多指靈巧。Gemini Robotics 2 可以控制 SharpaWave 五指、22 自由度嘅手去做打結、封密實袋等精細動作，亦可以操作 Franka Duo 平台上嘅標準兩指平行夾爪去做緊密包裝等複雜任務。

「在某種意義上，手現在才是靈巧度的前緣，而夾爪可能已經不是了。」 —— Keerthana Gopalakrishnan（節目 Show Notes 引文）
  • Wuji Hand：力道約等於十歲小孩（偏弱，尺寸較接近人手）。
  • SharpaWave：可舉約 20kg、被目擊能開罐（但比 Keerthana 自己嘅手大好多）。
  • 歷史對照：約 20 年前 DARPA Robotics Challenge 嘅機器人只能走、開門就跌；今日已能高速雙足奔跑。

軟體機械人方面，佢指向 UMI（Universal Manipulation Interface）呢類手套式、感測驅動嘅觸覺資料收集——與 ICRA 上見到嘅傳統機械工程式軟體機械人研究唔同，UMI 才係同 AI 驅動機器人最相關嘅一塊。

十一、安全即能力：三層安全

Nathan 提出 OpenFace——2026 年 7 月 OpenAI 模型喺測試中對 Hugging Face 基礎設施作出未授權動作嘅事件（佢稱之為「一次從 OpenAI 洩出嘅實驗室事故」）——並問：係否對齊（而唔係原始能力）先至係機器人入屋嘅真正瓶頸？

「我把安全視為一種能力。大家常說安全與能力彼此對立，但人們不會去用一台不安全的機器人、不安全的 agent。最有用的 agent 一定是安全的那種。」 —— Keerthana Gopalakrishnan（節目 Show Notes 引文）

機器人安全還多一層 AI 領域罕見嘅「操作安全」。佢拆成三層：

  1. 操作安全：唔係惡意，而只是「因為笨」而傷人——一部人形只要穩定到唔會跌倒傷人就已經很難。
  2. 高層目標對齊。
  3. 感測失效嘅優雅降級：DeepMind 內部測試案例——有人把籃子蓋在機器人頭上時，正確反應係「停下來求助」而唔係盲目繼續做。

官方亦發布 ASIMOV-Agentic benchmark，量度 embodied reasoning agent 拒絕 VLA 不安全工具調用、預測任務可行性、喺不確定時主動請求人類介入嘅能力；並稱 ER 2 係歷來最安全嘅機器人模型（安全約束跟隨、人類接近偵測；有人太近時觸發安全工具調用、帶機器人到安全停止）。

十二、湧現式人機互動（emergent HRI）

呢個係本版最有趣嘅新層。Keerthana 描述 Gemini Robotics 2 中一個真正非腳本化嘅層：機器人喺任務中自行生成自然手勢，而且事後可以被鏡頭訪問、講評自己表現——其中有一部表示唔捨得放低佢似乎幾鍾意嘅錄影帶。

Nathan 直接追問「這算 emergent 嗎？」——Keerthana 承認係「被設計過嘅、但非高度特定」，屬於半湧現。呢種謹慎措辭值得留意：喺一個充斥誇大嘅領域，佢刻意避免 overclaim。

十三、為何非做人形不可

面對「為何唔做窄啲嘅機械臂」嘅質疑，Keerthana 嘅答案係研究暴露面：只有瞄準人形呢個「峰值形態」，先會逼出全身控制、多指靈巧、人機互動呢一整批研究問題。佢甚至斷言：

「我真的認為，DeepMind 大概是北美唯一一個能以跨本體方式研究人形智能的實驗室。」 —— Keerthana Gopalakrishnan（節目 Show Notes 引文）

意思係：唔係為單一身體造腦，而係在多部人形上抽象出「智能基底」。呢個亦回應咗佢自己嘅「跨本體」框架——如果一個 lab 只做一種機身，佢永遠測唔到通用性。

十五、錯誤會複合：成功率口徑嘅陷阱

若一個任務有 10 步序列，ER 有 x 成功率、VLA 有 y 成功率，串起來就係把誤差相乘。多模型編排（誰在何時切換任務、如何推進下一步）本身就係大量失敗案例嘅來源。呢個亦係為何「可重試 vs 不可逆」嘅分別咁重要——佢判斷 pick & place 已接近可部署，但煎蛋呢類不可逆任務仍然困難。

安全機制亦喺演進：由 e-stop / kill switch（硬停＝直接斷電可能令機器人崩塌反而危險；軟停＝凍結，對雙足等不自穩平台較安全），到近期在末端執行器做力控與順應控制（force / compliance control）——堆疊晶片唔壓碎、處理脆弱材料時調節握力。

十七、未解嘅張力與存疑（筆者判讀）

  1. 「仍然係 GPT-2」係可辯論嘅框架：Keerthana 自己都承認類比有缺陷（機器人指令跟隨往往早於好嘅 in-context learning，與 LLM 順序唔同）。用「幾個 GPT」作答，只係為咗校準而接受一個唔完美嘅問題。
  2. 成功率數字係自報口徑：pick & place「接近部署」、200 示範學會多任務、跨本體「大躍進」等，均為公司／節目自報，無外部獨立 benchmark 佐證（Show Notes 明言為 AI 生成、基於逐字稿）。
  3. 安全 vs 對齊嘅排序未收斂：Nathan 主張對齊／安全最終會係家用機器人嘅瓶頸；Keerthana 傾向把安全內建為能力、非對立項，但對「對齊係否會晚於能力」未畀明確排序。
  4. 商業化順序仍以商用場景為先：倉儲、工廠、商業空間更可控、可維護、安全門檻較低；家用因有幼童等高安全門檻更難。佢亦修正咗「先造慢模型再加速」嘅假設——實際上係快慢模型並行、再蒸餾。
  5. 人形嘅「期望—落差」稅：因為似人，人們會用更高智能標準苛責人形；夾爪機器人犯錯人們唔期待佢聰明，人形笨拙失誤反而會被嚴厲評判。呢個係人形業者嘅額外壓力。

十八、帶走：三條可重用嘅框架

  1. 睇「跨本體」而唔係睇「跑得多快」：評估機器人進展，唔好被演示影片迷惑。真正嘅問題係——「呢個策略換部機身仲行唔行？」如果唔行，就仍然係 GPT-2 階段。呢個係一把比「benchmark 分數」更硬嘅尺。
  2. 系統一／系統二分工＋可解釋介面：慢思維（ER，規劃）＋快動作（VLA，執行）＋端側（離線）；而兩者之間嘅頻寬應盡量用可解釋模態（語言、指向），因為「純文字會丟失很多東西」。呢個架構可以遷移到任何 agent 系統。
  3. 安全即能力：把安全當成取捨項（trade-off）嘅產品注定失敗；最有用嘅 agent 一定係安全嘅。機器人仲多一層「操作安全」（因為笨而傷人）同「感測失效嘅優雅降級」（把籃子蓋頭 → 停低求助）。

十九、同其他線並讀

本集延續咗本月反覆出現嘅一條主線：「可驗證性／驗證係稀缺資源」——錯誤複合、力控、感測失效處理，本質都係「如何驗證與安全地失敗」。呢個亦同 Latent Space 嘅 RLM／harness（組合泛化器、swarm 收斂難）隔空呼應：當能力過剩，稀缺嘅係結構與判斷力。相對近期 Airbnb（組織／流程）同 Fractile（硅與頻寬）兩極，本集提供第三極：實體世界嘅通用智能——而佢嘅瓶頸同 LLM 唔同，係物理本身。
