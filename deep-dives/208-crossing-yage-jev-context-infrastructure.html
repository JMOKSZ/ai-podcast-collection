二、Jev 為何在「此刻」爆發

① 本質：GPT + JSON Mode 嘅極致化

節目把 Jev 定性為「GPT + JSON Mode」嘅極致化，而唔係又一個聊天模型。佢唔係生成文本，而係輸入一個 state（狀態數據）＋ 一組類型化問題，直接輸出帶校準概率嘅結構化決策；軟件拿到就用。呢個呼應 Kahneman 嘅 System 1／System 2 隱喻——TypeSafe 賣嘅，係快、類型化、可直接行動嘅「系統一」決策層。

② 爆火嘅三個條件

節目把 Jev 嘅走紅歸因於「agent 成本結構 ＋ 開發者痛點 ＋ 時機」三者疊加——當 agent 需要對海量微小步驟逐一分類／路由／打分時，用前沿 LLM 為每一步寫一段文字，帳單會爆炸；而 Jev 正好卡喺「決策便宜、行動很貴」嗰一層。（同一句亦見於 42 章經 9-27 嗰期標題，屬跨節目共振。）

③ Agent 裡嘅「分類器」其實無所不在

鴨哥觀察：真正運轉起來嘅 agent，內部充滿各種判斷節點——工單分流、工具調用係咪越權、輸出應唔應該放行、檢索結果夠唔夠。呢啲過去被埋在 prompt 裡、靠大模型逐字「想」出嚟嘅判斷，本質上係分類問題，正是 Jev 這類模型要接管嘅。

二手 · 未經獨立核實 TypeSafe AI 於 2026-09-15 推出 Jev，36 小時內約 14 萬名候補使用者取得資格，初期需求一度令 API 無法正常服務；Cloudflare、LangChain、Langfuse 等工具迅速加入支援。有中文財經媒體（虎嗅，10-06）稱 TypeSafe AI 因 Jev 而「十天估值飆漲約 50 倍」；Latent Space 嘅 AINews（10-10）更給出 >$100M ARR、$7.5B 估值（上線約三週）嘅口徑。競品方面：Jev 爆火後，OpenAI 發布 Decisions API 正面回應，社交平台上出現「Jev Is Dead」嘅爭論。
三、Context 才是真正嘅基礎設施（全集理論核心）

① 「給 AI 裝上耳朵同眼睛」嘅一年期實驗

鴨哥持續一年採集自己嘅客觀行為數據：錄音轉寫、會議記錄、微信對話導出、同 AI 嘅每一次對話同糾正、甚至發嬲——佢嘅講法係「這些是我們在真實決策場景下展現出來的判斷邏輯」。關鍵觀察：人太接近自己嘅數據，很難自己提取模式，所以需要一個旁觀者（AI）去讀。所有數據放喺同一個資料夾，令 AI 開箱即可對任何專案做 cross-reference——呢個就係 context density 嘅基礎。

② 控制變量實驗：checklist vs insight

鴨哥同一位朋友「老王」各自叫自己嘅 agent 就同一篇 OpenAI Harness Engineering 博文做深度調研，條件刻意對齊：同檔次嘅 LLM（Claude Opus 4.6 vs GPT-5.4）、同一個調研 skill、同一個搜索工具 Tavily、同一個 agentic 後端 OpenCode、甚至同樣嘅 prompt。唯一嘅唔同，係兩個 agent 背後嘅 context：鴨哥嘅接入了過去一年積累嘅判斷框架，老王嘅無。

  • 老王嘅報告（行動建議部分）：「先做知識底座，再做更強 agent。給倉庫建立清晰的 AGENTS.md 目錄索引；把產品規則、架構規則、執行計畫、質量標準寫進 repo；用 CI 檢查文檔 freshness 同 cross-link completeness。」——正確、安全，換邊個嚟問都得到差不多嘅嘢。
  • 鴨哥嘅報告（同一話題）：「完美主義是吞吐量的敵人。OpenAI 採用最小阻塞合併、後續修復的策略。Cursor 發現要求 100% 正確性會導致系統停滯，接受小而穩定的錯誤率反而更高效。兩者都接受了『糾錯比等待便宜』的權衡。」——跨兩個獨立來源提煉出有立場嘅判斷，並歸納出底層權衡。

鴨哥嘅總結好狠：一個係搬運工，一個係分析師。而佢由此推出全集最重要嘅一句——變量只有一個，所以結論好顯然。

「（在模型智能跨过一道坎以后）决定产出性质的是 context，而不是模型的智能。」 鴨哥，〈為什麼 AI 只會說正確的廢話〉（yage.ai）——本集 Part 3 嘅方法論底稿

③ LLM 嘅 Consensus 天花板

鴨哥把「AI 講正確嘅廢話」歸因於訓練機制：LLM 訓練本質係 next token prediction，每一步輸出概率最高嘅 token，而概率最高意味最多人認同，即 consensus（共識）；RLHF 再加一層——安全對齊專門懲罰有爭議、帶強烈立場嘅輸出，鼓勵平衡、全面、冇明顯偏向嘅答案。兩層機制疊加，默認行為就係回歸均值。

「Deep Research 是一個非常有誤導性的名字……它做的事是自動化的高頻搜索、多文檔綜合、擴大信息覆蓋面。充其量是 Wide Research。」 鴨哥，〈為什麼 AI 只會說正確的廢話〉

佢區分兩種唔對稱：Deep Research 解決嘅係信息不對稱（你以前唔知，而家知），但真正嘅深度來自另一條軸——認知不對稱。面對同一份行業報告，一個二十年老兵同一個新手看到嘅嘢完全唔同：老兵有一套經多年試錯沉澱嘅認知系統，知道邊啲數據係噪音、邊啲異常值預示趨勢；新手冇呢個濾鏡，就算拿到十倍厚嘅報告都做唔到同等質量嘅決策。

「AI 可以把一個小白提升到大眾平均水平，因為它的訓練數據就是大眾平均水平的壓縮。但對於已經在平均水平之上的人，AI 的 consensus 輸出對他的判斷幾乎沒有增量。」 鴨哥，〈為什麼 AI 只會說正確的廢話〉

④ AI 由 CPU Bound 走向 Memory Bound

面對「正確嘅廢話」，大家嘅直覺係去優化模型：換更好更貴嘅模型、改更複雜嘅 prompt、加更完備嘅工具，Multi-Agent、Harness 全上——但呢啲都係喺同一個維度（模型智能）上加碼。開頭嘅實驗已經給出答案：兩邊模型智能幾乎一樣，工具一樣，prompt 一樣，唯一唔同嘅係 context。

呢個轉變喺計算機史上出現過：CPU 快到一定程度之後，繼續升級 CPU 就冇意義，主要提升都來自內存架構；LLM 而家到咗同樣嘅拐點。而呢個判斷係反直覺嘅——每次模型升級，智能就更便宜一點，你用嘅模型別人也能用；但你嘅 context 只屬於你，模型升級唔會令它貶值。所以：

持續投入喺一個不斷貶值嘅維度（模型智能）上，收益遞減；投入喺一個唔貶值嘅維度（個人 context）上，收益累積。

⑤ 為何刻意「本地優先」，唔搬上雲端

節目明言：系統刻意本地優先——呢啲數據係私人判斷嘅載體，本地保存既係隱私考量，亦令 AI 能喺同一資料夾內對任何專案做 cross-reference（context density 嘅前提）。至於微信聊天記錄：佢提供咗模型訓練資料裡唔存在、卻最能代表「你係邊個」嘅判斷痕跡——你如何權衡、如何取捨、咩嘢會令你發嬲。

六、技術詳情：Context Infrastructure 嘅實作拆解

鴨哥嘅系統開源為 github.com/grapeot/context-infrastructure（參考實現，內含實際使用嘅 44 條 axiom、核心 skill 檔、三層記憶系統代碼）。三要素如下：

① 大量積累（採集客觀行為，而非只寫 prompt）

起點係數據採集：錄音轉寫（Intake Skill）、會議記錄、微信對話導出（wechat_db_parser）、以及同 AI 嘅每次對話／糾正，全部落成本地檔案、放喺同一資料夾。相關公開 repo：Intake Skill（Apple Voice Memos → data/YYYYMMDD/ → MLX Qwen3 ASR 轉寫 → Codex 後處理，刻意做得「窄」：唔錄音、唔做說話人分離）、Semantic Search Skill（面向 agent 嘅本地語義搜索 CLI；單一 SQLite 元資料庫 + 追加式 float32 NumPy 段檔；支援任意 OpenAI 相容 embedding 端點，預設 text-embedding-3-small）、Health Quantification（iPhone HealthKit → Tailscale 網內 POST → Mac FastAPI:7996 → SQLite → CLI → AI agent）、Apple Photos Skill（本地優先 CLI，憑證只存本地 .env，明言「不要貼進 AI 會話、issue、log 或 commit」）。

② 分層提煉（三層蒸餾，以「穩定性」為篩選標準）

單一事件可能只係情境反應（冇睡好、資訊唔全、隨機選擇），不可靠；跨場景、跨時間反覆一致嘅，才係「你」。流程分三層：

層級角色做咩
L1 Observer每日掃描檔案變動，提取有意義嘅觀察，寫流水帳
L2 Reflector每週合併重複、清理過期、識別跨專案模式，分離信號同噪聲
L3 Axiom蒸餾從穩定模式蒸餾決策原則，只保留真正代表你嘅嘢（→ 44 條 axiom）

與 Mem0 等流行記憶系統嘅關鍵區別：後者蒸餾到「事實層」就停（「你偏好 TypeScript」「你住在上海」）；本系統繼續蒸到「判斷原則層」（「評估技術方案時你如何權衡可維護性同性能」）。事實告訴 AI 你係邊個，判斷原則告訴 AI 你點諗。

③ 按需加載（用 skill 當記憶層級）

全部塞入 context window 唔可行（有限，且無關資訊會稀釋信號）。解法係 skill 系統，類比 CPU 記憶體層級：L1 cache = AGENTS.md（根路由表）；L2 = skill 庫索引（告訴 AI 需要咩就往哪找）；L3 = 具體 skill 檔。按需加載、漸進披露。

④ 循環

三要素運行起來之後，知識產品開始湧現，而每個產品喺消費 context 嘅同時亦產生新 context：鴨哥 AI 手記（每日 AI 行業簡報）同領域調研報告（Superlinear Academy）都係喺呢個循環上運轉。

關鍵數字（節目／嘉賓公開口徑） 系統運行約一年，蒸餾出 44 條 axiom；repo 內含 43 條決策公理（展示層）＋ 39 份 skill Markdown；Superlinear Academy 社區 2 萬+ 成員、700+ 真實 AI 項目；Skill 目錄對外公佈為 81 個 Skills、62 個工具 Repo、19 份 Doc 與工作流（會員解鎖）。控制變量實驗：Claude Opus 4.6 vs GPT-5.4／同一 skill／Tavily／OpenCode／同一 prompt。
七、行業 insight：呢集真正嘅訊號
  • 「決策層」正變成一個獨立嘅產品品類。Jev 嘅爆發唔係因為它更會寫，而係因為它把 agent 裡大量微小、高頻、可類型化嘅判斷，從「用大模型逐字想」剝離出嚟，做成便宜、快、可直接消費嘅結構化輸出。當 agent 走到「每步都要判斷」嘅規模，成本結構必然催生呢一層——呢個就係 Jev 喺「此刻」而非一年前走紅嘅結構性原因。
  • 雲端電腦持久化係 agent 由「工具」變「員工」嘅分水嶺。Manus／Grok Bot／Muse 嘅同一動作，本質係把狀態還畀 AI：有檔案系統、有背景任務、有跨會話記憶。冇持久化，就永遠係「每次重新開機嘅實習生」。
  • Context 係唯一唔貶值嘅資產。模型每次升級都把「智能」變成公共品，而你嘅判斷框架、審美、由失敗提煉嘅教訓只屬於你。呢個係全集最可遷移嘅判斷。
  • 「AI 變強，管理原則沒變」係畀從業者嘅定心丸。執行成本坍塌，但交付標準、驗收、授權邊界仍然係人嘅工作——呢個亦解釋咗為何「領域經驗 × 管理 AI」被列為 AI 時代最被獎勵嘅組合。
  • 自媒體／內容生產係被 agent 化最徹底嘅場景之一。「0 人公司」半年嘅訂閱／粉絲數據，係本輪最直接可驗證嘅「個體產能放大」樣本。

九、爭議點／存疑（必讀）
  • 「Jev 只係包裝精緻嘅 JSON 分類器」。技術圈最常見嘅吐槽：由數學輸出來睇，Jev 確實係「面對幾個選項返回概率分布」嘅分類器；其「快」亦非全然神秘——社區已有人用共享計算、並行解碼等老辦法復刻類似推理形狀。質疑者嘅核心係：缺乏真正護城河，先發優勢可能迅速被抹平。
  • 「Jev Is Dead」嘅爭論同巨頭入場。爆火後 OpenAI 即發布 Decisions API 正面回應——當決策層被證明係真需求，它就由「創新」變成「大模型廠商嘅一個功能」。支持方反駁：傳統分類器圍繞固定任務／固定標籤訓練，而 Jev 允許開發者喺運行時用自然語言定義問題同候選項，無須為每套標籤重新訓練。（研究者 Sebastian Raschka 亦認為呢種「面向動態標籤嘅零樣本泛化」係關鍵區別。）
  • 方法論上嘅潛在爭議：鴨哥嘅 context 系統把 AI 產出由 consensus 推向 non-consensus，靠嘅係刻意注入個人 bias——佢自己亦承認「有品味嘅 bias 係深度來源，但 bias 亦可能係低品質偏見」。同一機制既能提純判斷力，也能固化偏見。
