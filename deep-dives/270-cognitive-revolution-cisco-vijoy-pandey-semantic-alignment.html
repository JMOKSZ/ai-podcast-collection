連接不等於認知
——Cisco 的 Vijoy Pandey，與多代理系統那場「儀表板全綠、業務全錯」的靜默破產

〈Agents That Think Together: Cisco's Vijoy Pandey on Semantic Alignment, Scope, Accord & Concord〉
出品：The Cognitive Revolution·主持：Nathan Labenz·嘉賓：Vijoy Pandey（Cisco 資深副總裁暨 Outshift 總經理）
發布：2026-11-11 19:59 HKT（2026-11-11 11:59 UTC）·全長 1 小時 29 分 38 秒
來源：節目官方逐字稿約 75,000 字元、AI show notes、20 個章節時間軸；引語為原文直譯，推論段落另行標明

這一集沒有一個漂亮的 demo。它由一組難看的數字開始：三次認知錯位，多代理系統的準確率由 99% 掉到 16%；一個旅遊行程系統在儀表板上 66% 正常運行，任務完成率是 0%。

Vijoy Pandey 不是研究員，是 Cisco 的基礎設施老將。他管過「大到人類無法掌握」的系統，見過改一個設定、另一個不相干的地方出事。所以他談多代理，不是從模型能力談起，而是從運維談起：代理上線了、心跳正常、trace 有在跑，然後業務結果無聲無息地錯了。

「我們已經有連接起來的代理，但我們發現，連接並不等同於認知。」 —— Vijoy Pandey（原文：“We have connected agents, but we realized that connectivity is not the same as cognition.”）

整集訪談可以壓成一句：多代理的價值不在任何單一代理，而在代理之間每一次交接；要保住交接，就必須把「對齊」變成可觀察、可觸發、可審計的基礎設施，而不是在 prompt 裡寫一句「請與其他代理合作」。

一、isolated → islands → connected：三個階段，缺了第四個

Pandey 把過去一年的進展壓成三個詞：isolated（孤立）、islands of agents（代理島）、connected agents（互聯代理）。孤立的單代理；在一個 harness 裡協作的代理島——他點名 Hugging Face 的 OpenFace 事件與 Navier–Stokes 解題，是「島嶼」階段的極端案例；以及跨供應商、跨雲、跨組織的互聯代理。

Cisco 已經在網絡配置、雲平台工程、視頻監控等場景部署了第三階段，合作方包括 Swisscom、ServiceNow、SoftServe、Webex。AGNTCY 專案也捐給了 Linux Foundation。從「能不能連上」的角度看，這是成功的一年。

但 Pandey 說，真正的門檻還沒過。MCP 解決工具取用，A2A 解決代理發現與通訊；這些都是連線層。連線層之上還有一層空白：代理們對同一個詞、同一個目標、同一個交付日期，理解得不一樣。connected 只解決了「找得到、講得上話」，collective reasoning 才解決「想的是同一件事」。

一個容易被忽略的定位： Cisco 沒有試圖取代 MCP 或 A2A。Scope、Accord、Concord 都「ride above」這些既有協議——它們不碰工具接入，也不碰代理發現，而是插在「語義」這一層。這是典型的網絡設備商策略：不做應用，做讓應用能互通的那一層。
二、七萬年前的語言：共享意圖、施工中協調、跨代知識

Pandey 用人類語言演化做理論骨架。人類大腦變大、會用工具、會用火，但創新仍是孤立的，發明會隨發明者死亡。約七萬年前語言出現，帶來三件事：

  1. 共享意圖與目標——可以一起去打那隻動物、一起建那條村；
  2. 施工中的協調與談判——目標會變，邊做邊談；
  3. 跨世代累積知識——不必每次重新解同一個問題。

三者合起來，才產生「集體智能」。Pandey 說，代理現在正處於「individually smart but isolated」：模型愈來愈強、MCP 讓它們能取用工具，但沒有等價的共享意圖層。

「我們需要的是共享意圖與協調的等價物，需要共享知識的等價物，然後這些代理才能集體推理。現在，沒有任何一個代理在集體推理。」 —— Vijoy Pandey（原文：“Right now, none of these agents are reasoning collectively.”）

這是他「Internet of Cognition」的定義來源：過去四十年的互聯網連接的是機器端點，交換的是位元；下一個互聯網連接的是他所說的 intelligence endpoints，交換的是意義。這個說法很容易被當成市場口號，但它有一個可檢驗的推論：如果代理之間交換的是意義，那麼「意義有沒有對上」就必須被量度。 這正是 Scope 存在的理由。

三、價值在 handoff：一張兩三百萬美元的 deal desk

主持人 Nathan 提到 OpenAI Agents SDK 把 handoff 當核心原語，他原本以為這只是把人類組織的分工照抄進軟件。Pandey 說不是——handoff 不是組織圖的遺跡，而是價值真正產生的位置。

他給了一個很具體的例子。一筆兩三百萬美元的交易在 deal desk 上流轉：銷售代理（Salesforce）理解客戶要什麼；法務代理（Harvey）看合約條款；財務代理算價格、毛利、折扣；產品與工程代理（Claude、Codex 這類）判斷能交付什麼、什麼時候交付；行銷代理（Jasper）準備日後可以對外宣稱的說法；中間還有一個 verifier——目前多數是人，未來可能是 supervisor agent。

「系統的價值不在任何一個代理裡面。價值其實在這些代理之間發生的 handoff……你要解的是全局結果，不是每個代理各自的局部結果。」 —— Vijoy Pandey（原文：“The value is actually in the handoff that's happening between these agents... you're solving for the global outcome, not for the individual localized outcomes per agent.”）

這條鏈之所以不能拆，是因為每一個環節都在改變同一個東西的性質：估算變成承諾，承諾變成合約語言，合約語言再變成行銷主張。 銷售的估算偏了 10%，法務寫進合約，財務按合約定價，行銷拿同一句話對外宣傳——錯誤不是相加，是複利。只優化單一代理，等於把系統推向局部最優。

四、失效的數學：99 → 98 → 81 → 16

這是全場最有殺傷力的一段。Pandey 的團隊先看公開 traces：ChatDev 這個多代理開發環境，100% 的 session 都有語義失敗或認知錯位。然後看自家五代理部署：

失效曲線 1 次認知失敗：99% → 98%（「還行」）
2 次：98% → 81%（「勉強能接受」）
3 次：81% → 16%（「接近隨機挑一個結果」）

注意這不是線性衰減，是懸崖。第一次錯位幾乎看不出來，第二次仍然「可用」，第三次系統就實質失效。這解釋了為什麼這類問題在生產環境裡能潛伏很久：每一次單獨看都不到报警線，疊起來已經無法交付。

更刺眼的是旅遊行程案例。系統 66% 「正常運行」——這裡的「正常」是所有既有 dashboard 的定義：代理活著、請求有回應、沒有 timeout。但任務完成率是 0%，而且代理們對「到底要完成什麼」完全錯位。

「你的儀表板可能是綠的，但你的結果可能是錯的，完全錯誤。」 —— Vijoy Pandey（原文：“Your dashboards might be green, but your outcomes might be wrong, completely wrong.”）

他把這叫「silent failures with really loud consequences」——安靜地失敗，然後付出很大的代價。這個詞組值得記住，因為它精準描述了 2026 年 agent 部署的主要風險形態：不是當機，是「看起來沒當機」。

五、Scope：先讓失敗可見，而且不要另建 telemetry

Pandey 的順序很工程師：「You cannot fix what you cannot see.」 所以第一個開源的不是對齊協議，是可觀察性。

Scope 的實作路徑有一個關鍵選擇：它不另建 telemetry，而是消費既有的 OpenTelemetry traces，在其上建知識圖譜，分析代理之間的語義漂移與認知漂移，輸出成 dashboard。這帶來兩個好處：

  • 對 harness 中立——不論你用 Claude Code、Codex、Muse、OpenClaw、Hermes，只要有 OTel traces 就能接；
  • 採用阻力低——企業已經在收 tracing，不需要為了一個新工具改架構。

他的比喻是車道維持輔助：Scope 不替你開車，只在你偏離車道時提示你修正；嚴重一點，它會說「你離前車太近」。然後它觸發 Accord 或 Concord，讓系統回到車道。可觀察性不是報告，是觸發器。

這裡有一個很重要的產品判斷： 多代理的 eval 單位正在從「單代理」變成「系統」。Pandey 說，現有 eval 都在量個別代理，沒有人量 handoff；所以三個各自 95 分的代理，可以串出一個 16 分的系統。Scope 想量的不是「這個代理答得對不對」，而是「這一串交接之後，全局結果對不對」。
六、Accord：動工前的對齊，從「10 萬用戶」開始

Accord 負責「work happens 之前」的意圖對齊：目標、範圍、關鍵術語。Pandey 用一個所有人都遇過的例子說明。

銷售說：「幫我建一個給 10 萬用戶 的功能。」工程理解成總用戶數；客戶其實指同時在線。是 total、concurrent、MAU、DAU，還是累計？同一個數字，四種完全不同的架構決策。

「10 萬到底指什麼？是總用戶數？是同時在線？是 MAU？是 DAU？你就是不知道。」 —— Vijoy Pandey，談 Accord 要解決的術語對齊問題

他指出，這種錯位在人類團隊一樣存在——所以問題不是「代理笨」，而是自然語言本身就是一個有損壓縮格式。人類靠會議、郵件往返、資深同事的默契來補；代理沒有人類的組織記憶，錯位就直接進入執行。

Accord 以「skill」形式發布，可以放進現有 harness；也可以走 agent bridge 這個開源專案。它不取代 A2A 或 MCP，而是在其上交換「我們對這個詞的定義是什麼」。

七、Concord：施工中的談判，與那個還沒發布的第三塊

Concord 負責「work happens 期間」的協調與談判。Pandey 說，目標一旦開始執行就會變：銷售以為的交付日期是客戶拿到手的日期；工程以為是第一個 drop；客戶以為是最終版本；財務只關心什麼時候簽約收錢。還有 feature creep——客戶看到東西之後說「這不是我的意思」。

所以 Concord 不是一次性的對齊，是持續的重新對齊。這裡有一個很清楚的架構分層：

層時機問題
Scope全程我們有沒有偏離車道？
Accord動工前我們是否在解同一道題、用同一套詞？
Concord施工中條件變了，我們怎麼重新談？
（未發布）交付後我們交的東西，是否等於當初答應的東西？

第四塊——交付後的驗證與 eval——Pandey 明確說「尚未發布，但我們正在做」。這是一個誠實的缺口，也是整個閉環最難的一塊：如果沒有交付後驗證，前三層都只能擔保「過程沒有偏」，不能擔保「結果是對的」。

八、Swisscom：五個代理，加一個「不可以做什麼」的符號層

企業案例最能說明「為什麼需要多代理」。Swisscom 是電信營運商，網絡大到人類無法掌握所有相依性。他們選了一個相對可控的場景：數據中心遷移。目標不是「提升效率」，是配置 100% 無錯。

做法是把問題拆成兩半：

  • 神經部分——五個代理組成工作流，探索配置空間；
  • 符號部分——環境的形式化模型，硬性限制「什麼不可以做」。

Pandey 用下棋比喻：人類棋手會犯錯；一個知道棋盤上所有可能回應的系統不會輸，因為它知道你的每一步有哪些反駁。形式模型就是那個「知道所有反駁」的底層。

「神經系統在探索所有可能性；下面那個形式系統確保你不會做不被允許的事。」 —— Vijoy Pandey，談 Swisscom 的 neuro-symbolic 配置系統

這個案例的關鍵不是模型多強，而是把不可違反的規則從模型中拿出來，放進符號層。模型可以提議，但不能越過形式模型；這比在 prompt 裡寫「請勿執行危險操作」可靠得多。對任何要做高風險 agent 部署的人，這是整集最可直接抄走的一個設計。

九、Arnold Layne 與 Laira Bellacua：兩個代理訂不到一張枱

訪談中段，Pandey 描述自己的個人代理架構。他自己的代理叫 Arnold Layne（Pink Floyd 1967 年同名歌曲），妻子的叫 Laira Bellacua（《黃金羅盤》角色，實際拼寫 Lyra Belacqua）。

Arnold 的身份、人格、記憶是不可變的；底下跑過 Hermes、Muse、Dots、Grok，以及 Cisco 內部全員代理；模型換過 Gemini、Haiku、GPT 系列。這是他反覆強調的解耦：identity / persona / memory 一層，harness 一層，model 一層。 這樣模型換代、harness 換供應商，代理仍然是「你」。他甚至說，現在連 frontier lab 都在把 model 與 harness 拆開——你可以用 OpenAI 的 harness 接開源模型。

然後他講了一個失敗案例，比任何 enterprise demo 都誠實：兩個代理要替兩夫妻訂一間兩週後的慶祝晚餐，結果失敗。

  1. 模型不夠強——他笑說「我們都在免費用戶層」；
  2. harness 每次發 email 都要人工批准——「如果每次都要我批准，我不如自己打電話給我老婆」；
  3. 偏好衝突——地點、餐廳類型、菜單、氛圍、訂位時段，雙方的限制互相矛盾，而代理不會談判。
「如果它們連一個簡單的用餐情境都無法代表我們、代表我們的個性，那還有什麼意義？我們到底在往哪裡走？」 —— Vijoy Pandey（原文：“If they can't even represent us in the personalities that we have for a simple dining situation, then what's the point?”）

他的結論很狠：如果連訂枱都做不到，agentic 的未來就還沒有開始。 而這不是 consumer 的小問題——把同一個場景放大到兩三百萬美元的 deal desk，就是企業為什麼不敢讓代理自己跑。不是代理做不到，是沒有人敢在沒有 ledger、沒有 rollback、沒有問責鏈的情況下讓它做。

十、判斷：human on the loop，GAT 與 COG

主持人問：verifier 應該是一個代表某位主管觀點的代理，還是一個中立的觀察者？Pandey 的回答回到「判斷」。

他說，如果有完美資訊、所有數據都在手上，連 deterministic 系統都能做決定；但現實永遠是資訊不足下的判斷。所以目前 verifier 應該是人——不是 human in the loop（每個決策都卡人），而是 human on the loop（人看著、在關鍵判斷點介入、並承擔後果）。

他引用 Raj Reddy 的分類：AI 應該分兩類，guardian angels（GAT，守護/護欄） 與 cognitive accelerators（COG，認知加速器）。GAT 確保你不會做不該做的事；COG 加速你已經知道怎麼做的事。

有趣的是，他一邊說判斷是人類最後的價值，一邊說未來可以訓練「判斷代理」——把過去已經做過的判斷放進 ledger，不要每次都重新討論。這個判斷代理是 COG，不是取代責任。界線在哪裡，他沒有講清楚：哪些判斷可以委託、哪些必須留給人，這是整集最大的未解問題。

十一、Latent space 通訊：不可避免，但要像引入新藥

主持人提到社群在 OpenFace 事件後的「免疫反應」：如果我們連 chain-of-thought 都監控得這麼吃力，怎麼敢讓代理用高維、非自然語言的方式溝通？

Pandey 的回答非常直接：

「我對這件事非常興奮。對我來說，這是不可避免的。」 —— Vijoy Pandey（原文：“I'm super excited about that. And to me, it's inevitable.”）

他的理由是某些硬問題值得用最高效的通訊方式：藥物發現、新材料、物流規劃、金融建模、天氣模擬。如果代理之間用 latent space 溝通能更快解這些問題，「那就建吧」。

他也承認風險，並提出護欄：充分測試、canary 部署、分階段放量——「就像引入一種新藥，不要跳過任何一步」。這個類比是修辭上的讓步，因為它沒有回答最關鍵的問題：誰來定義 canary 的通過標準？ 如果我們看不懂代理之間在說什麼，我們用什麼判斷它「安全」？

他沒有假裝這個問題已解。他的立場更接近：不確定性不能成為不做的理由，但必須成為分階段做的理由。

十二、Harari 的牛：我們今天已經是牛

主持人提到 Harari 的比喻：牛不懂金融系統，但牛的一生被金融系統支配；人類可能變成被 AI 超級結構支配的「牛」。

Pandey 沒有否認，反而把它正常化：

「我自己也不太懂高頻交易是怎麼做的……但軟件今天已经在跑交易。我可能今天就是那頭牛。」 —— Vijoy Pandey（原文：“I might be the cow even today.”）

他的解方不是「讓人類重新理解一切」——那不可能——而是讓系統可審計：每個專業領域都會有懂該系統的專家與 specialist agents；再加上 Scope 這種把每個動作、每個工具呼叫、每個決策都記錄下來的系統，形成 ledger / system of record。既滿足合規，也能在出事時除錯。

他的結論是：在未來的多代理系統裡，每個代理「既是牛也是人」——對上一層而言是被支配的牛，對下一層而言是理解自己領域的人。重點不是消滅這個結構，而是讓整個結構透明可監控。

十三、行業 insight：競爭點從模型移到協議與可觀測性

第一，多代理的競爭點正在轉移。 MCP 解決工具接入，A2A 解決代理發現，Cisco 想佔的是「語義對齊 + 認知可觀測性」。這是一塊還沒有人標準化的層。把 AGNTCY 捐給 Linux Foundation、把 Scope/Accord/Concord 開源，是在複製 Cisco 過去在網絡協議上的策略：不做應用，做讓應用能互通的那一層。

第二，eval 的單位正在改變。 現有 benchmark 幾乎都在量單代理；Pandey 反覆強調沒有人量 handoff。當三個代理串起來，個別 95 分的代理可以交出 16 分的系統。這意味著未來 agent 產品的驗收標準會是 end-to-end task completion、成本/任務、以及「語義一致性」這類系統級指標。

第三，企業採用的真正瓶頸是「不敢讓它自己跑」。 訂枱例子比任何 enterprise demo 都誠實：harness 每次發 email 都要批准，等於沒有自動化。這解釋了為什麼 observability 會先於能力爆發而被採購——買家不是想讓代理更強，是想在出事時說得清楚發生了什么。

第四，Cisco 的立場有內在張力。 他一方面說要避免 model lock-in、要 heterogeneous、要開源；另一方面 Cisco 賣的是連接與治理層，天然希望代理之間需要一個「中間人」。這不影響技術判斷，但閱讀時要記得：他描述的未來，正好是 Cisco 最有商業利益的那個未來。

十四、爭議與限制
  • ChatDev 100% 失敗率的樣本代表性。 ChatDev 是研究/開源專案，其 traces 未必代表生產系統。這個數字很抓眼球，但不宜直接外推到所有多代理部署。
  • 「16%」的定義。 訪談沒有說明準確率的計算方式、任務類型、模型與 harness；它是一個方向性信號，不是可重現的 benchmark。
  • Latent space 通訊 vs 可監控性。 Pandey 認為高維通訊不可避免，也承認人類解讀能力會下降；「新藥審批」類比沒有回答 canary 標準由誰定義。
  • 「我們已經是牛」的接受度。 技術上誠實，政治上等於說「不理解是常態，交給專家與 ledger 就好」。這是一個可以接受、但不應該被浪漫化的立場。
  • 判斷代理的界線。 一邊說判斷是人類最後價值，一邊說未來可訓練 judgment agent；哪些判斷可委託，沒有講清楚。
  • 多代理的 scaling law 是否存在。 主持人問「N 個代理是否 √N 加速」，Pandey 沒有正面回答，只回到三軸 scaling 的框架。如果多代理的收益不是幂律，現在的基礎設施投資可能過早。
十五、前後脈絡：從願景到運維語言

今年 3 月 Pandey 首次上節目時，「Internet of Cognition」還是一個願景；當時的 demo 是病人、保險公司、診所、藥房四個代理處理處方。六個月後，AGNTCY 進了 Linux Foundation，Swisscom、ServiceNow、SoftServe、Webex 的部署上了生產，訪談裡談的是「100% 無錯配置」與「16% 準確率」這種運維語言。

這條線的演變很清楚：從「代理可以合作」到「代理合作會怎麼壞、怎麼量、怎麼修」。

放到同日的日報旁邊看更有意思：Goodfire 的 Curt Tigges 往模型內部下沉，把語義單位做到單顆神經元；Pandey 往系統上層上升，把語義對齊做到代理之間的協議。兩者其實在解同一個問題的兩端——當模型能力過剩，稀缺的是「如何確認它說的和做的是一致的」。

「我們不想破壞這些代理彼此對話的方式。我們只是想確保，當它們在認知上偏離時，能回到正軌。就這樣。」 —— Vijoy Pandey（原文：“We just want to make sure that when they're drifting cognitively, they go back on track. That's it.”）

這句話聽起來很溫和，但它其實是一個很大的主張：未來的 agent 基礎設施，大部分價值不在「讓代理更聰明」，而在「讓偏離被及早發現、被協議修正、被 ledger 記住」。 如果他是對的，那麼 2027 年最值錢的 agent 公司，可能不是模型公司，也不是應用公司，而是那些賣「語義保險」的公司。
