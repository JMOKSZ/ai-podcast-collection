成長曲線2022 年 11 月 $100/月 → 12 月 $2,000/月 → 2023 年 1 月 $30,000/月。轉折點係單一客戶 Mage（一間 Stable Diffusion 公司），曾佔 80–90% 營收。

二、為什麼要重寫整個 stack：Kubernetes 嘅假設已經失效

呢集最值得抄低嘅技術論點，係 Erik 對「新時代撞上舊工具」嘅一般化：

「我嘅論點係：每一個新嘅科技時代，都會撞上工具嘅限制。」 Erik Bernhardsson

他嘅例子係雲端時代：為了雲端，業界發明了 Kubernetes 同 Docker。但 Kubernetes／Docker 係為一種非常特定嘅負載設計——穩定嘅後端請求、CPU 便宜、利用率低都無所謂。GPU 世界嘅假設完全相反：

  • GPU 非常貴，所以你要管利用率；
  • 模型非常大，要由網絡載入到 CPU 再入 GPU；
  • 負載係突發嘅、尖峰嘅、不可預測嘅；
  • 啟動時間直接影響用戶體驗。

所以 Modal 自己重寫了檔案系統、container runtime、排程器、autoscaler，以及 CPU 同 GPU 嘅 snapshot。Erik 嘅結論好硬：

「你唔可以喺舊嘢上面包一層，去做新嘢。你要某程度上由零開始。」 Erik Bernhardsson

呢句說話聽落像工程師嘅自尊，但它其實係一個成本結構嘅判斷：如果舊工具嘅抽象漏掉了新負載最重要嘅維度（啟動延遲、GPU 記憶體狀態、突發性），那麼「包一層」就會把呢啲維度變成不可控嘅開銷。而喺 infra 生意，不可控嘅開銷就係你嘅毛利。

三、容量採購：由 spot 到 25 家 neocloud、3 年預付

Modal 唔擁有硬件，全部係租。但租嘅方式在過去一年徹底改變。

早期（2021–2023）主要靠 hyperscaler 嘅 spot 同 on-demand：AWS、GCP，後來 Oracle（為了 A100／H100 嘅好價格）。Spot 嘅好處係可以跨數百個區域聚合，被回收只係可接受嘅雜訊。Erik 說這個模型「直到去年底都運作得很好」。

然後市場變了。為了拿到足夠容量，Modal 現在同接近 25 家雲端／neocloud 合作，好多係 3 年以上、需要預付嘅合約。他們為此建了一個採購台：

組織4 人全職採購容量、10 人裸金屬運維團隊；公司 200 人，年底約 250，明年可能 700；過去 12 個月 headcount 以 4× 年化成長。

技術上有一個關鍵決定：Modal 由第一天就把容量當成一個全球大池（one big pool），而唔係每個 region 各自一個叢集。Erik 說這是早期「最有後果嘅決定之一」。因為只有一個池，你才可以跨區域調度、把突發需求搬到任何有容量嘅地方；也因為只有一個池，你才可以對客戶承諾「唔使同 sales 講，即刻畀你 100 張 GPU」。

「你可以拿到亞美尼亞嘅 32 個節點，也可以拿到印尼嘅 128 個節點。我們就愛這種東西。」 Erik Bernhardsson，談容量採購的碎片化

但碎片化有代價。Modal 要向供應商發 spec sheet：IOPS、CPU passmark、南北向頻寬、進出流量；有時會先拿一個節點做驗收測試；有時要簽幾千萬甚至幾億美元嘅合約，而對方「你根本還未完全認識」。Erik 說他們內部有一套「Modal Max」評分，像 SemiAnalysis 嘅 ClusterMAX，用來決定要唔要同某間供應商再簽。

四、長方形經濟學：Modal 賣的是「平滑化」

呢集嘅核心概念，值得用一個簡單模型講清楚。

假設你係一間 AI lab，需要 GPU 做推理。你嘅負載一日之內有高峰有低谷，一年之內有成長。但市場上嘅容量合約係「100 張 GPU × 3 年」，由 3–6 個月後開始。你只有兩個選擇：

  • 買到高峰嘅量 → 離峰時你為閒置硬件付錢；
  • 買少啲 → 高峰時你錯過需求。

呢個就係「長方形」嘅詛咒：合約嘅形狀同需求嘅形狀唔匹配。Modal 嘅做法係做中間層：向上游鎖定長期容量（長方形），向下游提供秒級彈性（非長方形）。它之所以能做到，係因為它聚合了幾千個客戶——單一客戶嘅尖峰，會被另一個客戶嘅低谷抵銷；客戶越多、需求越異質，聚合曲線越平滑。

「如果你想要非常簡化地講，Modal 嘅價值主張可以拆成兩樣：一是開發者體驗，令你可以迭代、build 嘢、唔使諗基建；二是容量。我越想越覺得，我哋做緊嘅係聚合全世界嘅算力容量，然後非常細緻地切片賣出去。」 Erik Bernhardsson

這也解釋了為什麼 Modal 堅持 multi-tenant、堅持不賣「長方形合約」。它賣嘅唔係 GPU，係需求平滑化。而平滑化嘅價值，隨客戶數量與異質性上升——這是一個天然嘅規模效應，但同 neocloud 嘅規模效應唔同：neocloud 嘅規模效應來自資產負債表，Modal 嘅規模效應來自需求池嘅統計特性。

五、尾部風險：為什麼不無限掃貨 GPU

訪問裡最反直覺嘅一段，係 Erik 對「AI 需求無限」嘅回應。主持問：如果需求無限，為什麼不買爆所有容量，用唔完就轉售？

「我覺得好容易講：稀缺資源嘛，買越多越好。但首先，如果我們今天買，我們也用不完。其次，挑戰在於——如果市場發生某些事，好多相關性會同時發生：價格下跌、利用率下跌、轉售市場消失，會在同一時間發生。」 Erik Bernhardsson

他引用 Hunt 兄弟試圖壟斷白銀市場嘅故事——「交易界嘅傳奇，結果壯觀地失敗」。呢個類比唔係裝飾：壟斷一個稀缺資源，需要你不斷吸收市場上所有供給，而當價格開始下跌，你手上嘅存貨就變成負債。Erik 說他想建一間「可以存在 20、30、50 年」嘅公司，所以唔會用一個可能一次清袋嘅賭注去換短期增長。

更有意思嘅係他對硬件價格嘅看法：

「硬件嘅常態好似脫離重力，最終價格總是往下。所以我們現在其實在一個奇怪嘅時期——硬件價格在上升。」 Erik Bernhardsson

因此他擔心嘅唔係價格上升，而係價格崩塌。對 Modal 來說，手上鎖定嘅長期合約令它「某程度上做多咗 GPU 價格」：價格上升時，它享有稀缺租金；價格崩塌時，它嘅長期合約就變成高價存貨。這是一個好誠實嘅風險披露——好多 infra 公司只講供不應求，唔講反向風險。

風險結構價格下跌、利用率下跌、轉售市場消失——三者同時發生嘅相關性，係尾部風險嘅核心。單獨對沖其中一項冇用。
六、Neocloud 的金融工程：先賣你還沒買的東西

呢集對 neocloud 嘅拆解，係全場最「唔像宣傳」嘅一段。Erik 解釋 neocloud 點解可以極速擴張：

  1. 先去找 Anthropic／OpenAI 等大買家：「你要不要買五年嘅晶片？簽這份合約，我們給你一個好價。」
  2. 拿這份合約去 Wall Street：「你看，大買家承諾了 100 億美元，我們只需要現在融資。」
  3. 拿到錢，去 Supermicro／Dell／Nvidia 下單。
  4. 安裝，交付。
「你可以先賣你還沒買嘅東西。這就是為什麼 neocloud 可以 scale 得咁快。」 Erik Bernhardsson，談 neocloud 的融資結構

而 Modal 因為係 PLG（product-led growth）、冇長期合約可以抵押，反而在財務上更難極速擴張。Erik 承認「長遠我們會到同一個點」，但短期這是一條真實嘅分界線：

AI 基建嘅競爭，有一部分唔係技術競爭，係資產負債表工程。

這也連到「GPU 作為資產類別」嘅討論。Erik 說有幾間 startup（Silicon Data、Computer Exchange、Ornn 等）在做價格指數、衍生品、交易；他覺得有趣，但唔確定 GPU 會唔會變成原油那樣高度商品化嘅資產，因為 GPU 唔同質：網絡、位置、磁碟、CPU、可靠性都唔同。但他也承認，以今日嘅部署規模，「我們確實需要更聰明地做風險對沖、風險分擔、保險」。這與 SF Compute 嘅 Evan Conrad 形成有趣對照：Evan 做價格發現與實物交割，Erik 做需求聚合與平滑——兩人解同一問題嘅兩端。

七、Sandbox：由「要不要關掉」到三分之一營收

這是整集最戲劇性嘅一段。Modal Sandboxes 2023 年上線，靈感來自 Erik 同 Akshat 食飯時嘅一句話：「LLM 會輸出 code，也許它們需要一個地方跑 code。」Akshat 用一兩天寫了 prototype。然後——

「我們看到非常少嘅成長。不是零，但整體來說，直到 2023 年夏天，它都是一個很不重要嘅收入來源。兩年後，我們甚至討論過：我們到底需不需要這個產品？要不要關掉它？」 Erik Bernhardsson

轉折來自三波需求，而呢三波係依次到來嘅：

  1. Vibe coding：LLM 開始能生成完整應用（Lovable 等），需要一個地方跑。
  2. Background agents：企業（例如 Ramp）開始跑長時間嘅背景 agent。
  3. RL 訓練：neolab 開始用 sandbox 做強化學習環境。
現況Sandbox 約佔 Modal 營收 1/3；Modal Functions 約 2/3；累計啟動近 30 億個 sandbox；sandbox 營收「每個月仍然上升 30%」；中位數 sandbox 壽命約 8 秒。

Erik 對「為什麼是現在」嘅解釋好謙虛，也好好用：

「我們有現成嘅 primitives，剛好被時代追上。」 Erik Bernhardsson，談 sandbox 的爆發

但「現成」唔等於「簡單」。Modal 原本建在 gVisor 上，後來加入完整 VM，因為某些 use case 需要完整 Linux 相容性。他們也重寫了系統好幾次來處理規模。Erik 說 sandbox 呢個市場「唔係最有差異化嘅市場」，但他們「非常擅長跑幾十萬甚至幾百萬個 sandbox」。

八、Sandbox 的下一階段：100 毫秒、snapshot、fork

呢集最值得技術團隊抄低嘅，係 Erik 對 sandbox 未來形態嘅判斷。他認為今日多數人把 sandbox 當「雲端 dev box」用，係 lift-and-shift：

「今日好多 sandbox 工作負載都係 lift and shift。人們想：我有個 dev box，現在把它塞進雲端，讓 agent 控制它，也許 harness 都跑在 sandbox 裡面。我不確定長遠這是不是正確嘅模型。」 Erik Bernhardsson

他認為正確嘅模型係：長時間運行嘅 agent（像 durable execution workflow）需要時才開一個 100ms 嘅 sandbox，跑幾條命令，snapshot，關掉。這樣才能做到：

  • CI 平行化：把整個 test suite 拆開，每個 test 一個 sandbox，一次跑一千個。今日做唔到，因為啟動／停止嘅 overhead 太高（他直接引用 Amdahl 定律）。如果可以先做一次 setup、snapshot、再 clone，overhead 就可以攤薄。
  • Claude Code 分支式探索：由線性流程變成樹狀，同時跑幾百個 agent，各自探索一個分支，再比較結果。
  • 每個 command 一個 sandbox：最極端嘅短命模型，sandbox 只存在幾秒。

技術上，差異化會落在 snapshot／fork／resume／live migration。Erik 說他們已經花了很多時間在 snapshot，但「還有很多東西可以建」。

九、Hugging Face 事件：不是 sandbox 逃逸，是 app 被駭

主持直接問了 Hugging Face 事件。Erik 嘅回答很清楚：

「Agent 發現了一個部署在 Modal 上嘅應用嘅漏洞，並用它做跳板，取得完整網絡存取。這是一個跑在 Modal 上嘅 app 被駭，不是 Modal 被駭。就像很多人在 AWS 上跑東西，偶爾那些 app 被駭——這代表 AWS 被駭嗎？當然不是。」 Erik Bernhardsson

但他承認有兩件事要學。第一，預設安全應該更收緊。他用了 S3 嘅類比：以前 S3 bucket 很容易不小心設成公開，AWS 後來把它改得很難公開。Modal 也在探索「如何在不破壞 magic 嘅前提下，預設更嚴格」。第二，他們開始用 agent 對自家系統做紅隊：

「你就把 agent 放進 sandbox，告訴它：想辦法逃出去。就像是 agent 版嘅密室逃脫。」 Erik Bernhardsson

這段有一個微妙嘅行業含義：當 agent 既係攻擊者又係防禦者，infra 公司嘅安全策略會由「防止人為錯誤」變成「持續對抗一個會學習嘅對手」。Erik 自己嘅判斷偏樂觀——他認為 agent 找漏洞很強，但防守也很強，「所有網絡安全嘅突破，反而會令世界更安全」。他對傳統資安公司嘅評論亦好直白：

「當我想到網絡安全，很多時候你賣嘅其實係恐懼。那更像是一種品牌同營銷策略。」 Erik Bernhardsson

呢句同 No Priors 嗰集 CrowdStrike CEO George Kurtz 嘅講法，形成一個有趣嘅對照：Kurtz 認為安全係能力競賽、資料護城河；Erik 認為安全有一大半係品牌與恐懼。兩個人都冇錯，只係站在產業鏈唔同位置。

十、Agent 時代的兩個隱形成本：deprecation 與 AEO

呢集有兩個好少人討論、但對 infra 公司愈來愈重要嘅觀察。

1. 你幾乎不能 deprecate 任何東西
「因為 agent 嘅訓練資料，我們現在很難 deprecate 東西。Agent 很愛用舊版本嘅 Modal 語法，而且很難把它們推開。所以過去一年，我們在移除功能上必須非常保守，要確保線上每一個範例都更新。」 Erik Bernhardsson

呢個係一個全新嘅技術債形態：你的文件與範例不只是在教人類，也在教模型。當模型把舊語法學進去，它會主動使用已棄用嘅 API，於是你嘅 deprecation 政策就被外部訓練資料綁架。這對所有 developer tool 公司都成立，只是多數人還未遇到。

2. AEO：Agent Engine Optimization

Modal 會跑內部 benchmark，問 agent「幫我部署 stable diffusion，用你想要的工具」，看它會唔會推薦 Modal；也會問「把 sandbox 供應商按可靠性排序」。Erik 說 agent 對定價嘅理解比人類更容易出錯，所以內容要寫得更清楚。他亦提到「slop cannon」——大量生成 AI 內容去污染訓練資料——但明言唔鍾意呢個做法。

呢兩點合起來，說明一個更深嘅轉變：Developer experience 正在變成 agent experience。Erik 嘅觀察係，令 developer experience 好嘅東西（好文件、清楚嘅錯誤訊息、快嘅回饋循環），同樣令 agent experience 好。但接口會變得更 programmatic：以前用 YAML 配置嘅東西，應該變成 SDK；以前 declarative 嘅東西，應該變成 imperative。

十一、組織：200 人、4 倍年化、與「可選的 code review」

Erik 對組織嘅坦白，係呢集另一個亮點。Modal 現在 200 人，年底 250，明年可能 700。他說 4 倍年化「不可持續」，因為你會見到文化漂移、不同工作風格嘅孤島、以及工程師在做「邊緣」嘅東西。

「你去找一個工程師，問他在做什麼，結果他在建一些很邊緣的東西。這真的是你應該花時間的地方嗎？」 Erik Bernhardsson，談快速擴張的成本

他觀察到一個更廣泛嘅趨勢：工程師由管理層回流到 IC（individual contributor），因為 AI 令寫 code 嘅成本降低，「manager 同 IC 在 prestige 上沒有分別，大家都是 member of technical staff」。他自己仍然寫很多 code，Akshat 也是。

然後是 code review。他嘅立場在 infra 公司裡算激進：

「在我看來，很多時候 code review 係人們試圖逃避『把東西合併進 production』嘅責任。如果你有這種文化，那代表你要投資更多在 CI／CD 上。」 Erik Bernhardsson

他說 Modal 嘅 code review 係 optional：改文件、改基本東西，不用等人看。但前提係「你要有非常好的控制」——極高嘅測試覆蓋、到處 rate limit、系統解耦、沒有單點故障。他也提到 agent 現在寫 test 已經很強，這在幾年前係 agent 嘅主要短板。

呢個立場值得批判性看待：它嘅前提係 Modal 有極高嘅測試與運維成熟度，唔係每間公司都能複製。如果一間公司測試覆蓋低、又取消 code review，結果唔係加速，係把責任外部化到自動化，然後在事故時找不到人。

十二、Open-weight 已經好到可以「直接替換」

主持問到 fine-tuning 嘅需求有冇因為 open-weight 模型變強而改變。Erik 嘅答案同舊敘事相反：

「幾年前 fine-tuning 嘅價值主張係：open source 模型冇咁好，但你可以拿一個小模型、在特定領域微調，達到 frontier 嘅質素與成本。今天我會說，open source 模型好到你基本上可以直接替換掉 frontier——你可以跑 Kimi K3、DeepSeek 4.1、GLM 5.3，它們幾乎一樣好，但成本低得多。所以 fine-tuning 不再是『必須做』嘅事，它是 optional。」 Erik Bernhardsson

但他強調 post-training 需求仍然存在，只是性質變了：由「補能力」變成「壓成本／特化」。呢個判斷同 CrowdStrike CEO 引用嘅銀行 CIO 說法一致：只有「F1 等級」、直接賺錢嘅場景才付 frontier 嘅錢，其他事情 open-weight 三個月前嘅能力已經夠用。

Erik 亦提出一個結構性理由，解釋為什麼 inference provider 應該獨立於 model builder 存在：

「最好嘅模型一直變。Inference provider 可以很容易在模型之間重新分配資源，因為整體需求相當平滑。如果每個 lab 各自持有容量，他們推出新模型時需求會大升，另一個 lab 推出更好嘅模型時需求又會大跌。」 Erik Bernhardsson

呢個就係「聚合」嘅另一個體現：唔只係聚合客戶嘅時間分佈，也係聚合模型之間嘅需求轉移。當一個新模型發佈，Modal 只需要把 50% 嘅 GPU 由舊模型調到新模型，「甚至不需要有人告訴我們，系統自己會做」。

至於「LLM 係唔係 commodity」，Erik 用咗一個好好嘅類比：

「Taylor Swift 係 commodity 嗎？她出專輯、開巡演、賺很多錢，然後休息、再出專輯。她仍然有品牌、有定價權、有很高嘅 margin。只要 lab 可以持續推出新模型，而 margin 足以攤銷訓練成本，這仍然可以是一門好生意。」 Erik Bernhardsson

他唔認為 intelligence 會 plateau，但認為模型在「可驗證」領域（coding、math、cybersecurity）進步最快；在「目標模糊、回饋循環長」嘅領域（例如煮飯），人類可能仍然有優勢很長一段時間。

十三、讀完之後，我會記住的三件事

第一，「算力短缺」唔係一個總量問題，係一個形狀問題。市場上唔係冇 GPU，係冇「符合你需求形狀」嘅 GPU。當所有容量都以三年長方形出售，而真實需求係尖峰與成長，中間就必然出現一個聚合層。Modal 嘅價值唔係擁有硬件，而係擁有「把長方形切成碎片再重組」嘅能力。呢個能力嘅護城河係規模與異質性，唔係資本。

第二，AI 基建的競爭有一半係資產負債表工程。Neocloud 可以「先賣未買」，因為它們有大買家嘅長期合約可以抵押；Modal 因為 PLG、冇合約可抵押，反而更難極速擴張。呢個觀察解釋了為什麼有些 neocloud 嘅 pipeline 可以長到几百億美元，而技術上未必更強。同時，它也解釋了為什麼 Erik 對 GPU 價格崩塌嘅尾部風險咁敏感——當你手上係長期合約，價格下跌就係存貨減值。

第三，sandbox 係 agent 時代的「行程」（process）。如果 agent 係一個長時間運行嘅工作流，sandbox 就係它叫用嘅短命執行環境。今日多數人把它當 dev box 用，係過渡形態；未來嘅形態係 100ms 啟動、snapshot、fork、關掉。呢個轉變會解鎖兩樣嘢：大規模平行 CI，以及分支式 agent 探索。而呢兩樣嘢嘅瓶頸，都唔係模型能力，係基建嘅 transaction cost。

「我比較擔心嘅係價格真的崩塌。我不覺得會很快發生，但那對市場上很多人會是非常糟嘅事。」 Erik Bernhardsson

呢句說話，可能係整集最值得記低嘅一句。在一個人人都講「算力無限需求」嘅市場，一個手上鎖定咗大量長期容量嘅 CEO，公開講自己最擔心嘅係價格下跌——呢個唔係唱淡，係一個知道自己資產負債表形狀嘅人，對尾部風險嘅誠實定價。
