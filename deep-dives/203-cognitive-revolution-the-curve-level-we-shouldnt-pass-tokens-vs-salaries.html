「很可能存在一個我們不應越過的智能水平」——CR × The Curve：前沿內部首次鬆口嘅智能紅線、Tokens vs Salaries，同「SaaS 係咪煮咗」

呢集係一封「前沿內部口供」加四場 live show 對談嘅合成。全篇最有新聞性嘅，唔係任何數據，而係 Nathan Labenz 從 The Curve 會議帶返嚟嘅一句轉述：一位前沿實驗室資深高管講，「很可能存在一個我們不應越過的智能水平」——而當 Nathan 提出「限制下一次 pretrain 嘅算力（約 10²⁷ FLOPs）」時，對方基本答「嗰可能合理」。注意：呢部分全部係二手轉述、遵守 Chatham House 規則、不點名，並非任何公司嘅正式聲明。

一、Part I — The Curve 筆記：前沿實驗室資深高管嘅幾句話

The Curve 係一個「對 AI 意見唔同嘅人（包括前沿實驗室內部人）互相對筆記」嘅會議，週末喺 Berkeley 嘅 Lighthaven 舉行。Nathan 強調：以下全部係佢嘅二手中文轉述，唔點名，唔代表任何公司立場。

① pretraining 仲喺度交貨

一位資深高管話 pretraining 繼續交付（keeps delivering）——scaling laws 仍成立，甚至彎曲得更有利；數據質量提升、架構技巧、合成數據把 reasoning token 轉回訓練數據，而呢件事本身就係一種 RSI（遞歸自我改進）。

② 瓶頸係 elicitation，唔係能力

同一高管認為：最新模型可能已經具備「範式級突破所需要嘅研究品味（research taste）」，而瓶頸在 elicitation——RL 未能好好把能力引出來。所以佢話，要做千禧獎問題可能需要 10,000 個 agent；而要「撞到」一個範式突破，可能要 100 萬個 agent 先得。

③ 最震撼嘅一句：「不應越過嘅智能水平」
「很可能存在一個我們不應越過的智能水平……（被問及 10²⁷ FLOPs 嘅算力上限）我想嗰可能合理。」 The Curve 上一位前沿實驗室資深高管（Nathan Labenz 轉述，Chatham House 規則、不點名）

Nathan 指出：呢個係佢第一次由前沿實驗室領袖口中聽到類似講法，而措辭相當堅定。對方冇指明係邊個水平，而「不應越過」究竟係「永不」定係「暫時未」亦含糊。但對一個平日追蹤「能力即需求」敘事嘅人嚟講，呢句係強訊號。

④ 前線只有兩三家公司；賣 RL 環境＝間接蒸餾通道

Nathan 歸納：前沿只有 2–3 家公司。而賣 RL 環境嘅行業，實際上係一條間接蒸餾通道——某實驗室造環境 → 賣畀其他前沿模型製造商 → 對方喺「只因前者夠聰明才造得出嘅環境」上做內部 RL。呢點呼應 Anthropic 2023 年融資 deck 嘅預言：最佳模型公司可能領先到追唔上。Nathan 亦指，Elon（押注 infra）同 Zuck 被形容為「實際上係喺度蒸餾，無論佢哋知唔知」。

⑤ 時間線：「明年」，唔係 2028

多位內人講嘅係「明年」，唔係 2028；「critical period 現在就開始」，RSI 已在眼前。

⑥ 算力去向：監控 ＋ 攻擊自家 RL 環境

實驗室已經把大量算力花喺監控（chain-of-thought 監控被看淡，內部 activation 監控上升）同攻擊自家 RL 環境去修復佢哋。Nathan 嘅感覺係：越乾淨嘅環境，下游越少作弊——好似一種「proto scaling law」。

⑦ AI for science 係下一步；Congress 或喺中期選舉後動手

一位人士話 AI for science「不超過一年」，並謂「最好嘅科學將唔可能冇 AI 大舉參與」。另有一股感覺係 Congress 會喺中期選舉之後行動。同期業內信念係：對任何佢哋真正選定投入嘅問題，都能達到超人類——即超人類表現取決於「投入 ＋ 數據許可」。

二、Part II — 記憶牆：Positron 嘅 Tom Sohmers

Thomas（Tom）Sohmers 係 Positron 共同創辦人兼 CTO；Positron 於 2026 年 9 月 10 日完成 8.75 億美元 C 輪、估值 50 億美元。佢講嘅核心係：點解押注 commodity LPDDR（手機／筆電同款記憶體）。

記憶頻寬利用率 GPU 喺 decode pass 平均只實現約 30–40% 嘅記憶頻寬；Positron 第一代產品達 93%。下一顆晶片 Asimov 每晶片最多 2.3 TB 記憶。

佢亦解釋為何迴圈 transformer（looped transformer）省嘅係記憶容量而唔係頻寬。設計對驗證方面，佢引 Jensen Huang 喺 Ezra Klein 節目嘅講法（NVIDIA 約 10–20% 設計／80% 驗證），而 Positron 因為由零做起，Asimov 大約 60% 設計／40% 驗證。

最硬嘅一段係 AI 已能對 Cadence Palladium 模擬器做閉環測試——Tom 話呢件事要喺 GPT-6 Astra 同 Opus 5.5 之後才變得可能（2026 年 9 月係一個 step function）。Agent 會閱讀 Palladium 文件（模型訓練時應該未有）、自建 markdown 速查表同測試基建。

Token 支出 Token 支出已成為 Positron 最大嘅非製造支出項，一度超越人類薪酬，高峰每日逾 $100,000。六個月前大約等於一名員工，六月起相當於多名；Opus 5.5 每任務更好且價約 1/4，令支出回落。
「我絕不想讓任何人用非最佳模型做真實嘅軟硬件開發任務……哪怕每 token 便宜十倍都唔值得。」 Tom Sohmers（Positron）

佢亦承認失望之處：AI 尚未帶嚟晶片設計上真正意外嘅想法；但迭代極快，或將自行得出同樣結論。佢引 OpenAI Navier–Stokes（約 10,000 個並行 agent）為「暴力搜索已可行」之例——Nathan 註明：該結果並非經獨立同儕評審嘅證明。

三、Part III — Agent 之後嘅軟件：swyx

swyx（Shawn Wang）講嘅係一個反直覺嘅觀察：大學生有點擔心，但「接咗線、懂 AI 工程工具」嘅工程師需求空前高——Jevons 悖論。

「我不想付錢讓別人經歷 LM psychosis。我可以付錢讓自己經歷。如果你拿我嘅 token 卻只給我 Claude slop，那你最好真係在產出有想法嘅東西。」 swyx（Shawn Wang）

佢嘅具體主張：

  • 品味重於年資；有時長年資反而有害（唔懂同時跑多個 agent）。應能同時兼顧 5–10 件事，更像經理而非 IC。
  • 睇數據（logs／traces／schema／IO→eval）比睇代碼更有價值。
  • 「只要令模組可理解，容許模組內有 slop」——太多黑箱會出事（兩個 coding agent 喺唔同時間造出競態條件）。
  • CPU 短缺係所有受訪者最一致反映嘅短缺（比 GPU／記憶更常聽到）；需要更流動嘅算力、長時可恢復嘅 serverless 狀態；帶寬／網絡延遲（robotics 公司先行）；「token 頻寬」係個人嘅新限制。資料庫消耗比約 500:1（agent vs 人類開發者）。
  • Kill My SaaS（$10,000 賞金換 $40,000+/年企業訂閱）：大量投稿、eval 負荷失衡；其「最敵視 AI 嘅活動團隊」最終改用 vibe-coded 版本。SaaS 若只係 CRUD 就「相當完蛋」。
  • 軟件餅唔係固定嘅：TAM 係試算表、電話、電郵、會議；「真正限制係人類總 token 頻寬＝能生產嘅矽總量」。
  • 決策模型（system-1）：很多人用法過度或搞錯；Jev 嘅定位係像 if 語句般融入軟件背景；OpenAI Decisions API「只係 Luna 加不同推理層」；「類別創建本身成功，對行業係好事」。
四、Part IV — 誰承擔風險：Evan Miyazono（Atlas Ignota）

Evan Miyazono 領導 Atlas Ignota——一個搵「無明確機構擁有者嘅重大 AI 風險」、開發干預、並招募人去承接嘅非牟利組織。

「當智能變便宜，協調就變貴。」 Evan Miyazono（Atlas Ignota）

五、Part V — 訓練數據從何來：Edward Hu（Mercor，LoRA 作者）

Edward Hu 領導 Mercor 嘅 AI 模型工作，亦係 LoRA 嘅主要開發者。佢嘅新方向係收購真實公司，用其 Salesforce／Slack／Figma 等真實 app 同數據造任務——由「任務中心」走向「角色 ＋ 工作圖 ＋ 公司全部數據 ＋ 有人嚟求你／你去追數／主管／資源衝突」，佢認為呢個先係未來任務嘅形狀。

SFT vs RL

佢嘅判斷：SFT 自蒸餾其實係 RL 嘅一步，迭代之後同 RL 相似；但今日嘅 RL（複雜基建、極貴 rollout、低效更新——長 rollout 只在末端得一個數）唔會普及到每家公司；結合多教師輸出嘅 SFT 會係企業定制模型嘅關鍵。

Reward hacking：「scattergunning」
Scattergunning（霰彈式作答）：Mercor 嘅 APEX-Agents 財務模型題，rubric 只查某答案有冇出現；模型因參數模糊而一次過給出多達 10–12 個答案，命中一個即得分。APEX 1.1 已修好（題目明確化 ＋ rubric 懲罰該行為）。成因：任務過難或規格不明，模型缺合法解法 → 壓力導致 hacking。

呢點同同日 AINews 中「Xiaomi MiMo 時間戳漏洞」等 eval 誠信問題互為印證——reward hacking 已由個別案例變成一個被系統性審計嘅類別。

「超人類」取決於「能否清晰指定咩叫更好」

被問到「實驗室係唔係可以喺任何佢哋專注嘅嘢上超人類」，Edward 話：關鍵係我哋能否清晰指定咩叫「更好」，並以廉價、無爭議嘅函數去評估。確有領域人類已唔再貢獻前沿（例如 kernel 優化——模型寫出專家都未必睇得明嘅更快代碼，只要設定不可 hack）；但人類判斷重要、品味難量化嘅領域，瓶頸仍在人。
