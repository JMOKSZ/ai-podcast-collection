「十億美金我都唔 pre-train」——Latent Space × Diogo Almeida（TypeSafe AI）：Jev 一週破 1 兆 tokens／日、RLCD 成為第三條北極星、同「refusal 係 type error」

📅 2026-09-21 22:13 UTC 發布·⏱ 約 2 小時 21 分（官方 timestamps 至 02:20:51）·🎙 swyx（Latent Space）·👤 Diogo Almeida（TypeSafe AI 創辦人兼 CEO，InstructGPT 共同作者）·🏷 System One 模型 / 後訓練北極星 / RLCD / coding agents

呢集對本 fleet 有特殊意義：Jev 正是四艦隊 harness 現正使用嘅 System One 決策層。而呢集係佢作者嘅「自白」——一位 InstructGPT 共同作者，用兩個幾鐘講清楚佢點解認為過去幾年所有 API 前沿模型都「行錯路」，以及佢要用一個全新模型類別去修正嘅係乜嘢。呢集唔係產品發佈會嘅延伸，而係一份技術宣言加路線圖：從「究竟 RLHF 錯在邊」講到「code 應該係模型嘅消費者」，從「十億美金我都唔 pre-train」講到「coding agent 被 KV cache 鎖死」。

一句話抓住全集：Diogo 認為 LLM 領域迄今只發生過約 2.2 次「北極星轉移」——RLHF（把任務改成 instruction following）→ RLVR（小修小補）→ 而家佢主張嘅 RLCD（Reinforcement Learning for Calibrated Decisions）。佢嘅核心斷言係：「You get what you optimize for（你得到你所優化嘅嘢）」，而 ML 最苦嘅一課係「最重要嘅部分根本唔係 ML」——係任務同數據。所以 TypeSafe 自稱 data lab 而非 model lab，指標係 intelligence per dollar（唔係更大，係更平），命名取自 Jevons Paradox。
一、Jev 是什麼：machine-native、large programmable 模型

Diogo 開場唔講功能，先講「類別」。佢認為需要一類新模型，最準確嘅名係 System 1 models（佢刻意唔叫「decision models」，話「System 1 係超越呢個嘅，我哋 tank 裡面仲有嘢」）。佢對呢個類別嘅定義係：目標係「讓 code 成為消費者」——所以公司叫 TypeSafe。

「There's a class of models that we describe as machine-native, System 1, large programmable… the goal is for code to be the consumer. As opposed to pre-trained large language models, which are meant for autocomplete of the internet, or RLHF models which are meant to reply to text.」 —— Diogo Almeida，定義 Jev 所屬嘅模型類別

佢用對照方式講清楚三種模型嘅「用途形態」：

  • 預訓練 LLM——為「互聯網自動補全」而生；
  • RLHF 聊天模型——為「回覆文字」而生；
  • Jev / System One——為「被程式消費」而生。

佢嘅名字邏輯亦一脈相承：Jev = Jevons Paradox。Jevons 悖論講嘅係效率提升反而令總消耗上升——放喺模型上就係「當智慧變平，用量會爆炸」。所以 Jev 嘅品牌定位係一句好硬嘅話：

「I don't care how much smarter it is, it needs to be in the Pareto frontier. That is what the brand of Jev is. It is the best thing at intelligence per dollar.」 —— Diogo Almeida，談 Jev 嘅定位與「intelligence per second」嘅分別

呢句值得停一停：佢將「intelligence per second」（實時、少數毫秒敏感行業，正如佢講「每減一半 100ms 以下延遲＝double intelligence」）同「intelligence per dollar」明確分開，並宣佈 Jev 唔會主打前者。呢個係一個市場定位選擇，唔係技術突破宣稱。

二、RLHF 的結構性缺陷：mode dropping（＝mode collapse）

全集技術含金量最高嘅一段，係佢拆解「點解 Yann LeCun 嗰張『LLMs are doomed』圖，數學上顯然、經驗上明顯唔成立」。佢嘅答案係 mode dropping——而且佢直接話「mode dropping 同 mode collapse 係同一樣嘢」。

佢嘅推理鏈係咁：

  1. 一張覆蓋整個分佈（mode covering / calibrated）嘅模型，會容許自己「有時 out of distribution、有時 in distribution」——即係會有時錯。呢個係舊式（GAN 之前）模型嘅行為：影像偏模糊。
  2. 但 GAN 選擇 mode drop——丟棄少數類別，只做最常見嗰啲。
  3. 同理，要生成極長字串而唔出錯，模型必須「極度保守」，因為錯誤好易被看見，而微妙嘅偏差好難被看見。
  4. 而呢種「校準」係對字串機率分佈嘅劇毒（total poison into the probability distributions of strings）。
「Strings are so bad at decision-making… overloading the string models for decision-making is a bad time.」 —— Diogo Almeida，談 RLHF 嘅 mode dropping 為何令字串不適合承載決策

佢進一步將大眾抱怨嘅一切，都歸因於呢個結構性缺陷：sycophancy（諂媚）、overconfidence（過度自信）、hallucination（幻覺），甚至 LM Arena 式排版（粗體、斜體、emoji、長篇大論再反問你一句）。佢嘅原話係：「呢啲全部係因為 strings 係好奇怪嘅嘢，你必須 miscalibrated、必須 mode drop、必須 hyper-confident，先唔會 off the rails，因為 reward model 一旦見到明顯錯誤就會狠狠懲罰你——而咁樣會扭曲整個機率空間。」

技術要點 mode covering vs mode dropping：前者保留少數模式、容許偶爾出錯，代價係模糊；後者丟棄少數模式、追求字面上唔出錯，代價係「對字串機率分佈有毒」。Diogo 認為 LLM 係後者，而呢個正係「點解 AI 可以解千禧年難題、但自動化唔到最基本嘅文書工作」嘅深層原因。
三、RLCD：第三條北極星

Diogo 把後訓練嘅歷史拆成三次「北極星」：

家族北極星（佢嘅定義）佢嘅批評
RLHFplease humans（討好人類）→ 幻覺、諂媚、永久依賴人類；且係 instruction following 嘅副產品
RLVRoptimize benchmarks（其實就係優化 benchmark）→ 解到 Navier–Stokes，但加劇 jagged intelligence；同其他軟件整合差
RLCDmake it reliable for programmatic use（未發表嘅新技術；TypeSafe 自家路線）

佢對 RLVR 嘅批評最有結構性：「RLVR 嘅北極星其實就係 optimize benchmarks」——因為 benchmark 按定義就係「可被程式驗證嘅簡單輸出」，所以模型在數學上呈 fractal（分形）式 jagged：唔止「有尖峰」，而係「放大之後仍然有尖峰」。

「RLHF is please humans… RLVR is optimize benchmarks… And RLCD is make it reliable for programmatic use.」 —— Diogo Almeida，三條北極星嘅一句話對照

佢亦強調「RLHF」一詞本身被混淆使用：第一代係 Christiano 等 2017 年教機械人後空翻（ill-specified output），第二代係 OpenAI 嘅 learning-to-summarize（PPO on language models），而佢本人參與嘅係第三代 InstructGPT（Ouyang et al. 2022）。佢話「我稱之為 RLHF 嘅，係 instruction following 呢個任務，唔係 PPO 呢個 algorithm——algorithm 唔重要，北極星先重要」。

四、the bitterest lesson：任務與數據勝過算力

呢段係佢整套世界觀嘅地基，亦係佢離開 OpenAI 創業嘅真正理由。佢引 Sutton「algorithms beats compute」再推一步：

「You get what you optimize for and the bitterest lesson in ML is that the most important part of it isn't ML at all.」 —— Diogo Almeida，the bitterest lesson

由此推出兩個自稱定位：

  • TypeSafe 係 data lab，唔係 model lab。「Model capabilities means data. Data is so unbelievably complicated, and that is what gets nines.」佢話 onboaring data 員工嘅內部 talk「比呢集播客仲長」。
  • 數據全為合成，並拒用用戶數據——即使可以用。理由有兩個：① 真實世界數據有 power law 偏差（人人問同一樣嘢），會令模型 overfit 到「現在」；② 佢瞄準嘅係「幾年後嘅科幻未來用例」，要為未出現嘅情境準備。

佢用一個好形象嘅比喻：「LLM 係 UDP，我哋係 TCP」——上面可以疊好多層、被好多唔可想像嘅東西建構。亦因此，data team 嘅職責係「研究呢個 cognitive core、找出 jaggedness、然後手術式修補」，覆蓋「過去／現在／未來所有維度」。

數據形狀 Diogo 強調「數據同合成數據取決於任務」——RLHF 嘅數據係人類反饋；RLVR 嘅數據≈環境／可驗證獎勵；RLCD 有自己獨特嘅數據形狀。佢刻意指出：RLVR 不只係 reward 唔同，仲有「shape」同內嵌嘅 reasoning（一個 latent variable）。
五、反公開 benchmark；可靠性 ≠ 確定性

① 公開 benchmark 極易被 game

佢嘅態度非常鮮明：強烈反 public benchmark、中性對 private proxy benchmark。原因唔止「可以作弊」，而係一種結構性扭曲：

「Public benchmarks are antithetical to this… they are extremely gameable. Back in the old days, every lab had a team to collect data that looks like MMLU to make it look better, which is just benchmarking with extra steps.」 —— Diogo Almeida

佢嘅替代方案係：「vibes and trust」（直到你把模型放進具體 workflow 自測）。內部 evals 當然有——「但要有紀律唔好 game 佢」，並且「唔好呃自己個模型有幾聰明」係佢最看重嘅鐵律。佢甚至承認：「I don't believe in benchmarking」係佢延遲發佈嘅原因之一，並且「去年融資時冇人信我哋，因為佢哋只想要 benchmark」。

② robustness > determinism

swyx 問「冇 seed、同輸入會唔會同輸出？」Diogo 嘅回答係一個重要區分：determinism（同輸入→同輸出）係錯嘅北極星，robustness（相似輸入→相似輸出）先係關鍵。佢嘅測試方法好實用：往 prompt 塞 nonce（UUID），睇輸出係唔係語義上仍然穩定。佢承認可以為特定用例做 deterministic 模型，但「嗰樣嘢係用 intelligence per dollar 換返嚟嘅」。

六、最具爭議：反 safety alignment／「refusal 係 type error」

呢段係本集最可能引戰嘅部分，亦係佢 Discord 上被問得最多嘅問題（「你點解反對 safety alignment？點解唔 refuse？」）。佢嘅立場要逐一拆開：

  • 「我唔反對 safety 呢個原則，但我反對 safety alignment，因為佢一般係同用戶 misaligned 嘅。」
  • 「Refusal 就係明顯嘅 type error。」佢嘅場景係：你喺 Claude Code 裡面做嘢，忽然彈一句「I'm sorry, I can't read DNA.py」——「你頂得順，因為你有 Stockholm syndrome」。但如果呢個係一個跑喺背景嘅 dependency 呢？「你想你套軟件因為有人傳咗句奇怪 message 就隨機崩壞？」
  • capability alignment vs safety alignment：前者係「做用戶想嘅事」（對軟件工程師係好事，越可預測越唔使測試）；後者係「跟隨別人（OpenAI／Anthropic）嘅指令」。佢承認後者對 ChatGPT 呢類產品合理，但「喺 API 層就係 nuts」。
  • 對「用嚟殺人」嘅回應：swyx 直接 pushback「如果被用嚟殺人呢？」Diogo 答：「我當然希望唔好，我會用其他方式（開源、慈善）去影響，但我絕對唔會喺技術層做，因為每次你為某啲奇怪用途 overfit，都係喺 fracturing its intelligence。」
「I think intelligence will be more like a database than a coworker. I don't think it's up to databases to add checks on whether or not they're used for something that's not great.」 —— Diogo Almeida，談為何 API 層不設 refusal

佢嘅世界觀係：模型應該「像 regex 一樣不起眼」地消失在背景；而「refusal 應該係一個問題＋閾值嘅組合」——即唔係問「要唔要拒絕」，而係問一串獨立小問題再設閾值。

七、API 原語：choice／score／noulli

呢段對正在用 Jev 嘅人最實用。三個原語都係故意新造嘅概念，唔映射到 int／float，目的係唔要被 Instructor／Pydantic 式映射「cook」掉：

原語對應編程原語說明
choiceenum 上嘅 switch／match「最接近 function call，但 function call 係好 disgusting 嘅嘢」
noulliif 陳述名取自 Bernoulli；「Bool-ish 但連續」，因為「對我哋嚟講所有嘢都係機率」
score排序／閾值比較（>、<）類似 LM judging，但係一個獨立類型

更實用嘅係佢對「點用」嘅建議：

  • 結構化 state／instructions／criteria——全部可以係 JSON object；「如果你仲係砌 template 或者塞入 system message，你係用緊舊思維」。
  • 「System message 係噁心嘅 global variable」——你將所有 instruction 塞一齊，然後希望每一句都中。應該由程式把結構插到正確位置。
  • 拆成大量平行嘅小問題——「The biggest saving grace… AI code bases are gonna be so much better」，因為每個小決策「extremely evaluable」。
  • 省錢技巧：為長 state 裡面每條 message 掛 ID，只付一次 state 成本，然後對每個 ID 並行提問。
  • thresholding 係用戶主要槓桿；目前不提供 fine-tuning，但可以想像「calibration + model cascade」（不確定就升級去更大模型）。
八、coding agents 與 KV cache 的暴政

係全集最具前瞻性嘅一段。Diogo 認為 Claude Code／Codex 係當前前二贏家，但佢哋都建基於「單一模型世界」；而 KV cache 正係嗰個鎖：

「It locks you into one model… in order to do it efficiently, you need to keep on appending to it. So now you're not doing best software practices, like state management, abstraction, decomposition.」 —— Diogo Almeida，談 KV cache 如何鎖死 coding agent 嘅設計空間

佢話呢篇《KV cache Rules Everything Around Me》可以解釋三件業界一直覺得難嘅事：① routing 為何難、② sub-agent 為何唔 work、③ compaction 為何難——全部係「state 要點傳遞」嘅成本問題。而佢想去嘅未來係：「一旦 context 變便宜」，就可以做「標籤化子任務樹 ＋ 按需檢索歷史 context」；甚至多 agent 之間可以「讀彼此嘅 state」、「唔係用低能 lock，而係 Jev 決定邊個先寫」。

佢仲提出一個好深嘅觀察：「continuous learning 其實係一個 memory management 問題」——因為你冇一個聰明嘅方式去 lookup memory，所以每次都要從零開始。

速度場景 佢提到 computer use 同 遊戲 係「速度型」用例——因為每減一半 100ms 以下延遲＝double intelligence。佢自己最想做嘅「fun one」係「會思考嘅遊戲 NPC」（唔一定 call 遊戲 loop，state machine 就夠）；而 Ali 嘅 Doom demo（NPC 控制場景）係佢眼中嘅 proof of concept。
九、經濟觀與 neo-lab 批評

① TFP growth > 3% ／ 5 年，自動化 ≈ 0

佢講出一個罕見嘅宏觀指標：「5 年內 TFP growth 超過 3%」。swyx 話「我從未見過一間 lab 在意 TFP growth」。Diogo 嘅邏輯係：呢個先係「經濟革命」嘅定義，亦係 OpenAI 憲章舊日嘅精神（majority of the world's economically valuable work）。佢認為今日所有模型對「有經濟價值嘅工作」嘅自動化大約等於零（「我猜仲唔夠 1%」），而當佢真係發生，會出現喺經濟統計數字上面。

「It will not cause mass unemployment, but it will cause a whole bunch of awesome shifts… I'm really tired of AI always being the foreground character.」 —— Diogo Almeida，談宏觀影響

② inverse SaaS-pocalypse

佢提出一個反直覺預測：SaaS 唔會被 AI 取代，反而會被 AI 增能（inverse SaaS-pocalypse）。論據好具體：「2019 年嘅軟件好值錢，2026 年嘅軟件基本上完全一樣，除咗有時側邊多咗個 chat box」——因為 AI 唔被信任去做「公司有 stake 嘅決策」。而 SaaS 公司係「最知道邊啲嘢值得自動化」嘅人。

③ 「多數 neo-lab 係 crap」、「我唔 value researchers」

呢段係全集最得罪人嘅一段。佢原話：

「My sense is that most neo labs are crap… they are redoing work from scratch with a low probability of actually moving the frontier… they don't really have a direction.」 —— Diogo Almeida，談 neo-lab 生態

佢進一步講：「I don't really value researchers. I value people who give a lot of fucks about the right task.」——「當人們重視純研究 pedigree 而唔係『做正確任務』，係本末倒置」。同時佢亦講「如果你給我十億美金，我唔會 pre-train……Frankensteining 唔優雅但解決問題」，並將 mid-training 定義為「本質上係省成本手段」。

十、開放問題與爭議點
  • 「refusal 係 type error」係唔係混淆咗兩個層次？Diogo 嘅論證建立喺「API 應做成 software primitive」之上；但 frontier lab 嘅 refusal 係針對「模型權重本身嘅風險」，而唔係「某個 dependency 嘅錯誤處理」。技術層面「唔設限」同社會層面「唔想被用嚟殺人」之間，佢選擇咗前者。Theo 已公開 pushback（Diogo 亦寫咗 KV cache 一文回應）。
  • 「fracturing intelligence」係唔係一個可證偽嘅講法？呢個概念係全集嘅理論核心（refusal 會 fracture、多目標優化會 fracture），但佢冇提供任何公開度量方式——即係佢自己主張嘅「robustness/nonce 測試」都未必量度得到。
  • 1 兆 tokens／日、38M 觀看、Discord 10 萬人——全部係公司／受訪者一手口徑，未經第三方復現。Diogo 亦承認「signups 唔重要」，所以「用量」嘅真實性係呢間公司最需要被外界檢驗嘅部分。
  • RLCD 未發表、無同儕評審——佢自己講「not yet published」。所以「第三條北極星」今日仍然係一個主張，而唔係一個已被驗證嘅結論。
  • 「Jev everything」會唔會係新一輪 overpromise？swyx 直接問「咩係 System 1 問題、咩唔係」，Diogo 答「that's a hard one」——然後話「呢個係 empirical problem」。即係話，連佢都認為邊界未清。
