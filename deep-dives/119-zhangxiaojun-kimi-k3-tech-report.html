「領讀」係張小珺節目一種好新嘅形態：唔係訪問一個人，而係帶住聽眾逐段讀一份 47 頁嘅技術報告。對象係月之暗面（Moonshot AI）2026 年 7 月 27 日全量開放權重嘅 Kimi K3——全球首個開源嘅「三萬億級別」MoE 模型（報告口徑約 2.8 萬億參數）。本集想解答嘅問題好具體：呢隻巨獸點樣訓練得起、推得動？一百萬 token 上下文點樣唔爆顯存？一個 base model 點樣煉成一個識幹活嘅 agent？答案唔係乜嘢新科學，而係四條工程路線——線性注意力、MoE、RL、系統工程——組合到開源世界天花板嘅「偷懶嘅藝術」。

一、呢集係咩：一份 47 頁報告，拆成三個「靈魂問題」

Kimi K3 喺 2026 年 7 月 27 日發布完整開放權重，定位一句講晒：能力咬住閉源前兩名（Claude Fable 5、GPT-5.6 Sol），穩坐開源第一，成本只有對手嘅幾分之一。張小珺今集冇請嘉賓，改為帶住聽眾將成份報告拆成三個靈魂問題：

  • 2.8T 嘅大家伙，點樣訓得起、推得動？ → 架構「三板斧」：KDA + AttnRes + LatentMoE
  • 100 萬 token 上下文，點樣唔俾顯存炸爆？ → 換一種「記憶方式」：固定大小嘅筆記本，取代無限增長嘅會議記錄
  • Base model 點樣練成一個識幹活嘅 agent？ → RL + 九個領域專家蒸餾回一個模型

呢個 framing 本身就係張小珺今集最重要嘅判斷：K3 嘅架構創新唔係炫技，而係工程約束下嘅設計取捨——每一個「靚位」背後都有一條成本或者數值穩定嘅理由。聽完你會發現，呢份報告最值錢嘅唔係某一個 breakthrough，而係佢展示咗「前沿級開源模型」成套嘅工程解法。

二、全景：K3 嘅架構可以用三句話講完

成個架構三句話：token 維度靠 3 層 KDA + 1 層 MLA 混搭；深度維度靠 AttnRes 跨層查檔；寬度維度靠 LatentMoE 稀疏調用專家。先感受下 K2 → K3 嘅體格變化：

K2 → K3 ① 總參數：1.04T → 2.78T（×2.7）；激活參數：32.6B → 104.2B（×3.2）
② 層數：61 → 93（+52%）；專家數：384（每 token 激活 8）→ 896（每 token 激活 16）
③ 訓練上下文：128K → 1M（×8）；注意力：全 MLA → 69 層 KDA + 24 層 MLA 混合
④ 綜合 Scaling 效率：2.5×——同等 loss 慳 60% 算力

「混合」係成集嘅關鍵詞——75% 平價層 + 25% 貴價層 ≈ 全部貴價層。呢個唔單止係 K3 嘅架構哲學，張小珺喺度特別指出：呢個同緩存、數據庫、索引嘅分層設計係同一個道理——「混合」打敗「純粹」，係 2026 年大模型工程嘅一條隱藏主線。

三、第一板斧 KDA：將「無限增長嘅會議記錄」換成「固定大小嘅筆記本」

傳統 attention 嘅痛點：每嚟一個 token，都要同之前所有 token 重新算一次關係，KV cache 無限變長——好似一場永不散會嘅會，每頁發言記錄都要永久存檔。KDA（Kimi Delta Attention）係線性注意力嘅一種：無論序列幾長，只維護一個固定大小嘅筆記本 S，成本 O(n)、緩存恆定。

筆記本每嚟一個 token 做三個動作：褪色（forget gate α 令每個通道嘅舊筆記按各自速度變淡）、擦除（delta rule——寫入前先將舊值精準擦走，呢個係佢同普通線性注意力嘅關鍵分別，防止內容越疊越糊）、寫入（新內容按強度 β 落筆）。

報告入面最靚嘅一個工程細節：數學上「1/累計衰減」會指數級膨脹，BF16 裝唔落就會溢出。K3 嘅解法係俾褪色速度設一個下限——用 sigmoid 將 log-decay 壓入 (-5, 0)——16 個 token 嘅累計衰減倒數最大 e⁸⁰，啱啱卡喺 BF16 動態範圍入面。一個數值穩定性嘅小改動，令成條計算路徑都可以跑滿 Tensor Core，直接消滅咗最慢嘅 kernel 分支。

兩個配套設計都值得記住：3:1 混搭——光靠筆記本會丟全局細節，所以每 4 層插 1 層 Gated MLA 全量注意力「開全員大會」；NoPE（無位置編碼）——唔顯式存「第幾個位置」，靠筆記本嘅衰減自然感知遠近，上下文由 8K 一路擴到 1M 完全唔使改位置編碼。

「注意力美學」——K3 嘅架構設計被解讀為有美學追求：896 專家 + 16 激活嘅 MoE 配置、KDA 混合注意力機制，本質係喺「大容量」與「低成本運行」之間搵平衡，同時解決百萬 token 長文本嘅注意力計算難題。架構創新唔係炫技，而係工程約束下嘅設計取捨。 ——張小珺 Ep.152 對 K3 架構嘅核心解讀
四、第二板斧 AttnRes：將 attention 嘅思想搬去「深度」方向

普通殘差連接好似傳話遊戲：第 93 層只可以攞到第 92 層傳過嚟嘅話，前面 91 層嘅細節全部被壓扁喺一個向量入面。AttnRes 嘅思路好直接：每層帶一個可學習嘅「查詢詞」，主動去檢索 embedding 同所有前序 Block 嘅輸出——想要邊個嘅資訊就攞邊個嘅。

93 層切成 8 個 Block，塊內先求和壓縮、塊間再做檢索，開銷可以忽略，實驗上 N=8 就能攞返大部分收益。呢個設計嘅意義在於：資訊流唔再係「逐層轉交」，而係「按需直達」——attention 原本係橫向（token 之間）嘅選擇機制，K3 將佢延伸到縱向（層之間），令深層網絡唔會因為層數增加而「訊息稀釋」。

五、第三板斧 LatentMoE：896 個專家嘅「分診藝術」

MoE 嘅核心矛盾：專家越多知識容量越大，但每個被揀中嘅專家都要收一份 7168 維嘅完整 token 表示，通信同顯存跟住爆。K3 嘅三連解法：

  • 先壓縮再送診：token 先被 W↓ 壓成 3584 維「簡報」，專家喺簡報空間入面幹活。於是專家數翻倍（384→896）、激活數翻倍（8→16），通信量卻冇漲。
  • SiTU-GLU 激活函數：SwiGLU 嘅兩個相乘因子都無界，2.8T 尺度下會數值爆炸。SiTU-GLU 俾兩個分支都裝上 tanh「限高桿」（輸出硬上限 100），原點附近同 SwiGLU 一階等價——形狀不變，永遠唔會失控。
  • QB 分位數均衡：傳統 MoE 靠輔助損失逼負載均衡（傷性能），K3 改成俾每個專家加一個「排班偏置 b」——b 只影響邊個被揀中、唔入梯度、唔改權重。每步訓練後按分位數調：太火嘅專家降分、冷門嘅加分，直到每個專家接待量精確達標。工程上用直方圖估分位數，一次 all-reduce 只傳幾百個 bin，幾乎免費。
稀疏度 每個 token 只激活 16/896 個專家 ≈ 104B / 2.78T ≈ 1/27。知識容量（2.8T 總參數）同推理成本（104B 激活）徹底分離——呢個就係「大而慳」嘅全部秘密。
六、後訓練：先分頭練出 9 個專家，再蒸餾返一個模型——「冇單一超級教師可抄」嘅中國解法

今集技術含量最高嘅部分，係後訓練嘅多教師同策略蒸餾（MOPD）。流程係：K3 先喺九個領域各自強化學習，煉出 9 位「各懷絕技」嘅領域專家模型；再用 MOPD 融合——俾定查詢 x 同領域/難度條件 e，由對應嘅教師模型提供指導；學生模型喺自己生成嘅軌跡上、逐 token 接受「對應領域、對應力度」教師嘅打分指導。

用戶最後拿到嘅唔係 9 個模型，而係一個可以喺低/中/高/最高檔推理強度之間自由切換嘅統一 K3。呢個設計有兩層深意：

第一層，係「思考預算控制」。每題先發預算 b₀(x)，輸出超 τ·b₀ 直接獎勵 -1。先訓 max 檔，再退火出 high/low 檔——模型自己學會「簡單題咪過度思考」。仲有「防話癆」：GRM 打分時回答長度超 σ·ℓ₀ 直接判負，專治 reward hacking 嘅囉嗦傾向。

第二層，係中國實驗室嘅路線選擇。張小珺喺度點出一個好重要嘅行業觀察：多教師蒸餾路線說明中國實驗室喺「冇單一超級教師可抄」嘅前提下，用領域分工 + 蒸餾融合嚟逼近閉源前沿——呢個正正係矽谷討論「中國模型進步唔可以全歸因於蒸餾」嘅技術證據。DeepSeek 時刻嘅敘事係「性價比替代品」；K3 時刻嘅敘事已經變成「直接開源前沿級權重」嘅戰略姿態。

學生模型喺自己生成嘅軌跡上、逐 token 接受「對應領域、對應力度」教師嘅打分指導——用戶拿到嘅唔係 9 個模型，而係一個能喺低/中/高/最高檔推理強度之間自由切換嘅統一 K3。 ——MOPD：多教師同策略蒸餾嘅核心機制（Kimi K3 技術報告）
七、基建：2.8T 唔係堆卡就搞掂

報告最被低估嘅部分係基建。張小珺今集花咗唔少篇幅，因為「agent 能力 ≈ 環境複雜度」——K3 嘅 agent 能力係 5,122 萬個沙箱餵出嚟嘅。六個工程難題同對應解法：

  • FlashKDA：KDA 遞歸本質係串行，GPU 唔鍾意——chunk 內並行、chunk 間流水重疊。
  • KCP：1M 上下文並行訓練——將每段嘅狀態轉移分解成可本地計算嘅兩部分，一次 all-gather 搞掂——線性 attention 嘅通信量與序列長度無關。
  • MoonEP：專家並行負載不均、顯存碎片——每個 rank 精確收 S×K 個 token，冗餘專家 ≤ E/R（有數學證明），shape 全靜態免同步。
  • 外部 KV 池：1M agentic RL 嘅 KV cache 顯存放唔落——GPU 逐出嘅前綴寫返 CPU DRAM，KDA state 與 MLA KV 生命週期對齊。
  • AgentEnv：agent 將容器沙箱搞到 kernel panic——Firecracker microVM，支持暫停/分叉/快照（checkpoint 133ms）；成個訓練共創建 5,122 萬個沙箱、150 萬個鏡像。
  • 預算制准入控制：1M token 長請求擠死 2K 短請求——長短請求各有獨立資源池，互不餓死。
規模數字 ① AgentEnv：5,122 萬個沙箱 + 150 萬個鏡像，checkpoint 快照 133ms
② 訓練任務：知識圖譜自動擴展出題、mock Gmail/Notion/Slack「連續幹活好幾日」助理任務、GPU kernel 優化（獎勵 = 正確性 + 逼近 roofline 程度，仲配反作弊系統）、黑盒系統復刻
③ 數值穩定：sigmoid 將 log-decay 壓入 (-5, 0)，16 token 累計衰減倒數上限 e⁸⁰，啱啱卡喺 BF16 動態範圍
