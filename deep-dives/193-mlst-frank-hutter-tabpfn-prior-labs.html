「一次前向傳播，唔需要特徵工程」——MLST × Frank Hutter：TabPFN 點樣用合成先驗攻破最唔 glamorous 嘅表格資料，同 AdamW 作者嘅工具鏈史

📅 2026-09-23 17:56 UTC·🎙 Machine Learning Street Talk（主持 Tim Scarfe）·👤 嘉賓：Frank Hutter（Prior Labs 共同創辦人，前弗萊堡大學機器學習教授）·⏱ 長訪談（含 TabPFN-3.5 補錄）·🏷 表格基礎模型 × AutoML

金融、醫療、公衛、科學——世界上大部分「預測」其實都發生在表格上，而呢個領域深度學習攻咗十幾年都攻唔下，一直由 XGBoost / CatBoost 呢類梯度提升樹（GBDT）統治。Frank Hutter 呢集講嘅係：TabPFN 用「合成先驗」預訓練，喺一次前向傳播內完成預測，唔需要逐資料集訓練、唔需要超參數搜索，並且打敗傳統 ML。而佢本人嘅履歷——AdamW 共同作者——令呢集多咗一層「深度學習工具鏈史」嘅意義。以下內容按 MLST 官方 RSS Show Notes、Prior Labs 官方 TabPFN-3.5 頁與訪談逐字稿要點整理；引號為中文意譯。

一、一句話總結

核心命題只有一句：表格資料一直輸，唔係因為深度學習唔夠強，而係因為缺乏一個「表格嘅 ImageNet」。TabPFN 嘅解法相當聰明——既然真實表格資料稀缺、又散落各處（兼涉隱私），就唔用真實資料，改用從結構因果模型（Structural Causal Model, SCM）先驗生成嘅合成資料集去 meta-train 一個 transformer。推論時，把整張訓練表當 context 一次餵入，直接輸出貝氏後驗預測分布嘅近似——一句講晒：「一次前向，唔需要特徵工程」。

「TabPFN 係一個表格基礎模型，喺一次前向傳播內完成預測……佢喺『結構因果模型先驗』上生成嘅合成資料集上預訓練，而唔係喺真實資料上。預測時佢把整張訓練表當 context，輸出一逼近貝氏後驗預測分布嘅結果——冇逐資料集訓練、冇超參數搜索。」 —— MLST 官方 RSS 節目簡介（原文英譯）

二、Frank Hutter 係邊個：一部深度學習工具鏈史

理解本集嘅份量，先要理解講者。Frank Hutter 係 Prior Labs 共同創辦人，此前任德國弗萊堡大學機器學習教授約 12 年。佢嘅履歷幾乎就係現代 ML 工具鏈嘅一條主軸：

  • AdamW 同 Cosine Annealing 嘅共同作者——「世界上每個 transformer 嘅訓練都在用」。呢點令本集多咗一種「造工具嘅人回頭用工具」嘅況味。
  • AutoML 領域奠基者之一：創辦 AutoML 研討會系列、寫咗首本 AutoML 專書、首個 AutoML MOOC。
  • Neural Architecture Search（NAS） 早期論文作者之一（Auto-WEKA 等）；經典綜述「Neural Architecture Search: A Survey」。博士論文由 Holger Hoos、Kevin Leyton-Brown、Kevin Murphy 共同指導。
  • 歷史起點：AutoML 源自一個十分具體嘅痛點——SAT solver 要接受數百種解法，逐一手動決定參數；Kaggle Otto Group 產品分類競賽（2015）係重要節點。
個人史即一條方法論弧線：由「用手調 SAT solver 參數」→「用 ML 搵自己演算法嘅最佳參數」→「用 ML 搵 ML 演算法嘅最佳超參數（AutoML）」→「直接學一個學習演算法本身（learned algorithm）」。TabPFN 就係呢條弧線嘅最新一站。

三、為什麼表格咁難：冇 ImageNet

Hutter 嘅診斷好直白——表格「很髒」：缺失值、類別特徵、特徵工程、語意轉換，全都需要人工判斷。佢形容每次做完都「覺得有點髒」：

「表格資料非常髒……你做完之後總覺得有點髒，因為你感覺自己對它做了各種降維、不知怎麼就把它弄壞了。」 —— Frank Hutter（中文意譯；節目內容）

更深層嘅問題係資料。互聯網上嘅表格大約有數萬到數百萬張，但多數係維基百科球員表（「背號」）嗰種表格（table），而唔係能學統計規律嘅資料集（dataset）；真正可用嘅大約只有 5 萬個，而且人們唔會主動把表格放上網——因為「唔 glamorous」。呢個就係對照：圖像有 ImageNet、文本有 Common Crawl，表格冇一個夠大、夠乾淨嘅公開語料。

對比圖像有 ImageNet、文本有海量語料；表格領域只有約 5 萬個真正可用資料集，且大家唔會把表格放上網。→ 剛需：自己造資料。

四、解方：合成先驗與結構因果模型（SCM）

既然真實表格資料稀缺、又涉隱私，TabPFN 選擇完全用合成資料訓練——從結構因果模型（SCM）嘅先驗生成大量合成資料集，令模型學習逼近任意先驗下嘅貝氏後驗預測分布。呢個做法有兩個立竿見影嘅好處：

「我們是第一個（表格）基礎模型，完全在合成資料上訓練——這很好，因為我們沒有洩漏、沒有記憶化問題，可以直接控制資料裡到底有什麼。」 —— Frank Hutter（中文意譯；節目內容）
  • 冇測試集洩漏：資料係自己造嘅，同 benchmark 嘅真實資料集完全隔離。
  • 冇記憶化：模型唔可能「背」咗某個真實資料集嘅答案。
  • 可控性：可以精確設計先驗裡有咩因果結構、噪聲、缺失模式。

而「合成資料先驗」亦係一個繞過資料稀缺同隱私嘅通用手法——同近期各界「用生成資料訓練」嘅大趨勢同源。

五、learned algorithm：合成資料上嘅「學習演算法」

Hutter 用「learned algorithm（學到嘅演算法）」描述 TabPFN 嘅本質：你唔再為每個新資料集寫／搜一個 pipeline，而係事先 meta-learn 一個能泛化到新資料集嘅學習演算法。佢喺數億個合成資料集上 meta-training。呢個係 NAS 嘅自然終點——由「搜架構」走到「搜／學整個學習演算法」。

用 ML 歷史嘅語言講：AutoML 自動化咗「選模型與調參」，TabPFN 想自動化埋「由資料到預測嘅整段推理」。

六、一次前向嘅貝氏預測：為何「重」但「快」

呢個係理解 TabPFN 性能嘅關鍵直覺。訓練表可能好大——Hutter 舉嘅尺度係一百萬列 × 一千行，即約十億個元素；若強行 tokenize 成 LLM 上下文，會係約 30 億 token。TabPFN 唔係咁做——佢以表格為原生輸入，喺一次前向傳播內出結果。所以佢係一部「很重、但很快」嘅模型：重喺預訓練與 context 承載，快喺推論階段唔需要任何 per-dataset 訓練／調參。

機制整張訓練表 → context → 一次前向 → 貝氏後驗預測分布嘅近似。零特徵工程、零超參數搜索、零逐資料集微調。

對實務嘅意義好直接：企業 ML 嘅默認工作流係「清洗 → 特徵工程 → 選模型 → 調參 → 交叉驗證」；TabPFN 把中間一長串壓縮成一次 predict call。「Predictions in seconds, not months」——呢個係產品頁嘅原話精神。

七、TabArena：表格界嘅「LM Arena」

要證明「打敗 XGBoost / CatBoost」呢個 claim，就要有可信嘅評測基建。呢個就係 TabArena（Erickson 等）——被形容為表格界嘅「LM Arena」：

  • 用 Elo 分數排名；完全開放（公開所有預測與可複現代碼）；
  • 跑一次 GPGPU 對比約2 美元，人人可做——極低邊際成本令「第三方驗證」變成常態；
  • 第一作者 Nick Erickson（原 AWS、AutoGluon 作者）與數位作者已加入 Prior Labs。

呢個係「競技場化（Arena）作為評測基建」嘅範例——把 LM Arena 模式橫向複製到新模態，用開放＋低成本去對抗廠商自報口徑。

八、架構 v1 → v3：output head 與更大嘅表

訪談涵蓋 TabPFN 嘅架構演進（v1 2022 → v2 登上 Nature 2025 → v3 / v3.5），包括 output head 嘅設計。重點唔在每個細節，而在方向：由細表走向大表（官方稱 TabPFN-3.5 已能原生處理多達 1,000,000 行），以及更快嘅推論（kv-cache 令部分場景加速約 840×；官方稱比之前版本快約 20×、大規模下可達約 1000×）。

值得一提嘅係 v2 登上 Nature（Hollmann et al., 2025）——「Transformers Can Do Bayesian Inference」（Müller et al.）係其理論前身。呢個令 TabPFN 唔只係產品，亦係有同行評審背書嘅科學成果。

九、擴展到大表、coding agents、test-time compute

訪談中段幾個實務主題：

  • 擴展到大表：如何令架構喺更大、更寬嘅表格上仍然有效。
  • 用 coding agents 操作 TabPFN：把 TabPFN 當工具交畀 agent 調用嘅工作流。
  • test-time compute 與適應：推論時加算力（「Thinking」模式）可以再提升表現——官方 TabPFN-3.5 頁即標榜「with Thinking 對傳統 ML 有 99% 勝率」。

呢幾點指向一個更闊嘅圖景：表格基礎模型唔係「一個靜態模型」，而係一個可以被 agent 調用、可以喺推論時加算力嘅組件——同 LLM 生態嘅演進路徑趨同。

十、Google TabFM 與競爭

訪談直接討論咗 Google 嘅 TabFM（表格 zero-shot 基礎模型）作為競爭對手。呢個係一個健康嘅訊號：表格基礎模型賽道已經唔止一家。官方產品頁亦列出多個競品／相關工作：TabICL / TabICLv2、TALENT benchmark、Do-PFN、CausalPFN、Causal Foundation Models with Partial Graphs 等。對用家而言，競爭意味住「打敗 GBDT」呢個 claim 會被多方交叉檢驗。

十一、先驗點設計、因果與干預（interventions）

呢段係本集最有研究深度嘅部分——先驗係點設計同修訂嘅。合成資料嘅質素完全取決於先驗；先驗太窄，模型泛化唔到；先驗太闊，模型學唔到結構。Hutter 亦延伸到：

  • 相關性 vs 因果：SCM 框架天然連接因果推論——Do-PFN（因果效應估計）、CausalPFN（帶部分圖嘅因果基礎模型）；
  • 干預（interventions）：唔止預測「見到咩」，仲要回答「如果我咁做，會點」。

呢個把 TabPFN 由「更強嘅預測器」推向「可干預嘅決策工具」——對金融風控、醫療決策、政策評估呢類唔可以亂做 A/B test 嘅場景，意義重大。

十二、關聯與多模態資料、組織落地、開放研究分支

  • 關聯資料（relational）：真實世界嘅表格往往跨多張表（外鍵關聯）。相關工作：RelBench、RelArena-α、TabPFN-Rel、RPI。
  • 多模態：表格唔再係純數字——官方產品頁展示「自由文本當特徵讀」（例如維修單據嘅自由描述：「cracked bracket, water ingress at the seal…」）、「數千個 distinct ID 無需編碼」（SKU 編號直接餵入）、「每行數百個測量值」。
  • 組織使用：官方列舉 Affirm（風控與決策模型）、Hitachi Rail（鐵路預測性維護，官方稱偵測軌道異常準確度提升 40%）、liquid biopsy／蛋白組學肺癌檢測（Simon Meier）、Databricks（Dael Williamson 形容「單次前向嘅生產級預測，通常以秒計」）。
  • 開放研究分支（open research arm）：Prior Labs 有專門嘅開放研究部門——呢個係商業公司維持學術連結嘅常見設計。

十五、爭議與存疑（筆者判讀）

  1. 「打敗 XGBoost / CatBoost」係廠商基準：主要來自 Prior Labs 自家參與嘅 TabArena。雖然 TabArena 主打開放可複現，但「自家模型自家榜」嘅結構性利益衝突仍需第三方獨立檢驗。
  2. 「合成資料真無洩漏」值得持續檢驗：先驗設計嘅自由度極大，外界會問——benchmark 上嘅優異表現，係否部分反映咗先驗恰好覆蓋咗這些任務嘅結構？Hutter 嘅回應係 benchmark 用真實社群資料集而非合成資料，且每步策展都有精確文件記錄。
  3. 「99% 勝率」附帶「with Thinking」條件：呢個係 test-time compute 換嚟嘅表現，同「一次前向就贏」嘅直覺有落差——成本模型唔同。
  4. Google TabFM 嘅競爭：一個巨頭嘅 zero-shot 表格基礎模型，會直接壓力測試 Prior Labs 嘅護城河——尤其當「表格基礎模型」開始商品化。
  5. 由預測到決策嘅跳躍：因果／干預（Do-PFN、CausalPFN）係更高風險嘅 claim，因為「干預效應」嘅 ground truth 往往冇得驗。

十六、帶走：三條可重用嘅框架

  1. 「冇 ImageNet」係一種通用診斷：當一個模態深度學習打唔贏傳統方法，先問一句——「係模型唔夠強，定係我哋冇一個夠大夠乾淨嘅資料集？」若係後者，出路唔一定係等資料，而係用一個好嘅生成先驗自己造（合成先驗 ≈ 可控制、無洩漏、無隱私問題嘅資料引擎）。
  2. learned algorithm ＞ 逐任務 pipeline：AutoML（調參）→ NAS（搜架構）→ TabPFN（學整個學習演算法），係一條清晰嘅遞進。可遷移嘅問題係：「我而家呢個流程，邊一段係可以『一次學好、終身受用』？」
  3. Arena + 開放 + 極低邊際成本 ＝ 可信評測基建：TabArena 用 Elo＋全開放＋2 美元成本，把「廠商自報」變成「人人可驗」。呢個模式值得複製到任何新模態——包括你自己行業嘅內部評測。

十七、同其他線並讀

呢集有幾個交匯點：其一，合成先驗與近期小米 MiMo 嘅 RL 環境、SmolDataEnvs 嘅 5K RL 環境同屬「用生成資料訓練」大趨勢；其二，Hutter 係 AdamW 共同作者——今天所有 transformer 訓練嘅預設優化器都出自佢；呢條「優化器 → AutoML → NAS → 表格基礎模型」嘅個人史本身就係一部深度學習工具鏈史；其三，與同週 Latent Space 嘅 AI-for-Science（John Platt 嘅 ERA、scoreable task）同屬「資深研究者用 ML 改寫科學／工程流程」。若 TabPFN 真如所述打敗 GBDT，等於重寫企業 ML 嘅默認工具鏈——呢個係一個「唔 glamorous 但極賺錢」嘅領域被基礎模型撬動嘅典型案例。
