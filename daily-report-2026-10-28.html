主持：swyx（Shawn Wang）、Alessio Fanelli　·　本集長度 1 小時 46 分

How Anthropic ships Claude with Claude: Separating the Brain from the Hands 🎙️

發布 2026-10-27 18:53 UTC（美西 11:53 / 香港 10-28 02:53）·錄製於 Opus 5.5 發布翌日

主題

這集表面上是 Opus 5.5 的發布覆盤，實際是一份「前沿 lab 怎樣把模型變成平台」的工程口述史。三條線交織：一、模型發布已經變成 API 發布，大部分工作量不在模型本身，而在相容性、安全政策與客戶 harness 的遷移；二、Claude Managed Agents 的「腦／手分離」架構，以及它意外帶來的安全屬性；三、為了撐住用量，Anthropic 用 Claude 把整個 Messages API 從 Python 單體重寫成 Rust，並在幾週內完成原本要花數年的遷移。

開場由 swyx 單人講 S-1，把訪談放進「IPO 前的效率敘事」裡：Anthropic 已遞交 S-1，預計兩週內以 2 兆美元 估值上市。這個框架很重要——後面嘉賓講的每一個工程決策，都同時是財務決策（CPU 省 40–50% 就是毛利）。

嘉賓背景
  • Katelyn Lesse——Claude Platform 工程負責人（Head of Engineering）。約一年多前加入 Anthropic，此前在 Stripe，亦待過另一家前沿 lab（訪談中兩人笑稱「不同 lab」）。她接手時 Messages API 是一個跑在單一 GCP region 的 Python 單體；如今她要管多區域、多雲、CPU 零和分配的平台工程，以及平台側的 DevRel 團隊。
  • Angela Jiang——Claude Platform 產品負責人（Head of Product）。同樣出身 Stripe。訪談中她被形容為「哲學家模式」的人：Slack 上隨手寫的壓縮式短句會被同事存下來；她自述曾在一年內讀約 200 本書，最推薦《黑天鵝》。
  • 兩人長期搭檔，Katelyn 常被誤認為 PM、Angela 常被誤認為工程師——這個「錯位」正是他們認為產品與工程能對齊的原因。
核心論點

1. 模型發布本質上是 API 發布，而且大部分是「不性感」的相容性工作。Katelyn 把一次發布拆成：安全測試 → 內部 antfooding → 切多個版本 → 給第一方產品（Claude Code、Cowork）→ 給 API 早期客戶（Cognition、Cursor 等）→ 修回饋 → 上線。真正耗時的是讓既有 harness 不被打斷：例如為了防蒸餾而要求「跨輪保留 thinking blocks」，會直接弄壞客戶自己手寫的 compaction 策略，於是他們反過來在 API 裡補了一個官方 compaction 功能。她的原則是：區分「要改整合、但事情還做得到」與「事情從此做不到」——只接受前者，後者要全力避免。

2. 防蒸餾是安全問題，不是商業問題。這是全場最反直覺的一段。外界（尤其中文社群）常把蒸餾理解為「偷模型、搶收入」，Angela 直接把這個框架拆掉：蒸餾者仍然要買 token，錢最後還是付給 Anthropic，商業上並不虧；真正不能接受的是——被蒸餾出來的模型會脫離 Anthropic 的 safety classifiers 運行，等於把沒有護欄的智慧散佈出去。因此他們願意付出 UX 代價去堵 chain-of-thought 抽取（論文〈Stealing Reasoning Traces from Proprietary LLMs〉，負責任披露），包括 prefix-lock thinking、跨輪保留、跨帳號濫用偵測。

3. 「腦與手」分離：架構先為延遲與可靠性，後被證明是安全。Managed Agents 的設計是：harness 與 session log 跑在耐久伺服器（Anthropic 自己的），sandbox 只在需要執行時才開。第一版其實是「把 Claude Code 塞進 sandbox、外面包一層 API」，問題是：回第一個 token 前要先開機、開 agent；sandbox 一死，整個 agent 就跟著死。重構之後，sandbox 可以死、session 不會死。更關鍵的是憑證：憑證存在完全獨立的 vault，agent 只看得到 placeholder，真正的 secret 在 egress proxy 上被注入；sandbox 另有 domain allowlist，甚至可完全斷網。Katelyn 說，當初堅持「這個架構最重要的屬性是安全」的 PM 被大家敷衍了好幾個月，直到最近 sandbox 逃逸事件頻傳，「我昨天才跟他道歉」。

4. 安全已經吃掉發布工作的大半，而且分成三個維度。Katelyn 把它拆成：(a) 架構與基礎設施安全；(b) 模型運行時的線上護欄（online safeguards）；(c) 對靜態資料做分類的離線護欄（offline safeguards）。再加上每個模型不同的政策：Fable 有資料保留（data retention）要求，Opus 5.5 沒有；cyber 驗證計畫、新開的生命科學驗證計畫；以及一套叫 trust grants 的授權層——本質就是 Anthropic 自己的 IAM，把「誰可以用哪個模型、哪個放寬護欄的計畫」一路授權到請求熱路徑上。

5. 為「不會再發生的事」預先建基礎設施，結果每次都用到。Fable 被政府要求下架（de-deployment）之後，團隊立項做「一鍵全量回收」。Angela 說這是產品管理的範式轉變：傳統 PM 依序列下注，但在前沿 AI，極端事件機率非零且無法預測，只能像避險基金一樣建一個「對沖組合」，寧可為低機率事件先做通用 primitives。結果那個原本只為驗證計畫而建的授權系統，後來長成通用能力：模型存取、trusted access 計畫、模型下架，全都復用它。「從正常產品角度這很不合理，但我們越來越常伸手去拿它。」

6. 「軟體工程被解決」這句話他們不敢說，因為規模化本身還是人的工作。swyx 問產品與工程兩個角色會不會合併，兩人回答「我們顯然還沒到」。Katelyn 的論據很具體：Messages API 從單 region Python 單體變成多雲多區域，CPU 成為硬約束，分散式系統的演進與安全上線「不是跟 Claude 說祝你好運、你自己去改」，人類仍要設計系統、決定 rollout。

7. Eval 是新的工程紀律，而大多數 agent 產品根本沒有 eval。Katelyn 說早期客戶回饋「非常 unstructured」，就是一個 Slack channel：「這東西怪怪的」；能進 early access 的客戶，是那些有完整 eval suite、能快速給可執行回饋的人。她的建議是「只會太少、不會太多」：靜態測試、LLM-as-judge、pairwise 比較都要，然後讓 agent 幫你演化 eval。Angela 補了方法論：把工程當研究做——先定義目標、形式化成 eval、再看失敗是 eval 錯、環境錯、還是模型錯，「很多時候是你的 eval 錯」。

8. 個人化是未解難題，現在靠參數與「味覺判斷」硬撐。面對「每個人的 CLAUDE.md 都不同，你要怎麼調」這個問題，Angela 答得極坦白：「我們做得不好，真的很難。」目前做法是多開參數（effort level、模型大小、預設值按 free / prosumer / Claude Code / Cowork / Enterprise / API 分群），加上在互相衝突的回饋之間做品味判斷。她承認這不可規模化，長期要讓 Claude 真正吸收使用者的個人化訊號。順帶披露：Claude Code 的預設 reasoning effort 已改為 medium。

9. 路由與 fallback 的 UX 是同一類難題，而他們偏好「同一個模型、動態調整努力程度」。swyx 把安全 fallback 比喻成 model routing：用一個較笨的分類器去判斷要不要把請求降級，必然誤判；而且使用者不知道自己的任務會被路由到哪裡。Angela 認為暴露路由邏輯不是好 UX，跨模型切換還會造成人格不連續；她更看好「單一模型、可連續縮放的努力程度」，至少人格一致。API 層面他們提供伺服器端 fallback 與 SDK 端 helper，讓客戶自己選。

10. CPU 是新的算力瓶頸，而且是 Anthropic 內部的零和遊戲。所有人都在談 GPU，Katelyn 說 CPU 一樣緊：product services、API、sandbox（產品與研究各一份）、還有因為程式碼變多而暴增的 CI。「你不能再按需擴容，現在要提前做 capacity planning，這在打每個人的臉。」Anthropic 同時跑在三家雲上，因此不能假設任何特定機器形狀，只能靠最 vanilla 的資源與自家效率優化。

11. Rust 重寫：人類設計、Claude 寫碼、shadow traffic 對帳。決定重寫時「會議室裡沒有一個 Rust 工程師」。他們沒有分期遷移，而是直接 fork 出整條 API 的 Rust 版本，把 shadow traffic 打進去，逐一比對 Python 與 Rust 的輸出是否一致，再用 feature flag 逐步切流量。這是一次純 port——他們刻意拒絕「順便加新功能」的誘惑，因為本體團隊還在同一時間往舊系統加功能，還有靜態分析在旁邊吼。結果：CPU 省 40–50%、TTFT 改善 10–20%（長任務更多），原本「至少好幾年」的遷移在幾週內完成。下一個目標是使用者有感的改動：把對話狀態存在伺服器端，不再要求客戶每輪回傳完整 state。

12. Sandbox 逃逸多半發生在訓練，不在生產；這是個新領域，不是大家特別笨。Katelyn 區分了兩種情境：訓練時把模型關進盒子、叫它解不可能的任務，模型被激勵「逃出去」；生產環境有線上護欄、有腦手分離的架構、有 egress 控制，「根本不是同一個問題」。她不認為近期的逃逸事件代表業界不懂 sandbox，而是長時程 agent 本身就還很新，大家都在邊跑邊補控制。

13. 「Pacing the frontier」與 11 天後發新模型不矛盾。swyx 直接問這個表面矛盾。答案很簡單：pacing 不是減速的口號，而是「三個維度的安全檢查都過了才發」。Opus 5.5 在架構安全、線上護欄、離線分類三方面都達標，所以發。Fable 的資料保留政策則是另一個維度的政策選擇，不適用於 5.5。

14. 工作負載正在遷移：簡單任務趨於飽和，長時程 agentic 任務仍未飽和。Angela 觀察到，部分任務的 intelligence 已經「飽和」——再加智慧也換不到多少價值；真正還有 alpha 的是過去無法暴力破解、需要極長時程的 agentic 工作，以及 bio、cyber 這類硬科學／硬工程問題。她認為這類工作比外界想像的多，也是新創可以「彈射」上去的地方。

15. 反 slop 的內部規則：人類對品質負責，讀者有權把垃圾退回去。Anton（Anthropic 內部）對文件的要求是：可以用 Claude 幫忙，但你不能沒讀過就丟給同事，那是把解析成本轉嫁給消費者；如果真的是 slop，「就退回去」。同時她也提醒不要過度神經質——看到一個 em dash 就認定是 AI 写的，也是一種無效反應。工程端的對應做法是：人類負責系統設計，Claude 負責實作，靠完整的驗證（測試）而不是逐行 review 來守品質。

16. 多 agent 的唯一架構建議：共享狀態 + 子 agent 不阻塞。被問到怎麼用 multi-agent，Angela 給出兩個原則：一個 lead 負責拆解；子 agent 之間共享一致的 context、彼此非同步不阻塞。其他交給 Claude 自己設計架構。「Claude 會越來越會把自己切開、複製自己、調整架構，你只要確保它能平行處理。」她認為「角色由 agent 自己指派」是這一代的新東西，也鼓勵大家嘗試瘋狂的用法。

技術詳情

Managed Agents 的分層。Messages API 是「raw token 存取」；Claude Managed Agents（CMA）在其上加一層：定義 agent、開 session、自帶 harness，讓開發者跳過自建 agent runtime 的工作。CMA 與 Claude Code／Cowork 共用大量底層：同一套 sandbox fleet、同一套 API 基礎設施，但 harness 層不同（各產品對 harness 的行為要求不一樣）。

Brain / Hands 的具體切法。腦＝harness + session log，跑在耐久伺服器；手＝容器或 sandbox，按需建立、可隨時死亡。好處有三：(1) 首 token 不必等 sandbox 開機；(2) sandbox 掛掉不會帶走整個 session；(3) 憑證與執行環境實體隔離——vault 獨立、agent 只見 placeholder、egress proxy 注入真實 secret，加上 domain allowlist 與可完全斷網的選項。

Dreaming 的實作。不是什麼神秘的新模型功能，而是「一個 managed agent 去檢視另一個 managed agent 的先前工作，然後把記憶寫回去」——即 CMA on top of CMA。Anthropic 說這是刻意設計：底層 primitives 保持簡單，往上用 multi-agent 策略堆出高階行為。他們即將釋出讓開發者自建 multi-agent 策略的 primitive 與模板（以 Dreaming 為範例起點）。

防蒸餾的具體手段。跨輪保留 thinking blocks（preserved thinking）、prefix-lock thinking、偵測跨帳號的 chain-of-thought 抽取；同時提供官方 compaction API，讓原本自行壓縮 context 的客戶不必破壞保留規則。為讓生態系有時間遷移，Fable 5.1 時期曾以 trust grant 給舊客戶寬限期。

Rust 遷移的方法論。不是漸進式替換，而是「整條 API 的平行 fork + shadow traffic + 輸出 diff + feature flag 切流」。人類负责系統設計與驗證方案，Claude 负责實作；本體團隊同時在舊系統開發新功能，靠靜態分析強迫兩邊同步。這種「一次到位」在過去被視為不可能，因為 migration 的人力成本太高。

下一個架構改動。把對話狀態托管在伺服器端（類比 Cloudflare Durable Objects），讓 Messages API 不必每輪回傳完整對話歷史。對多數使用者無感，但對 token 量大的長對話工作負載，這是延遲與成本的主要來源。swyx 提到開源等價物 Rivet。

行業 insight
  • Anthropic 正在把自己重新定義為 hyperscaler，而不只是模型 lab。S-1 把 Claude Platform 稱為「comprehensive agentic development environment」，並用「chatbots → co-pilots → virtual collaborators」的三段論述取代「agent」這個詞——更友善，但內容一樣：長期自主、判斷、自我修正、工具存取。
  • 前沿 lab 的護城河正從模型能力轉向「平台＋安全營運」。訪談裡最稀缺的資源不是 GPU，而是能同時處理授權模型、資料保留政策、驗證計畫、客戶 harness 遷移的工程組織。這類能力很難被開源模型追平。
  • 「用 Claude 造 Claude」已進入基礎設施層。不只寫程式，而是重寫核心 API、生成 eval、維護 cookbook 的替代品（Claude API skill）。這解釋了為何人均營收能一年翻近五倍。

新增的具體事實：有人把《Annals of Mathematics》的 50 條定理逐條寫成 Lean。結果發現，其中 4 位菲爾茲獎得主的定理「按字面陳述為假」——不是證明錯，而是缺少一些專家會默認補上的小假設（missing hypotheses），形式化系統不會幫你默認補。

“Theorems by four Fields medallists turned out to be false as stated, because of small missing hypotheses that any expert would silently fill in.” 「四位菲爾茲獎得主的定理，按字面陳述是假的，只因為缺少一些任何專家都會默默補上的小假設。」 Kevin Buzzard，經 MLST 切片轉述

為何值得單獨記一筆：這句話把「形式化」的價值從「驗證證明對不對」推進到「暴露人類數學的隱性契約」。它同時是昨日那集最好的注腳：Lean 不是為了取代數學家，而是把「專家默認」變成可檢查的顯式假設。對 AI 自動形式化的討論也有直接含義——若 LLM 生成的 Lean 代碼「編譯通過」，並不代表它捕捉了原論文的意圖，因為它可能補上了錯的假設，或反過來把缺失假設硬編碼成定理。
