Jev: System One models for Prod, not God — with Diogo Almeida, CEO, TypeSafe AI 🎙️

发布时间：2026-09-21 22:13 UTC（09-22 06:13 CST）时长 ≈ 2:21逐字稿：官方全文

主题

Jev 上线一周后的「哲学与使命」长访：为什么现有 API 前沿模型都走错了路、什么是 System One / machine-native 模型、为什么 TypeSafe 选择「intelligence per dollar」而非 scaling，以及 RLCD 这条新北极星如何区别于 RLHF / RLVR。节目也深入 Jev 的 API 设计细节、coding agent 的未来形状，并以 Diogo 对 neo-lab、frontier pacing、安全对齐的尖锐批评收尾。

嘉宾背景

  • Diogo Almeida：TypeSafe AI 创始人兼 CEO；InstructGPT（Ouyang et al. 2022）共同作者，在 OpenAI 期间参与开创后训练（post-training）方向；此前曾参与 ChatGPT 之前的指令跟随（instruction following）工作，并自述「极力推动 InstructGPT 部署」。
  • 自述在 OpenAI 多年反复主张「API 可用的前沿模型走错了路」——从对齐、refusal 到可靠性；认为 ChatGPT 的成功让整个领域丢掉了除「自回归 chat-tuned LLM」以外的所有模式。
  • 创业历程：他自述这是「更像四年的旅程」（非表面上的两年），圣诞节前后曾趁假期拿空闲 GPU 做实验，发现有「生命迹象」；先问 Sasha 是否还缺东西，Sasha 当场决定关掉自己的创业加入；两周内拿到融资，团队搬进他公寓。X：@CompleteSkeptic。
  • 本集主持为 swyx；Diogo 在节目中多次自称「unhinged / practical」，并承认自己「0% 创业型人格、从来没想过当 CEO」。

核心论点

  • 1）需要一个新的模型类别：System One / machine-native / large programmable。与「为互联网自动补全而生」的预训练 LLM、「为回复文字而生」的 RLHF 聊天模型不同，新类别的目标是让「代码」成为消费者——所以公司叫 TypeSafe。Jev 这个名字取自 Jevons Paradox，定义是「站在 intelligence per dollar 前沿的模型系列」。
  • 2）RLHF 有结构性缺陷：mode dropping（=mode collapse）。他以 Yann LeCun「LLMs are doomed」那张图切入：该图在数学上显然、经验上却明显不成立，原因正是 mode drop——为了在长字符串上不出错，模型必须极度保守，而这种校准是「对字符串概率分布的剧毒」。推论：字符串根本不适合做决策，「把字符串模型过载用于决策是糟糕的选择」。RLHF 的副产物即大众抱怨的一切：sycophancy、过度自信、幻觉，以及 LM Arena 风格的排版（粗体、斜体、emoji、反问式追问）。
  • 3）RLCD = 新北极星。「Reinforcement Learning for Calibrated Decisions」（未发表的新技术），优化目标是「在 System One 任务上给出epistemically honest probabilities」，而不是 human-rated feedback（RLHF：导致幻觉、谄媚、永久依赖人类），也不是 programmatically verifiable outputs with rubrics（RLVR：能解 Navier-Stokes 但加剧 jagged intelligence、与其他软件整合差）。他进一步指出 RLVR 的北极星其实是「optimize benchmarks」——因为 benchmark 按定义就是可程序验证的简单输出，所以模型在数学上呈「fractal（分形）」式 jagged。
  • 4）the bitterest lesson（最苦的一课）：任务与数据胜过算力。他的原话逻辑是：「You get what you optimize for and the bitterest lesson in ML is that the most important part of it isn't ML at all.」LLM 领域迄今只发生过约 2.2 次北极星转移：RLHF（把任务改成 instruction following，没人料到可行）→ RLVR（小修小补）→ RLCD（programs in the loop）。
  • 5）TypeSafe 是 data lab，不是 model lab。数据全为合成；即使可以也不训练用户数据，因为真实世界数据有 power law 偏差，会 overfit 到「现在」；他要为多年后的科幻用例准备——比喻是「LLM 是 UDP，我们是 TCP」。data team 的职责是研究这个 cognitive core、找出 jaggedness 并「手术式」修补，覆盖过去/现在/未来所有维度（他称 onboarding data 员工的内部 talk 比这集播客还长）。
  • 6）反对公开 benchmark。「public benchmark 极易 game……以前每个 lab 都有一队人专门收集像 MMLU 的样本来让分数好看，这只是 benchmarking with extra steps。」长期只能靠「vibes and trust」，再放进具体 workflow 自测。内部 evals 当然有，但要「有纪律不要 game 它们」；他真正在意的是 intelligence，而「cost 与 speed 是你付钱去换的东西」。
  • 7）可靠性 ≠ 确定性。他反对把 determinism（同输入→同输出）当北极星，主张 robustness（相似输入→相似输出）才是关键；测法是往 prompt 塞 nonce（UUID），看输出是否语义稳定。可为特定用例做 deterministic 模型，但那会换来「更低的 intelligence per dollar」。
  • 8）反 safety alignment / refusal。「refusal 就是 type error」——在 dependency 里运行时会让软件随机崩坏；安全对齐本质是「遵循他人的指令（OpenAI / Anthropic 的）」，与 capability alignment（做用户要的事）正好相反。他承认「被用于战争/杀人」是合理的政策分歧，但主张不该在技术层设限：「每一次为了某些奇怪用途 overfit，都是在 fracturing its intelligence。」他的世界观是「intelligence 更像 database，而非 coworker」——数据库不会去审查用户拿它干什么。
  • 9）批评 frontier pacing。他认为 pacing 论述的隐含前提是「所有人都必须做更多 RLVR」，但对 TypeSafe 而言「zero 才是最佳量」；这把「路线选择」包装成了「技术必然」，是一种 sleight of hand。swyx 转述研究者圈的说法：这更多是政治 positioning，关乎 2028 大选；Diogo 回应「beyond my pay grade」「that makes me lose faith in humanity a bit」。
  • 10）neo-lab 与「不 pre-train」。「给我十亿，我不会 pre-train……anything except pre-training」；Frankensteining 不优雅但解决问题；mid-training 本质是省成本手段。他称「多数 neo-lab 是 crap」「在 destroy value」「我没方向就不该拿钱」；并直言「我不 value researchers，我 value 关心 right task 的人」。
  • 11）coding agents 与 KV cache 暴政。Claude Code / Codex 是前二赢家，但建在「单一模型世界」上；开源 coding agents 正「getting their Jev on」，一旦有人做出只属于自己的 killer use case，所有人会涌过去。他刚写了《KV cache Rules Everything Around Me》，认为 KV cache 锁死了模型选择与状态管理，可以解释「routing 为何难、sub-agent 为何不 work、compaction 为何难」。
  • 12）经济与产品观。他关心「5 年内 TFP growth 超过 3%」；认为所有模型对「世界有经济价值的工作」的自动化程度现在都约等于 0（「我猜还不到 1%」）；AI 会带来巨大 shift 但不会造成大规模失业；他想要 AI「disappear into the background」（像 regex 一样不起眼），并预言「inverse SaaS-pocalypse」——SaaS 会被 AI 增能而非取代。
  • 13）对 product-market fit 的反思。上线前「超过一半试用者根本不懂」，公司几乎没有收入，非技术同事非常恐惧（「卖的是维他命而非止痛药」）；他要质疑 PMF 这个概念——产品与市场都在，是开发者的热情点着了 FOMO。

技术详情

三种后训练家族与其「数据形状」：RLHF 的数据＝人类反馈；RLVR 的数据≈环境／可验证奖励；RLCD 有自己独有的数据形状。Diogo 强调 RLVR 的要点不只在 reward，还在「shape」与内嵌的 reasoning（一个 latent variable）；RLVR 让模型在「do anything」区做数学时呈现 fractal 式 jagged。

Jev 的 API 设计：输入（state / instructions / criteria）全部可为结构化 JSON，输出亦为结构化类型。他反对把一切塞进 system message——「system message 是恶心的 global variable」，应该让程序把结构插到正确位置，并把大 prompt 拆成大量平行的独立小问题。省钱技巧：给长 state 里每条 message 挂 ID，只付一次 state 成本，然后对每个 ID 并行提问。

原语映射到编程原语：choice→enum 上的 switch；noulli→if；score→排序或阈值比较。三者都是新概念，故意不映射成 int/float，以免被 Instructor/Pydantic 式映射「cook」掉。

置信度与阈值：thresholding 是用户主要杠杆；不提供 fine-tuning（目前），但可想象「calibration + model cascade」（不确定就升级到更大模型）甚至自动 fine-tuning。refusal 的正确做法不是问「要不要拒绝」，而是问许多独立问题＋设阈值。

其他能力边界：长 context 抗退化自称「遥遥领先」；视觉／多模态「都在牌桌上」；不承诺 latent reasoning；context 便宜后可做「标签化子任务树 + 按需检索历史 context」的 coding agent 新范式。

行业 insight

  • 「machine-native 模型被程序消费」正在爆发：一周 1 兆 tokens/day、且夜间仍在跑，是他用来论证「agent/runtime 消费模型」的最硬证据。
  • benchmark 政治：他接受 private proxy benchmark，反对 public benchmark；这与整个行业以公开榜单做 launch 营销的惯例正面冲突。
  • 供应链与地理：他预期 GPU 约束长期存在；LTS 化模型可移植到其他 silicon（被追问时「不评论」）；他抱怨欧洲用户只快 3 倍而非 100 倍，因为当地没有服务器。
  • coding agent 市场结构：单一模型 harness（Claude Code / Codex）vs 多模型开放 agent——他预言前者会被「只能在某个开放 agent 上做的 killer use case」搅乱。
  • 宏观经济叙事：TFP >3%／5 年、AI「消失在背景里」、inverse SaaS-pocalypse——他把「AI 能否出现在经济统计里」当作衡量是否真的自动化的标尺。
  • 对 neo-lab 生态的判断：他认为大量资本正在被「没有方向的重复劳动」摧毁价值，这与他自己「不 pre-train、靠数据与任务取胜」的路线互为镜像。
