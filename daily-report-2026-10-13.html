How Anthropic's Dynamic Workflows Coordinate Claude Agents 🎙️

發布：2026-10-12 18:18 UTC ／ 2026-10-13 02:18 北京時間 ｜ 現場：AI Engineer New York 2026（開幕日 workshop）｜ 原文：latent.space

主題：Anthropic 在 AI Engineer NYC 2026 開幕日 workshop 上介紹其 Claude Managed Agents 的編排方式，並首度公開一個上周五剛在 X 宣布的新特性：dynamic workflows（會上反覆簡稱「flows」）——定義為「一種全新的 multi-agent 編排，為你最有野心的 workload 而生」。核心是：由 Claude 自己決定整個 multi-agent 拓撲。

嘉賓背景：CJ Avilla 與 Harrison Stall，皆為 Anthropic Members of Technical Staff。本集為 Latent Space 編輯 Richard MacManus 撰寫的現場報導型 article-interview。

核心論點：

  • flows 是「下一代 multi-agent 編排」。Stall 原話：讓 Claude「fully orchestrate the entirety of its own multi-agent topology」。運作方式：lead agent 先為任務制訂計劃，Claude 接著自己寫一段 orchestration program——由它啟動 agents、收集結果、管理資訊流。
  • 與舊機制的關鍵差異。此前的 Claude Managed Agents 需要開發者自行配置一個 coordinator 加一組 roster 子代理；有了 dynamic workflows，由 Claude 自己決定如何切分與編排工作。Stall：跨越多個編排階段，「它能在你完全不需管理任何互連關係的情況下，完成一個個離散、可驗證的工作單元」。
  • 組織學類比。開場以作業系統史作喻：從 Ken Thompson 寫出初版 Unix，到 Linux 由「一個人（Linus Torvalds）」演化為層層 trusted maintainers。教訓是——agents 需要同等的組織度，才能承擔 Anthropic 設想的那種大型任務。問題意識也很直白（Avilla）：當大量 agent 貢獻大量 PR，「我們這些編排與管理 agent 的人，會開始覺得自己是瓶頸、是斷點」。
  • 仍然可注入專家子代理。Avilla：在 agent config 中可以傳入預先配置好的 sub-agents。全部功能都在 Claude Console（開發者經 API 存取 Claude 的界面，即 Managed Agents 的所在）中提供。
  • 示例工作流——股票 watchlist scanner。故意選了一個「遠不及 Anthropic 所鼓吹的大型項目」的簡單例子來講清基本模式：scan 階段把個別 ticker 分發給帶 isolated context 的 agents，之後的 review 階段檢查這些發現、再產出一份報告。
  • 「Claude 怎麼決定要用多少個 agent？」觀眾問：一次簡單的 ticker 掃描會不會觸發數百個子代理？Stall 答：「答案其實就是 evals 和 lower defaults」——並補充，有野心的任務通常需要顯式地鼓勵更高的並行度。
  • token 預算：模型不知道自己有多少錢。有人問 lead agent 是否知道可用預算。Stall 答：模型在運行時並不知道自己的預算，但開發者可設定 session budget。他補了一句引來全場輕笑的話——把預算告訴模型，可能會讓這些 agent「有點焦慮」（a little bit anxious）。
  • 如何讓重複的 flow 越來越便宜——「dreaming」。除了讓 Claude 檢視自身成本，Avilla 建議用另一個較新特性 dreaming（目前為 research preview）：一個 dream「讀取既有的 memory store 與過往 session transcripts，然後產出一個新的、重組過的 memory store」，其中重複條目被合併、「陳舊或互相矛盾的條目」被替換、「新洞見被浮現出來」。Avilla 用 flow 語境說，它能「crystallize 並基本改進與那些 sessions 相關的 memory store」。
  • flow 能否自我改進？有人問 watchlist flow 能否察覺「自己的掃描模型不夠好、並改掉下一次排程」。Stall 說這不是內建功能，但他與 Avilla 建議可用 hill-climbing 與 dreaming 來改進這個迴路。
  • 可觀測性。開發者隨時可透過 Claude Console 內的 graphing 功能檢視：Avilla：「你可以看出 lead agent 究竟把什麼傳給了 sub-agent——在這裡檢視那個 payload，去深入理解整張圖中每一次轉移到底發生了什麼。」
  • 子代理之間能否互相通訊？Stall：agents 共享一個 filesystem，可藉此交換資訊；但開發者不能透過 API 直接指示某個 workflow 子代理去給另一個發消息。
  • 成本權衡。在 watchlist-scanner 的對比中，Avilla 說 flows 比單 agent 方案「貴得多」（much more），但也「在找出所有細節上有效得多」（much more effective at finding all of the details）。
  • 野心能有多大？有觀眾問 dynamic workflows 能否驅動大型科研項目，並援引 OpenAI 近日宣布的 Navier–Stokes 千禧年大獎難題證明。Stall 不願就 Anthropic 如何處理大型科學問題的細節多談，但表示目標是讓一般用戶也能處理這類問題。

關鍵數據／事實：

  • dynamic workflows 於上周五（2026-10-09 前後）在 X（@ClaudeDevs）宣布；本集為其公開後的首場深度現場解說。
  • 發布時間 2026-10-12 18:18 UTC；場合為 AI Engineer New York 2026 開幕日 workshop。
  • 示例：單一股票 watchlist scanner（scan → review 兩階段）。
  • dreaming 屬 research preview；flow 的預算控制點為 session budget。
  • 觀眾引用的前沿參照：OpenAI 的 Navier–Stokes 千禧年難題進展。

重點引用：

「Flows are essentially the next version of multi-agent orchestration… where you can let Claude fully orchestrate the entirety of its own multi-agent topology.」 — Harrison Stall（Anthropic MTS）
「I think a lot of us who are orchestrating and managing lots of agents now might start to feel this feeling of being the bottleneck and being the breaking point as we have lots of agents contributing tons and tons of PRs… And we're sitting there in our GitHub trying to approve PRs.」 — CJ Avilla（Anthropic MTS）
「The answer really is evals and lower defaults.」 — Harrison Stall，答「Claude 如何決定需要多少個 agent」
「Flows are basically a way to throw test-time compute at hard problems and get more capability faster out of the models… unlocking the power of this is the first step for us making these types of discoveries, or scientific progress, broadly doable by the general public.」 — Harrison Stall，談 flows 的野心

技術詳情：orchestration program（由 Claude 生成）、隔離上下文（isolated context）的子代理、跨 agent 的共享 filesystem、session budget、dreaming（memory store 重組：去重／替換矛盾條目／浮現新洞見）、Console 內 graphing 可視化每次 transition 的 payload、以及 hill-climbing＋dreaming 構成自我改進迴路的可能性。

行業 insight：

  • 編排的瓶頸正在從「人」轉移到「預算與評估」：當 agent 拓撲由模型自生成，「該開幾個 agent」不再由開發者配置，而由 evals 與 lower defaults 決定；人退到「設預算、看圖、審查」的位置。
  • test-time compute 成為能力擴展的主軸：Stall 把 flows 直接定義為「把 test-time compute 砸到難題上」的手段——算力換能力，且目標是 democratize 科學發現。
  • Anthropic 把 multi-agent 從「開發者配置」推向「模型自編排」：這是繼「a harness for every task」（Claude Code 起源）之後的下一步——flow 可運行得比單 agent 或 roster 更久。
  • 成本結構的誠實披露：Anthropic 自己承認 flows「貴得多」，但「找出所有細節的能力強得多」——這是一次明確的「貴但值」定位。
