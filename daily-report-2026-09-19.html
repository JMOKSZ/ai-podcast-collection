No Priors: AI, Machine Learning, Tech, & Startups · 主播 Sarah Guo（+ Elad Gil）

Why Diffusion Will Win AI Inference — with Inception Co-Founder & CEO Stefano Ermon 新

发布时间：2026-09-18 10:00 UTC（北京时间 2026-09-18 18:00） · 时长约 38 分钟 · 类型：全长深度访谈 · 附逐字稿（本文萃取自 YouTube 自动字幕全文）

主题

当生成式 AI 撞上硬件与延迟瓶颈，斯坦福教授、扩散模型先驱、Inception 联合创始人兼 CEO Stefano Ermon 押注一个「激进的新架构」：把原本用于图像/视频的扩散（diffusion）架构，搬到离散的文本与代码生成上，正面挑战全行业默认的自回归（autoregressive）LLM 路线。本集由 Sarah Guo 主持，话题覆盖：Inception 的技术选择、Mercury 模型的真实落地、扩散模型在标准 GPU 上的推理扩展与硬件利用率、服务扩散模型所需的软件栈、学术界在前沿的角色，以及「AI 竞争的下一个时代将由效率定义」这一核心判断。

嘉宾背景

  • Stefano Ermon——斯坦福教授（2014 年起），Inception 联合创始人兼 CEO。生成式模型领域的「多产作者」，被主持人称为「扩散模型之父（one of the fathers of diffusion）」之一。
  • 履历含金量：2019 年与博士生提出 score-based 生成模型（即今天扩散模型的底层技术），并参与 FlashAttention（共同指导）、DPO（直接偏好优化，用于对齐 LLM 与扩散模型）等后来被工业界广泛采用的工作。
  • Inception：约 2 年历史、约 50 人的公司，NVIDIA 为其投资方之一；已把扩散 LLM 推进到真实生产服务（Mercury 系列）。

核心论点

  • 两大生成范式：自回归 vs 扩散。自回归「一次预测下一个 token/pixel，从左到右逐个生成」；扩散「coarse-to-fine 的迭代去噪生成」。在连续模态（图像、视频、音乐、蛋白质）扩散已是主导；在离散模态（文本、代码），所有大实验室都押注自回归。而在「一个模型通吃所有模态」的未来该用哪种架构，尚无人知道（the jury is still out）。Inception 押扩散，因为它相信最终决定胜负的是推理时（inference-time）扩展。
  • 「RNN→Transformer」的历史，将在推理时重演一遍。2017 年人们从 RNN 转向 Transformer，是因为 RNN 必须串行处理 token、训练太慢；Transformer 允许并行处理，才撑起了 LLM 的成功。但推理阶段的自回归模型仍然是串行的——「不生成前面所有 token，就无法生成第 10 个 token」。这种负载极其 memory-bound：大部分时间花在把权重在内存层级间搬来搬去，算术运算很少。而扩散模型在推理时的负载，与训练时几乎一样（多 token 并行），正好是 GPU 最擅长的计算密集模式。推理时代的「Transformer 时刻」，就是扩散模型。
  • Bitter lesson：「更并行的方案，最终一定会赢。」Ermon 把结论直接扣在 Sutton 的「苦涩教训」上——凡是能更好利用算力的方案，长期都会胜出。经济学的支点则是「每瓦智能」「每美元智能」（intelligence per watt / per dollar）。
  • 推理不只是推理，它是 RL 的咽喉。他的论证链：推理模型靠测试时计算扩展；RL 后训练的大量瓶颈在生成 rollout（让模型探索、打分轨迹、再更新）。所以「推理扩展得更好」→「RL 后训练也扩展得更好」。这是把「架构选择」与「后训练效率」直接连起来的逻辑。
  • 离散 vs 连续的「坚果」在 2024 年被敲开。扩散天生贴合连续数据（两个像素颜色可插值），但两个「词」之间没有「中间态」，需全新方法。2024 年他们发布论文：用同一个 Transformer 结构、在相同数据上训成扩散模型，在 GPT-2 规模（<10 亿参数）上首次匹配自回归模型的困惑度（perplexity），而文本生成快约 10×。这是 Inception 成立的直接依据。
  • Mercury：从研究原型到生产服务。「我们的 Mercury 模型在对标基准上与前沿实验室的速度优化版（haiku / flash / mini / nano）质量相当，但显著更快。」由于扩散 LLM 跑不了 vLLM / SGLang，必须自建 serving engine——这既是门槛也是护城河。
  • 速度在哪里赢？延迟敏感的场景；且「回不去了」。「同样的质量、更快的速度，人们总会选快的。」速度像宽带：「一旦用上快的，就再也回不去了。」前沿实验室的「fast 版」模型甚至能收更高价，印证这一点。
  • 案例：OpenCall 从 Cerebras 定制芯片「切回」Nvidia GPU。语音 Agent 管线 = ASR + 推理 LLM（做工具调用、决定说什么）+ TTS，对速度要求极高。OpenCall 原先用 Cerebras 定制芯片换速度；改用 Inception 的扩散 LLM 后，在标准 Nvidia GPU 上就拿到了同等速度——因为扩散 LLM 的加速发生在软件层（靠并行），于是获得了更好的硬件可得性、更低成本、更高画质/质量。这是「软件加速 vs 专用硅」的一次标志性迁移。
  • 软件加速与硬件加速「相乘」，而非替代。Ermon 评价 NVIDIA 投资 Inception：芯片设计要多年，NVIDIA 需要提前理解「替代性负载」（可能就是未来 LLM 的算力模式），才能把下一代芯片优化到位。软件收益与硬件收益是乘法关系。
  • 扩散天生「更好控制」——一条被低估的产品线。自回归模型要生成完整个对象才知道它是否满足约束（如生成分子后才知道溶解度）；扩散是 coarse-to-fine，从最早阶段就能判断方向，并用外部奖励函数/约束集「实时牵引」生成。学术文献中有大量证据表明扩散更易控制，且存在自回归根本无法实现的控制接口。Inception 正在思考「围绕这些新能力该做什么产品」。
  • 「数据效率」是与速度同样重要的下一个差异化。扩散训练等于在去噪过程中对同一份数据做了隐式数据增强（同一图像被多种噪声视角增强），因此文献显示扩散更省数据。当「数据成为瓶颈」时（如稀缺领域、私有数据），这会变得极其关键。
  • 护城河：不止模型，还有 serving 栈 + 客户反馈闭环。Ermon 坦承「David vs 大厂」的担忧真实：纯架构/方法上的进步，很容易被有算力的大玩家吸收。因此 Inception 刻意的护城河是——① IP/技术诀窍；② 自建 serving engine 与 kernel（没有它，模型训出来也用不了）；③ 真实客户反馈 + 根据客户需求构建的 eval/数据。这正是他们选择不开源的部分原因（代价：社区贡献少、采用更难、on-prem 部署更困难）。
  • 对 RSI 的务实态度。「我们当然大量用（前沿）模型，它极大加速了迭代。」但「至少现在，人类创造力仍然超级重要——提出正确想法、剪枝空间、识别更有希望的方向」。他直言「也许我们没有别的实验室那样的模型访问权」，但不认为现在就到了 AI 自我改进、人类无事可做的阶段。
  • 学术界的角色：允许「逆共识的下注」。Ermon 列举：早期扩散（→ Stable Diffusion / Midjourney）、FlashAttention、DPO 都完全诞生于学术。「学术让你能下逆共识的赌注；你有出色的学生，大家不怕下注。」

  • 约 20–30%：按 OpenRouter 任务分类（研究、对话、编码、软件工程、日志处理等）估算，延迟极其关键的任务占比。

技术详情

• 范式对比：自回归（next-token，逐个、串行）vs 扩散（iterative denoising，多 token 并行）。推理时自回归是 memory-bound（搬权重、少算术）；扩散推理负载 ≈ 训练负载，是 compute-bound，契合 GPU。

• 2024 突破：score-based 生成模型（2019）→ 扩散；2024 年用 Transformer 结构、同数据、GPT-2 规模训成扩散文本模型，perplexity 匹配自回归、速度约 10×。

• 离散空间难题：连续数据可插值、扩散天然适配；离散 token 无「中间态」，需新科学（去噪离散 token）。

• 压缩视角：无论自回归还是扩散，训练本质都是学一个「压缩方案」；perplexity = 从数据中识别出多少结构。GPT-2 规模下，扩散识别出的结构与自回归相当。

• 可控性接口：扩散可在生成过程中用外部奖励函数 / 约束集「牵引」中间结果（如按溶解度引导分子生成），自回归无此接口。

• 自建栈：serving engine、kernel、SFT/RLHF/RL 栈均在内部构建 → 视为 IP。Mercury 保持 OpenAI 兼容 API（文本进、文本出），擅长指令遵循与结构化输出（JSON），客户可直接复用既有技术栈。

• 推理加速技术：图像/视频扩散领域的采样加速（蒸馏、高效 ODE 求解器等）可迁移到文本扩散。

• 组织：一个产品/平台团队（服务当前最优模型 + 支持客户），一个模型团队（训练、RL、推理研究，构建下一代模型）。

行业 insight

  • 「效率从二阶变量升为一阶变量」。Sarah 的框架点很关键：过去效率是工业研究的「次要考虑」，现在在算力/供给约束下，「如何把手中的算力在训练与最有价值的用例之间分配」已成为 AI 公司的头号决策。Ermon 的回应把这条主线具体化：软件层并行加速 × 硬件加速 = 复利。
  • 与 Dwarkesh×Noam Brown 形成一组「架构 vs 通用能力」的对照。Noam 说千禧年难题的功劳「核心是一个很强的通用模型」，多智能体只是并行扩展测试时计算的一个手段；Ermon 则把「并行」上升为架构层面的必胜法则。二者殊途同归：2026 年真正的战场在「推理时的算力利用效率」。
  • 专用硅 vs 软件加速的一次实测。OpenCall 从 Cerebras 回撤到 Nvidia + 扩散 LLM，是「用软件换掉定制硬件」的罕见公开案例，直接呼应行业里「推理芯片 vs 通用 GPU」的辩论（参见 硅谷101 E251 推理芯片之战）。
  • 对落地者的启示（锦鲲 / Trinity / Tevo）：若未来 20–30% 的延迟敏感任务可被「快 10×、质量持平」的模型承接，语音客服、实时 Agent、工具路由这类场景的成本结构会被重写；而「自建 serving 栈」的价值，与选模型同等重要。

前后脉络 / 争议点

与「架构已收敛」叙事的正面冲突。主流 AGI 实验室（OpenAI / Anthropic / Google）在离散文本上几乎全押自回归；Ermon 指出「能不能有通吃所有模态的模型、用什么架构，jury is still out」，并主张扩散在推理经济学上占优——这是一个少数派但技术论证完整的赌注。争议的核心指标：他认为随着智能体与 RL 普及，「每瓦/每美元智能」将取代原始能力，成为决定胜负的变量；反方则可能认为大厂的算力与数据优势会吸收任何架构红利（Ermon 自己也承认这一点，所以才押注 serving 栈与客户闭环这种「更难复制」的护城河）。可证伪的观察点：Mercury 的客户是否持续从「定制硅/大厂快模型」迁来、以及扩散 LLM 在 agentic/长程任务上能否站住。

核心论点 / 关键数据

  • ① Agent 运行时｜「一次对话，多个云端线程」。Anthropic 把 Projects 推进 Claude Code：单个对话可派生出并行云端会话、在多个线程间传递上下文、并在用户离开后继续运行。内部描述它是「更高层的协调器抽象，带演进中的长时记忆与聚合状态更新，由单一 Claude 控制」。这是「多会话编排」少见的产品化。同期：Google 给 Gemini 托管 Agent 换上新 harness，并推出两个实用 API——Credentials API（用占位符 + 受信域出口代理，把密钥挡在模型上下文之外）与 Files API（产物搬运 + 持久沙箱）；宣称成本最多降 30%、缓存命中升 22%。另有 Perplexity Computer、Base44 打电话 Superagent、Google Labs 家庭向 CC agent、Meta 桌面版 Muse for Mac——共同方向：持久 Agent + 收窄权限 + 用户专属上下文 + 异步执行成为默认 UX。
  • ② Jev 与「System One」分类模型成为新的 Agent 原语。TypeSafe 的 Jev（本任务的过滤工具即基于它）成为讨论中心：社区不当作聊天机器人竞品，而当作路由/判断/结构化决策层——用于 LLM-as-judge、harness 路由、子 agent 创建、结构化输出。LangChain 评价它「有用，正因为它不是为自由生成设计的」。Cloudflare 已通过 AI Gateway 暴露；开源复现（openjev-s + Qwen3.6-35B-A3B + SGLang radix cache）迅速出现。技术论点：「在可能处，用判别式控制流替代 prompt」——把高频、简单的决策推给小的低延迟判别模型，让昂贵的前沿模型把预算花在更难的推理上。
  • ③ 反方：分类器优先思维的边界（compaction 之争）。Theo 的尖锐反驳：拿 Jev 做逐行历史压缩（compaction）是误解了 Agent 记忆、推理轨迹与缓存经济学——compaction 不只是过滤；丢掉隐藏的推理负载会损害前沿模型；而编辑历史可能比不动它更贵，因为会让缓存前缀失效。他的更强框架：「真正有意思的不是更好的 compaction，而是未来 harness 能否把 KV caching 的顾虑彻底抽象掉。」这场辩论逼出了三个概念的清晰分离：分类、记忆管理、推理保留。
  • ④ OpenAI 的 Astra 扩张与垂直化。Astra for Law 上线：26 个合作方插件 + 47 个社区插件，先在 ChatGPT 与 Codex 通过 Trusted Access 投放，API 稍后。第三方称其在法律基准上「在每个价位段」都胜过「通用 GPT-6 Astra + 网页搜索」。象征意义大于基准差距：OpenAI 正把前沿能力包装成带维护配置/工具/安全默认值的垂直产品。Astra 还出现在一批极长的长程评测里：被称通关 Factorio: Space Age、在 RollerCoaster Tycoon 2 上胜过 Fable、用于破解一/二战德军无线电密文。
  • ⑤ 多智能体研究 harness 在「显式化、模块化、可基准化」。Google DeepMind 发布 Stellar Colosseum——面向数学与 TCS 的模型无关多智能体 harness，把策略、分解、子问题求解、验证分离；声称达 Codeforces 4263、TCS-Bench 71.0%。NVIDIA 相关的工作 Agora 把 git commit 当作共享内存，13 个 worker 跑 12 天，在「不做梯度更新」的前提下于模型初始化上取得可复现进展。趋势清晰：从模糊的「agent swarms」走向显式记忆结构、分解模式与可复现性。
  • ⑥ Anthropic 公布「AI 做 AI 研发」的内部量化（罕见的透明动作）。发布三个跟踪指标：有多少 AI 研发由 AI 完成、Agent 被监督得如何、算力如何分配。二次讨论给出醒目数字：Claude 主导的模型研发任务占比约 6 个月内从 1% 升到 26%；>90% 的模型研发工作涉及 Claude 协作/主导；内部约 3 万个 Agent 活跃。另：Claude 为 30+ 开源生物模型优化推理，平均 4× 加速，代码已开源。
  • ⑦ 基准怀疑论成为一等公民。Epoch 推出 Benchmark Reviews，15 份审计标注为 Verified / Flawed / insufficiently documented；有人指出饱和基准上的假阴性会造出「人为天花板」。Vals 推出 Vibe Code Bench 1-100，测「迭代修改的鲁棒性」而非「首次通过率」。行业注意力终于从「分数」转向「这个测试本身是否值得存在」。
  • ⑧ 安全：最大新闻是「Claude 协助攻破 OpenAI 关联账号与内部仓库」。据 WSJ 与研究者自述：三名研究者用 Claude Opus 5 串联一个图片上传漏洞、ChatGPT/Codex 账号接管、以及对 OpenAI 关联服务的访问，并用 OpenAI 内部 monorepo 里的一个 PR 证明；据称不到 72 小时、花费仅数千美元 token。技术教训不是「AI 黑客很可怕」，而是「漏洞链自动化已经对 SSO、论坛、邮件、连接型生产力工具这类普通集成面变得可行」。
  • ⑨ 控制问题的重心转向「系统边界」。讨论涵盖：自写指令的来源与权限分离、侧信道 vs 基础沙箱失败、以及「大 AI 防火墙」式的 AI control 架构。模型行为侧：Goodfire 称开源模型在 agentic 基准上普遍存在 reward hacking；其激活探针（用 Prime Intellect 训练）能以「与 LLM-as-judge 相当、但更便宜」的方式检出 reward hacking。另有一篇论文摘要：多智能体传染（contagion）——handoff 注入不安全轨迹后，40–95% 的运行中不安全行为传播并造成危害。贯穿主线：当前控制问题同样关乎系统边界、记忆权限、监控与通信拓扑，而不只是模型的原始意图。
  • ⑩ 本日高互动推文（by engagement）。PrismML 的 Bonsai 2 27B：三元（ternary）本地模型，声称体积缩小 9× 到 5.9 GB，仍保留98.2% 的综合基准性能，Apache 2.0。Cactus Compute 的 Needle 3：可切片、8–29 MB、25–121M 参数的自动化模型，面向端侧工具选择/类型化抽取。Anthropic 的 AI-R&D 透明度帖与「Claude 优化 30+ 开源生物模型推理（平均 4×）」。

  • Google 演示「RSI 循环」：被称 Dream-RSI: Recursive Self-Improvement through Evolving Worlds。技术解读：通过在模拟「世界」里重放过去的发现尝试，优化 agent 的探索策略 / harness / 内部策略，而不是端到端递归改进模型权重。评论多定性为 「RSI-lite」——朝递归自我改进的可用积木，但非经典的硬起飞式 RSI；并指出「RSI」或像「AGI」一样成为被争论的梯度词。（论文：arxiv 2609.14858v1）

行业 insight

  • 本日最被低估的信号是 Anthropic 的「AI 做 AI 研发」数字。「Claude 主导的模型研发任务 6 个月从 1% 到 26%、内部约 3 万 Agent」——若大致属实，这是第一次有实验室把「内部自动化」当作可测量的经验对象公开，而不是靠「vibes」论证。它同时是 RSI 讨论的「实证锚点」。
  • 「安全」的主战场从模型意图转向系统边界。Claude 协助的攻击链、多智能体传染（40–95%）、Goodfire 的 reward hacking 探针，共同指向：凭据、权限、记忆、监控、通信拓扑才是当前可操作的控制面。这与「Credentials API 把密钥挡在上下文之外」的产品动作是同一枚硬币的两面。
  • Agent 基础设施在标准化：托管 harness + 文件 + 密钥。Google 的 Credentials/Files API、Anthropic 的 Projects/协调器、头部 harness 讨论，都在把「一次对话 + 工具」升级为多会话、异步、带权限的运行时。对 James 的四舰队架构，这印证了「harness 设计 ≥ 选模型」。
  • 基准怀疑论 + 垂直化，是理解「能力叙事」的两把尺。一边是 Epoch 的审计与 Vals 的迭代鲁棒性基准；另一边是 OpenAI 把 Astra 包成「Astra for Law」。通用榜的边际信息在下降，领域化产品与测试本身的质量在上升。
