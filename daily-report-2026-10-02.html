Dwarkesh Podcast （主播：Dwarkesh Patel；嘉賓：Si Sheppard）

Si Sheppard – How did a few hundred Spanish soldiers topple two empires? 歷史 × AI 接管隱喻 發布：2026-10-01 15:28 UTC（北京 10/1 23:28）｜片長約 1 小時 48 分（時間軸至 01:33:42+）

主題

阿茲特克與印加帝國，如何在短短數年內被數百名西班牙征服者顛覆；以及為什麼這可能是人類史上最令人震驚的軍事／外交事件——並被主持人直接框成「AI 接管」的思想實驗。

嘉賓背景

Si Sheppard——軍事史學家、長島大學布魯克林分校（LIU Brooklyn）教授，專攻早期現代軍事史與殖民主義，著有大量戰役史與殖民擴張研究。Dwarkesh 在開場即說明：本集主要談歷史，但「不要聚焦 AI」的同時，整條敘事線就是為了回答——一個動機難以理解的外來力量，如何用技術與外交狡詐，接管一個更大、更成熟的既有秩序。

核心論點
  • ① 帝國的脆弱性來自「階層化」——斬首即可控制全局。阿茲特克的 huey tlatoani（大演說者）與印加的 Sapa Inca 被擒後，整個體系幾乎即刻瓦解。這套邏輯的關鍵不是消滅百萬人，而是抓住社會金字塔頂端的那一個人，然後「透過傀儡繼續治理」——取代的只是頂端，底層結構儘量保留。
  • ② 技術差距其實沒有想像中大。槍炮在當時裝填極慢，「原住民一旦克服震撼，就發現它戰場價值有限」；真正決定性的是鋼（托萊多鋼長劍作突刺、鋼盔）與馬。到征服後期，金屬甲在高溫下反而累贅，征服者大量換回原住民的棉甲——連「盔甲優勢」都不是絕對的。
  • ③ 外交與技術同等重要——99% 的戰鬥力是被征服民族。科爾特斯與皮薩羅都把自己的力量「插入」一個多民族帝國的離心結構中：特拉斯卡拉人（Tlaxcala）本是阿茲特克的最後死敵，主動結盟並開出條件（割地、在特諾奇提特蘭建自己的堡壘）；進攻首都的最終部隊中，純西班牙人可能只佔 0.5%。
  • ④ 「大輪子 vs 小輪子」：決定論與偶然性的整合。地理與氣候是「碾得很慢的大輪子」，個人（科爾特斯、皮薩羅、蒙提祖馬、阿塔瓦爾帕）是「前景的小輪子」。即使原住民在若干戰役取勝，歐亞大陸馴化動物所孕育的傳染病與附庸民族的離心，仍會在長期把他們拖垮——「一個或另一個方式，西班牙人（或後來的歐洲殖民者）都會在海岸紮根，再慢慢往內陸推」。
  • ⑤ 原住民為何無法反向利用西班牙人的內部分裂？因為西班牙人的內鬥（Velázquez 派 Narváez 來抓科爾特斯、Almagro 與皮薩羅翻臉）是同一文明內的私人恩怨；一旦面對共同的存亡威脅，他們會團結。反之，特拉斯卡拉與阿茲特克是世代結構性死敵，即便 Cuitláhuac 派使者提議組成新的「三方同盟」共同抗外，特拉斯卡拉的老一代仍斷然拒絕——「這是你的問題，也許你會被滅，對我們沒損失。」
  • ⑥ 組織／治理的優勢被低估。作者以印度為類比：莫臥兒與滿清都揹著「外族統治」的原罪，一旦勢頭逆轉，地方權力掮客就轉向；而東印度公司是「公司」——有董事會，能汰換 CEO 與將領，沒有血統繼承的「壞國王」風險。呼應英法百年戰爭：法王查理六世發瘋（以為自己是玻璃做的）→ 英格蘭贏；英王亨利六世發瘋 → 英格蘭輸。「這些（征服）都是商業行為……是compañeros（同夥），不是soldados（士兵）。」
  • ⑦ 「快錢詛咒」。西班牙因白銀而坐享其成，反而沒有發展出功能性的資本主義（資本市場、獨立銀行體系）；英格蘭與荷蘭（尤其荷蘭「什麼天然資源都沒有」）被迫創新，最終領先。同一邏輯延伸到美國南北：南方靠奴隸與現金作物取得「快解」，北方被迫發展貿易、金融與工業——內戰時所有優勢都在北方。
關鍵數據／事實
  • 科爾特斯 1519–1521、約 2 年半征服人口約 600 萬的阿茲特克帝國；皮薩羅十年後以相似劇本，約 5 年征服人口約 1,000 萬的印加帝國。
  • 卡哈馬卡戰役（1532）：皮薩羅約 168 人（一說 160–190）對上剛贏得內戰、規模達數萬至 10 萬的印加軍隊；殺敵近萬、己方零陣亡——唯一的傷者是皮薩羅本人，被過度熱心的同僚在擒拿阿塔瓦爾帕時割傷手。
  • 皮薩羅設伏前的心理戰：派中尉策馬直衝 Sapa Inca 與其全朝，在阿塔瓦爾帕面前數吋處急停；阿塔瓦爾帕面不改色，事後將當場退縮的將領全部處死以立威。
  • 帝國內部的語言壟斷：只有少數人說納瓦特爾語（阿茲特克）／克丘亞語（印加）；帝國是「多民族拼裝」——這正是離心力的來源。
  • 波托西（Potosí，今玻利維亞）銀礦為西班牙帝國補上「真正全球化」的最後一塊拼圖；白銀經馬尼拉流向中國，換取瓷器、絲綢、香料。明末 1640s 銀根斷裂，加上滿洲壓境，明朝無法發餉養軍而亡。
  • 西班牙本土通脹：白銀大量湧入→物價上升、實際工資下降→未發展資本市場，19 世紀未能工業化，20 世紀仍相對落後。
  • 1876 年小巨角河戰役（Custer’s Last Stand）：美國第七騎兵團全軍覆沒——分散式、騎馬持槍、可聚可散的原住民武裝，極難被「釘住」，最終靠「總體戰」（鐵絲網、屠殺野牛）才被壓制。
  • 阿茲特克 vs 塔拉斯坎（Tarascans，今米卻肯 Purépecha）：塔拉斯坎人會冶銅，用銅頭箭「大量屠殺入侵的阿茲特克人」；阿茲特克有金有銀（招來貪婪），卻不會冶鐵——「最壞的兩端都佔了」。若南北美洲有更廣泛交流（例如阿茲特克取得駱馬），將是決定性的平衡力量。

技術詳情（當時的軍事科技）
  • 火器：火繩槍與火炮裝填極慢，實質殺傷有限，但「能控制雷霆」的爆炸聲具極大心理震懾（印加帝國創始者 Pachacuti 意為「雷霆持有者」）。
  • 金屬：托萊多鋼長劍為突刺武器，專破原住民「掄砍」（開邊）式攻擊；鋼盔連黑曜石刀（火山玻璃，鋒利但脆）也難破。
  • 馬 + 騎兵衝擊：真正的「決定性資產」。原住民從無馬（馬起源於北美後絕種），也無馱獸（阿茲特克只有火雞與吉娃娃；印加有駱馬但駱馬不能騎乘衝鋒）。鬆散的戰陣是騎兵最理想的突破口；反騎兵需要長矛密集陣＋紀律（瑞士方陣、佛蘭德），而這套制度知識原住民沒有。
  • 戰爭犬：披甲、受過撲倒訓練的大型獒犬。
  • 工程：為控制湖面，遠征隊下到 Popocatépetl 火山口用繩索垂吊取硫磺造火藥；並預製 brigantines 拆解，由無數人力搬運翻山，在湖上組裝下水。
  • 原住民的反制（他們確實在學）：以狹窄空間剝奪騎兵優勢（堤道、屋頂作戰、鑿牆洞穿行）；水攻（破壞堤壩淹城，金屬甲反而拖人下沉）；把擄獲的劍綁上長桿當長矛；用bolas 纏馬腿；拿俘虜的西班牙人當老師學弩與火器；曼科·印加（Manco Inca）親自學騎馬以示範「我們也能」。Cuzco 圍城戰中，若持續夜襲而非只白天進攻，守軍早就崩潰——但學習曲線太陡、時間太短。
  • 制度工程：歐洲堡壘的「星形棱堡」＋海權壟斷＝難以拔除的據點；阿茲特克與印加連攻城武器都沒有（無撞城槌、無投石機）。
行業 insight（AI 接管的隱喻）
  • 接管往往不是「更強文明碾壓」，而是「較小的外來力量 × 既有秩序的內部裂痕 × 少量技術優勢 × 外交狡詐」。技術差距可以很窄（鋼與馬，而非槍炮），勝負卻極端。
  • 單點脆弱性：高度階層化的系統，只要頂端被「擒獲」，整個系統就可用「傀儡」延續運轉——這是權力結構而非力量的脆弱。
  • 「數量」是被接管者最容易誤判的變量：原住民以為能利用外來者（「他們人少」），卻無法想像追隨而來的移民潮；AI 場景的對應物是：今天看似可控/可用的系統，其「未來規模」才是長期決定因素。
  • 組織優於血統：能汰換領導層、不被繼承危機綁死的組織（公司型）比王朝/個人魅力型更耐用。

爭議點
  • Dwarkesh 直言西班牙人的暴行是「字面意義的種族滅絕——不只是疾病，是蓄意的」，並追問其「人道動機」的敘事站不站得住腳；Sheppard 承認「就是最好的情況，也只是殖民過程的裝飾」。兩人對殖民的道德評價坦率而沉重。
  • 對蒙提祖馬的逆向評價：一般史學譴責他把科爾特斯迎入首都；Sheppard 認為那其實是他最好的選項——把不可控的「隨機變量」留在自己屋簷下，好過讓他在帝國腹地煽動附庸。真正錯誤是他自己留在首都成了目標（本可藉口朝聖／遠征、透過下屬治理）。
  • 歷史必然性的分歧：Dwarkesh 追問「重跑模擬，西班牙在多少比例的平行宇宙中仍會在數年內得手？」Sheppard 給出「取決於大輪子」但承認個人（科爾特斯若早死、阿塔瓦爾帕若不親入陷阱）確實可能改寫短期結局——兩人游移於決定論與偶然性之間。

Latent Space （主播：swyx + Vibhu；嘉賓：Alex Zhang，MIT）

Academia is for Ambition — Alex Zhang, MIT（RLM、harness 作為組合泛化器、agent swarm 的真相） RLMHarness 發布：2026-10-02 00:28 UTC（北京 10/2 08:28）｜片長約 1 小時 41 分

主題

從 GPU kernel（KernelBench／GPU Mode）一路談到 RLM（Recursive Language Models）：為什麼 harness 不只是「工具集合」而是「組合泛化器」、為什麼所有主流 harness 結構上其實一樣、以及未來你調用的「語言模型」為何可能是一整群看不見的 agent swarm。

嘉賓背景

Alex Zhang（@a1zhang）——MIT 博士生（第二年），RLM 論文第一作者；GPU Mode／前身 CUDA Mode 社群核心成員（由 Mark Saroufim 引介），KernelBench 相關工作、GPU Mode leaderboard 推手；曾在 Princeton 與 SWE-bench 團隊（John Yang、Carlos Jimenez、Ofir Press 等）共事；曾在 Sakana AI 暑期研究。主持為 swyx 與 Vibhu。swyx 把本集定位在 Latent Space 每年「發掘一位新星 PhD」的傳統——2024 是 Shunyu Yao（姚順雨，現騰訊首席 AI 科學家），2025 是 Jack Morris（Engram 共同創辦人），2026 是 Alex Zhang。

核心論點
  • ① Harness 是「組合泛化器」（compositional generalizer）。核心概念是 locally in-distribution：把一個 out-of-distribution 的整體任務，拆解成一連串每個都由 in-distribution 的 LLM call 完成的局部子任務。若每個局部 call 都落在分布內，「你大概就能拿到正確答案」。
  • ② 主流 harness 結構上根本一樣。「我愛 Claude Code、Codex、Pi、Oh My Pi、Prime Agent……但老實說，它們全都一樣。」多數設計決策相同（都是「trajectory as a prompt」的迴圈），差異主要在成本；他點名 Grok Bot 較不同。真正該被重新想像的，是 harness 能為模型做的事。
  • ③ RLM 的定義（極簡）。一個 RLM 就是：唯一工具是「程式碼」，模型可以程式化方式呼叫子代理（甚至呼叫自己），而它處理的 context永遠存在程式環境的某個記憶裡（檔案系統／REPL）。「這個抽象很原始——但它的設計與我們目前的做法非常不同，因此可能隨資料與環境大幅擴展。」
  • ④ 訓練 RLM 會自然跨任務泛化。用 RLM 訓練後發現：在一個任務（如檢索／彙總）學到的高層策略是相同的，於是短任務訓練能遷移到 8–30 倍長的任務；不同領域（數學 vs 寫作）只要 meta 策略相同也能遷移。而且這個論證可歸納遞迴——子代理解的子任務，可能又是同一種形式。
  • ⑤ Agent swarm 的真相：95% 是浪費，難的是「收斂」。「我相當確定，95% 的 swarm 完全沒用——你在燒 token。」OpenAI 的 swarm 之所以能解 Navier–Stokes，是因為它明顯被訓練成一個 swarm，不是「模型夠聰明就自然湧現」。「沒有一件難事是免費的。」
  • ⑥ Capability overhang：這是 skill／harness 問題，不是能力問題。Alex 認為，連「讓模型連續一個月穩定做好一份簡單工作」都做不到「這件事本身很蠢」——「我真的覺得我們能解決。這其實是 continual learning 問題。」他甚至主張：即使不用 RLM、不碰那些抽象，單靠設計一個 harness 就能做到。
  • ⑦ 未來你 query 的「語言模型」可能是整個 swarm。用戶只看到前端（像 Claude Code / Codex 那種可讀的串流），底下其實是「很怪、很複雜、但擴展性很好的 swarm / scaffold」——「這是相對安全的賭注。」
  • ⑧ Jev 的意義：打開「輸出空間」這個新設計維度。「語言模型只是在建模語言，它不必是一個自迴歸解碼器。」Jev 的價值不在「又一個分類器」，而在它逼問：你願意為輸出空間付出多少推理延遲／成本？如果只需要二元分類，為何要付 400 倍代價？他認為 Jev 對 RLM 特別有用，因為 RLM/swarm 最大的瓶頸就是慢。
  • ⑨ 學術的唯一護城河是「敢下大注」。「作為 PhD 學生，你能對幾乎任何事情為所欲為……如果你只想做業界會做的熱門 benchmark／harness，那你乾脆去業界實驗室。」最成功的研究「往往來自業界多數人不會看的問題」。好研究常以「這也太蠢了吧？」開場（RLM、Quiet-STaR、ReAct、SWE-bench 最初都被冷落）。
關鍵數據／事實
  • OpenAI 的「解難題」成本（近公開）：解 Navier–Stokes／ARC-AGI-3 用了 10,000 個 agent、88 小時、1,300 億 output tokens，以公開定價估計約 4,000 萬美元（Alex：「比我想的少」；Vibhu 補充總 agent 訊息量是這數字的兩倍以上）。
  • GPU Mode leaderboard：近期題目「幾乎所有解法都是 AI 生成」，但 top 10 中只有一個（由人類專家 Gauners 引導 AI 完成）在真實端到端系統中穩定——kernel 存在嚴重的 verification／reward hacking 問題。
  • GPT-5.6 寫出更高效 kernel，令 Terra 與 Luna 可能便宜 80%。
  • RLM harness 是首個近似解 ARC-AGI-3 的系統，早於 OpenAI Astrav；Prime Intellect 的 Prime Agent（8/5 發布）被引用為「自我改進的 RLM harness」。
  • 第三方 RLM 應用：Harvey（法律 AI）× Base 10 post-train RLM 於法律文件；Headlong（Andy Konwinski，前身 Terminus）做「持續思考、always-on 但昂貴可控」的 harness；DSPy 內建 RLM；ARC-AGI-3 Kaggle 上多個 harness 引用類 RLM 抽象（如 TUFA）。
  • Prime Agent 的設計：建於 Pi（極簡 harness）之上；唯一工具是 IPython，其餘工具以 Python module／Bash script 載入；含 continual harness（可自我修改技能、子代理、system prompt）與 persistent subagents（子代理可存活於原 agent 之外，可再互動）。
  • Dots：每個 Dot 擁有自己的雲端 Linux 電腦（與「雲端瀏覽器」或「你的電腦」不同）。

技術詳情
  • RLM 機制：context offloading（把 context 卸載到檔案/REPL）＋以程式碼執行＋遞迴子代理＋共享記憶。凡是「唯一工具是 code、context 存於 code 環境」者，皆屬此抽象。
  • 為何 harness 設計能改變泛化：傳統 harness 把整條 trajectory 當 prompt 不斷附加（「trajectory as a prompt」），多數情境最終都變成 out-of-distribution；RLM 則把計算拆成「meta-harness 或程式」，使每一步局部 call 都 in-distribution。
  • Loop transformers 與 harness 的同構：某種意義上 looped transformer 就是「在模型內部做 harness 迴圈」；由此可問——能否把 harness 的行為內化進 forward pass？能否只 loop 模型的一部分？能否 route 到不同子模組？「harness 選擇」與「模型架構選擇」之間的橋樑是開放問題。
  • Speculative programmatic tool calling（PTC）：模型寫程式碼時，很多工具是序列／阻塞的，應該提前並行啟動——類似 JIT + 靜態分析推斷變數。他認為在函數式語言（Lisp、OCaml、Effect-TS）更容易做 pipeline；「這其實是 no-brainer，尤其對 coding 與 RLM 類系統」。
  • Calibration：模型被問「你多有信心」時，只會吐出「最可能的下一個答案」（例如 43%），而非真實校準後的機率；Jev 的價值在於「grounded classification」——這是「反覆問它、以為你在用機率」與「真的拿到校準訊號」之間的巨大差異。
  • GEV／Neuralese：GEV 探討「語言模型不必是自迴歸 text-to-text 解碼器」；Neuralese 一節談模型「母語」——Alex 押注英文 + Python 的混合（能力反映訓練資料），不買「binary」的說法；swyx 引 Sapir–Whorf 假說與《Arrival》的「擴散式（一次顯現整句）vs 自迴歸」對比。

Machine Learning Street Talk （主持：Tim Scarfe；嘉賓：Shawn Wen，PolyAI CTO）

How a Voice Agent Learns the Rhythm of Conversation — Shawn Wen 語音 agent 發布：2026-10-01 20:00 UTC（北京 10/2 04:00）｜片長 70:10（4210 秒）

主題

語音 agent 為何比文本 agent 難——多出來的「時間」維度、端到端 turn-taking、真實噪聲資料，與企業部署的現實政治。本集與 PolyAI 合作製作。

嘉賓背景

Tsung-Hsien（Shawn）Wen——PolyAI 首席技術官（CTO）。PolyAI 專攻企業級語音 agent（客服中心、銀行、公用事業、物流、餐飲、酒店、零售外呼），自建語音辨識、LLM 與端到端語音模型。主持人 Tim Scarfe 本人有語音／音訊研究背景（本集大量使用頻譜圖、mel scale、Victor Zue、雞尾酒會效應等技術錨點）。

核心論點
  • ① 語音比文本難，因為多了「時間」。「語音是通往真實世界的一步。」文本世界已有海量文件與線上論文，連博士級物理題都不算難；但語音場景多了一個關鍵維度——時間。「我們還沒訓練模型去真正理解這個概念。」
  • ② 智能的本質是「適應」，不是「推理」。人類對話中的智能「不在於推理，而在於適應」——同一句話，對老人要放慢、給思考時間；對本地人要帶地方口音。傳統 cascade（ASR + LLM + turn-taking 三段）天生不協調，只能靠「多加一個偵測器、再 tweak 一個參數」硬湊，「非常 cranky，而現實根本不是那樣運作」，因此必須塌縮成端到端。
  • ③ 企業要的是矛盾組合。「他們想要 agent 像人一樣強大，卻又想要它像機器人一樣可控。」具體是：品牌化聲音（能正確念出品牌名）、可控、可審計；期待值錨定在「我團隊裡最好的人類」。採用曲線的關鍵是找到「效率」的切入點。
  • ④ 為何自建模型：大型通用語音模型「demo 很神、部署即崩」。最新 speech-to-speech 模型在 demo 中自然到「像奇點已至」，但一進客服中心就在各種地方崩掉——打斷太激進（老人第一次對 bot 說話、一直被打斷，極度挫折）。「前沿實驗室不是在為我們在意的東西（B2B 的真實對話輪替）優化。」
  • ⑤ 資料：過度清洗反而更差。真實 call 已含大量噪聲；團隊再刻意用生成模型疊加噪聲（例如「機器人念我的名字 ＋ 背景嬰兒哭聲」）。諷刺的是，傳統管線的「去噪／清洗」組件反而令新的對話推理模型變差——因為它從沒見過「被過度清洗」的環境。這直接呼應 Rich Sutton 的 The Bitter Lesson：失敗模式組合呈指數增長，端到端訓練能覆蓋大量失敗模式。
  • ⑥ 瓶頸已從「生產內容」轉向「驗證與審計內容」。組織內部已是 AI slop 滿天飛（Slack 大段 AI 文字）；「工程師從年初就一直在說：我們有太多 call 要 review，而我不信任 agent 做 code review。」他主張必須教育員工：自己讀過、同意，才轉發，不要轉發你沒讀過的 AI 文字。
  • ⑦ Harness vs weights：多數企業該先做 harness。企業想「擁有智能」，但唯一能 in-house 的是 harness（模型太貴、要大量 GPU）。Shawn 建議多數客戶先從 harness 著手，真的繞不過才微調權重；並提出一個新定位——語音 agent 當「前台」，品牌與「主腦」留在後台，企業不必擁有全部。
關鍵數據／技術
  • 模型：Dialog-RSN-1（audio-native）。底層仍是一個輸出文本的 LLM（因為企業需在 text 上施 guardrail，比在語音上容易），但原生接收串流音訊 chunks——輸入是 mel 頻譜圖，對模型而言更像「逐段影像辨識」任務。
  • 推理順序被反轉：① 音訊串流入時，模型先預測第一個 token＝turn-taking 訊號（對方是剛開始說／還在說／已說完；極便宜）；② 判定句尾後，因為音訊已在嵌入空間預處理好，不必從頭再編碼整句，直接預測回應（text 或 tool call，像典型 chat API 串流）；③ 回應後才生成 citations（企業可查到引用來源）；④ 最後才輸出 transcript（供審計／除錯）——「我們把舊的順序反過來了」。
  • 檢索也改寫：沒有 transcript 可 embed，無法用傳統 RAG；改為讓 LLM 生成「search 工具 + 查詢」（agentic search，本質是 tool call）。
  • 延遲工程：模型大小選對，模型處理本身延遲不大；cascade 時代真正的痛點是「何時判定句尾」的粗參數（太短會打斷老人、太長令人不耐）。端到端後由模型基於音框（含語速 + 語義）自行判斷——「如果我話講到一半暫停，語義未完成，agent 知道要繼續等」。加上自託管模型，避免網路長尾延遲（P99.5）。團隊正加入 latency-budgeted auto reasoning：模型自問「現在停在這能不能給好答案？能不能壓在 1 秒內？」——「像比賽答題倒數」。
  • 信任工程（人類心理）：思考時可播電梯音樂、打字聲、filler sentence；「AI 在電話上沉默 3–5 秒，用戶會恐慌」；contact center 有現成做法（等真人去問同事時會播音樂）。
  • 聲音選擇的外交學：最好表現的聲音通常帶地方口音（英國 Newcastle 口音因客服多來自當地而受歡迎；南美賭場客戶想聽「howdy」開場，最終仍覺「太過了」沒上線）。最自然的英文聲音，早期竟是「帶法國口音的法國聲音去講英文」——不完美令其真實。通用聲音（聯想到傳統 IVR）表現最差。
  • Benchmark 困境：公開語音 agent benchmark 不足且偏合成；語音資料隱私性高、難以公開。PolyAI 用真實 call 數據自建 benchmark（含延遲、ASR、指令遵循、引用、tool call 等維度），計劃在數月內公開。
  • production agent 每輪 output token 約 50 tokens（故語音的「認知負擔」遠小於長篇文字 agent）。

技術詳情（補充）
  • 雞尾酒會效應與 speaker diarisation：傳統 diarisation 假設「speaker1/2/3」標籤，是為 ASR 而生、並不自然；端到端後模型可原生感知 crosstalk，且可透過 prompt 控制（「不要回應背景插話」或「背景插話時也主動加入」）。關鍵差異在於「你如何訓練它、收集什麼資料、下什麼指令」。
  • 歷史錨點：Victor Zue（MIT）在 1990 年代即主張「光看頻譜圖就能辨識語音」；mel scale；傳統 RAG 論文。
