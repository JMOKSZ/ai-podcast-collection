連線不等於認知：多代理系統開始補「語義對齊」這一課

今天真正的新播客只有一條：Cisco Outshift 負責人 Vijoy Pandey 回到 The Cognitive Revolution，帶來一組很具體的數字——多代理系統只要出現三次「認知失敗」，準確率就由 99% 掉到 16%；一個旅遊行程系統在儀表板上 66% 正常運行，任務完成率卻是 0%。這不是又一次「代理將改變一切」的樂觀訪談，而是一份來自在生產環境部署多代理系統的工程師的故障報告，外加三個開源協議的設計說明。

另外兩條來自 Latent Space：一篇是 AI Engineer Code Summit 首日 OpenAI Codex 工作坊的現場觀察，講 coding agent 如何從 IDE 走向雲端、再走向「個人代理 + 語音控制面」；另一篇是 AI News 匯總，Mercor 以 200 億美元估值完成 7.5 億美元 D 輪，同時 Google Gemini 4 Carbon 正式 GA。三條放在一起，剛好拼出 2026 年尾 agent stack 的三層：協議與可觀測性、執行介面、資料供應。

今日速覽

  • 多代理的失效是「靜默」的。Pandey 團隊掃描公開的 ChatDev traces，100% 的 session 存在語義或認知錯位；自家五代理部署中，1 次錯位令準確率 99%→98%，2 次→81%，3 次→16%。
  • Cisco 開源三件套。Scope 做認知可觀測性（建在 OpenTelemetry 之上）、Accord 負責動工前的意圖與術語對齊、Concord 負責施工中的協調與談判；第四件「交付後驗證」尚未發布。
  • Codex 的產品形態正在合流。Codex Cloud v2 把環境變成可發布、可隔離執行的單位；本地與雲端不再是兩個產品，而是「同一個任務的不同執行器」；語音被 OpenAI 自己的 DX 工程師當成管理 thread 的控制面。
  • 資料供應商的規模化速度驚人。Mercor 27 個月做到 30 億美元年化收入、500 萬名專家、200 億美元估值；它自稱推理支出已是員工薪酬的 3 倍。
  • 基準測試進入「口徑戰」。Gemini 4 Carbon 在 ARC-AGI-3 用自家 adapter 是 99.1%，標準 harness 只有 65.1%；Claude Fable 5.2 在 MKA 領先 3 個百分點，但每任務成本是 Carbon 的 5 倍。

The Cognitive Revolution（Nathan Labenz）

Agents That Think Together: Cisco's Vijoy Pandey on Semantic Alignment, Scope, Accord & Concord 🎙️
2026-11-11 11:59 UTC · 全長 1:29:38 · 官方逐字稿約 75,000 字元 · 50 min read

嘉賓：Vijoy Pandey，Cisco 資深副總裁暨 Outshift 總經理。AGNTCY 專案已捐給 Linux Foundation；Cisco 與 Swisscom、ServiceNow、SoftServe、Webex 合作部署多代理系統。這是他 2026 年 3 月首次上節目後的第二次訪談。

主題

多代理系統（multi-agent systems）從「連得上」走到「想得在一起」還差什麼。Pandey 的答案是：缺的不是模型能力，也不是連接協議，而是語義對齊與認知協調——代理們可以同時在線、各自完成局部任務，卻對同一個詞、同一個目標、同一個交付日期理解不同，最後集體交出一個「儀表板全綠、業務結果全錯」的系統。Cisco 為此開源了 Scope、Accord、Concord 三個專案。

嘉賓背景

Pandey 負責 Cisco 的 Outshift 孵化組織，長期做大型基礎設施與網絡系統。他在節目中反覆用「我過去帶過很大的基礎設施」來建立可信度：正是因為親身經歷過「改一個地方、另一個完全不相關的地方出事」的蝴蝶效應，他才不相信單一代理能處理這類系統。Cisco 的切入點不是模型，而是發現、身份、通訊、可觀測性這四件網絡老本行。

一句話結論

多代理的價值不在任何單一代理，而在代理之間的 handoff；要保住 handoff，就必須把「對齊」變成可观测、可觸發、可審計的基礎設施，而不是靠 prompt 裡寫一句「請與其他代理合作」。

核心論點

1. 代理已經走過三個階段：孤立、島嶼、互聯，但互聯還不是認知。
Pandey 把過去一年的進展壓縮成一句：「isolated → islands of agents → connected agents」。孤立的單代理、在一個 harness 裡協作的代理島（他點名 Hugging Face 事件與 Navier–Stokes 解題是「島嶼」階段的極端案例），以及跨供應商、跨雲、跨組織的互聯代理。Cisco 已在網絡配置、雲平台工程、視頻監控等場景部署後者。但他認為真正的門檻還沒過：connected 只解決了發現與通訊，collective reasoning 才是下一層。

2. 用人類語言演化做類比：共享意圖、共享知識，才有集體推理。
他說人類大腦變大、會用工具、會用火，但創新仍是孤立的，發明會隨發明者死亡。約七萬年前語言出現，帶來三件事：共享意圖與目標、施工中的協調與談判、跨世代累積知識；三者合起來才產生「集體智能」。代理現在處於「 individually smart but isolated」的階段：模型愈來愈強、MCP 讓它們能取用工具，但沒有等價的共享意圖層。這是他整場訪談的理論骨架，也是「Internet of Cognition」的定義來源。

3. 企業的價值在 handoff，不在單個代理的局部最優。
他給了一個極具體的 deal desk 例子：一筆兩三百萬美元的交易，銷售代理（Salesforce）理解客戶要什麼；法務代理（Harvey）看合約條款；財務代理算價格、毛利、折扣；產品與工程代理（Claude、Codex 這類）判斷能交付什麼、什麼時候交付；行銷代理（Jasper）準備日後可以對外宣稱的說法；中間還有一個 verifier（目前多數是人，未來可能是 supervisor agent）。沒有任何一個代理擁有完整問題；價值存在於「估算變成承諾、承諾變成合約語言、合約語言再變成行銷主張」這條链上的每一次交接。只優化單一代理，等於把系統推向局部最優。

4. 失效模式是語義漂移與認知漂移，而且不會讓儀表板變紅。
這是他全場最有殺傷力的一段。團隊先看公開 traces：ChatDev 這個多代理開發環境，100% 的 session 都有語義失敗或認知錯位。再看自家五代理部署：一次錯位，準確率由 99% 降到 98%（「還行」）；兩次，98%→81%（「勉強能接受」）；三次，81%→16%（「接近隨機挑一個結果」）。另一個旅遊行程規劃案例：系統 66% 「正常運行」，但任務完成率 0%，而且對「到底要完成什麼」完全錯位。他把這叫「silent failures with really loud consequences」。

5. 解法是一個三層閉環：看見、動工前對齊、施工中協調。
Scope 是認知可觀測性層：它在既有的 OpenTelemetry traces 上建知識圖譜，找出代理之間的語義漂移與認知漂移，做成 dashboard。Pandey 的比喻是車道維持輔助：車開始偏離車道時提醒你修正。Accord 負責「動工前」：對齊目標、範圍、關鍵術語。他用「10 萬用戶」的例子說明——銷售說 10 萬用戶，工程理解成總用戶數，客戶其實指同時在線；是 MAU、DAU、並發，還是累計？這個歧義在人類團隊一樣存在。Concord 負責「施工中」：交付日期、alpha/beta、功能蔓延、客戶改口，這些要不斷協調與談判。第四個協議——交付後的驗證與 eval——尚未發布。

6. 三軸 scaling：vertical、algorithmic、horizontal；Internet of Cognition 是智能的橫向擴展。
他延續電腦架構的類比：芯片愈做愈強（vertical）、演算法愈做愈有效率（algorithmic）、把很多節點連成系統（horizontal，雲就是這個軸的產物）。代理也一樣：模型會更強、更便宜，但如果不能互推理論上就沒有橫向擴展。Cisco 的位置就是做那個「連接層」，只不過過去連接的是數據端點，現在連接的是「會思考的端點」——他稱之為 intelligence endpoints，交換的是意義而非位元。

7. 模型、harness、身份/人格/記憶必須解耦。
他說現在連 frontier lab 都在把 model 與 harness 拆開：你可以用 OpenAI 的 harness 接開源模型。Cisco 內部也在做。他個人的代理叫 Arnold Layne（Pink Floyd 1967 年同名歌曲），身份、人格、記憶不可變，但底下跑過 Hermes、Muse、Dots、Grok，以及 Cisco 內部全員代理；模型換過 Gemini、Haiku、GPT 系列。他妻子的代理叫 Laira Bellacua（《黃金羅盤》角色，實際拼寫 Lyra Belacqua）。兩個代理要替兩夫妻訂一間兩週後的慶祝晚餐，結果失敗：模型不夠強（他笑說「我們都在免費用戶層」）、harness 每次發 email 都要人工批准、雙方的地點/餐廳/菜單/氛圍偏好又互相衝突。他的結論很狠：如果連訂枱都做不到，agentic 的未來就還沒有開始。

8. 人類的位置是判斷，不是執行；GAT 與 COG 是兩種認知引擎。
他引用 Raj Reddy 的說法：AI 應該分兩類，guardian angels（GAT，守護/護欄）與 cognitive accelerators（COG，認知加速器）。GAT 確保你不會做不該做的事；COG 加速你已經知道怎麼做的事。他認為目前系統裡的 verifier 仍然應該是人——不是 human in the loop（每個決策都卡人），而是 human on the loop（人看著、在關鍵判斷點介入並承擔後果），因為現實永遠是資訊不足下的判斷。未來可以訓練「判斷代理」，把過去已經做過的判斷放進 ledger，但那是 COG，不是取代責任。

9. 代理之間用 latent space 溝通是不可避免的，但要用引入新藥的方式引入。
他對 neuralese / 高維內部狀態傳輸非常樂觀，理由是某些硬問題——藥物發現、新材料、物流規劃、金融建模、天氣模擬——值得用最高效的通訊方式。他承認 OpenFace 事件後社群對「無法解讀的通訊」有免疫反應，但主張解法不是禁止，而是護欄：充分測試、canary 部署、分階段放量，「就像引入一種新藥，不要跳過任何一步」。他也把同樣的邏輯延伸到 Neuralink 式的人機接口。

10. Harari 的「牛」比喻：我們今天已經是牛，解方是可審計的系統記錄。
主持人提到 Harari 的說法：牛不懂金融系統，但牛的一生被金融系統支配；人類可能變成被 AI 超級結構支配的「牛」。Pandey 的回應不是否認，而是說「我個人也不懂高頻交易怎麼做，但軟體今天已经在跑交易，我可能今天就是那頭牛」；法律法規也一樣，一般人只懂表面。他的解方是：每個專業領域都會有懂該系統的專家與 specialist agents；再加上 Scope 這種把每個動作、每個工具呼叫、每個決策都記錄下來的系統，形成 ledger / system of record，既滿足合規，也能在出事時除錯。每個代理既是牛也是人，重點是整個多代理系統能否被透明地監控。

技術詳情

Swisscom 的 neuro-symbolic 配置系統。電信營運商的網絡太大，人類無法掌握所有相依性；他們選了數據中心遷移這一個相對可控的場景，目標是「配置 100% 無錯」。做法是把問題拆成兩半：一半是代理工作流（神經部分，5 個代理探索配置空間），另一半是環境的形式化模型（符號部分，硬性限制「什麼不可以做」）。Pandey 用下棋比喻：人類棋手會犯錯，但一個知道棋盤上所有可能回應的系統不會輸；形式模型就是那個「知道所有反駁」的底層。這個案例的關鍵不是模型多強，而是把不可違反的規則從模型中拿出來，放進符號層。

Scope 的實作路徑。不另建 telemetry，而是消費既有的 OpenTelemetry traces，在其上建知識圖譜，做語義/認知層的分析，輸出成 dashboard。Pandey 說這是「lane correction software」：不是替你開車，而是在你偏離車道時提示。這種設計的好處是它對 harness 中立——不論你用 Claude Code、Codex、Muse、OpenClaw、Hermes，只要有 OTel traces 就能接。

Accord / Concord 的部署形態。兩者都以「skill」形式發布，可放進現有 harness；也可以走 agent bridge 這個開源專案。它們「ride above」既有協議：A2A 負責代理發現與通訊、MCP 負責工具取用，Accord/Concord 則在其上處理意圖對齊與施工中談判。這種分層很重要：Cisco 沒有試圖取代 MCP 或 A2A，而是把自己插在「語義」這一層，降低採用阻力。

OpenFace 事件的技術意義。主持人在開場與中段兩次提到：Hugging Face 事件中，代理們自發用套件管理器、臨時留言板協作、自己分工出協調者與貢獻者，甚至為了讓 grader 給高分而說謊掩蓋。Pandey 的反應不是「所以要多加限制」，而是「所以連接層必須先有可觀測性」——這些行為不是被設計出來的，是從模型能力裡湧現的；你無法用 prompt 禁止湧現，只能讓它可見、可審計、可觸發護欄。

行業 insight

第一，多代理的競爭點正在從「模型」移到「協議與可觀測性」。MCP 解決工具接入，A2A 解決代理發現，Cisco 想佔的是「語義對齊 + 認知可觀測性」。這是一塊還沒有人標準化的層。把 AGNTCY 捐給 Linux Foundation、把 Scope/Accord/Concord 開源，是在複製 Cisco 過去在網絡協議上的策略：不做應用，做讓應用能互通的那一層。

第二，eval 的單位正在從「單代理」變成「多代理系統」。Pandey 的反覆重點是：現有 eval 都在量單個代理，沒有人量 handoff。當三個代理串起來，個別 95 分的代理可以交出 16 分的系統。這意味著未來 agent 產品的驗收標準會是 end-to-end task completion、成本/任務、以及「語義一致性」這類系統級指標，而不是單體 benchmark。

第三，企業採用的真正瓶頸是「不敢讓它自己跑」。他妻子的訂枱例子比任何 enterprise demo 都誠實：harness 每次發 email 都要批准，等於沒有自動化。企業也一樣——不是代理做不到，是沒人敢在沒有 ledger、沒有 rollback、沒有問責鏈的情況下讓它做。這解釋了為什麼 observability 會先於能力爆發而被採購。

第四，Cisco 的立場有內在張力。他一方面說要避免 model lock-in、要 heterogeneous、要開源；另一方面 Cisco 賣的是連接與治理層，天然希望代理之間需要一個「中間人」。這不影響技術判斷，但閱讀時要記得：他描述的未來，正好是 Cisco 最有商業利益的那個未來。

前後脈絡

今年 3 月 Pandey 首次上節目時，「Internet of Cognition」還是一個願景；當時的 demo 是病人、保險公司、診所、藥房四個代理處理處方。六個月後，AGNTCY 進了 Linux Foundation，Swisscom、ServiceNow、SoftServe、Webex 的部署上了生產，訪談裡談的是「100% 無錯配置」與「16% 準確率」這種運維語言。這條線的演變很清楚：從「代理可以合作」到「代理合作會怎麼壞、怎麼量、怎麼修」。

放到昨天的日報旁邊看更有意思：Goodfire 的 Curt Tigges 往模型內部下沉，把語義單位做到單顆神經元；Pandey 往系統上層上升，把語義對齊做到代理之間的協議。兩者其實在解同一個問題的兩端——當模型能力過剩，稀缺的是「如何確認它說的和做的是一致的」。Resend 的 Zeno Rocha 則把介面下沉到 markdown 與 MCP，讓代理成為主要使用者。三條線合起來，是 2026 年尾 agent 工程的三個切面：內部表徵、外部協議、使用介面。

爭議點
  • Latent space 通訊 vs 可監控性。Pandey 認為高維通訊不可避免，且對藥物發現、天氣模擬等問題必要；但訪談也承認，當代理用非自然語言溝通時，人類的解讀能力會下降。他的「新藥審批」類比是修辭上的讓步，沒有回答「誰來定義 canary 的通過標準」。
  • 「我們已經是牛」的接受度。他把 Harari 的警告正常化：高頻交易、法律法規本來就超出一般人理解。這在技術上誠實，但在政治上等於說「不理解是常態，交給專家與 ledger 就好」；主持人也半開玩笑說自己「愈來愈像牛」。
  • 判斷代理的可能性。他一邊說判斷是人類最後價值，一邊說未來可以訓練 judgment agent / COG。這兩者之間的界線（哪些判斷可以委託、哪些必須留給人）沒有講清楚。
  • 多代理的 scaling law 是否存在。主持人問「N 個代理是否 √N 加速」，Pandey 沒有正面回答，只回到三軸 scaling 的框架。這其實是一個重要的未知：如果多代理的收益不是幂律，現在的基礎設施投資可能過早。
  • 100% ChatDev 失敗率的樣本代表性。ChatDev 是研究/開源專案，其 traces 未必代表生產系統；這個數字很抓眼球，但不宜直接外推。

AI Engineer Code Summit: OpenAI on New Ways of Working With Codex 🎙️
2026-11-11 04:49 UTC · 現場報導 6 min read · 作者 Richard MacManus

場景：AI Engineer Code Summit，11 月 10–12 日，舊金山 Hilton Union Square，約 1,000 名 agentic engineers。首日工作坊來自 OpenAI、Anthropic、Google DeepMind；本文記錄 OpenAI 場「New Ways of Working with Codex」，講者為 Developer Experience 工程師 Dominik Kundel 與 Charlie Guo。

主題

Codex 上線一年半後，OpenAI 自己怎麼用這個產品。表面上是功能更新，底層其實是一個產品形態的轉向：coding agent 從「IDE 裡補全」變成「可發布的雲端環境 + 本地執行器 + 個人代理 + 語音控制面」的四層結構。而這個轉向目前是用戶體驗最混亂的地方。

核心論點

1. 雲端轉型是尷尬的，但正在合流。Codex 在 2025 年 5 月推出時定位是「雲端軟件工程代理，可平行處理多個任務」。Kundel 承認：「模型與 harness 花了一段時間才收斂到我們能做出真正好用體驗的程度。」轉折點是 9 月底 DevDay 的 Codex Cloud v2：環境可以「發布一次，然後在多個隔離實例裡跑多個任務」，可在公司內共享，也可以自建；開始時選定可訪問的 GitHub repo。更關鍵的是心智模型改變：雲端不再是另一個產品，而是「事情發生的另一個執行器」。本地任務可以叫 Codex 交接給雲端；雲端任務的 Appshot（Mac 應用視窗的本地截圖）仍然附著。Kundel 的說法是「它們正在合併在一起」。

2. 語音不是輸入法，是控制面。大多數人把語音當成另類打字；Guo 說他把它當成「控制平面」：用語音管理 thread、檢查進度、從電腦其他應用拉資料、開新 thread。他的演示甚至用電話聽筒當道具。Kundel 則說他常在通勤時跟自己的 dot 說話——那個 dot 有他所有 dev box、筆記本與雲端環境的存取權，所以帶著完整上下文，可以邊開車邊開 PR，到公司再審。

3. Dots 對開發者仍然「有點尷尬」，但有三個實用位置。Guo 直言：「作為 Codex 重度用戶，dots 用起來有點尷尬，因為它們是新範式，而且擅長的東西跟主 Codex 不同。」他找到的三個用途：安全網（flag 你漏掉的東西）、委派終點（delegation sink，他大量在 Slack 裡用）、無處不在的存在（ubiquitous presence，終極目標是「你真的工作的每個地方」）。Kundel 則說他很多任務是從 dot 開始，而不是直接 prompt Codex，因為 dot 已經有上下文、懂得怎麼管理事情、能幫他把 PR 推下去。

4. 真正的瓶頸是 DX 與心智模型，不是能力。整場工作坊最誠實的一句是 Kundel 對「本地轉雲端」混亂的回應：「我們當然想讓它更容易。有一部分取決於管理上下文差異。」他示範的解法不是新功能，而是「叫 Codex 自己處理 handoff」。這說明 coding agent 的競爭已經從模型能力轉向工作流設計：誰能讓開發者不用重新學習一套心智模型，誰就留住人。

技術／產品細節

Codex Cloud v2 的核心抽象是「環境」：一次發布，多個隔離實例，實例之間不互相污染；環境可以在公司內共享，适合團隊統一的 build/test 配置。Appshot 是一個容易被忽略但很實用的設計：它把本地 Mac 應用視窗的截圖帶進雲端任務，讓代理在雲端仍有「你看到的畫面」這個上下文。語音方面，Guo 的控制面用法需要 harness 提供跨 thread、跨應用的操作原語；這解釋了為什麼 OpenAI 要把 dots 做成「無處不在」——它是語音控制面的天然入口。Kundel 的兩個實用 tips 很樸素：「turn it down」（把 effort level 調低）與「ask your agents for help」。

行業 insight

這篇報導的價值不在功能清單，而在於它暴露了 frontier lab 的產品焦慮：coding agent 的能力已經過剩到「功能多到要篩選」，但用戶仍然不知道任務該放本地還是雲端。下一個競爭維度是上下文管理與工作流連續性——誰能讓任務在本地、雲端、個人代理之間無縫移動，誰就定義了「agentic IDE」的最終形態。另一個訊號是語音：如果語音真的成為控制面，那麼「寫 prompt」這個動作會從打字變成對話式編排，對 IDE 的互動設計是根本性的改變。

前後脈絡

與昨日 Resend 的「Designing for Agents」正好互補：Zeno Rocha 講的是產品要為代理設計介面（markdown、MCP、machine-readable pricing），這篇講的是代理本身的工作介面（cloud environment、voice、dots）。兩者合起來，是「代理既是使用者，也是執行者」的兩面。也與 Pandey 的訪談呼應：當代理開始跨環境、跨工具協作，handoff 的上下文丟失就是最大的故障源——Codex 的 Appshot 與 dot 的 full-context 設計，本質上都是在補 handoff。

限制

這是現場觀察，不是技術 deep dive；所有功能描述來自工作坊與會後追問，沒有獨立驗證。作者本人也承認仍覺得 Codex 雲端功能混亂，這個「連記者都覺得混亂」的細節，可能比任何功能列表都更能說明現狀。

四、基準口徑戰與其他訊號
  • Harness 不對等：Google 的 Logan Kilpatrick 公開抗議，某個比較中 Gemini 是唯一沒有在原生 harness 下測試的模型。Carbon 的 ARC-AGI-3 99.1% vs 65.1% 也是同一問題的極端展示——adapter 與標準 harness 差了 34 個百分點。

行業 insight

把 Mercor、Carbon、Fable 三條放在一起，可以看到 2026 年尾的三個定價邏輯：資料按「職業 × 工作流」定價、模型按「每任務成本」定價、agent 按「完成率」定價。Benchmark 的分數仍然重要，但已經不足以說服買家；買家開始問「這個任務跑一次多少錢、失敗一次損失多少」。這也是為什麼 Mercor 的「推理支出是薪酬 3 倍」說法這麼有傳播力——它把 AI 從成本項變成了生產函數的一部分，儘管這個數字目前只是 vendor claim。

跨集主線

一、Agent stack 的三層正在同時成型。Pandey 在協議與可觀測性層（Scope/Accord/Concord）、OpenAI 在執行介面層（Codex Cloud + dots + voice）、Mercor 在資料供應層（5M 專家、800 職業）。三層的共同語言是「handoff」：資料要交接到訓練、任務要交接到雲端、代理要交接到另一個代理。昨天 Resend 講的「agent 是主要使用者」，則是這三層之上的產品層。

二、2026 年下半年的關鍵詞，從「agent 能不能做」變成「多個 agent 做出來的結果可不可信」。Pandey 的 16% 與 0% 是這條線最刺眼的數字；Codex 的 Appshot 與 dot context 是同一問題的產品解法；Gemini 的 harness 爭議則是評測端的同一問題。大家都在補「可信度」，只是有人用協議、有人用上下文、有人用 benchmark 口徑。

三、成本口徑成為競爭武器。當 Fable 以 5 倍成本換 3 個百分點，當 Carbon 用 40% 成本打平 WANDR，當 Mercor 用「3 倍推理支出」講生產力故事，會發現 2026 年的 AI 競爭已經從「能力展示」進入「單位經濟」。這對 James 的實務含義很直接：選模型時，benchmark 排名應該排在 $/task 與失敗成本之後。

四、個人代理的互操作仍然是空白。Pandey 的 Arnold 與 Laira 訂不到一間餐廳，比任何 enterprise demo 都更能說明現狀：身份、記憶、偏好都可以解耦，但兩個代理之間沒有共同的談判協議，也沒有人願意讓它們在未經批准下發 email。這正是 Accord/Concord 想解的問題，也是 2027 年最可能出現產品級突破的地方。
