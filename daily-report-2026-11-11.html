今日重點
  • Resend 的「agent 體驗」不是玄學，是 64/102。在一項 AEO 研究裡，Claude Code 在可抽出的 102 次 email 建議中，64 次把 Resend 排在第一位；SendGrid 只有 7 次第一，卻有 55 次被列為替代方案。Zeno Rocha 說這就是為什麼他把定價頁做成 .md、把 MCP 從 20 個工具加到 80 多個。
  • NaiveAI 的 2,100 tok/s 是上限，不是常態。實際 decode 約 984 tok/s（思考階段）／1,816 tok/s（回答階段）；中位數回答 3.1 秒，但 HLE 難題平均花 108,500 個 completion token，是 GLM 5.3 Flash 的 9 倍。快，是用更多 token 換來的。
  • Goodfire：砍掉 90% 神經元，模型幾乎不掉分。Qwen3.6-35B-A3B 的 500 萬顆 MLP 神經元裡，只留每層最極端的啟動值，reasoning 先崩（迴圈、過度自我檢查），用 1 億 token 微調一天就回到平價或更好；某些 ARC-AGI 分數甚至上升。
  • 「74% 恢復」不是「理解 74%」。那是把描述預測的啟動值貼回模型後，修復了 ablation 造成的 KL 散度傷害的 74%（按傷害加權）。Curt Tigges 自己說得很清楚：你可以讀懂每一顆神經元，仍然沒有反工程整個模型。

Designing for Agents — Zeno Rocha, Resend 🎙️

發布：2026-11-11 04:05 HKT（2026-11-10 20:05 UTC）｜長度 1:25:52｜形式：訪談，官方 VTT 逐字稿 109 KB 全片可讀

agent experienceAEOMCPdeveloper tools

主題：一封「為什麼 agent 老是推薦 Resend」的偵探故事。swyx 開場就說，他本來是 Cloudflare Email 的用戶，域名、DNS、DKIM 都設好了，結果 Claude Code 還是叫他加 Resend。他請來 Resend 共同創辦人兼 CEO Zeno Rocha，把这件事拆成兩半：一半是「agent 怎麼選工具」（AEO／AX），一半是「選中之後，信到底怎麼送到信箱」（deliverability）。

嘉賓背景：Zeno Rocha，巴西人，前端出身，2013 年做出 Dracula 編輯器主題（至今仍是很多人認識他的原因），曾是 GitHub 上最活躍的開源開發者之一（前 20 名，2020–22）。React Email 的作者，Resend 共同創辦人兼 CEO，YC W23。公司全遠端約 50 人。他在節目中說，Resend 目前 430 萬用戶、12 萬付費用戶、1,000 萬美元 ARR。他沒有 email 基礎設施背景——「如果我一開始知道 email 有多難，我大概不會開這家公司。」

核心論點
  • 論點一：agent 時代的分發，是在「模型讀得到的地方」贏，不是在 Google 首頁贏。Resend 2023 年才起步，SEO 落後 Twilio、Postmark、Mailgun 十幾年，正面搶關鍵字几乎不可能。他們的做法是把 docs 寫到極長尾（「Python + Django 怎麼設」這種），再把每一個行銷頁面加上 FAQ、llms.txt、以及可 append .md 的 markdown 版本。Zeno 的說法是：模型不會去拖一個 JavaScript 定價滑桿，所以定價頁的 .md 必須直接把表格寫出來。
  • 論點二：AEO 的重點不是「被提到」，是「被正確描述」。他某個週日做競品分析，問模型「用 Resend 發 120 萬封信，跟 X、Y、Z 比誰便宜」，結果模型把 Resend 的價格講得亂七八糟，還說「Resend 的定價很不透明」。他於是把定價頁的 markdown 版本補齊，幾天後再問，答案就對了。這件事的副作用是：他現在有兩個真相來源（HTML 與 MD），必须手動同步——他承認「這完全很鳥」，但這就是做 email 的代价。
  • 論點三：MCP 的工具數量不是越少越好，覆蓋率才是。Resend 的 MCP 從上線時 20 個工具以內，長到 80 多個。Zeno 說早期大家擔心「工具太多模型會混亂」，但他現在看不到這個問題；真正的難點是把 dashboard 的長尾（用量、帳單、邀請成員、刪帳號）也搬進 MCP，而「做到 100% 覆蓋非常非常難」。他與 Cloudflare 的 Code Mode（只暴露 search() 與 execute() 兩個工具）是兩種相反路線，節目裡沒有裁判，只有各自的取捨。
  • 論點四：deliverability 是一場「跟濫用者反著做」的遊戲。他的原則是預設信任（不設人工審核），但一看到 bounce rate、complaint rate 異常就立刻封鎖並聯絡。他舉例：最近有一組日本集團帶了約 20,000 個域名進來，全是不同 TLD、不同註冊商；他們看域名年齡、網站是否回 200、是否用 lookalike 域名。正常寄件者要做的，正好是這些事的反面：慢慢加量、穩定寄送、維繫互動。
  • 論點五：免費層不是慈善，是人才與產品的來源。他說自己當年靠 Heroku 免費層這類產品才能開始寫程式，所以不願意砍掉 Resend 的免費層；即使這代表要自己吞下大量濫用成本。他甚至把「應徵方式」做成 CLI／API：用 CLI 投履歷的人，他會多看一份——「這種人願意下載、認證、走完整個流程，動機不一樣。」

技術詳情
  • 定價頁的雙軌渲染：同一頁提供 HTML 與 .md；/pricing.md、/security.md 直接 append 即可取得。JS 滑桿對 agent 不可見，所以 markdown 版本改成靜態表格。追蹤靠 server-side（Datadog），因為一般 analytics 腳本抓不到 .md 請求。
  • MCP 的權限模型：要做 remote MCP，先得補 OAuth，再補 RBAC，逐一檢查每個資源的存取邊界；完成後才有 observability 與 Datadog dashboard，最後才是「跟 labs 談上架」。第一版 MCP 其實是 a16z 的 Yoko 寫的本地開源版，後來才轉到官方 org。
  • 投遞管線：大量寄送要排隊、分批、依互動調整；100,000 封信不能一次倒給 Gmail，否則會被 throttle。要把最活躍的收件人排在隊首，讓 Gmail 先看到正向互動。多提供商之間要錯開，還要買 IP block、看 IP 歷史、分散到不同 IP pool、隨時間平衡。
  • 信譽單位的轉移：早期是 IP 信譽，現在更多是域名信譽；因此用子域名分流（transactional / marketing / 甚至 confidential.resend.com 寄投資人信）。共享 click-tracking 域名有「吵鄰居」風險：一個客戶拿去釣魚，整個域名被列黑，別人的正常信也遭殃——所以他們做 custom tracking domains。
  • SES 的隱藏成本：表面每封便宜，但還需要 SNS 收 bounce/complaint 事件、CloudWatch 存 log、SQS 排隊、自己寫 webhook；「footprint 會比你想的大很多」。Resend 早期就建在 SES 上，現在往下自己做傳輸層，寄送路徑已改用 Go，追求 P99。
  • Inbound 與多信箱：下一個產品是把「收信」抽象成可程式化的多信箱（read / mark unread / star / label API），目標是 Front、Missive 那類 shared inbox 的 API 版；Zeno 說已經有 feature flag 給 swyx 試。
行業 insight

這一集最重要的不是 email，而是「分發管道正在被模型重寫」。Zeno 的說法很直接：以前不確定用什麼工具，你會問 Google，拿到三個比較頁；現在你只會拿到一個答案，而人多半會選最無摩擦的那個。這使得「免費層」與「免登入」變得比以前更重要（他提到 WorkOS 的 Michael Grinich 在推 off-MD／免認證使用），但也更難防濫用。另一個 insight 是規模不一定有優勢：Twilio 買下 SendGrid 後，Zeno 認為他們「睡著了」，把注意力移到別的通道；新世代的工具可以在開發者心智裡慢慢取代老巨頭，而不需要在 enterprise sales 上正面對撞。

前後脈絡

Latent Space 過去幾集一直在問同一個問題：agent 時代的軟體長什麼樣。Supabase 那集談「把文件與定價寫成 agent 讀得懂的形狀」，這集是把同一套方法論搬到 email，並且補上「選中之後」的現實摩擦：DNS、IP、黑名單、詐騙。與 11-09 的 Handshake AI 那集（資料市場）相比，這集是需求端——不是「模型要什麼資料」，而是「模型會推薦誰的 API」。

爭議點
  • 80 個工具 vs 2 個工具。Zeno 承認工具變多目前沒出問題，但這與 Cloudflare Code Mode 的極簡哲學直接衝突；他也沒有給出「何時會翻車」的判準，只說會持續觀察。這是一個尚未有答案的架構賭注。
  • 「AEO 是否真的可歸因」。swyx 自己在節目裡說「我不確定這有沒有用」，Zeno 也承認很多做法是丟到牆上看看。64/102 是一個有說服力的觀察，但不是因果實驗。
  • 免費層與濫用的張力。他一邊說預設信任、一邊說要快速封鎖；對大規模濫用者（20,000 域名）而言，這種「先信任再封」的模式是否反而提高了他們的 ROI，節目沒有正面回答。

The Neuron Basis: Goodfire's Curt Tigges on Agentic Interp, Monosemanticity & Reverse Engineering 🎙️

發布：2026-11-11 03:09 HKT（2026-11-10 19:09 UTC）｜長度 1:56:17｜形式：深度訪談，官網提供 AI 生成逐字稿與編輯註記

mechanistic interpretabilityneuronsGoodfirealignment

主題：單顆 MLP 神經元到底能不能讀？過去幾年的共識是不能——表徵分散、疊加（superposition）、一顆神經元混雜多個概念，所以我们需要 SAE 這類輔助模型把內部狀態攤開。Curt Tigges 與 Nick Cammarata 的新論文〈Neurons as an Interpretable Basis〉（搭配 Nick 十月中爆紅的長文〈Neural Networks Are Already Clean〉）直接挑戰這個共識：神經元比想像中乾淨，而且現在有 agent 可以大規模地把每一顆讀完。

嘉賓背景：Curt Tigges，Goodfire 的 Member of Technical Staff。Goodfire 是專做機械可解釋性的新創，Nathan 說這是他們系列訪談中「可能最重要的一集」。共同作者 Nick Cammarata 是前 OpenAI 研究員，長文在 AI 圈引發大量討論；這篇論文是把長文中以視覺模型為主的論證，延伸到語言模型，並量化。

核心論點
  • 論點一：MLP 神經元是「可枚舉的」，不是「不可解的」。Curt 的說法很克制：神經元「比學界至今以為的更可解釋」；你通常不需要同時有很多顆啟動；即使一顆神經元有多個意思，那也是「一組緊湊的意思」，不是幾百個混在一起。真正該問的問題不是「它是不是單義（monosemantic）」，而是「你能不能把它代表的所有東西列出來」。
  • 論點二：會變乾淨，一半是工具的功勞，一半是架構的功勞。工具面：agent 可以掃過一顆神經元所有啟動的情境、做最小對比、改句子、steering，然後提出假設並反覆修正。架構面：現代模型幾乎都用 gated MLP（SwiGLU），gate 與 up 兩組獨立參數相乘，等於讓神經元自帶一個小開關；Curt 說在他們看過的模型裡，ReLU／GELU 比 SwiGLU 難讀。
  • 論點三：稀疏不是「刪神經元」，是「每個 token 只留最極端的訊號」。在 top-K 方案裡，每個被路由到的 expert 只保留最強的 64 顆（共 512 顆），其餘歸零，等於壓掉約 88% 的啟動；在百分位方案裡，則是依每顆神經元自己的歷史分布，保留最極端的正負值，其餘用該神經元的平均值取代（因為雙極性，平均值接近零但不是零）。兩種方案的差別在於「誰決定什麼重要」：百分位是資料集相關的、全域的；top-K 是讓模型自己決定、逐 expert 的。
  • 論點四：讀懂一顆神經元，可以用另一個模型來「考試」。Neuron Scientist 產出一段 paragraph 長度的描述，再由另一個模型（節目中使用 JEV）只看描述、逐 token 預測這顆神經元會有多強（0–9 分），把預測值貼回已被 ablation 的模型，量測 KL 散度傷害恢復了多少。結果是 74%（按傷害加權）。這不是「74% 準確率」，也不是「理解 74% 的模型」。
  • 論點五：很多神經元是「動詞」，不是「名詞」。它們不是偵測一個物件，而是送一個訊號，讓下游去做某事：更有信心、再檢查一次、停下來、換路徑、指出「這個數字錯了」。Curt 把這稱為控制流（control flow）；Nathan 的總結是「routing energy or activation through the model」。
  • 論點六：事實不在神經元裡，在神經元的連接裡。500 萬顆神經元不可能裝下比 500 萬更多的離散事實，但 10 顆神經元之間的網路可以有遠多於 10 條路徑。「A neuron is not a fact. But the fact is in the connections between neurons.」他舉例：一組幾十顆的神經元社群，決定哪些畫家屬於印象派、新印象派、後印象派。

技術詳情
  • SwiGLU 的兩個訊號：輸入進入神經元層後，分別走 up projection 與 gate projection（兩組完全獨立的參數矩陣），gate 的輸出再乘上 SiLU，最後與 up 的結果相乘。Curt 的例子：gate 偵測「烹飪」這個語境，up 偵測「大蒜」這個食材，兩者相乘才會強烈啟動。這讓神經元可以當一個小型的 conjunction／switch，同一個神經元在不同語境下被不同下游讀者解讀。
  • Neuron Scientist 的工作流：（1）收集數千個讓該神經元啟動的 prompt；（2）按輸入連接、文本本身、或共同啟動的神經元分群；（3）frontier model 提出統一假設，並可生成／改寫句子、做最小差異對比、steering、觀察啟動變化；（4）另一個獨立系統只看描述，逐 token 打分，預測值貼回模型；（5）失敗則回饋、修正描述，迭代。最後由 helper agent 生成一頁結果。
  • 驗證方法不只一種：除了 KL 恢復，還包括「只給描述、不給範例，讓另一個模型寫出一段比資料庫中任何文本都更能啟動該神經元的文字」，以及「給定序列，判斷該神經元是否應該啟動」——後者是較簡單的任務，準確率常在九成以上。
  • Double-negative activations：當 gate 與 up 同時為負，乘起來變正。Curt 說這種情況「很怪」：有時整批移除不影響，有時會弄壞 reasoning 或記憶；把這些啟動以相反 token 順序貼回、甚至從完全不同的序列貼回，reasoning 都能恢復。含義未明，是後續研究題目。他也提到 Gemma 4 用的 ReGLU 在設計上不會出現這種情況，而 Kimi K3 的神經元幾乎不用這種模式。
  • 稀疏後的 reasoning 修復：一開始模型會迴圈、過度自我檢查、對答案沒信心；但知識與基本推理機制還在，問題更像「校準」而不是「能力」。1 億 token 微調後，MMLU、MedQA、GPQA Diamond、SuperGPQA 都回到與原模型相差一分以內；部分 benchmark 甚至提升 5–15 分。Curt 的解釋是：內部干擾變少，「最有信心的東西會浮上來」（the most confident thing rises to the top）。
  • Expert 的語義集中度：他們檢查的 expert 大多集中在 1–3 個主題，例如法律／憲法判例、代數、時間單位與時間流逝、醫療細分主題。這與「expert 不可解釋」的舊說法相反；也讓 router 的工作變得可理解——它必須有某種可辨識的專家分工，否则不可能在 256 選 8 時做出有意義的選擇。
  • SAE vs 神經元：Curt 引用 Shabalin & Piotrowski 的新工作（〈Comparing Sparsified MLPs and Transcoders〉）：許多 transcoder 特徵其實就是神經元，或是會共同啟動的稀疏組合。他的說法是：用 transcoder 替代 MLP 的 loss，比直接保留 top-K 神經元更高；因此對 MLP 而言，直接讀神經元更划算。SAE 仍有價值的地方是 residual stream——那裡幾何更複雜，還有 superposition，甚至 SAE 未必是最佳工具（Goodfire 自己有 block-sparse featurizers 的路線）。
行業 insight

主題：一家叫 NaiveAI 的中國公司發布開源權重模型 Naive-N0.5-Flash，主打「每秒塞進最多 token」，聲稱峰值可達 2,100 tok/s。Latent Space 用同一組題目與 app 生成任務，把它跟 DeepSeek V4.1 Flash 1017、GLM 5.3 Flash 對比，結論是：速度是真的，但「快」有很大一部分是用更多思考 token 換來的。

背景：Naive-N0.5-Flash 不是從零訓練，而是從小米 MiMo-V2.5 繼續訓練。MiMo-V2.5 是 310B 參數的稀疏 MoE、15B 活躍參數、48T token 訓練；NaiveAI 在其上再做約 3.25T token 的繼續訓練，其中約 3T 是在固定 1M 上下文、固定 learning rate 下完成，並把注意力層改成 DeepSeek Sparse Attention（DSA）。推論端搭配自研 NaiveRT 引擎與 FP8 draft model 做 speculative decoding。官方定位是「 largely built by AI、被訓練來做 AI 研究本身」，長期目標是 recursive self-improvement。

核心論點／發現
  • 速度確實驚人，但峰值不是常態。官方數字：thinking 階段 decode 約 984 tok/s、answer 階段約 1,816 tok/s，單一秒峰值約 2,100 tok/s。Latent Space 明確標註「treat this as an upper bound, not a typical rate」。
  • 中位數快很多，平均數沒有。30 題混合測試中，中位回答時間 3.1 秒（Naive，thinking），對比 GLM 5.3 Flash 5.3 秒、DeepSeek V4.1 Flash 10.1 秒；但平均是 45.3 秒 vs 45.0 秒 vs 86.9 秒。換句話說，大多數問題很快，少數難題拖得很長。
  • 難題上它反而更慢。HLE-Diamond hard 題平均 89.8 秒，DeepSeek 是 79.7 秒；而且平均 completion token 達 108,500，是 GLM 5.3 Flash 的約 9 倍、DeepSeek 的約 11 倍。中位數只有 3,200 token——少數極長的推理把平均拉高。
  • 寫 app 的品質在線，但不穩定。三個任務中，它的太陽系 3D 場景最好（有太陽黑子、地球夜面城市燈光），樹的生成與 DeepSeek 打平（但關掉 thinking 的版本完全做不出可用 app），ray tracer 正確但 JavaScript 效率不如 DeepSeek。
